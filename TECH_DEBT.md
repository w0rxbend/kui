# KUI technical debt register

Debt is recorded when it is taken, not when it hurts. Every row names the ADR or task that
accepted it, the reason, the exit condition and an owner. Rows are closed by a commit that
references the row id.

**ADR-048 (2026-09-05) replaced the Scala.js and Laminar frontend with TypeScript, SolidJS and
Vite.** Four rows below — TD-013, TD-015, TD-016 and TD-020 — describe defects in code that has
since been deleted. They were marked *superseded* rather than *closed*, because "the code is gone"
is not the same statement as "the problem is gone": whether an equivalent defect exists in the
TypeScript frontend had not been assessed, and a row silently closed is a question nobody asks
again. Assessing them is the exit condition each names.

**On 2026-09-06 two of them were assessed, and the assessment went both ways.** TD-016 is closed on
exactly the evidence its own exit condition asked for, read out of a real build's Vite manifest —
and the *other* half of that exit condition, the build rule that would catch the same regression
without a browser, was not built, so it is now TD-022 rather than a sentence inside a closed row.
TD-013 is *not* closed: the sentence written into it when it was superseded — that CodeMirror and
uPlot are now used through their own published TypeScript types — was an assumption nobody checked,
and it is false. That is the failure this register exists to catch, and it happened inside the
register itself, so it is worth naming here: a row rewritten from what the rewrite *expects* to be
true has stopped recording anything.

**Later the same day, TD-022 closed too, and the manner of it is the point.** The rule its exit
condition asked for exists as `frontend/scripts/bundle-shape.mjs` and runs in CI — but the row is
closed on having *run the check in both directions*, green against the real manifest and red against
one edited to move a feature out of the entry's `dynamicImports`, rather than on the file existing.
TD-016 became TD-022 by being closed on a check nobody had run; a register that repeated that would
be recording nothing twice. **Rows are ordered by id.** TD-022 was filed between TD-020 and TD-021
and has been moved, because a register that is not in id order is a register a reader stops
scanning and starts searching, and the row they were looking for is the one they then fail to find.
