# KUI technical debt register

Debt is recorded when it is taken, not when it hurts. Every row names the ADR or task that
accepted it, the reason, the exit condition and an owner. Rows are closed by a commit that
references the row id.

**ADR-048 (2026-09-05) replaced the Scala.js and Laminar frontend with TypeScript, SolidJS and
Vite.** Four rows below — TD-013, TD-015, TD-016 and TD-020 — describe defects in code that has
since been deleted. They were marked *superseded* rather than *closed*, because "the code is gone"
is not the same statement as "the problem is gone": whether an equivalent defect exists in the
TypeScript frontend had not been assessed, and a row silently closed is a question nobody asks
again. Assessing them is the exit condition each names.

**On 2026-09-06 two of them were assessed, and the assessment went both ways.** TD-016 is closed on
exactly the evidence its own exit condition asked for, read out of a real build's Vite manifest —
and the *other* half of that exit condition, the build rule that would catch the same regression
without a browser, was not built, so it is now TD-022 rather than a sentence inside a closed row.
TD-013 is *not* closed: the sentence written into it when it was superseded — that CodeMirror and
uPlot are now used through their own published TypeScript types — was an assumption nobody checked,
and it is false. That is the failure this register exists to catch, and it happened inside the
register itself, so it is worth naming here: a row rewritten from what the rewrite *expects* to be
true has stopped recording anything.

**Later the same day, TD-022 closed too, and the manner of it is the point.** The rule its exit
condition asked for exists as `frontend/scripts/bundle-shape.mjs` and runs in CI — but the row is
closed on having *run the check in both directions*, green against the real manifest and red against
one edited to move a feature out of the entry's `dynamicImports`, rather than on the file existing.
TD-016 became TD-022 by being closed on a check nobody had run; a register that repeated that would
be recording nothing twice. **Rows are ordered by id.** TD-022 was filed between TD-020 and TD-021
and has been moved, because a register that is not in id order is a register a reader stops
scanning and starts searching, and the row they were looking for is the one they then fail to find.

**On 2026-09-12 a row was closed, a row was amended rather than duplicated, and six were filed —
and the reason the amendment is written into the preamble is that the register nearly grew a second
copy of a row nobody had closed.** Wave 10's ksqlDB packet drafted two new rows as *TD-035* and
*TD-036*. Both ids were taken (the style-gate exemptions, and `build.mill` outside the style gates),
and the subject of the first — `KsqlObjects.of` leaving `unreadable` unbounded — was **already
filed, as TD-040**, by wave 9's adversarial pass, with the same exit condition. A register that
accepts a draft's id without reading its own table produces two rows for one defect and closes
neither. So: **ids are allocated by reading the last row of the table, never by counting**, and an
amendment to an open row is preferred to a new row on the same subject.

**And since 2026-09-12 that is a gate rather than a convention.** Until then
`./scripts/feature-matrix-check.sh` had never opened this file at all, so the sentence telling the
next writer which id to use was read by nobody, and the duplicate above could be made again by one
paste. The block below is compared against the table on every run, in both directions: the id it
publishes has to be one past the highest id the table holds, and no two rows may carry the same id.

**And what that gate reads is two pieces of arithmetic, which is worth stating because this
register has now been wrong about itself in the one way the block cannot see.** The comparison
below opens the table's first column and nothing else: the published id against the highest id in
the table, and the ids against each other. It never reads a row. **Nothing in this repository
mechanically checks that a row marked `open` still describes the tree** — and at the wave-12 close
three rows did not. TD-049, TD-050 and TD-052 each described a defect that wave had repaired, each
with an exit condition this tree already met, under a green `feature-matrix-check` run that had
just counted their ids.

Wave 13's W13-01 derives the sweep's roster from the `<!-- checked: -->` markers on disk instead of
a hand-written list, which is what puts the region below into the quotation sweep. **And the shape
it reads is narrower than the sentence that stood here, which said a row attributing *a sentence* to
a file by path is compared against the file it names.** Measured rather than described
(`quotation_attributions`, `scripts/feature-matrix-check.sh`): what is compared is a **quotation
written as a marked span after a backticked path** — the span backticked or *italic*, eight
whitespace-separated words or more, with a backticked path earlier in the same block, `**bold**`
struck out before any of it is read and a path recognised only when the token ends in `.md`,
`.scala`, `.ts`, `.tsx`, `.yaml` or `.sh`. A false sentence written in plain double quotes is read
by nothing, and W13-02's verifier appended exactly one inside the region below and the run stayed
green at 439 claims; rewritten as a backticked path plus the same words in italics, the same command
answered *"docs/operations/masking.md: … is absent"* and refused the run. That is the only reader
this file has beyond the arithmetic, and it reads a quotation and not a claim. If you are reading
this and appending such a span — in that shape — inside the region below leaves
`./scripts/feature-matrix-check.sh` green, that item did not land and this paragraph is the thing
to correct.

So the staleness of this register is caught by a person reading exit conditions at a wave close,
and nothing else. **That is why every row carries a command.** A row whose exit condition is a
sentence about how the code should feel cannot be re-run by the next reader, and a row that cannot
be re-run is a row that will be closed on a transcript — which is how TD-047 came to publish a
false measurement for a whole wave. When a row is closed here, the command and what it printed go
into the row, and not the phrase *closed by wave n*.
