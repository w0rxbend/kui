# WHAT IT IS EVIDENCE FOR. ADR-052 refuses three of the figures SCREENS-V4.md draws. A refusal is
# only distinguishable from an endpoint nobody wrote if the absence is on the record, so:
#
#   * there is NO purgatory percentage. `PurgatorySize` below is a queue length -- 481 parked Fetch
#     requests, which is ordinary long-polling on a broker with consumers -- and the broker
#     publishes no ceiling anywhere in the other 12,968 lines to divide it by.
#   * there is NO per-client.id byte rate. Nine lines in the whole capture carry a client label,
#     three values between them, all on the broker's own `app_info` and replica-fetcher beans and
#     none of them a byte rate; and there is no client-quota metric family at all. What IS
#     dimensioned per producer is the TOPIC, and those lines are below.
#   * there is NO record-size distribution. The capture contains zero `_bucket` lines and no
#     histogram of message size under any name. `BytesInPerSec / MessagesInPerSec` is a mean, and a
#     mean is what the endpoint answers.
