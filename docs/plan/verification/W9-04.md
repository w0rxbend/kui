Confirmed. The packet's process-hazard note is worth repeating and is worth extending: node
block-buffers stdout to a pipe, so the output file above sat at **0 bytes for the whole ~18-minute
run** — an empty output file is not evidence that a sweep is hung. And do not wait on
`pgrep -f "a11y-stories.mjs"`: the waiting shell's own argv contains that string, so the pattern
matches the waiter and the loop never ends. Wait on a PID (`[ -d /proc/<pid> ]`).

**A second hazard this pass hit and the packet did not record:** `npx --yes http-server … &` leaves
**two** processes — the `npm exec` wrapper and the `http-server` child that actually holds the
socket. `kill $!` reaps only the wrapper and `:6017` stays bound. Kill the listener you find with
`ss -ltnp`, and re-check the port rather than trusting the kill. (Done: `:6017 FREE`.)

Two `http-server` processes that are **not** this pass's and not W9-04's are still listening:
`:6018` (npm exec pid 4016 / http-server pid 4057, 22 h old, serving a `scratchpad/sb-w706` directory)
