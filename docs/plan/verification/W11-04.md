## 5. The two headers, and what they say now

**`record.ts`.** The header promised *"the printed figure is always in `[0, 1000)`"* over a ladder
that stopped at `TB`, so `formatBytes(1.5e15)` — an ordinary size for a retained log — printed
`1500.0 TB`, the exact four-digit-under-a-three-digit-unit defect the `999.95` threshold exists to
remove. `PB` is on the ladder (the spelling `feature-topics` had chosen independently, which is what
made the merge lossless) and the sentence is **scoped**: `[0, 1000)` at every unit below the last
one. The last unit still saturates — `formatBytes(1.5e18)` is `1500.0 PB` — and the header now says
so and argues for it rather than denying it. `record.test.ts` pins all three points.

**The duplicate is gone.** `TopicListPage.tsx` exported a second `formatBytes`, re-exported from
`feature-topics/src/index.tsx`, so two functions with one name and one meaning were both public
surface. They disagreed about more than rounding: the kernel's promotes at the value that *rounds*
to the next unit (`999.96 B` → `1.0 kB`), this one promoted at a bare `1000` and printed `999.96 B`;
its byte branch was `String(value)` unrounded, which is the shape that once put `81.2359955010432 B/s`
on the cluster dashboard. The name still exports from `TopicListPage.tsx` because four files in the
package import it from there and those files are not in this packet's `Owns` — what is gone is the
second implementation, which is the whole of the defect. `topics.test.tsx`'s three pinned figures
are unchanged under the merge and are now also pinned in `record.test.ts`, so the merge is asserted
on both sides.

## 6. Two things decided in the open, because inheriting them again was the alternative

### 6.1 The stat-tile rosters: production now holds one

There were **four** hand-written rosters of the same six tiles, and the brief names them: `STAT_ORDER`,
`overview.render.test.tsx`, `e2e/shell.spec.ts:468` and `e2e/traffic.spec.ts:142`. There was in fact
a fifth inside the first file — `StatRow` wrote the order out again as six JSX elements in sequence,
so a tile added to `STAT_ORDER` appeared on the unasked row and not on the real one, with every count
assertion still green.

`StatRow` now draws `STAT_ORDER` through `STAT_TILES`, a `Record<StatId, …>`. **Production holds one
order**, and a seventh id is a compile error until somebody says how it draws — which is a property
no roster of literals has, in any file.

`overview.render.test.tsx`'s literal is **kept, deliberately, and the file says why**. Deriving it
from `STAT_ORDER` would turn both cases that read it into tautologies: they would assert that the
page draws what the page says it draws, which is true of any page. That literal is the **design's**
copy — §3.2's list, transcribed once — and it is the only thing in this repository that can notice
production and the design disagreeing. Two copies with different provenance is the right number;
four copies with the same provenance was not.

The two `e2e` rosters are `frontend/e2e/**`, which is W11-02's. Filed there — see §7.

### 6.2 The 1,144 hidden-table dashes: the filed repair would have made the page worse

W10-01's verifier counted 1,144 bare `<td>—</td>` cells under `panel-throughput` and `panel-latency`
and filed them as carrying *"no `aria-hidden` and no visually-hidden alternative"*, beside
`feature-topics`' `Quantity`, which pairs its dash with *"not known"*.

Read against the source, **the comparison does not hold and the prescription is the wrong repair**.
`ChartDataTable.tsx:45` prints `format.ts:20`'s `ABSENT` into each cell of a
`<table class="kui-visually-hidden">` — a table hidden by clipping rather than `display: none`
precisely so it stays in the accessibility tree, reached through the plot's `aria-describedby`.
`Quantity` draws a **visible** dash and hides words beside it, so `aria-hidden` on the glyph is
right there: the words are the screen reader's copy. This table has no visible copy. It *is* the
screen reader's copy. `aria-hidden` on those cells would delete the only rendering an unmeasured
bucket has for the one audience that cannot see the gap in the bars.

What is genuinely wrong is narrower: a reader announces that cell as an em dash — *"dash"*, or
silence — where the sighted reader gets a visible gap **and** a caption counting the gaps in words.
The repair is an absent-spelling prop on `ChartDataTable` (*"not measured"* in a table nobody looks
at, the em dash wherever a figure is being replaced on screen), and that is one change under
`frontend/packages/kernel/src/components/charts/`, which this packet does not own. Written into
`ThroughputCard.tsx`'s header and cross-referenced from `LatencyCard.tsx`, and filed in §7 **as this
rather than as the `aria-hidden` the original finding asked for**.
