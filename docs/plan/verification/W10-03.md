## 3. Findings — rules that stayed green under mutation

### F-1 · The published cost of the capability gate is wrong: the cheapest attack is ONE line, not two

| | |
| --- | --- |
| **File** | `scripts/feature-matrix-check.sh`, `service_state_fact` (line 2404) |
| **Severity** | The packet's own house-rule-17 measurement, published in the script header and in `TECH_DEBT.md` TD-023, overstates the price of the attack by 2×. |
| **Exact mutation** | Insert **one line** as the second line of `service_state_fact`'s body: `if [[ -n ${declared_service_state[$name]+x} ]]; then printf '%s' "${declared_service_state[$name]}"; return; fi` — then move `connect` and `ksql` into **Not built:** in `README.md`. |
| **Suite command** | `./scripts/feature-matrix-check.sh` |
| **Observed** | `404 claims checked, all true.` **EXIT=0**, every section count unchanged (self-check 7, rows 30, …, capability-claims 35), with `README.md:126` publishing ``**Not built:** `acl`, `quota`, `connect` and `ksql`.`` |

**Why the two-reading design does not see it.** The claim site and `audit_service_states` are two
statements, but they call **one** fact reader. `service_state_fact` is a global function and
`declared_service_state` is a global array, so a body that consults the roster makes *both* readings
compare the label with itself. `service-roster` is not reached (all eleven directories are still
named, merely under wrong labels), `service-count`/`service-routed-count` still count off disk, and
`service-audit-coverage` still balances at 9 = 9.

**Why the fixture does not see it.** `verify_service_fact_independence` is called on line 2592,
**before** `check_marked_file` populates `declared_service_state` on line 2595. The fixture proves
independence only in the state where there is nothing to depend on. This is an ordering hazard of
exactly the kind the packet's own "a fixture that shadows `ledger` silently checks nothing" surprise
describes, committed one section later.

**The case that would close it.** Call the fixture a **second** time after the blocks are read, with
the roster seeded against it:

```bash
verify_service_fact_independence_after_blocks() {
  local root=$fixtures/services contracts=$fixtures/Contracts.scala answer
  declared_service_state[fixture-routed]='Built and routed'   # the lie a mutated body would echo
  answer=$(service_state_fact fixture-routed "$root" "$contracts")
  unset 'declared_service_state[fixture-routed]'
  scope capability-claims "service_state_fact after the roster is read"
  claim service-fact-roster-independence "" \
    "$answer" "Not built but routed" \
    "\`service_state_fact\` answered \`$answer\` for a fixture service the roster claims is \
\`Built and routed\`; the fact reader is reading the claim, so the claim site and the audit are \
one statement wearing two hats."
}
```
Called after `audit_service_states`, with `close_section capability-claims` moved 35 → 36 and
`service-fact-roster-independence` added to `registry[capability-claims]`. That restores the
published two-line price, because the audit and the claim site then have to be edited separately.

### F-2 · Prose inside the checked block is still invisible — the exact sentence the packet exists to stop can be written back, with **zero** script lines

| | |
| --- | --- |
| **File** | `README.md` (inside `<!-- checked: capability-claims -->`), gated by `check_capability_region` in `scripts/feature-matrix-check.sh` |
| **Severity** | This is the packet's headline promise — *"the gate that can now see a sentence"*. It sees a **list of backticked tokens**, not a sentence. |
| **Exact mutation** | Append one sentence **inside** the marked block, after the **Not built:** paragraph and before `<!-- /checked -->`, changing nothing else: `Neither Kafka Connect nor ksqlDB is built: KUI has no Connect screen and no ksqlDB screen.` |
| **Suite command** | `./scripts/feature-matrix-check.sh` |
| **Observed** | `404 claims checked, all true.` **EXIT=0**, all nine section counts unchanged. |

`check_capability_region` reads only ``\`name\``` tokens that follow one of the three literal
`**<label>:**` markers in `service_labels`, and `report_unclaimed_figures` refuses only digits and
**bold** number words. Free prose inside the region carrying a product name — which is the shape the
original defect had, *"No Kafka Connect, no ksqlDB"* — is struck out by nothing and compared by
nothing. The region therefore guarantees its three lists and nothing else that is written in it.

**The case that would close it.** A `capability-prose` claim over the block's residue text after the
three labelled lists have been consumed: build a service-identity alias map out of the block's own
lists (`connect` → `Kafka Connect`/`Connect`, `ksql` → `ksqlDB`/`KSQL`, …, read from a table beside
`service_labels` so that adding a service forces adding its alias), then refuse any residue sentence
that names an identity together with a negation token (`no`, `not built`, `neither`, `nor`,
`without`). Driven by a fixture in both directions — one block whose prose agrees with its lists,
one whose prose contradicts them — so the refusal has a failing case that arrives.

Until then, `docs/overview/README.md`'s new paragraph *"it compares one thing that is not a
figure"* should say which thing: the roster, not the prose around it.
