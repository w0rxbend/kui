### F-1 — `TerminalWatch.seen` is not a latch, and nothing new holds it

| | |
| --- | --- |
| **Rule** | Once a terminal SSE line (`event: done` / `event: error`) has gone past, the watch must never un-see it. It is what decides whether the gateway appends its own `event: error` to a stream that already ended. |
| **File** | `services/gateway/api/src/kui/gateway/api/StreamProxy.scala:150` |
| **Exact mutation** | `.flatMap(complete => seen.update(_ \|\| complete.exists(isTerminalLine)))` → `.flatMap(complete => seen.update(_ => complete.exists(isTerminalLine)))` |
| **Suite command** | `./mill --no-daemon services.gateway.api.test.testOnly kui.gateway.api.StreamProxySuite` |
| **Result** | **GREEN — 0 failed, 0 ignored, 16 total** on one of four runs. The other three reddened only the *pre-existing* `aTerminalEventSplitAcrossChunkBoundariesIsStillSeen` (see F-2). **Neither of W10-06's two new cases ever went red.** |
| **Cost** | Any chunk arriving after the terminal frame — a `:` comment keepalive, a final flush, a stray `\n` — clears the flag. `withTerminalEvent` then appends `event: error` after a `done` the upstream really sent, and a stream that ended perfectly reaches the browser as one that broke. That is verbatim the defect the packet's own new case (`theTailOfAChunkIsCarriedIntoTheNextOne`) says the mechanism exists to prevent. |
| **Closing case** | In `StreamProxySuite`, extend `theTailOfAChunkIsCarriedIntoTheNextOne` (or add a sibling) with a **fourth** `observe` carrying a non-terminal complete line after the terminal one — e.g. `chunkOf(": keepalive\n\n")` — and assert `sawTerminal` is *still* true. That reddens under the mutation above and is unreachable from `withTerminalEvent`, for the same reason the two new cases are. |
