## The five items

### 1. The third skip, decided in the open

`deployment/quickstart/kui-quickstart.yaml` ships `alerts.thresholds.diskUsedWarningPercent: 1`,
with the reason, the cost and the counter-recommendation written beside the key. The alternative —
the case seeds and reverts — was rejected because the threshold is configuration, changing it needs
the gateway restarted, and a browser case that restarts the shared stack takes every other case in
the run down with it.

**Measured here rather than inherited from W10-02**, whose verifier could not reproduce the packet's
seeded-stack claim. On the stack brought up from this tree, `/api/v1/clusters/quickstart/alerts/events`
answers `openCount: 1`, `total: 1`, one item:

```
"title": "Log directory /tmp/kafka-logs is 48% full on broker 1"
"detail": "threshold 1% · broker-1:/tmp/kafka-logs"    "resolution": null
```

Exactly one event, from one rule (`disk-usage` reports `openEvents: 1`; the other three report 0).
It re-opens after acknowledgement — `AlertRules.evaluate` counts only events that are still open, so
the next pass at `evaluationInterval` (60s) opens a fresh one — which is what makes the case
re-runnable against a long-lived stack rather than green once per boot.

**The acknowledgement case moved to the end of `shell.spec.ts`.** Acknowledging moves the open count
twice within a minute, so every case that reads the feed and then asserts a figure off the page now
runs before it, and nothing after it reads alerts. Ordering rather than a tolerance: a tolerance is
an assertion that has stopped being one.

`alerts.spec.ts`'s header said the reader had to set this key by hand and revert afterwards. That
sentence was true and is now false; it is rewritten rather than left.
