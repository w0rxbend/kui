## 8. Does it do what the packet was asked, or merely exit zero?

It does the thing. The placement argument is not decoration: the mask is applied inside `decode`,
both filters are handed the masked record, and `BrowseUseCaseSuite` has cases in **both** directions
including the search-oracle one (`the string filter reads the masked text, so a masked value cannot
be searched for`). The refusals in `MaskingConfig` are real refusals with real messages and a case
each. The engine's dangling `docs/operations/masking.md` reference was replaced with a sentence that
says the file does not exist, which is better than the alternative.

**The gap between the report and the tree is the gap between "the mask is applied" and "the mask is
applied to the right topic".** Every case in the two use-case suites uses a `RecordMasking` fake of
the shape `(_, _) => …`, which discards the cluster and the topic. That is why **F1** and **F2** are
green: the product's decision of *which* rules apply — the only thing `topicKeysPattern` and
`topicValuesPattern` exist for — is made in the use cases and asserted nowhere. `MaskingEngine`'s own
scope matching is well tested, and `ConfiguredRecordMasking` is well tested given a topic; the
argument hand-off between them is not. This is A1's clue in its exact wave-8 form: the fixture could
not express the failing input, because the fake never had the input.

No panel renders a zero or an em dash for this feature — it has no UI — but the row that stands in
for one, `docs/FEATURE_MATRIX.md:367`, currently tells a reader the opposite of what the code does.
