## 1. `docs/operations/masking.md:47-49` — a false invariant with a security rationale

**Before.** *"Three things hold for all of them … **A masked value is never longer than the value it
replaced.** A mask that padded a four-digit field out to sixteen characters would announce that the
field was not a card number, and somebody counting characters would learn what the mask was
hiding."*

It is false for `kind: replace`. `MaskingEngine.scala:202` is
`case MaskingKind.Replace(replacement) => Some(Json.fromString(replacement))` and `:229` is
`case MaskingKind.Replace(replacement) => replacement` — the literal, verbatim, with no length
bound. `replacement: "<redacted by policy>"` over a four-character field returns twenty-two
characters.

**After.** The bullet is scoped to `mask` (and `remove`, which returns no value at all), states the
`replace` exception with the reason it cannot be closed, tells an operator who is relying on the
length side channel which kinds to use, and says in its own words that the page invited the reliance
until wave 11.

**And the same sentence was in production.** `MaskingRule.scala`'s `## What it protects, exactly`
published the invariant unscoped too — the kind table three declarations above scopes it correctly
to the `Mask` row, and the prose under it did not. Both are repaired, and each now names the other.

## 2. The ungated rule this packet owns — `MaskingMetrics.otel4s` → `.noop` in `MessageWiring`

**The defect, as W10-04's verifier filed it.** `MessageWiring.scala:129` was the only place that
decided which `MaskingMetrics` the running process holds, and nothing asserted the choice:
`MaskingMetrics.otel4s[F](meter)` → `MaskingMetrics.noop[F].pure[F]` left
`./mill -k services.message.__.test` at **1442/1442 SUCCESS** while `kui.masking.applied` was never
emitted in production again. `MaskingMetricsSuite` drives the real adapter directly,
`ConfiguredRecordMaskingSuite` drives a counting fake, and neither can see which of the two RUNS.
W10-A2's stopgap read the composition root's **source text**.

**The seam, landed.** `MessageWiring.maskingFor[F](clusters, meter): F[RecordMasking[F]]`,
`private[app]` — the same widening `describeMasking` already carries — holding the production
expression and called from `make`. `MessageWiringSuite` now takes that function, hands it a meter
over an in-memory SDK reader, masks `payments.settlements` through what comes back, and reads the
points off the meter: the series is present, both targets are recorded, and the `cluster` and
`topic` attributes are the ones a panel filters on.

**The mutation, and the thing worth reporting about it.** The plan's mutation line —
`MaskingMetrics.otel4s[F](meter)` → `MaskingMetrics.noop[F].pure[F]` — **does not compile**:

```
[warn] services/message/app/src/kui/message/app/MessageWiring.scala:235:7
      meter: Meter[F]
      ^^^^^  unused explicit parameter
[error] No warnings can be incurred under -Werror
```

Extracting the decision into a function whose only other job is to consume the meter turned
`-Wunused:explicits` into a second gate on it: the one-word edit is now refused outright and the
attacker has to write a second, visible one. That is W10-A1's finding (3 of 25 mutations refused by
the compiler) reproduced deliberately rather than by luck.

The second, visible edit —
`MaskingMetrics.otel4s[F](meter).as(MaskingMetrics.noop[F]).map(ConfiguredRecordMasking.of…)` —
compiles, and:

```

    nothing recorded kui.masking.applied for a masked read, so this process holds a silent adapter
```

`MessageWiring.scala` restored from bytes saved before the edit, `md5sum`
`883b8f783faf584d1c8f66d070b5501f`, and green again at 8/8.

**One thing the new case is *not*.** It does not use `OtelJavaTestkit.inMemory`, because
