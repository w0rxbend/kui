## 3. Three assertions that could not fail, and one that accepted every outcome

These are the most useful findings in the packet, because each one is a **green case guarding nothing**.

**`O5` — PKCE.** `OidcRelyingPartySuite`'s authorization-URL case asserted
`url.contains(s"code_challenge=${OidcRelyingParty.codeChallenge(verifier)}")` — the product compared
against itself. Replacing the SHA-256 digest with the verifier's plain bytes (PKCE downgraded to `plain`
while the request still says `S256`) kept all twelve cases green. Closed by pinning **RFC 7636 Appendix
B's own vector**: `dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk` →
`E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM`.

**`I24` — the password upper bound.** `PasswordRulesSuite`'s "an enormous password is refused" was written
as `check("a" * (MaximumLength + 1))`. Raising `MaximumLength` from 1,024 to 64 MiB kept it green. The
bound is a denial-of-service bound on a key derivation function reachable without a session. Closed with
an absolute figure: an 8 KiB password is refused, and `MaximumLength <= 8192`.

**`F7` — the per-record filter deadline.** `CelFilterEngineSuite`'s deadline case accepted `Right(_)` as
well as `Left(Timeout)` — "a trivial program can legitimately finish inside a one-nanosecond window" —
so it had no failing input. Deleting `.timeoutTo(limits.evaluationDeadline, …)` from `CelFilterEngine`
left `libs.filter.test` **and** `services.message.__.test` (1,442 targets) green, and takes with it
`FilterError.Timeout`, `consecutiveTimeoutLimit` and the entire per-record budget. Repaired by asking a
*population* instead of one evaluation: a one-nanosecond deadline cannot be met fifty times running; a
deadline that is not applied is met every time. Both directions are asserted. Three consecutive
unmutated runs: 24/24 green each time. Under the mutation:

```
==> X kui.filter.CelFilterEngineSuite.an evaluation that outruns the deadline is a Timeout, not a hang
    no evaluation of 50 hit a one-nanosecond deadline, so no deadline is being applied
```

**`O3` — the ID token's expiry.** "An expired token is refused" is green with `checkClaims`'s expiry
branch disabled, because nimbus's own `DefaultJWTProcessor` rejects a past `exp`. What only KUI's line
refuses is a token carrying **no `exp` at all** — a login that never stops being one. Closed with a
token built without an expiration claim.

### 4.1 `G10` — keeping an equivalent mutant equivalent (packet item 4)

W10-A1 argued `SessionMiddleware.scala`'s `session.fold(PrincipalKind.Anonymous)(…)` → `Bearer` down as
equivalent, correctly: it is a CSRF fail-open that is unreachable **today** because nothing outside
`/api/v1` declares a non-safe method. That is equivalence by accident of the route table, and nothing
was checking the accident. The first `POST` added under `/ui/`, or under a new prefix, turns it into a
live hole with nothing going red.

The invariant is now a case — `everyMutatingRouteTheGatewayServesSitsInsideTheSessionMintingSet` — and
it needed **a production edit rather than a case**: `SessionMiddleware.needsSession` now has a second
form taking already-split path segments, because a `ServerRequest` cannot be conjured out of an
endpoint's path template. That is the one production line this packet leaves in the tree, and its
scaladoc says what it is for. The case also refuses to pass vacuously: it fails if the set of non-safe
endpoints is ever empty.

## 5. The compiler gates, measured (packet item 5)

`-Werror` with `-Wunused:*` **refused 14 of 73 mutations outright**, before a single test ran. Four
distinct messages were observed:

| Message | Example |
| --- | --- |
| `unused private member` | deleting `LoginUseCase`'s decoy-hash verification stranded `DecoyHash` |
| `unused import` | deleting `ChangePasswordUseCase`'s `PasswordRules.check` stranded `DomainError`; deleting `CelFilterEngine`'s `timeoutTo` stranded `cats.effect.syntax.all.*` |
| `unused explicit parameter` | disabling `checkClaims`'s issuer branch stranded `provider` |
| `unused pattern variable` | dropping the expected version from a password write stranded `existing <- store.get(…)` |

**Where it fires, and where it does not, is a sharper rule than "3 of 25".** It fires when a guard's
*inputs* stop being read — which is what deleting a branch usually does. It does **not** fire for:

- a constant changed (`MinimumLength`, `MaximumLength`, POSIX `600` → `644`, 32 random bytes → 1);
- a boolean flipped (`httpOnly = true` → `false`, `handleError(_ => false)` → `true`);
- **any condition with `&& false` appended.** Every binding stays read and the file compiles clean.

So the honest summary is: `-Wunused` raises the cost of **deleting** a guard by one edit. It raises the
cost of **disabling** one by nothing at all, and disabling is the cheaper attack. Of the 14 refusals,
every one was defeated by a second edit that took under a minute, and in 10 of those 14 the rule turned
out to be gated anyway.

## 6. Equivalent mutants, argued down

Kept out of the denominator, as wave 9 and wave 10 did.

**`I9` — `SingleUseTokens.remember` no longer prunes expired entries.** The bound is applied on every
write and sorts by `expiresAt` ascending, so expired entries are always the first dropped. With pruning,
`alive` holds `k` live entries and the bound drops `1 + k − capacity` of them. Without pruning, the map
holds `k` live plus `e` expired and the bound drops `1 + k + e − capacity`, of which the first `e` are
exactly the expired ones — leaving the same `1 + k − capacity` live drops. No token's fate changes; only
how much memory is held between two writes, which the trait exposes no way to observe.

**`I17` — `Pbkdf2PasswordHasher.constantTimeEquals`'s length term set to 0.** `verify` derives with
`keyLengthBits = expected.length * 8`, so PBKDF2 returns exactly `expected.length` bytes and
`left.length ^ right.length` is always `0`. The term is dead by construction, not by coincidence.

**`O10` — `OidcRelyingParty` echoing the provider's error body.** The mutation replaces
`InfrastructureError.Upstream(label, status)` with `InfrastructureError.Unreachable(label, echoed)` —
and `Unreachable.message` is `s"$upstream could not be reached"`. The `cause` never reaches a response.
The redaction the comment claims is enforced one level down, in `KuiError`'s own ADT, not at this call
site. The comment is true; it is true for a different reason than it gives.

## 8. Two things that cost this packet time, and are worth writing down

**`./mill a.test b.test` runs zero tests and exits 0.** Extra words after a test target are passed to the
test framework as a *name filter*, not as a second target. Measured on this tree:

```
$ ./mill --no-daemon libs.filter.test services.message.__.test
kui.filter.StringContainsFilterSuite finished: 0 failed, 1 ignored, 0 total
kui.filter.CelFilterEngineSuite      finished: 0 failed, 1 ignored, 0 total
548/548, SUCCESS
```

Two suites, **0 total**, exit 0. A first pass of this packet's `libs/filter` sweep reported all twelve
mutations green on exactly that command; re-run correctly, eleven of the twelve were gated. Any
acceptance line of the shape `./mill x.test y.test` is a gate measuring nothing — this is W11-05's class
of finding, in the build tool rather than in a style task. *(The same mechanism is what made the
auth-only re-runs above cheap: `./mill services.gateway.api.test 'kui.gateway.api.auth.*'` is a
legitimate and much faster way to confirm a new case goes red.)*

**Two sessions on one `out/` directory serialise, and contaminate each other's source tree.** For most
of this packet's gateway window another packet was running `./mill --no-daemon services.gateway.api.test`
in a loop (the `StreamProxy` determinism measurement W11-A2 was asked for). Mill locks the workspace, so
a run that takes 105 seconds alone took 11 minutes; worse, a mutation of mine sitting in
`AuthRoutes.scala` is compiled into *their* run. The fifteen-mutation gateway sweep was **abandoned
twice and the production files reverted immediately** for that reason, which is why §7 lists eight
mutations as not measured rather than as clean. **A mutation sweep and a flake measurement cannot share
a working tree.** If wave 12 runs both, they need separate checkouts.
