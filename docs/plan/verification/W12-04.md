### The rule, and why it is not *navigated or opened a dialog*

The Overview-level question — *a press navigates or opens a `role="dialog"`* — is right for a header
action and wrong for a frame: the theme glyph repaints, the appearance glyph opens an anchored
popover and the bell opens an anchored panel, and none of those three is either. The widened sweep
asks the weakest question that still refuses the defect: **a press changes the address or changes
the document.** `document.documentElement` is the comparison, not the mounted host, because the
theme control writes its answer onto the root element.

Links are asserted to have a destination rather than pressed, which is the branch the old case took
and for a jsdom reason: jsdom refuses a navigation to another document, so a clicked `<a href>`
changes neither side of the question and every link would pass for the wrong reason.

Each press gets a **fresh mount**. Pressing the bell opens a panel that draws controls of its own,
so a sweep that pressed down one inventory would be pressing a frame its own earlier presses had
rewritten. The control is found again by position and its identity re-asserted, so a re-order fails
loudly instead of quietly pressing something else.

### A gate that was order-dependent for ten minutes, and how it was caught

The first version of this sweep was **green under `vitest -t` and red under `pnpm test`**. The toast
store in `@kui/kernel` is module-level, so a *"Switched to staging-eu-01"* receipt left by a case ten
`it`s further up was inside the first mount's inventory and gone from the second's. The sweep now
excludes `.kui-notice-stack` with the reason written beside it. **The lesson is the one the wave
file states about `./mill a.test b.test`, in another runner: a filtered run measures a different
thing from the suite, and this one would have shipped green.**

## 5. `ClusterSelector` — deleted, and here is the argument

**Deleted.** Component (214 lines), stories (8), styles (~130 lines of
`packages/shell/styles/34-chrome-topbar.css`), the `describe` block in `chrome.test.tsx` (**7** cases
— the wave file and TD-042 both say eight; the count on disk was seven), and the export from
`packages/shell/src/index.ts`.

The decision is not *"it has no callers, so delete it"*, which would be a chore. It is that **the
design decided against it and the component outlived the decision.** The shipped switch is `EnvRail`:
one always-visible tile per environment in the 48px column, and `EnvRail`'s own header says why —
a dropdown hides the one fact an operator needs in peripheral vision, which is the cluster they are
about to break. `Overview.tsx` names the same reason twice for refusing to open a chooser from
`/ui`. So the two exits TD-042 offers are not symmetric: *"give it the caller it was written for"*
means shipping the control the design rejected, which is a product decision and not a repair-wave
item, and this wave's own preamble says a packet writing a capability has misread its brief.

Three further facts that made this safe rather than brave: nothing outside `packages/shell` imports
`@kui/shell` (checked over every `package.json` and every source in `packages/`), so the export is
internal despite being public; `[data-testid="cluster-selector-trigger"]` has resolved to zero
elements on every screen of a running stack in three separate waves' measurements; and its eight
stories were being counted in the a11y sweep's published story total, which means a component nobody
can reach was inflating a figure this repository publishes about its own coverage.

**Five comments that referenced it are repaired rather than left**, which is house rule 25's shape
applied to a deletion: `Overview.tsx:507` and `:550`, `shell.test.tsx:545`, `e2e/shell.spec.ts`'s
`M08` header and `e2e/brokers.spec.ts:386`. `grep -rn "ClusterSelector\|cluster-selector"` over
`frontend/` now returns only past-tense sentences in those headers.
