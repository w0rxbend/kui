### 5.3 The `ksql` decision, decided against a running stack

**Decision: `--with-auth` keeps no `ksql` block, and it is a decision now rather than drift.**

The reason was not the one this packet expected, and it was measured rather than argued. Signed in
as `admin` through the form, against a stack `quickstart.sh --with-auth` had just built:

```
POST /api/v1/auth/login (admin)                                     -> 200, roles ["operators"]
GET  /api/v1/clusters/quickstart/ksql/objects                       -> 403 KUI-FORBIDDEN
GET  /api/v1/clusters/quickstart/connect/connectors                 -> 200, quickstart-file-source RUNNING
POST /api/v1/clusters/quickstart/connect/quickstart/connectors/quickstart-file-source/pause
                                                                    -> 403 KUI-FORBIDDEN
GET  /api/v1/auth/me (admin)   -> TOPIC, CONSUMER, CLUSTERCONFIG, SCHEMA and nothing else
GET  /api/v1/auth/me (viewer)  -> TOPIC [MESSAGES_READ, VIEW], CONSUMER [VIEW]
```

The **403 on ksqlDB with no ksqlDB configured at all** is the whole answer: an unconfigured feature
is supposed to answer `200 not_configured`, and the fold refuses before it gets there, because
`ksql.objects` declares `ResourceRequirement.unnamed(Resource.Ksql, KsqlView)` and **no role in
that file carries a `KSQL` permission**. Adding the block alone would buy a configured feature whose
first screen is a 403 for both accounts — worse than the row being hidden by ADR-032.

The contrast in the same pass is what makes it a decision rather than a shrug: the Connect **list**
answers 200 for the same principal, because ADR-021 keeps Kafbat's rule that a list filters rather
than refuses, while `pause` on that same connector is 403. So this deployment already ships one
feature that can be read and not operated. Making ksqlDB work is two edits (the block **and** a
`KSQL` permission), which is a change to what the deployment demonstrates; it is filed for W12-01
rather than taken here.

### 5.4 Two more false sentences, found while measuring the above

Neither is in the brief; both are in this packet's `Owns` and both are the wave's own class.

1. **`kui-quickstart-auth.yaml` and `quickstart.sh` described one screen in two contradictory
   ways.** The YAML said the `viewer`'s create/edit/add-partitions/empty/delete controls *"are not
   on the screen. They are not disabled — they are absent"*; `quickstart.sh`, printed four lines
   after that file is mounted, says they *"are still on screen, greyed out, and each says why"*.
   The interface settles it: `writeBlockedReason` in `frontend/packages/kernel/src/data/mutation.ts`
   returns *"You do not have permission to …"* and `TopicListPage` passes it as `disabledReason` on

   so and names the two files that decide it.
2. **"may do everything on this cluster"**, in both files, about the `operators` role. False, and

   `METRICS` and `ALERTS` are four resources in ADR-021's vocabulary that no role in the file names
   — which is why `pause` and `ksql/objects` answer 403 above. Both sentences now say what the role
   actually grants.
