## 4. `smoke.sh`'s stream read, proved in both directions

The `STREAM_READS` arm asserted `%{http_code}` only, and an SSE refusal **is** an HTTP 200 with the
refusal in the body. `first_sse_event` now reads the first frame of the one streamed read and
`await`s `phase`.

**The derivation is self-tested before the stack is touched**, like every other derivation in this
file: a CRLF stream framing `phase` then `consumed`, whose `data:` payload itself contains the word
`event`, must derive `phase`; and a stream whose first frame is `event: error` must derive `error` —
because a derivation that could only ever answer the happy name would pass a refusal exactly as the
status code did. Both fixtures were also run standalone against a 2,000-byte body with no `event:`
line at all (answers nothing, does not explode under `pipefail`).

`awk` remembering rather than `sed … | head -1`: this file runs under `set -euo pipefail`, and a
stage that quits on the first match SIGPIPEs the stage above it, so the happy path would exit 141 on
the kernel's scheduling. Named in the comment.

**Green**, `KUI_PORT=18080 KUI_FRONTEND_PORT=18090 ./deployment/compose/smoke.sh`:


**Red**, with `deployment/compose/docker-compose.yml:239` — `kui-message`'s `KUI_PRINCIPAL_KEY` —

**The status line still printed `200`.** That is the whole finding, visible in one run: the old

**One cost, said plainly:** a genuine refusal now takes the full `SETTLE_TIMEOUT` (90s) before the

carries and it was chosen for consistency, not for speed.
