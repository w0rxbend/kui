## 5. Disclosures — three rules of my own that survive mutation with the run green

House rule 5. Each was applied as one edit to the shipped script, run, and restored; each left
**`458 claims checked, all true`, exit 0**.

### D-1 (the serious one) · the omission direction can be switched off in one line

```
  [[ $flat == *" $token "* || $flat == *" $token/ "* ]] || omitted+="$token "
    ->  [[ -n $token ]] || omitted+="$token "
```

`$token` is never empty, so `omitted` is never filled, and **V-02 and item 4.2 both go green.** The
document going wrong is what drives that refusal today; nothing drives it if the *gate* goes wrong
instead. This is the half of the mechanism the wave brief calls "half the value", and it is the one
with no failing case of its own.

### D-2 · `listing_is_name` can forget that a listing names files

```
  [[ $1 =~ ^[A-Za-z0-9_.@/-]+\.($listing_file_extensions)$ ]]   ->   return 1
```

Only trailing-slash directory tokens are then checked. Green, because every file token the tree
draws happens to resolve — so a phantom `Dockerfile.jvm` or a `ci.yaml` that never existed would be
invisible.

### D-3 · `listing_quote` can stop escaping

```
  printf '%s' "$1" | sed 's/[][\\.^$*+?(){}|]/\\&/g'   ->   printf '%s' "$1"
```

Green, because an unescaped `.` matches the character that is actually there. It stops being green
the day a document names `build.mill` and the repository carries `buildxmill`, which is exactly the
resolution a reader would never think to check.

**And one thing that cost an hour, recorded so the next reader does not pay it twice.**
`printf '%s\n' "$listing_index" | grep -q …` is a pipeline whose `grep` exits as soon as it matches;
`printf` then dies of SIGPIPE and, under `pipefail`, the pipeline's status is 141. Every name that
resolved read as a name that did not, and every listing in the repository became a phantom. Every
reader in section 12 uses a here-string. Separately, `listing_word_value`'s last statement was a
failed `[[ ]]`, which inside `value=$(…)` under `set -e` ended the whole run with **no output at all
and exit 1** — the silent-death mode this file has warned about twice; it now ends with `return 0`.

## 7. What this closes, and the honest limit

**Five classes in five waves, and this one is strictly narrower than wave 13's.** Wave 10 closed
stale figures; wave 11 built the claim kind that reads a sentence; wave 12 the quotation against the
file it names; wave 13 derived the roster of what is swept; this one compares a documented listing
against the index. `screens/` — the phantom wave 13's own repair introduced, in the section whose
subject is phantom directories — is now one of seven reproduced red refusals above. **W14-01 landed.**

**The limit, stated rather than discovered later.** Section 12 resolves a drawn name as a path
component *anywhere* in the index, not at the depth the tree draws it. A `kernel/` drawn under
`apps/` would resolve on the strength of `libs/kernel`. That is deliberate — a depth-aware reader
needs to decide which column of a two-column tree a token sits in, and the columns of
`ARCHITECTURE.md` §16 are eight characters apart while `mill` (top level) and `kernel/` (nested) sit
one character apart. It costs nothing against the case the section was built for: `screens/` and
`benchmarks/` resolve nowhere at any depth.

**And the sixth class, if there is one, is not narrower than this one.** Nothing in this packet's
work turned up a new kind of false statement. What it turned up is two *sites of the same class* —
R-1 and R-2, both working-tree reads of a repository fact, both inside this gate, both filed with a
one-line shape. That is the class converging on itself rather than a new class appearing.
