# UI-006 — Kernel `QueryCache` and `Sse` wrappers

- **ID:** UI-006
- **Title:** Kernel `QueryCache` and `Sse` wrappers
- **Milestone / Feature:** M0 / KU-001, KU-014 (browser half)
- **Owner role:** Frontend Architect
- **Size:** M
- **Dependencies / blocked by:** UI-005

## Goal (user value)

Two pieces of plumbing every screen needs: server state that is fetched once and shared
(instead of five components each firing the same request), and a server-sent-events wrapper
that reconnects, parses named events, and can be aborted.

## Scope

1. `QueryCache[K, A]` — Airstream-based, modelled on react-query's role in the reference
   (`research/scala/frontend-research.md` §3.2): keyed entries holding
   `Status[Pending | Resolved]`, a staleness timestamp, prefix invalidation, and reference
   counting so an entry with no subscribers stops refreshing.
2. `Sse.eventSource(url)` — native `EventSource` (auto-reconnecting, cookie auth), used for
   `/api/v1/capabilities/stream`. Named events are routed by `addEventListener`, each parsed
   into `Either[SseError, T]` by a supplied decoder.
3. `Sse.fetchStream(request)` — abortable `fetch` + an SSE line parser, for POST streams and
   for cases needing cancellation (M3's message browser). Written now, exercised by one test,
   because M3 must not have to invent it under pressure.
4. Connection state: both wrappers expose `Signal[SseConnection]`
   (`Connecting | Open | Reconnecting(attempt) | Closed(reason)`), which UI-010 renders as the
   capability banner's connection indicator.

## Non-goals

No cursor / `Last-Event-ID` resume logic (M3, ADR-026). No message-specific events (M3). No
WebSocket (ADR-035 rejects it).

## Design references

ADR-011 §3.6 (both wrappers live in the kernel; `Sse.eventSource` and `Sse.fetchStream`),
ADR-035 (named events, heartbeat, one terminal event), ADR-032 (snapshot then deltas),
`research/scala/frontend-research.md` §3.2 and §3.6.

```scala
package kui.ui.kernel.query

final case class CacheEntry[A](value: Either[ApiError, A], fetchedAt: js.Date)

trait QueryCache[K, A]:
  def get(key: K): Signal[Status[K, Either[ApiError, A]]]
  def invalidate(key: K): Unit
  def invalidateWhere(p: K => Boolean): Unit
  def set(key: K, value: A): Unit
  def fetchedAt(key: K): Signal[Option[js.Date]]

object QueryCache:
  def make[K, A](
      fetch: K => EventStream[Either[ApiError, A]],
      staleAfter: FiniteDuration = 30.seconds,
      maxEntries: Int = 200
  ): QueryCache[K, A]
```

```scala
package kui.ui.kernel.sse

enum SseConnection:
  case Connecting, Open
  case Reconnecting(attempt: Int)
  case Closed(reason: String)

enum SseError:
  case Decode(event: String, cause: String)
  case Transport(cause: String)
  case Server(envelope: ErrorEnvelope)          // the `error` event of ADR-035

final case class SseHandle[A](events: EventStream[Either[SseError, A]], connection: Signal[SseConnection], close: () => Unit)

object Sse:
  /** Native EventSource: reconnects on its own, sends cookies. For GET streams. */
  def eventSource[A](url: String, eventNames: List[String])(decode: (String, String) => Either[SseError, A]): SseHandle[A]
  /** Abortable fetch + parser. For POST streams and explicit cancellation. */
  def fetchStream[A](request: FetchRequest, eventNames: List[String])(decode: (String, String) => Either[SseError, A]): SseHandle[A]

object SseParser:
  /** Pure incremental parser: feed chunks, get complete events. Handles CRLF and LF,
    * multi-line `data:`, comments, `id:`, `retry:` and split-across-chunk boundaries. */
  def feed(state: ParserState, chunk: String): (ParserState, List[RawSseEvent])
final case class RawSseEvent(name: String, data: String, id: Option[String])
```

## Tests required

- `SseParserSuite` (unit + property, pure — no DOM):
  - `parsesTheGoldenWireFormatFromHttp004` — the same golden bytes the server test uses, so
    client and server are provably compatible.
  - `handlesEventsSplitAcrossChunkBoundaries` — property: feeding any chunking of a byte
    stream yields the same events.
  - `handlesMultiLineDataAndComments`; `ignoresUnknownFields`; `handlesCrlfAndLf`.
  - `emitsNothingForAnIncompleteTrailingEvent`.
- `QueryCacheSuite` (unit + `TestControl`):
  - `twoSubscribersForOneKeyCauseOneFetch`.
  - `staleEntriesRefetchOnNextSubscription` and fresh ones do not.
  - `invalidateWhereRefetchesOnlyMatchingKeys`.
  - `anEntryWithNoSubscribersStopsRefreshingAndIsEvictedAtTheBound`.
  - `errorsAreCachedBrieflySoAFailingEndpointIsNotHammered` — 5 s negative TTL.
- `SseBrowserSuite` (browser): connects to a local stub server, receives a named event,
  reconnects after the server closes, and `close()` stops the connection (asserted by the
  server observing the disconnect).

## Observability

`SseConnection` is the browser's own health signal; UI-010 renders it. No metrics are sent to
the server in M0.

## Degraded behavior

A decode failure for one event must not kill the stream: the wrapper emits
`Left(SseError.Decode)` and keeps reading (the same rule ADR-035 applies to the server's
deserialization failures). Reconnection backoff is 1 s, 2 s, 5 s, then every 10 s, with jitter.

`docs/frontend/README.md`: when to use `eventSource` versus `fetchStream`.

## Deviations

1. **`SseBrowserSuite` is not implemented; an injectable `EventSourceLike` takes its place.** The
   spec calls for one suite run in a real browser under `JsEnvConfig.Playwright`, connecting to a
   local stub server. That needs three things M0 does not have yet: a Mill submodule mixing in
   `KuiBrowserTests`, a stub SSE server running outside the test process (a JVM server and a
   Scala.js test module cannot share one Mill invocation — blocker B-003), and the Playwright
   browser download in CI. Rather than leave the wrapper untested, `Sse.eventSourceWith` takes a
   factory for an `EventSourceLike` — the four members of `EventSource` the kernel actually uses —
   and `SseSuite` drives a fake one under jsdom. That covers everything the *kernel* does: routing
   named events, telling a server-sent `error` event apart from a transport failure, turning
   `readyState` into `SseConnection`, keeping the stream alive through a decode failure, and
   `close()`. What it does not cover is the browser's own `EventSource` behaving as assumed, which
   is exactly what the browser suite was for. It should be added when the first browser-run suite
   exists; it is recorded here so the gap is visible rather than forgotten.

2. **The documented backoff schedule applies to `fetchStream`, not to `eventSource`.** The spec puts
   "1 s, 2 s, 5 s, then every 10 s, with jitter" under degraded behaviour for both wrappers. The
   native `EventSource` reconnects on its own and its interval is set by the server's `retry:` field;
   a browser gives no way to override it. That is not a limitation to work around — it is the reason
   ADR-011 chose `EventSource` for the capability stream. The schedule is therefore implemented as
   `Sse.backoff`, tested as a pure function, and available to any caller that drives its own
   reconnection; `SseConnection.Reconnecting(attempt)` still reports what the browser is doing.

3. **`FetchRequest.method` is `dom.HttpMethod`, not a `String`.** A string would have to be converted
   with a cast, and `.scalafix.conf` forbids `asInstanceOf` (rule `DisableSyntax`). The typed value
   is better anyway: a typo in `"POST"` becomes a compile error.

4. **The clock is a constructor parameter instead of `TestControl`.** The spec's suites are written
   against cats-effect's `TestControl`, which is not on the frontend's classpath and would be a
   sizeable dependency to add to a browser bundle for the sake of one suite. `QueryCache.make` takes
   `now: () => js.Date`, exactly as `Notifications` already takes its clock in this module, and
   `QueryCacheSuite` steps time by hand.

5. **`QueryCache` entries carry a generation counter.** Not in the specification, and needed:
   invalidating a key that something is watching starts a second request while the first is still
   outstanding, and both eventually answer. Without a generation the cache can settle on whichever
   answer arrives last, which under a slow network is the *older* one. The counter makes a superseded
   answer be dropped.

6. **`Status` values come from a `Var[Map[K, Status]]` rather than one `Var` per key.** An
   implementation detail, recorded because it is visible in the signatures: `get(key)` returns a
   signal derived from that map, wrapped in an `EventStream.fromCustomSource` whose `start` and
   `stop` callbacks are the reference counting. Those callbacks are the only hook Airstream offers
   for "something is now looking at this", and the reference counting is what makes the cache
   demand-driven rather than a background poller.
