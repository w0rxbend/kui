# UI-007 — `KuiFeature` contract and lazy feature registry

- **ID:** UI-007
- **Title:** `KuiFeature` contract and lazy feature registry
- **Milestone / Feature:** M0 / KU-004
- **Owner role:** Frontend Architect
- **Size:** M
- **Dependencies / blocked by:** UI-001

## Goal (user value)

A feature that is unavailable or not configured is **never downloaded** — the browser fetches
a feature's code the first time it is actually needed. This is the frontend half of fault
isolation and the reason ADR-012 chose module splitting.

## Scope

1. `KuiFeature` — the interface every microfrontend implements: its id, its navigation entry,
   its routes, its fallback view, and the panels it contributes to other features' pages.
2. `FeatureRegistry` — `Map[FeatureId, () => js.Promise[KuiFeature]]` where each thunk is
   `js.dynamicImport(new XFeature())`. The registry is the **only** place a feature class is
   named, and it is written so the shell never holds a static reference (ADR-012's constraint,
   enforced mechanically by BUILD-006).
3. `LazyFeature` — the loading state machine: `NotLoaded | Loading | Loaded(f) | Failed(e)`,
   with the promise memoized so a feature is imported once, and a `Failed` state that is
   retryable (a chunk can fail to download on a flaky network; that must show the fallback
   panel, not a blank page).
4. `FeaturePanel` — the cross-feature slot of ADR-012: a feature registers panels by
   `(hostFeature, slotId)` and a host renders whatever is registered without importing it.

## Non-goals

No shell, no router (UI-009). No capability gating (UI-010). Only one real feature exists in
M0 (UI-012).

## Design references

ADR-012 (the whole decision: `js.dynamicImport` thunks keyed by `FeatureId`, the shell never
references feature classes statically, `FeaturePanel` for cross-feature panels),
PLAN §21, `research/scala/frontend-research.md` §4, `research/kafbat/ui-analysis.md` DC-H6.

## Public Scala signatures to implement

```scala
package kui.ui.kernel.feature

/** Stable ids: the same strings the capability registry uses as `service`, so a capability
  * maps to a feature without a lookup table. */
enum FeatureId(val value: String, val serviceId: String):
  case Clusters extends FeatureId("clusters", "cluster")
  // topics, messages, consumers, schemas, connect, ksql, security, metrics, admin follow in
  // their milestones. Adding a case here is the only registration step.

final case class NavEntry(
    featureId: FeatureId,
    label: String,
    icon: SvgElement,
    order: Int,
    requiresCluster: Boolean
)

trait KuiFeature:
  def id: FeatureId
  def nav: NavEntry
  def routes: List[Route[? <: Page, ?]]
  def render(page: Page): HtmlElement
  /** What the shell shows when the capability registry says this feature is unavailable.
    * ADR-032 requires reason, since, a retry action and "what still works". */
  def unavailableView(reason: DegradedReason, since: Option[Instant], retry: Observer[Unit]): HtmlElement
  def panels: List[PanelContribution]

final case class PanelContribution(host: FeatureId, slot: String, render: PanelContext => HtmlElement)

enum LoadState[+A]:
  case NotLoaded
  case Loading
  case Loaded(value: A)
  case Failed(cause: String)

trait LazyFeature:
  def state: Signal[LoadState[KuiFeature]]
  def load(): Unit          // idempotent; memoizes the promise
  def retry(): Unit         // clears Failed and loads again

object FeatureRegistry:
  /** The single place that names feature classes. Each thunk MUST be
    * `() => js.dynamicImport(new kui.ui.clusters.ClustersFeature())` and nothing else —
    * assigning the constructor to a val, or referencing the type in a signature, defeats the
    * linker's split border. BUILD-006's bundle check enforces this. */
  def default: Map[FeatureId, () => js.Promise[KuiFeature]]
  def lazyFeature(id: FeatureId): LazyFeature
```

## Tests required

- `LazyFeatureSuite` (unit, with a stubbed thunk — no real dynamic import in a unit test):
  - `loadIsIdempotentAndImportsOnce` — ten `load()` calls, one import.
  - `stateTransitionsAreNotLoadedThenLoadingThenLoaded`.
  - `aRejectedPromiseBecomesFailedAndRetryWorks` — the flaky-chunk case.
  - `neverLoadsUntilLoadIsCalled` — the whole point: assert the thunk is untouched.
- `FeaturePanelSuite` (unit + DOM):
  - `aHostRendersEveryRegisteredPanelForItsSlot`.
  - `anEmptySlotRendersNothingAndDoesNotThrow`.
  - `aPanelFromAnUnloadedFeatureIsNotRenderedAndDoesNotTriggerALoad` — panels never force a
    download; the host asks for the panel only when the feature is already loaded and
    available. (This is subtle and worth the explicit test: a naive implementation would make
    every topic page download the consumers feature.)

## Observability

Not applicable.

## Degraded behavior

`Failed` loading renders the feature's `unavailableView` with a reason of "the feature could
not be downloaded" and a working retry — never a blank route (ADR-011 §3.6).

## Deviations

- **`unavailableView` takes a kernel-owned `UnavailableReason`, not the capability DTO.** The spec's
  signature is `unavailableView(reason: DegradedReason, since: Option[Instant], retry: Observer[Unit])`,
  where `DegradedReason` comes from `libs/contracts-core`. Depending on it would make the bottom
  layer of the frontend depend on the shape of one service's HTTP response, so the kernel defines
  `UnavailableReason(code, message, since)` and UI-008 translates the capability registry's answer
  into it when it renders the fallback. `since` moved inside the case class, where it belongs — it is
  part of the reason, not a separate fact about it.
- **`Page` is defined in the kernel.** The spec's `KuiFeature` signature mentions `Route[? <: Page, ?]`
  without saying where `Page` lives. It has to be the kernel, because that is the only module both
  the shell (UI-009) and every feature can see.
- **`FeatureRegistry` delegates to a `Features` class.** The object is the application's one registry;
  the class takes its thunk map as a parameter so the tests can supply stubs. Same arrangement as
  `Theme` and `NotificationBus`, and for the same reason.
- **`FeatureRegistry.default` is empty, and there is a `MissingFeature` state for that.** No feature
  exists until UI-012. Rather than leaving an unregistered id `NotLoaded` for ever, it resolves
  immediately to `Failed("No feature is registered for 'x' in this build.")`, which the shell can
  render; a route that stays blank cannot be distinguished from a bug.
- **`FeaturePanel` takes `Signal[List[KuiFeature]]` — the loaded features — rather than consulting the
  registry.** The spec's own test `aPanelFromAnUnloadedFeatureIsNotRenderedAndDoesNotTriggerALoad`
  describes the requirement; making the loaded set the *input* makes it true by construction instead
  of by a guard someone can later remove. `FeatureRegistry.loaded` is what the shell passes.
- **`NavEntry.icon` is `() => SvgElement`.** A DOM node can only be in one place at a time, and the
  navigation may render more than one copy (a sidebar and a mobile menu).
- **`checkBundleShape` cannot yet prove anything.** It is implemented (BUILD-006) and runs, but with
  no feature registered it reports a skip. The assertion becomes meaningful with UI-012.
