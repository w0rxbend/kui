# UI-001 — `frontend/ui-kernel` module and CSS pipeline

- **ID:** UI-001
- **Title:** `frontend/ui-kernel` module and CSS pipeline
- **Milestone / Feature:** M0 / NX-007
- **Owner role:** Frontend Architect
- **Size:** M
- **Dependencies / blocked by:** BUILD-003

## Goal (user value)

The frontend has a home: a Scala.js module that links, tests under Node, and assembles its CSS
the way ADR-024 decided — before anyone writes a component.

## Scope

1. `frontend/ui-kernel` as a `KuiFrontendModule` (BUILD-003) with Laminar, Airstream,
   scalajs-dom, sttp 4 and the cross-compiled contract modules on its classpath.
2. The CSS pipeline of ADR-024: each module keeps `src/main/resources/css/*.css`; a Mill task
   `frontend.css` concatenates them in the fixed order **tokens → reset → kernel → features**
   into `kui.css`, with a stable order inside each group (alphabetical by file name) so the
   output is deterministic.
3. The `Css` object convention: BEM class names as Scala string constants per module
   (`object KernelCss { val Button = "kui-button"; val ButtonPrimary = "kui-button--primary" }`)
   so components never write a class name inline.
4. A `reset.css` (the small, boring one: `box-sizing`, margin reset, `:focus-visible` outline
   preserved, `prefers-reduced-motion` honoured).
5. One smoke component (`Kernel.version`) and one MUnit test, so the module is not empty.

## Non-goals

No tokens (UI-002). No components (UI-003, UI-004). No ScalaCSS, no CSS-in-Scala, no
preprocessor (ADR-024 rejects all three). No Tailwind.

## Design references

ADR-024 (plain CSS, one file per module, concatenation order, BEM with a module prefix,
`Css` objects), ADR-011 (Laminar versions), ADR-012 (`KuiFrontendModule` settings),
`research/scala/frontend-research.md` §6.

## Public Scala signatures to implement

```scala
package kui.ui.kernel

object Kernel:
  val version: String            // from BuildInfo, shown in the shell footer

package kui.ui.kernel.css

/** One object per module. Class names are `kui-<module>__<element>--<modifier>`.
  * Nothing in Scala code may write a class-name string literal outside such an object. */
object KernelCss:
  val Root = "kui"
```

```scala
// build.mill
def css: T[PathRef]     // concatenates in order: tokens, reset, kernel, features
```

## Acceptance criteria

```
$ ./mill frontend.uiKernel.compile
$ ./mill frontend.uiKernel.test               # green under Node
$ ./mill frontend.uiKernel.fastLinkJS         # produces ES modules
$ ./mill show frontend.css                    # a path to kui.css
$ head -3 out/frontend/css.dest/kui.css       # starts with the tokens file, then the reset
```

## Tests required

- `KernelSuite` (unit): `version` is non-empty; a trivial Laminar element renders under jsdom
  (this proves the jsdom environment works before UI-003 depends on it).
- A build-level test for the CSS task: given three fixture files, the output order is
  tokens → reset → kernel → features and is byte-identical across two runs.
