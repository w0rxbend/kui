# GW-010 — `GET /api/v1/info` build information

- **ID:** GW-010
- **Title:** `GET /api/v1/info` build information
- **Milestone / Feature:** M0 / CW-001
- **Owner role:** Infrastructure Lead
- **Size:** S
- **Dependencies / blocked by:** GW-001

## Goal (user value)

A support request starts with "which version are you running?". This endpoint answers it, and
the shell's footer shows it, so nobody has to guess from a container tag.

## Scope

1. A Mill-generated `BuildInfo` object per deployable: version, git commit (short and full),
   git dirty flag, build timestamp, Scala version, JDK version.
2. `GET /api/v1/info` → `AppInfo`: the gateway's build info, plus the enabled features
   (`authType`, `readOnly` placeholder for M5, `basePath`) and the list of configured services.
3. The same information at startup in one INFO log line (SVC-004 and GW-001 reference it).

## Non-goals

No release-check / update notification (OT-006, opt-in, M8). No per-service info aggregation —
each service's build info is visible in its own logs; the gateway reports its own. No
telemetry of usage.

## Design references

Feature matrix CW-001 ("App info: build info, enabled features; `GET /info`"), PLAN §35.

## Public Scala signatures to implement

```scala
package kui.gateway.contract.dto

final case class BuildInfoDto(
    version: String,
    gitCommit: String,
    gitDirty: Boolean,
    builtAt: Instant,
    scalaVersion: String,
    jdkVersion: String
)

final case class AppInfo(
    build: BuildInfoDto,
    authType: String,           // "disabled" in M0
    basePath: String,
    services: List[String],     // configured service ids, not their URLs
    features: Map[String, Boolean]   // e.g. "cors" -> false; extended per milestone
)
```

**Security rule:** `AppInfo` must never contain a URL, a hostname, a key id or any
configuration value that is not already public. `services` lists ids only. A test asserts the
serialized document contains no `http` substring.

## Library coordinates

None new (Mill generates `BuildInfo` without a plugin dependency in 1.1.x; if it does not,
use a small `Task` writing a generated Scala source — do not add a third-party plugin for
this).

```
  "authType": "disabled", "basePath": "", "services": ["cluster"], "features": {"cors": false} }
```

## Tests required

- `InfoRoutesSuite` (contract):
  - `infoMatchesTheGoldenDocumentShape` (with build fields normalized).
  - `infoListsConfiguredServiceIdsOnly`.
  - `infoContainsNoUrlOrHostname` — the leak guard described above.
  - `infoIsServedWithoutAuthentication` — it is the endpoint a health dashboard reads.
  - `gitDirtyIsTrueForALocalBuildWithChanges` — asserted on the generation function, not on a
    real build.

## Observability

The startup log line uses the same values, so a log and the endpoint can be cross-checked.

## Degraded behavior

If build info generation failed (a source checkout without git), the fields are
`"unknown"` and the endpoint still answers — a missing version must not break the UI footer.
