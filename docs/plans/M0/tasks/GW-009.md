# GW-009 — Session, CSRF and signed-principal edge skeleton

- **ID:** GW-009
- **Title:** Session, CSRF and signed-principal edge skeleton
- **Milestone / Feature:** M0 / KU-005 (security skeleton)
- **Owner role:** Security Engineer
- **Size:** L
- **Dependencies / blocked by:** GW-001, KERN-006

## Goal (user value)

The security boundary exists and is tested before there is anything behind it. When M6 adds a
login form, it plugs into a session, CSRF and principal-signing mechanism that has already
been exercised in CI for six milestones — instead of being bolted on at the end.

## Scope

1. `SessionStore[F]` port and its in-memory adapter (ADR-019: in-memory is the M0–M5 adapter;
   the Kafka-backed one is M6, TD-003). Session record: id, principal, CSRF secret, created,
   last seen, absolute expiry.
2. Cookie handling: `kui_session`, `HttpOnly; Secure; SameSite=Lax; Path=<basePath>/`, 32
   random bytes base64url, id rotation on privilege change, idle 30 min, absolute 12 h.
   `Secure` is omitted only when `server.devInsecureCookies = true`, a flag that logs a
   prominent warning and is rejected when the configured base URL is `https`.
3. CSRF: every non-GET, cookie-authenticated request requires `X-Kui-Csrf` equal to the
   session's secret **and** a `Sec-Fetch-Site` that is not `cross-site`. Bearer-authenticated
   requests are exempt. Failure is `403 KUI-FORBIDDEN`.
4. Anonymous mode (`auth.type = disabled`, the only M0 value): every request gets
   `Principal.Anonymous`; a session is still created so the CSRF machinery is live and tested.
5. `GET /api/v1/auth/me` returning `{ principal, csrfToken, authType }` — the endpoint the
   frontend's `ApiClient` reads its CSRF token from (UI-005).
6. `POST /api/v1/auth/logout` clearing the session (a no-op principal-wise in anonymous mode,
   but the route and its `POST`-only rule exist and are tested).
7. Outbound signing: the gateway signs the principal per upstream call (already used by
   GW-002); this task adds key loading, `kid` selection and rotation from
   `gateway.principalKeys[]`.

## Non-goals

No login form, no OIDC, no LDAP, no password store, no session persistence beyond memory, no
RBAC. `auth.type` values other than `disabled` are rejected by CFG-001.

## Public Scala signatures to implement

```scala
package kui.gateway.application.session

opaque type SessionId = String        // never logged; log SessionRef (a hash) instead
final case class Session(
    id: SessionId,
    principal: Principal,
    csrfSecret: Secret[String],
    createdAt: Instant,
    lastSeenAt: Instant,
    absoluteExpiry: Instant
)

trait SessionStore[F[_]]:
  def create(principal: Principal, now: Instant): F[Session]
  def get(id: SessionId, now: Instant): F[Option[Session]]      // touches lastSeenAt
  def rotate(id: SessionId, now: Instant): F[Option[Session]]   // new id, same principal
  def delete(id: SessionId): F[Unit]
  def sweep(now: Instant): F[Int]                                // expired removal, returns count

object InMemorySessionStore:
  /** Bounded (default 10 000 sessions, LRU eviction) so an unauthenticated flood cannot
    * exhaust memory — anonymous mode creates a session per browser. */
  def resource[F[_]: Async](config: SessionConfig): Resource[F, SessionStore[F]]

final case class SessionConfig(
    idleTimeout: FiniteDuration,      // 30 minutes
    absoluteTimeout: FiniteDuration,  // 12 hours
    maxSessions: Int,                 // 10 000
    sweepInterval: FiniteDuration     // 1 minute
)
```

package kui.gateway.api.auth

## Tests required

- `InMemorySessionStoreSuite` (unit + property + concurrency):
  - `getReturnsNoneAfterIdleTimeout`, `...AfterAbsoluteTimeout` (`TestControl`).
  - `rotateChangesTheIdAndInvalidatesTheOld` — the fixation defence.
  - `sweepRemovesOnlyExpiredSessions` (property).
  - `boundedStoreEvictsLeastRecentlyUsed` — 10 001 sessions leave 10 000.
  - `concurrentCreatesDoNotCollide` — property over 1000 parallel creates, all ids distinct.
  - `sessionIdIsNeverContainedInAnyToStringOrLogEntry`.
- `CsrfCheckSuite` (unit, exhaustive table): the full matrix of
  {GET, POST} × {cookie, bearer, anonymous} × {token present/absent/wrong} ×
  {`Sec-Fetch-Site`: same-origin, same-site, cross-site, absent}. Every row states the expected
  verdict. This table **is** the ADR-019 specification.
- `SessionMiddlewareSuite` (integration on a bound port):
  - `cookieAttributesAreExactlyAsSpecified` — a literal string assertion on `Set-Cookie`.
  - `logoutRequiresPostAndClearsTheCookie`; `getLogoutIsFourOhFive`.
  - `theCsrfTokenFromAuthMeWorksAndAStaleOneDoesNot`.
  - `everyInboundXKuiHeaderIsStrippedBeforeTheHandler` (with GW-001's `EdgeHeaders`).

## Observability

`kui.principal.rejected {reason}` on CSRF and session failures; log fields include
`session.ref` (a hash) and never the session id or the CSRF secret. A CSRF rejection is logged
at WARN with the path and the `Sec-Fetch-Site` value — it is a signal worth alerting on.

## Degraded behavior

If the session store is full or unavailable, requests still succeed in anonymous mode with a
transient principal and no session (the UI degrades to "no CSRF token", which in M0 means
mutations are refused). In M6 this becomes a hard failure; the M0 behaviour is documented in
TD-003's row.
