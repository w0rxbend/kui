# AIO-002 — Frontend assets packaged into the all-in-one build

- **ID:** AIO-002
- **Title:** Frontend assets packaged into the all-in-one build
- **Milestone / Feature:** M0 / KU-005, NX-005
- **Owner role:** Infrastructure Lead
- **Size:** M
- **Dependencies / blocked by:** AIO-001, UI-012, GW-008

## Goal (user value)

One command, one process, and a browser shows the shell — no separate frontend server, no
manual copy step, no "works on my machine" asset path.

## Scope

1. A Mill task chain: `frontend.uiShell.fullLinkJS` + `frontend.css` → a `webAssets` task that
   assembles `index.html`, `kui.css`, the linker output modules and the import map into one
   directory, with content-hashed file names for everything except `index.html`.
2. That directory becomes a resource of `services/gateway/api` (development: read from the
   filesystem via a config override; production: packaged into the jar), so GW-008's
   `StaticRoutes` serves it.
3. `apps.allinone.assembly` produces a single runnable jar containing backend and frontend.
4. `apps.allinone.run` uses `fastLinkJS` output when present (fast dev loop) and `fullLinkJS`
   otherwise, controlled by one flag, so a developer never waits for a full optimizing link.
5. Determinism: the same sources produce the same hashes, so the Docker layer cache works
   (INFRA-001 depends on this).

## Non-goals

No Vite, no npm bundling (ADR-012: not needed while there are no npm ES modules; the import
map covers M2+). No CDN upload. No source-map stripping decision — source maps ship in M0 and
the question of hiding them in production is raised in M8's hardening.

## Design references

ADR-012 ("CI `fullLinkJS` copied into the gateway's static resources"; dev loop with
`fastLinkJS` and a static server), ADR-024 (the `kui.css` concatenation), ADR-005,
`research/scala/frontend-research.md` §4 "Recommended M0 setup".

## Public Scala signatures to implement

```scala
// build.mill
def webAssets: T[PathRef]      // index.html + kui.css + linker modules + importmap.json
def webAssetsDev: T[PathRef]   // same, from fastLinkJS
```

`index.html` references assets by a manifest the build writes (`assets.json`) rather than by
hard-coded names, so hashing does not require editing HTML.

## Acceptance criteria

```
$ ./mill apps.allinone.run
$ curl -s localhost:8080/ui/ | grep -o 'main-[a-f0-9]*\.js'      # hashed module name
$ curl -s -o /dev/null -w '%{http_code}\n' localhost:8080/ui/kui.css
200
$ ./mill apps.allinone.assembly
$ java -jar out/apps/allinone/assembly.dest/out.jar --config deployment/compose/kui.yaml
# the shell loads at http://localhost:8080/ui/ from the jar alone
$ ./mill webAssets && ./mill webAssets && diff <(...)   # identical hashes on a rebuild
```

The milestone exit criterion "`./mill apps.allinone.run` serves the shell" is fully satisfied
here.

## Tests required

- `StaticAssetsSuite` (integration against the running all-in-one):
  - `indexIsServedAndReferencesExistingHashedAssets` — fetch `index.html`, extract every
    `src`/`href`, fetch each, assert 200. This catches the classic broken-manifest deploy.
  - `theClustersFeatureModuleIsPresentButNotReferencedByIndex` — it is fetched dynamically.
  - `kuiCssContainsTheTokenBlockAndTheKernelRules` — proves the concatenation order survived
    packaging.
  - `assetsAreServedFromTheJarWithoutAFilesystemDependency` — run with the working directory
    changed to `/` and assert everything still loads.

## Observability

Not applicable.

## Degraded behavior

If the assets are missing, GW-008's 503 page explains it (rather than serving an empty 200).
The backend continues to serve `/api/v1` normally — a broken frontend build must not take the
API down, which matters for API clients and for the E2E suite's diagnostics.
