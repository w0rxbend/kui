# UI-008 — Capability store and `FeatureState` derivation

- **ID:** UI-008
- **Title:** Capability store and `FeatureState` derivation
- **Milestone / Feature:** M0 / KU-002, KU-003
- **Owner role:** Frontend Architect
- **Size:** M
- **Dependencies / blocked by:** UI-006, KERN-005

## Goal (user value)

The browser always knows the current state of every feature, and the rule that turns a
capability plus a permission into what the user sees is one pure function — tested
exhaustively — rather than scattered conditionals in every screen.

## Scope

1. `CapabilityStore` — one of the five kernel-owned `Var`s: subscribes to
   `/api/v1/capabilities/stream` through `Sse.eventSource`, seeds from the snapshot event,
   applies deltas, and falls back to polling `/api/v1/capabilities` every 30 s if the stream
   cannot be established.
2. `FeatureState` derivation (ADR-032):

   ```
   FeatureState = Ready | Degraded(reason) | Unavailable(reason, since) | Forbidden | NotConfigured
   ```

   from `(CapabilityState for (feature.serviceId, currentCluster), permission)`. In M0 the
   permission is always granted (RBAC is M6), but the parameter exists and the `Forbidden`
   branch is implemented and tested, so M6 is a one-line change at the call site.
3. Transition notifications: an `Available → Unavailable` transition pushes one deduplicated
   `Danger` toast per (feature, cluster) via `NotificationBus` (ADR-032); recovery pushes one
   `Success` toast.
4. `staleness` helper: the timestamp a feature's last successful data load carries, used by
   ADR-032's "stale data stays on screen greyed with its timestamp".

## Non-goals

No rendering (UI-010 owns nav and panels). No RBAC evaluation (M6). No per-cluster switching
UI (M1 — M0 has no clusters, so `currentCluster` is `None` and the cluster-independent
capability key is used).

## Design references

ADR-032 (the five states, the derivation, the deduplicated toast, stale-data rule),
KERN-005 (the DTOs), ADR-011 (kernel-owned `Var`s), feature matrix KU-002 and KU-003.

## Public Scala signatures to implement

```scala
package kui.ui.kernel.state

enum FeatureState:
  case Ready
  case Degraded(reason: DegradedReason)
  case Unavailable(reason: ReasonCode, message: String, since: Option[Instant])
  case Forbidden
  case NotConfigured

object FeatureState:
  /** Pure. The single rule of ADR-032, testable exhaustively. */
  def derive(capability: Option[CapabilityState], permitted: Boolean): FeatureState
  extension (s: FeatureState)
    def isNavigable: Boolean       // Ready, Degraded, Unavailable  -> true; Forbidden, NotConfigured -> false
    def isHidden: Boolean          // NotConfigured, and Forbidden when hideForbidden is on
    def isDimmed: Boolean          // Unavailable

object CapabilityStore:
  val states: Signal[Map[CapabilityKey, CapabilityState]]
  val connection: Signal[SseConnection]
  def stateOf(feature: FeatureId, cluster: Option[ClusterId]): Signal[CapabilityState]
  def featureState(feature: FeatureId, cluster: Option[ClusterId], permitted: Signal[Boolean]): Signal[FeatureState]
  def start(client: ApiClient, bootstrap: Bootstrap): Unit
  def probe(feature: FeatureId): EventStream[Either[ApiError, Unit]]     // the Retry now action

object CurrentCluster:
  val selected: Var[Option[ClusterId]]      // always None in M0
```

**Derivation table** (the specification; the suite mirrors it row for row):

| capability | permitted | `FeatureState` |
| --- | --- | --- |
| `None` (unknown yet) | true | `Degraded(Starting)` |
| `Available` | true | `Ready` |
| `Degraded(r)` | true | `Degraded(r)` |
| `Unavailable(r, m, s)` | true | `Unavailable(r, m, Some(s))` |
| `NotConfigured` | true | `NotConfigured` |
| any | false | `Forbidden` |

`Forbidden` wins over everything: a user without permission must not learn from the UI whether
the service is healthy.

## Tests required

- `FeatureStateSuite` (unit, exhaustive): every row of the table above, plus the three
  extension predicates for every state. This suite is the executable form of ADR-032.
- `CapabilityStoreSuite` (unit + `TestControl`, with a stubbed `SseHandle`):
  - `seedsFromTheSnapshotEventAndThenAppliesDeltas`.
  - `aDeltaForAnUnknownKeyIsAdded`, `...ForAKnownKeyReplaces`.
  - `fallsBackToPollingWhenTheStreamCannotConnectAndSwitchesBackWhenItDoes`.
  - `pushesExactlyOneToastPerAvailableToUnavailableTransition` — including the dedup across a
    rapid flap (the ADR-032 rule).
  - `recoveryPushesASuccessToast`.
  - `decodingTheServerGoldenFixtureProducesTheExpectedStates` — the client/server contract
    check.
  - `aMalformedEventDoesNotClearTheStore` — an unparseable delta is logged and skipped; the
    previous state stays. Wiping the sidebar because of one bad frame would be the worst
    possible failure mode.

## Observability

Not applicable (browser).

## Degraded behavior

If the capability stream and the polling fallback both fail, the store keeps its last known
map and `connection` shows `Closed`; UI-010 renders a banner saying capability information is
stale. It does **not** mark every feature unavailable — the features may be perfectly fine and
only the gateway's stream is broken.

## Deviations

1. **`CapabilityStore.stateOf` returns `Signal[Option[CapabilityState]]`, not
   `Signal[CapabilityState]`.** The spec's signature has no way to express "the gateway has not told
   us yet", which is precisely the input ADR-032 amendment 2 is about: `derive` has to see `None` in
   order to answer `Degraded(Starting)`. Returning a non-optional value would mean inventing a state
   inside the store and then deriving from the invention, which puts the amendment's rule in two
   places.

2. **`isHidden` takes the `hideForbidden` switch as a parameter.** The spec has `def isHidden:
   Boolean` with the comment "NotConfigured, and Forbidden when hideForbidden is on". A no-argument
   method cannot know whether it is on, so it would have to read a global — which makes the function
   impure and the suite order-dependent. It is `isHidden(hideForbidden: Boolean = false)`; the shell
   passes the deployment's `kui.ui.hideForbidden` setting.

3. **`CapabilityStore.start` takes a stream URL and a poll function, not an `ApiClient` and a
   `Bootstrap`.** The `/api/v1/capabilities` endpoint is defined in `services/gateway/contract`, a
   module above the kernel, and naming it here would invert the layering. Same reasoning, and same
   resolution, as UI-005's deviation 2 for `AuthState.refresh`. The shell composes the URL from
   `Bootstrap` and supplies the poll.

4. **`probe(feature)` is not implemented here.** It is `POST /capabilities/{service}/probe`, another
   gateway-contract endpoint the kernel cannot name, and its only caller is the "Retry now" button on
   the fallback panel — which UI-010 owns. UI-010 should pass the probe function to whoever renders
   the panel, exactly as `KuiFeature.unavailableView(reason, retry)` already expects an `Observer`
   rather than reaching for one.

5. **The golden fixture is read from `libs/contracts-core`, not copied into the frontend.** The spec
   asks for `frontend/ui-kernel/test/resources/fixtures/capabilities-snapshot.json` as a copy of the
   server's golden file. A copy is a second source of truth: the day the server's file changes, the
   copy keeps passing while the real contract has moved, which is the exact failure the fixture
   exists to prevent. `build.mill` instead compiles the server's own file into the test binary as
   generated source — the same mechanism `ContrastSuite` already uses for the token stylesheet, and
   necessary in any case because code compiled by Scala.js has no filesystem to read a resource from.

6. **The transition rule is "was not unavailable, now is", not strictly "was available, now
   unavailable".** From the user's point of view a *degraded* feature going down is the same event,
   and reporting one but not the other would make the notifications depend on an intermediate state
   the user never saw. The first snapshot after start-up raises nothing at all: opening KUI while a
   service is already down is a state, not an event, and toasting it would greet every user of a
   partly-degraded deployment with a wall of red on every page load.

7. **A `CapabilityEvent` ADT was added for the stream's frames.** The spec does not name one, but the
   `capabilities` event carries two shapes — a snapshot on connect and deltas afterwards — and
   something has to decide which arrived. They are told apart by trying the snapshot decoder first
   rather than by adding a discriminator field, because a discriminator would be a contract change
   made for the client's convenience.

8. **`TestControl` is again replaced by injected collaborators**, for the reason given in UI-006's
   deviation 4: cats-effect is not on the frontend's classpath. `Capabilities` takes its stream, its
   poller, its notification sink and its timer as constructor parameters.
