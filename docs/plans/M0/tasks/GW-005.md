# GW-005 — Capability endpoints: snapshot, SSE stream and probe

- **ID:** GW-005
- **Title:** Capability endpoints: snapshot, SSE stream and probe
- **Milestone / Feature:** M0 / KU-001, KU-003
- **Owner role:** Chief Architect
- **Size:** M
- **Dependencies / blocked by:** GW-003, HTTP-004

## Goal (user value)

The browser can ask "what works right now?" once and then be told about every change as it
happens, without polling — which is what makes the sidebar dim within seconds of a service
dying (the milestone's headline demo).

## Scope

Three endpoints in `services/gateway/contract`, implemented in `services/gateway/api`:

1. `GET /api/v1/capabilities` → `CapabilitySnapshot`.
2. `GET /api/v1/capabilities/stream` → SSE. **On connect it sends a full snapshot as one
   `capabilities` event, then one `capabilities` event per change** (ADR-032). Heartbeat every
   15 s from HTTP-004. No terminal event: the stream ends only when the client disconnects.
3. `POST /api/v1/capabilities/{service}/probe` → 202 with the recomputed state for that
   service, or 404 `KUI-VALIDATION` when the service id is unknown.

Plus the `Last-Event-ID` behaviour: the capability stream does **not** use cursors, so a
reconnecting client is simply sent a fresh full snapshot. Document this explicitly — a future
reader will otherwise assume ADR-026 applies.

## Non-goals

No per-cluster filtering (M1, when clusters exist). No RBAC filtering of the snapshot (M6).
No notification bus (NX-001, M6).

## Design references

ADR-032 (snapshot on connect then deltas; the retry button hits the probe endpoint),
ADR-035 (named events, heartbeat), `ARCHITECTURE.md` §6, feature matrix KU-001.

## Public Scala signatures to implement

```scala
package kui.gateway.contract

object CapabilityEndpoints:
  val snapshot: PublicEndpoint[Unit, ErrorEnvelope, CapabilitySnapshot, Any] =
    KuiEndpoint.base.get.in("api" / "v1" / "capabilities").out(jsonBody[CapabilitySnapshot])
      .name("gateway.capabilities.snapshot")

  val stream: PublicEndpoint[Unit, ErrorEnvelope, Stream[IO, SseEvent], Fs2Streams[IO]] =
    KuiEndpoint.base.get.in("api" / "v1" / "capabilities" / "stream")
      .out(serverSentEventsBody).name("gateway.capabilities.stream")

  val probe: PublicEndpoint[String, ErrorEnvelope, CapabilityEntry, Any] =
    KuiEndpoint.base.post.in("api" / "v1" / "capabilities" / path[String]("service") / "probe")
      .out(statusCode(StatusCode.Accepted).and(jsonBody[CapabilityEntry]))
      .name("gateway.capabilities.probe")

  val all: List[AnyEndpoint]
```

  - `snapshotListsEveryConfiguredService` — including one configured but never polled, which
    must appear as `Degraded(Starting)`, not be missing.
  - `streamSendsAFullSnapshotAsTheFirstEvent` — golden text comparison of the first frame.
  - `streamSendsOneEventPerChangeAfterTheSnapshot`.
  - `streamSendsAHeartbeatWhileIdle`.
  - `twoConcurrentSubscribersBothReceiveEveryChange`.
  - `disconnectingASubscriberDoesNotAffectTheOther` — the leak/blocking guard.
  - `probeReturnsTheRecomputedStateAndTriggersAPoll`.
  - `probeForAnUnknownServiceIsFourOhFourWithKuiValidation`.
  - `reconnectingWithLastEventIdStillReceivesAFullSnapshot` — the documented behaviour.

## Observability

`kui.stream.active {service=gateway, stream=capabilities}` (from HTTP-004) so an operator can
see how many browsers are connected; `kui.stream.events` per emitted event.

## Degraded behavior

If the registry is empty (no services configured), the snapshot is an empty list and the
stream still opens and heartbeats — the browser must be able to distinguish "nothing
configured" from "gateway not answering", and only the second one shows the full-screen
error (UI-011).
