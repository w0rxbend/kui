# UI-009 — `frontend/ui-shell`: router, layout and page ADT

- **ID:** UI-009
- **Title:** `frontend/ui-shell`: router, layout and page ADT
- **Milestone / Feature:** M0 / KU-002, KU-009
- **Owner role:** Frontend Architect
- **Size:** L
- **Dependencies / blocked by:** UI-004, UI-007

## Goal (user value)

The application frame: a URL that survives a refresh and can be shared, a sidebar, a header
with the theme switch, and a content area — the thing a user actually sees when they open KUI.

## Scope

1. `frontend/ui-shell` module, the Scala.js **entry point** (`main`), linked with
   `ModuleKind.ESModule` and the `SmallModulesFor` split style (BUILD-003).
2. The `Page` ADT and the router:
   - shell-owned pages: `HomePage`, `SettingsPage`, `NotFoundPage(url)`, `ForbiddenPage(what)`;
   - feature pages come from each `KuiFeature.routes`, concatenated into one
     `Router[Page]` (ADR-011);
   - `Page` is serialized with Circe for `history.state`;
   - routes are written with explicit `endOfSegments` for Waypoint 10 forward compatibility
     (ADR-011);
   - `routeFallback = url => NotFoundPage(url)`.
3. Layout: header (product name, cluster switcher placeholder, theme switch, build version from
   `GET /api/v1/info`), sidebar (navigation, filled by UI-010), content region with a skip link,
   and the toast host from UI-004.
4. Page switching with `splitMatchOne` (ADR-011 §3.3) so each page element is created once per
   page instance and receives a refined `Signal`.
5. Error boundary equivalent: `AirstreamError.registerUnhandledErrorCallback` reports to the
   notification bus and the console; every feature route render is wrapped in a `Try` so a
   throwing page shows the fallback panel instead of blanking the app (ADR-011 §3.6).
6. A settings page stub: theme choice and the build info. Nothing else (the roadmap's
   "settings stub").

## Non-goals

Navigation entries and capability gating (UI-010). Error pages' content (UI-011 — this task
creates the route, UI-011 designs the page). No cluster switching (M1). No search (M2).

## Design references

ADR-011 (`Page` ADT per feature, one `Router`, `splitMatchOne`, `endOfSegments`, error
handling), ADR-012 (the shell is the single link's entry point), `ARCHITECTURE.md` §12,
PLAN §21, `research/scala/frontend-research.md` §3.3 and §3.4.

## Public Scala signatures to implement

```scala
package kui.ui.shell

sealed trait Page
object Page:
  case object HomePage                              extends Page
  case object SettingsPage                          extends Page
  final case class NotFoundPage(url: String)        extends Page
  final case class ForbiddenPage(what: String)      extends Page
  /** Feature pages extend this in their own module; the shell never names them. */
  given io.circe.Codec[Page]

object ShellRouter:
  /** Feature routes are appended at construction from the loaded features' `routes`.
    * Routes for features that are not loaded yet are registered from a static description
    * the feature provides through its registry entry's metadata — a route must exist before
    * its feature is imported, otherwise a deep link would 404 on first load. */
  def make(featureRoutes: List[Route[? <: Page, ?]]): Router[Page]

object Layout:
  def apply(
      sidebar: HtmlElement,
      header: HtmlElement,
      content: Signal[HtmlElement]
  ): HtmlElement

@main def main(): Unit        // reads Bootstrap, installs Theme, starts CapabilityStore, renders
```

**Route patterns are static, rendering is dynamic** (ADR-012 amendment 2): a deep link to a
feature route must work before that feature's module is downloaded, so route *patterns* live
in a small static description on the registry entry (a `List[RoutePattern]` next to the
thunk), while route *rendering* waits for the dynamic import. Document it in
`docs/frontend/features.md`.

## Tests required

- `PageCodecSuite` (unit + property): every shell `Page` round-trips through the Circe codec;
  an unknown serialized page decodes to `NotFoundPage` rather than throwing (a user with an
  old tab open after a deploy must not get a broken app).
- `ShellRouterSuite` (unit + DOM):
  - `everyShellPageHasAUrlAndTheUrlParsesBackToThePage` (property).
  - `anUnknownUrlYieldsNotFoundPage`.
  - `aDeepLinkToAFeatureRouteResolvesBeforeTheFeatureIsLoaded` — the decision above, tested.
  - `pageSwitchingCreatesEachPageElementOnce` — `splitMatchOne` behaviour: navigating away and
    back creates a new element; re-emitting the same page does not.
  - `aThrowingPageRendersTheFallbackAndTheRestOfTheShellStillWorks` — the error boundary.
  - `theSkipLinkIsTheFirstFocusableElement` (accessibility).

## Observability

Not applicable (browser). `ErrorReporting` writes to the console and the notification bus; a
future task may add a server sink.

## Degraded behavior

If `GET /api/v1/info` fails, the header shows the version as `unknown` and everything else
works. If the capability store is empty, the sidebar shows its features in the `Starting`
(degraded) presentation rather than an empty sidebar.
