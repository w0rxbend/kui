# UI-009 — `frontend/ui-shell`: router, layout and page ADT

- **ID:** UI-009
- **Title:** `frontend/ui-shell`: router, layout and page ADT
- **Milestone / Feature:** M0 / KU-002, KU-009
- **Owner role:** Frontend Architect
- **Size:** L
- **Dependencies / blocked by:** UI-004, UI-007

## Goal (user value)

The application frame: a URL that survives a refresh and can be shared, a sidebar, a header
with the theme switch, and a content area — the thing a user actually sees when they open KUI.

## Scope

1. `frontend/ui-shell` module, the Scala.js **entry point** (`main`), linked with
   `ModuleKind.ESModule` and the `SmallModulesFor` split style (BUILD-003).
2. The `Page` ADT and the router:
   - shell-owned pages: `HomePage`, `SettingsPage`, `NotFoundPage(url)`, `ForbiddenPage(what)`;
   - feature pages come from each `KuiFeature.routes`, concatenated into one
     `Router[Page]` (ADR-011);
   - `Page` is serialized with Circe for `history.state`;
   - routes are written with explicit `endOfSegments` for Waypoint 10 forward compatibility
     (ADR-011);
   - `routeFallback = url => NotFoundPage(url)`.
3. Layout: header (product name, cluster switcher placeholder, theme switch, build version from
   `GET /api/v1/info`), sidebar (navigation, filled by UI-010), content region with a skip link,
   and the toast host from UI-004.
4. Page switching with `splitMatchOne` (ADR-011 §3.3) so each page element is created once per
   page instance and receives a refined `Signal`.
5. Error boundary equivalent: `AirstreamError.registerUnhandledErrorCallback` reports to the
   notification bus and the console; every feature route render is wrapped in a `Try` so a
   throwing page shows the fallback panel instead of blanking the app (ADR-011 §3.6).
6. A settings page stub: theme choice and the build info. Nothing else (the roadmap's
   "settings stub").

## Non-goals

Navigation entries and capability gating (UI-010). Error pages' content (UI-011 — this task
creates the route, UI-011 designs the page). No cluster switching (M1). No search (M2).

## Design references

ADR-011 (`Page` ADT per feature, one `Router`, `splitMatchOne`, `endOfSegments`, error
handling), ADR-012 (the shell is the single link's entry point), `ARCHITECTURE.md` §12,
PLAN §21, `research/scala/frontend-research.md` §3.3 and §3.4.

## Public Scala signatures to implement

```scala
package kui.ui.shell

sealed trait Page
object Page:
  case object HomePage                              extends Page
  case object SettingsPage                          extends Page
  final case class NotFoundPage(url: String)        extends Page
  final case class ForbiddenPage(what: String)      extends Page
  /** Feature pages extend this in their own module; the shell never names them. */
  given io.circe.Codec[Page]

object ShellRouter:
  /** Feature routes are appended at construction from the loaded features' `routes`.
    * Routes for features that are not loaded yet are registered from a static description
    * the feature provides through its registry entry's metadata — a route must exist before
    * its feature is imported, otherwise a deep link would 404 on first load. */
  def make(featureRoutes: List[Route[? <: Page, ?]]): Router[Page]

object Layout:
  def apply(
      sidebar: HtmlElement,
      header: HtmlElement,
      content: Signal[HtmlElement]
  ): HtmlElement

@main def main(): Unit        // reads Bootstrap, installs Theme, starts CapabilityStore, renders
```

**Route patterns are static, rendering is dynamic** (ADR-012 amendment 2): a deep link to a
feature route must work before that feature's module is downloaded, so route *patterns* live
in a small static description on the registry entry (a `List[RoutePattern]` next to the
thunk), while route *rendering* waits for the dynamic import. Document it in
`docs/frontend/features.md`.

## Tests required

- `PageCodecSuite` (unit + property): every shell `Page` round-trips through the Circe codec;
  an unknown serialized page decodes to `NotFoundPage` rather than throwing (a user with an
  old tab open after a deploy must not get a broken app).
- `ShellRouterSuite` (unit + DOM):
  - `everyShellPageHasAUrlAndTheUrlParsesBackToThePage` (property).
  - `anUnknownUrlYieldsNotFoundPage`.
  - `aDeepLinkToAFeatureRouteResolvesBeforeTheFeatureIsLoaded` — the decision above, tested.
  - `pageSwitchingCreatesEachPageElementOnce` — `splitMatchOne` behaviour: navigating away and
    back creates a new element; re-emitting the same page does not.
  - `aThrowingPageRendersTheFallbackAndTheRestOfTheShellStillWorks` — the error boundary.
  - `theSkipLinkIsTheFirstFocusableElement` (accessibility).

## Observability

Not applicable (browser). `ErrorReporting` writes to the console and the notification bus; a
future task may add a server sink.

## Degraded behavior

If `GET /api/v1/info` fails, the header shows the version as `unknown` and everything else
works. If the capability store is empty, the sidebar shows its features in the `Starting`
(degraded) presentation rather than an empty sidebar.

## Deviations

1. **The page ADT is `ShellPage`, not `Page`.** `Page` is already taken: it is the base trait in
   `kui.ui.kernel.feature`, put there by UI-007 because it is the only module both the shell and
   every feature can see. The shell's own pages are `sealed trait ShellPage extends Page`, with the
   cases named `Home`, `Settings`, `NotFound(url)` and `Forbidden(what)` rather than `HomePage` and
   so on — `ShellPage.HomePage` reads as a stutter, and the page *objects* that render them keep the
   `HomePage` name.

2. **A `Gallery` page was added.** The component gallery was deferred from UI-003 and UI-004 to this
   task, because until the shell existed there was no router to register it with. It lives at
   `/ui/gallery`, shows every primitive in whichever theme is on, and its light and dark screenshots
   are in `docs/frontend/screenshots/`, referenced from `docs/frontend/README.md`.

3. **`SplitRender` rather than `splitMatchOne`.** The spec names Laminar's `splitMatchOne`;
   `SplitRender` is Waypoint's wrapper around the same Airstream `split`, is what Waypoint's own
   documentation uses for exactly this, and gives the property ADR-011 §3.3 asks for — each page's
   element built once per page instance, receiving a refined `Signal`. Its `collectStatic` takes its
   view *by name* and re-evaluates on every emission of that page, including a re-emission of the
   page already on screen, so each static page is held in a `lazy val`. `ShellRouterSuite` asserts
   that idiom (`pageSwitchingCreatesEachPageElementOncePerPageInstance`); without it a page silently
   loses its scroll position and any open menu on every update.

4. **`NotFound` has no route of its own.** The spec's test name is
   `everyShellPageHasAUrlAndTheUrlParsesBackToThePage`; the implemented property is
   `everyRoutableShellPageHasAUrlAndTheUrlParsesBackToThePage`. `NotFound` is what `routeFallback`
   produces, and giving it a catch-all pattern would swallow every mistyped address before the
   fallback ever ran — with a much worse failure mode once a feature adds a pattern of its own.

5. **The header's build version comes from the bootstrap block, not from `GET /api/v1/info`.** That
   endpoint is defined in `services/gateway/contract`, which is being built in parallel and which
   the shell does not yet compile against. `Bootstrap.buildVersion` carries the same value the
   gateway injects, and the header reads it through a `Signal`, so pointing it at `/info` later is a
   change of source and not a change of shape. The degraded behaviour the task asks for is already
   in place: with no bootstrap block at all the header shows `dev` and everything else works
   (`aMissingBootstrapBlockLeavesTheShellWorkingWithAPlaceholderVersion`).

6. **`Theme` was changed to tolerate a missing `matchMedia`.** Not in the spec, and required: jsdom
   does not implement `window.matchMedia`, so mounting the whole shell in a suite threw before
   rendering anything. Some embedded browsers do not implement it either, and its absence is not a
   reason to fail to start — the answer is then "the system does not ask for dark", `Auto` behaves as
   `Light`, and the explicit choices still work. This is a one-line guard in
   `frontend/ui-kernel/src/kui/ui/kernel/theme/Theme.scala`.

7. **`Shell.app` takes the URL and the origin as parameters.** `@main def main()` reads
   `window.location` and hands them in. Without that split a suite could not mount the application on
   an address of its choosing without writing to the browser's real history, and
   `ShellLayoutSuite` — which is where the skip link, the navigation and the 404 page are checked —
   could not exist.

8. **`ShellLayoutSuite` was added** beyond the two suites the spec lists. `PageCodecSuite` and
   `ShellRouterSuite` cover the router and the codec, but the layout requirements — the skip link
   being first, `aria-current` on the active entry, the 404 page keeping the navigation, the gallery
   rendering every section — are DOM facts about the assembled application and belong in a suite that
   mounts it.

9. **`NotFoundPage` and `ForbiddenPage` are minimal here.** The task's own non-goals say UI-011 owns
   their content; this task creates the routes and enough of a page for them to render.
