# E2E-001 — Playwright + MUnit harness against all-in-one

- **ID:** E2E-001
- **Title:** Playwright + MUnit harness against the all-in-one build
- **Milestone / Feature:** M0 / KU-002, KU-004, KU-009
- **Owner role:** QA Engineer
- **Size:** L
- **Dependencies / blocked by:** AIO-002

## Goal (user value)

The claim "the shell works" is checked by a real browser on every commit, in the same language
and build tool as everything else, so it never rots.

## Scope

1. A Mill `e2e` module: JVM Playwright + MUnit (ADR-018 chose this over TypeScript Playwright
   explicitly), with the browser version pinned by BUILD-006.
2. Fixtures: a `ResourceSuiteLocalFixture` that starts the all-in-one **jar** once per suite
   (not per test), waits for `/health/ready`, and provides a `Page` per test with a fresh
   browser context (no shared cookies between tests).
3. Page objects — one class per screen with `data-testid` selectors only (UI-003's rule), so a
   restyle never breaks a test: `ShellPage`, `NavigationPanel`, `ClustersPage`,
   `SettingsPage`, `ErrorPage`.
4. The M0 happy-path suite:
   - the shell loads, the sidebar lists the Clusters feature, the header shows a version;
   - **the clusters module is not fetched on first paint** and *is* fetched after clicking the
     nav entry (asserted on network requests — the ADR-012 promise, verified in a browser);
   - the ping round-trips and appears in the table;
   - a deep link to `/ui/clusters` works on a cold load;
   - `/ui/nope` shows the 404 page with the navigation intact;
   - the theme switch changes `data-theme` and survives a reload;
   - `GET /api/v1/capabilities` reports the sample service `Available` (asserted through the
     API, from the same suite, so a UI and API mismatch is caught).
5. Artifacts on failure: screenshot, the browser console log, the server log, and the
   Playwright trace, all uploaded by CI (BUILD-004).

## Non-goals

Fault injection (E2E-002). Performance assertions (M2's virtualized table budget). Visual
regression / screenshot diffing (deferred; note it as a question for M2 where tables and
charts arrive). Cross-browser: Chromium only in M0; Firefox and WebKit are an M8 question.

## Public Scala signatures to implement

```scala
package kui.e2e

abstract class BaseE2ESuite extends munit.FunSuite:
  /** Starts the all-in-one jar once per suite; the port is chosen freely and injected into
    * the config so parallel suites do not collide. */
  val allInOne: Fixture[RunningKui]
  val browser: Fixture[com.microsoft.playwright.Page]
  /** Fails the test with a screenshot and the console log attached. */
  def failWithArtifacts(message: String): Nothing

final case class RunningKui(baseUrl: String, logs: () => String, stop: () => Unit)

package kui.e2e.pages

final class ShellPage(page: Page):
  def open(path: String): ShellPage
  def navigation: NavigationPanel
  def version: String
  def toastMessages: List[String]
  def themeAttribute: String

final class NavigationPanel(page: Page):
  def entries: List[NavEntrySnapshot]
  def click(feature: String): Unit
final case class NavEntrySnapshot(label: String, dimmed: Boolean, disabled: Boolean, hasAmberDot: Boolean, tooltip: Option[String])
```

`NavEntrySnapshot` deliberately mirrors ADR-032's five rendering rules so E2E-002's assertions

```
  + clusters module is not fetched on first paint
  + clicking Clusters fetches the module once and renders the page
  + ping round-trips
  + deep link to /ui/clusters works on a cold load
  + unknown url shows the 404 page with navigation intact
kui.e2e.ThemeSuite:
  + theme switch sets data-theme and survives a reload
```

Runtime budget: the whole suite under 90 seconds on CI. Record the actual time.

## Tests required

The suites listed above. Three rules for every E2E test in this repository, established here:

1. **No `Thread.sleep`.** Use Playwright's auto-waiting and explicit `waitForCondition` with a
   timeout and a message naming what was expected.
2. **Selectors are `data-testid` or ARIA roles.** Never a CSS class, never text that is a
   `Messages` string (except when the test is *about* that text).
3. **Each test starts from a fresh browser context**, so ordering never matters.

## Observability

On failure the suite attaches: a full-page screenshot, `console` messages, failed network
requests with status codes, and the server's stdout. A flaky E2E without artifacts costs more
time than it saves.

## Degraded behavior

If Docker or the Playwright browsers are unavailable, the module's tests are **skipped with a
loud message**, never silently passed — BUILD-004's job condition makes the skip visible in
the CI summary.
