# SVC-003 — `services/cluster/api`: server logic, error mapping and OpenAPI

- **ID:** SVC-003
- **Title:** `services/cluster/api`: server logic, error mapping and OpenAPI
- **Milestone / Feature:** M0 / KU-006, OT-005
- **Owner role:** Domain Architect (Cluster Registry context)
- **Size:** M
- **Dependencies / blocked by:** SVC-002, HTTP-002, KERN-006

## Goal (user value)

The layer that turns a contract into a running endpoint, verifies the caller's signed
principal, translates typed errors into the one envelope, and publishes the service's OpenAPI
document — the template every other service's `api` module copies.

## Scope

1. `ClusterApi.routes(...)`: binds `ClusterEndpoints.ping` to `PingUseCase`, maps
   `KuiError → ErrorEnvelope` through `libs/http`'s mapper, and mounts the health and
   capability endpoints from HTTP-002.
2. Principal verification: every `/internal/v1` endpoint verifies `X-Kui-Principal` through
   `PrincipalCodec.verify` with `expected = ServiceId("cluster")` and the request digest;
   failure is `401 KUI-UNAUTHENTICATED` with no detail about which check failed.
3. `ClusterApi.openApi`: the service's OpenAPI document, generated from
   `ClusterEndpoints.all` + the health endpoints, written to
   `services/cluster/api/openapi.json` by a Mill task and committed.
4. Mapping `CapabilityReport` (application) → `ServiceCapabilities` (contract).

## Non-goals

No server startup (SVC-004). No RBAC. No aggregation.

## Design references

ADR-020 (verification steps, the uniform 401), ADR-034 (envelope), ADR-003 (OpenAPI per
service, merged at the gateway), `ARCHITECTURE.md` §3 (`api`: "server logic: contract →
application, KuiError → HTTP envelope, principal verification, OpenAPI document"), §5.

## Deviations

Recorded during implementation. Each is a place where the sketch above could not be built as
written, with what was built instead and why.

### `ClusterApi.routes` takes two more arguments than the sketch

The sketch's signature has no readiness checks and no metric counter. Both are needed:

- `readiness: List[ReadinessCheck[F]]` — `HealthEndpoints.make` (HTTP-002) takes the checks, and
  what a service checks before it says it is ready is a decision its composition root makes, not
  one this module can invent. It is passed in exactly as `GatewayApi.routes` passes it.
- `rejections: Counter[F, Long]` — the task's own observability section requires
  `kui.principal.rejected{reason}`, and an OpenTelemetry counter is a resource that has to be
  created once rather than per request.

The `F` bound is `{Async, Parallel}` rather than `Async`, because `HealthEndpoints.make` runs the
readiness checks in parallel and asks for `Parallel`.

### `PrincipalVerification.secured` has a different shape

The sketch returns `(SignedPrincipal, I) => F[Either[KuiError, O]]`, which cannot be built: a
signed principal is verified against the *request digest* and the current time (ADR-020), and the
sketch's arguments contain neither. It also does not fit where Tapir needs it — Tapir runs an
endpoint's security logic ahead of decoding the request, which is the whole point of
`KuiEndpoint.internal` declaring the header as a `securityIn`, so the wrapper has to be a security
logic function rather than a decorator around the endpoint's own logic.

What is implemented is `secured(...)(render)(token, ctx)`, which is exactly the function Tapir's
`serverSecurityLogic` takes: it answers with a verified `Principal` or with a failure rendered by
the caller. `RequestContext` — the digest and the correlation id — is read off the request by a
Tapir `extractFromRequest` input added in `ClusterApi`, so nothing here has to touch a request.

### A missing header needed an interceptor: `PrincipalInterceptor`

The acceptance criteria require `401 KUI-UNAUTHENTICATED` for a request with no principal header.
Without extra work it is a `400 KUI-VALIDATION`: the header codec in `libs/contracts-core` refuses
a blank value, so the request fails during input decoding and never reaches any security logic, and
`libs/http`'s shared decode-failure handler correctly reports that as a validation problem.

`PrincipalInterceptor` is a `DecodeFailureInterceptor` placed ahead of `ErrorInterceptor`'s. It
answers the identical 401 for a decode failure on that one input and returns `None` for every other
input, which delegates inward to the shared handler untouched. There is still exactly one
code-to-status mapping: the status comes from `ErrorEnvelope.statusOf`.

**It belongs in `libs/http` eventually.** All eleven services need it and none of them should write
it twice. It is in `services/cluster/api` because `libs/http` is another lane's module and this is
the first service to need the behaviour; hoisting it is a mechanical move.

### The status code is added at the server, not in the contract

`KuiEndpoint` fixes the error *body* and no status, so Tapir would answer every failure with its
default 400. The served endpoint adds `.errorOut(statusCode)` and the status is computed from the
`KuiError` by `ErrorEnvelope.statusOf` at the one point where the error is still in hand. The
contract value in `ClusterEndpoints.all` is untouched, so the gateway's derived client and the
generated document are exactly what the contract published.

### Two mapping files rather than one

The sketch lists `CapabilityMapping.scala`. `PingMapping.scala` is beside it, because the ping
mapping is a different mapping and putting both in a file named after one of them would be a file
whose name lies. Both use Chimney (ADR-033), which compiles clean under `-Werror` on Scala 3.9 —
so TD-001's fallback to hand-written mappers was not needed here.

### `openApi` and `openApiCheck` are Mill commands over a `main`

`build.mill` cannot see the service's classes, so both tasks call `runMain` on
`kui.cluster.api.OpenApiDocument`, which renders the document and either writes it or compares it
to the committed file. The document is stamped with a fixed contract version (`1.0.0`) and no build
number, so regenerating it on a different machine or commit produces the same bytes — otherwise a
committed generated file could never be checked.
