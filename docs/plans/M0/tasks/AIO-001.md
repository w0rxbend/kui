# AIO-001 — `apps/allinone` composition root and in-process client

- **ID:** AIO-001
- **Title:** `apps/allinone` composition root and in-process service client
- **Milestone / Feature:** M0 / KU-005
- **Owner role:** Infrastructure Lead
- **Size:** L
- **Dependencies / blocked by:** SVC-004, GW-006, GW-009

## Goal (user value)

`./mill apps.allinone.run` and one container give a developer or a small installation the
entire product on one port — running the *same* gateway code path as the distributed
deployment, so what works locally works in production.

## Scope

1. `apps/allinone` depending on every service's `application`, `infrastructure` (none in M0)
   and `api` modules plus the gateway's, with one MacWire root, one `IO` runtime, one Netty
   listener and one otel4s provider (ADR-005).
2. `InProcessServiceClient` — the second `ServiceClient[F]` implementation: it interprets the
   **same** Tapir endpoints against the service's server logic in memory
   (`TapirInProcessClient(endpoints, serverLogic)` in `ARCHITECTURE.md` §11), so routing, the
   capability registry and aggregation are shared code and only the transport differs.
3. `PrincipalCodec.inProcess`: no signing; `kui.gateway.principalKeys` is ignored **with a
   warning** (ADR-005's exact requirement).
4. Services bind no listeners; only the gateway port is exposed.
5. Capability state for an in-process service is derived from its use-case results — an
   `InfrastructureError` becomes `Unavailable` exactly as a remote 5xx would — so the degraded
   UX is exercised locally without Docker.
6. One in-memory instance each of the session store and the capability registry. There is no
   config store in M0 at all: configuration is the static Ciris load (CFG-001), and the
   `ConfigStore[F]` port with its file and Kafka adapters is M1 (ADR-036, ADR-042, OT-004).
   When it arrives, all-in-one keeps working unchanged with the file adapter and with a single
   dev broker as the store cluster.

## Non-goals

No optional-dependency classpath profiles (they matter when Confluent and cloud SASL jars
exist — M3/M7). No clustering. No hot reload.

## Design references

ADR-005 (the entire decision), ADR-010 (`<Name>Wiring.make` reuse), `ARCHITECTURE.md` §11,
PLAN §14, feature matrix KU-005.

## Public Scala signatures to implement

```scala
package kui.allinone

object InProcessServiceClient:
  /** Interprets `endpoints` against `serverLogic` in memory. Same inputs, same outputs, same
    * error envelope as the HTTP path — it must be impossible for a response to differ. */
  def make[F[_]: Async](
      service: ServiceId,
      serverEndpoints: List[ServerEndpoint[Fs2Streams[F], F]],
      principals: PrincipalCodec[F]
  ): ServiceClient[F]

object AllInOneWiring:
  def resource[F[_]: Async](
      config: AllInOneConfig,
      telemetry: Telemetry[F]
  ): Resource[F, GatewayServer[F]]

object AllInOne extends IOApp
```

Wiring order (documented because it is easy to get wrong): telemetry → logger → config →
`PrincipalCodec.inProcess` → each service's `<Name>Wiring.make` → `ServiceClients` built from
`InProcessServiceClient`s → capability registry → readiness poller (which now polls in-process
health endpoints) → gateway routes → one Netty listener.

The milestone exit criterion "`./mill apps.allinone.run` serves the shell;
`GET /api/v1/capabilities` lists the sample service as `Available`" is satisfied here (the
shell part after AIO-002).

## Tests required

- `AllInOneWiringSuite` (integration):
  - `startsAndServesEveryGatewayAndProxiedRoute`.
  - `bindsExactlyOnePort` — enumerate listening sockets; exactly one.
  - `isResourceSafe` — start and stop three times, no leaked threads, no port left bound.
  - `warnsThatPrincipalKeysAreIgnored`.
- `InProcessServiceClientSuite` (contract, the important one):
  - `producesTheSameResultAsTheHttpClientForEverySampleEndpoint` — run the same request
    through `SttpServiceClient` (against a locally bound service) and through
    `InProcessServiceClient`, and assert the results are **equal**, including the error cases.
    This test is the enforcement of ADR-005's "no second code path".
  - `propagatesThePrincipalAsAValueWithoutASignature`.
  - `cancellationPropagatesForStreamingEndpoints`.
- `FaultIsolationSuite` (failure):
  - `anInfrastructureErrorFromAnInProcessUseCaseMarksTheCapabilityUnavailable` — the ADR-005
    requirement that the degraded UX is exercisable without Docker.
  - `aFailingServiceDoesNotAffectTheGatewaysOwnEndpoints` — `/api/v1/info` and the capability
    endpoints keep answering.

## Observability

One otel4s provider, so a trace covers the gateway span and the in-process service span in one
tree — a developer can see the same trace shape they will see in production.
`service.name` remains distinct per service in logs (`gateway`, `cluster`), so log filtering
works the same in both shapes.

## Degraded behavior

The all-in-one process is a single failure domain by construction; fault isolation still holds
at the **code** level (a failing use case is a `KuiError`, the registry records it, the UI
degrades). Say this plainly in the docs so nobody claims all-in-one gives process isolation.
