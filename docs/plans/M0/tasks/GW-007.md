# GW-007 — OpenAPI aggregation and Swagger UI

- **ID:** GW-007
- **Title:** OpenAPI aggregation and Swagger UI
- **Milestone / Feature:** M0 / KU-006
- **Owner role:** Chief Architect
- **Size:** M
- **Dependencies / blocked by:** GW-006

## Goal (user value)

One URL documents the whole product API. An integrator reads `/api/docs`, generates a client
from `/api/v1/openapi.json`, and never needs to know KUI is eleven services.

## Scope

1. `GET /api/v1/openapi.json` — the merged document: the gateway's own endpoints plus every
   routed service's endpoints with their **public** paths (the `/api/v1` rewrite of GW-006).
2. `GET /api/docs` — Swagger UI from `tapir-swagger-ui-bundle`, pointed at the merged document
   and respecting `server.basePath`.
3. Merge rules, decided here:
   - Tags are the service ids (`cluster`, `topic`, …), so the UI groups by service.
   - Operation ids must be globally unique; a collision fails the **build**, not a request.
   - Component schema names are prefixed with the owning service when two services define a
     schema with the same name.
   - The `servers` entry is the gateway's public base URL including `basePath`.
4. An OpenAPI **style check** in CI (ADR-003): every operation has an id, a summary and a tag;
   every path is lowercase kebab-case; every 4xx/5xx response references `ErrorEnvelope`.
5. `./mill services.gateway.api.openApi` writes `docs/api/openapi.json`;
   `openApiCheck` fails when the committed file is stale (the "OpenAPI regenerated and
   committed" exit criterion of PLAN §46).

## Non-goals

No API versioning machinery beyond `/api/v1`. No client code generation (contracts are
cross-compiled Scala; that *is* the client). No MCP tool listing (M8).

## Design references

ADR-003 ("merged at the gateway with `tapir-swagger-ui-bundle`; an OpenAPI style check runs on
the merged document in CI"), `ARCHITECTURE.md` §5, PLAN §20.8, PLAN §46.

## Public Scala signatures to implement

```scala
package kui.gateway.api.openapi

final case class ServiceDoc(service: ServiceId, endpoints: List[AnyEndpoint])

object OpenApiMerge:
  /** Deterministic: the same inputs always produce byte-identical JSON (sorted keys, stable
    * ordering), otherwise the committed file churns on every build. */
  def merge(title: String, version: String, servers: List[String], docs: List[ServiceDoc])
      : Either[NonEmptyList[String], sttp.apispec.openapi.OpenAPI]

enum StyleViolation:
  case MissingOperationId(path: String, method: String)
  case MissingSummary(operationId: String)
  case MissingTag(operationId: String)
  case DuplicateOperationId(operationId: String)
  case NonKebabPath(path: String)
  case ErrorResponseIsNotTheEnvelope(operationId: String, status: Int)

object OpenApiStyleCheck:
  def check(doc: sttp.apispec.openapi.OpenAPI): List[StyleViolation]
```

```
$ ./mill services.gateway.api.openApi

$ git diff --exit-code docs/api/openapi.json
$ curl -s localhost:8080/api/v1/openapi.json | jq '.paths | keys'
[ "/api/v1/capabilities", "/api/v1/capabilities/stream", "/api/v1/capabilities/{service}/probe",
  "/api/v1/info", "/api/v1/ping" ]
$ curl -s -o /dev/null -w '%{http_code}' localhost:8080/api/docs      # 200
```

The milestone exit criterion "`GET /api/v1/openapi.json` aggregates the gateway and
sample-service contracts" is asserted by the `paths` list above.

## Tests required

- `OpenApiMergeSuite` (unit + golden):
  - `mergesGatewayAndServiceEndpoints` — the exact path list.
  - `usesPublicApiV1Paths` — no `/internal/v1` string appears anywhere in the document.
  - `isDeterministic` — merging twice yields identical bytes.
  - `duplicateOperationIdsFailTheMerge`.
  - `schemaNamesAreDisambiguatedAcrossServices` — with two stub services both defining `Info`.
  - `serversEntryIncludesTheBasePath`.
- `OpenApiStyleCheckSuite` (unit): one assertion per `StyleViolation` case, plus a clean
  document producing no violations.

## Observability

None beyond the standard request instrumentation. `/api/docs` and `/api/v1/openapi.json` are
excluded from authentication in M0 (auth is disabled) — a note for M6: the docs endpoint's
exposure becomes a configuration flag then.

## Degraded behavior

The merged document is computed at startup and cached; a service being down does **not**
remove its endpoints from the documentation (the API still exists, it is merely unavailable),
which is why the merge takes contract metadata and never calls the services.
