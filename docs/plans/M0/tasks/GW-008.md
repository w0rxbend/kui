# GW-008 — Static asset serving, base path and SPA fallback

- **ID:** GW-008
- **Title:** Static asset serving, base path and SPA fallback
- **Milestone / Feature:** M0 / NX-005, KU-004
- **Owner role:** Chief Architect
- **Size:** M
- **Dependencies / blocked by:** GW-001

## Goal (user value)

The browser gets the shell from the same origin as the API — no CORS, no second server, no
separate deployment — and it works when KUI is mounted at `https://example.com/kui/` behind a
reverse proxy.

## Scope

1. `GET /ui/**` serves the linked frontend from the classpath (`tapir-files`), with:
   - `index.html` returned for any path that does not match a file (SPA deep links, required
     by Waypoint — `research/scala/frontend-research.md` §3.4).
   - correct MIME types, in particular `text/javascript` for `.js` **modules** and
     `application/json` for the import map.
   - `Cache-Control: public, max-age=31536000, immutable` for hashed asset names and
     `no-cache` for `index.html`, so a deploy is picked up immediately but assets are not
     re-fetched.
2. `GET /` redirects to `<basePath>/ui/`.
3. Base path support (NX-005): every served URL, the injected `<base href>` and the API base
   the shell reads are derived from `server.basePath`. The shell must not hard-code `/api/v1`.
4. Runtime configuration injection: `index.html` is served with a small
   `<script id="kui-bootstrap" type="application/json">` block containing
   `{ "basePath": "...", "apiBase": "...", "buildVersion": "..." }` so the frontend needs no
   build-time knowledge of the deployment.
5. The ES module import map for the npm packages ADR-025 will need (empty in M0, but the
   mechanism and its `Content-Type` are proven now).

## Non-goals

No bundling step (ADR-012: `fastLinkJS` output is served as static ES modules). No CDN, no
compression tuning beyond enabling gzip for text assets. No service worker.

## Design references

ADR-012 (served as static ES modules; no Vite in M0), ADR-011 (`the gateway serves index.html

## Acceptance criteria

```
$ curl -s -o /dev/null -w '%{http_code} %{content_type}\n' localhost:8080/ui/
200 text/html
$ curl -s -o /dev/null -w '%{http_code} %{content_type}\n' localhost:8080/ui/main.js
200 text/javascript
$ curl -s -o /dev/null -w '%{http_code}\n' localhost:8080/ui/clusters/some/deep/link
200                       # index.html, not 404
$ curl -s localhost:8080/ui/ | grep kui-bootstrap
<script id="kui-bootstrap" type="application/json">{"basePath":"","apiBase":"/api/v1",...}</script>
$ curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' localhost:8080/
302 http://localhost:8080/ui/
```

With `KUI_SERVER_BASEPATH=/kui`, every URL above works under `/kui` and the bare paths 404.

## Observability

Static asset requests are excluded from `kui.http.server.duration` (they would dominate) but
counted separately as `kui.http.server.duration {route="static"}` with a single label value,
so an operator can still see traffic without cardinality explosion.

## Degraded behavior

If the frontend assets are missing from the classpath (a backend-only build), `/ui/**` returns
a plain 503 HTML page saying the UI is not bundled, rather than a stack trace or an empty
200 — a developer running the gateway alone must get a comprehensible message.

## Deviations

### Hand-written classpath serving instead of `tapir-files`

`tapir-files`'s `Resources.get` interpreter serves a classpath tree correctly but treats every
unmatched path as `404 KUI-ROUTE-NOT-FOUND`. That is exactly the SPA fallback rule this task
implements, so building on top of the library would still mean writing the fallback logic by
hand, on top of machinery (byte ranges, conditional requests) this route does not need. GW-008
serves assets directly via `getClass.getResourceAsStream`. `tapir-files` stays a declared
dependency (GW-001) for GW-007, where the merged OpenAPI document is served the way Swagger UI
expects.

### A traversal attempt answers `404`, not `400`

The specification's acceptance criterion accepts either. `400` would tell an attacker their
probe reached the sanitisation logic and was recognised as a traversal attempt; `404` looks
identical to any other path this route does not have — the same answer a request for a
genuinely missing file gets. Indistinguishability was chosen deliberately.

### Two defects found only by running a real server

Both are recorded here because neither is visible from the code in isolation, and both would
have shipped invisibly if this task's acceptance run had been skipped:

- **An endpoint declared with no path input matches every request, not the empty path.** The
  root-redirect handler (`GET /`) was written first as a bare `endpoint.get`, on the ordinary
  assumption that "no path segments declared" means "match a path with zero segments". Tapir's
  actual rule is the opposite: with nothing to check, it matches any path at all — so the
  redirect answered every unmatched request in the whole gateway, including a typo under
  `/api/v1`. Fixed with `rootOnly`, an explicit `paths` input mapped to decode-fail (`Missing`)
  on any non-empty segment list, which is the same signal `libs/http`'s `ErrorInterceptor`
  already treats as "try the next endpoint" for a path capture.
- **A bare directory path resolves via `getResourceAsStream` to a listing of its children, not
  a 404.** `GET /ui/` (zero segments after `ui`) initially looked up the resource
  `/web` itself; on the JVM this succeeds against a directory and returns its immediate child
  names as the body — `index.html` and `importmap.json`, one per line — with no exception to
  signal anything unusual. `StaticRoutes.respond` now drops a trailing empty path segment and
  routes straight to the `index.html` fallback rather than attempting to resolve the bare
  prefix as a file.

Both are covered by tests that fail without the fix: `pathTraversalIsRefused` (with the
embedded-slash case added) and `servesIndexAtTheBareUiRootRatherThanADirectoryListing`.

### The `<base href>` value is HTML-attribute-escaped

Not specified, but necessary: the JSON bootstrap block already escaped its values for the
`<script>` context, but the `<base href="...">` interpolation did not, and a `basePath`
containing a quote could terminate the attribute early. `IndexHtml.htmlAttribute` closes that
gap. In practice `basePath` reaches this function already validated by
`kui.http.BasePath.normalize`, so the escape is defence in depth rather than a fix for a
reachable value.
