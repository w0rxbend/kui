# UI-004 — Kernel primitives B: dialog, drawer, toast, tooltip, breadcrumbs, empty state, `DataTable`

- **ID:** UI-004
- **Title:** Kernel primitives B: overlays, feedback and the non-virtual table
- **Milestone / Feature:** M0 / NX-007
- **Owner role:** Frontend Architect
- **Size:** L
- **Dependencies / blocked by:** UI-003

## Goal (user value)

The second half of the design system: the pieces that carry feedback and navigation context —
confirmation before a destructive action, a toast when a service goes down, a breadcrumb that
says where you are — all accessible and all built once.

## Scope

| Component | API highlights | Accessibility contract |
| --- | --- | --- |
| `Dialog` | `open: Var[Boolean]`, `title`, `body`, `actions`, `size`, `onClose` | `role="dialog" aria-modal`, focus trap, focus restored on close, `Escape` closes, background inert, initial focus on the first control |
| `ConfirmDialog` | wraps `Dialog`: `message`, `confirmLabel`, `danger`, `onConfirm` | destructive confirm is not the default-focused button |
| `Drawer` | `open`, `side: Right/Left`, `width`, `title` | same focus rules as `Dialog`, `aria-labelledby` |
| `Toast` + `NotificationBus` | `push(Notification)`, tone, `dismissAfter`, dedup key | `role="status"` (polite) or `role="alert"` (assertive for errors); dismissible by keyboard |
| `Tooltip` | `content`, `placement`, delay | `aria-describedby`, shows on focus as well as hover, never contains interactive content |
| `Breadcrumbs` | `List[Crumb(label, href)]` | `<nav aria-label="Breadcrumb">`, current page is `aria-current="page"` |
| `EmptyState` | `icon`, `title`, `description`, `action` | headings in order, no `role` needed |
| `DataTable` | `columns`, `rows: Signal[List[A]]`, `rowKey`, sort observer, `loading`, `empty` | `<table>` with proper `<th scope>`, sortable headers are buttons with `aria-sort` |

`NotificationBus` is one of the five kernel-owned `Var`s PLAN §21 allows; ADR-032 requires a
**deduplicated** toast per feature and cluster on an Available → Unavailable transition, so
`push` takes an optional dedup key with a window (default 30 s).

## Non-goals

No virtualization (`VirtualizedTable` is M2, SF-003). No column resize or reorder (M2). No
row expansion (M3). No inline editing anywhere.

## Design references

ADR-024 (primitive list including dialog, drawer, toast, tooltip, focus trap),
ADR-025 ("plus a non-virtual `DataTable` for small lists"), ADR-032 (deduplicated toast on
transition), `research/kafbat/ui-analysis.md` §IA.4, feature matrix NX-007 and SF-003.

  - `autoDismissRemovesAfterTheDelay`; `dangerToastsDoNotAutoDismiss`.

- `DataTableSuite` (DOM + property):

  - `emptyStateReplacesTheBodyButKeepsTheHeader`.
  - `loadingShowsASkeletonAndKeepsThePreviousRowCount` — no layout jump.

## Degraded behavior

`NotificationBus` must never lose a `Danger` notification to the visible-list bound: the
queue keeps it. `DataTable` renders `—` for a `None` cell value rather than an empty gap
(the convention every later screen follows for missing metrics, ROADMAP M1: "bytes in/out
render as `—`").

## Deviations

- **`Dialog.body` and `Dialog.actions` are thunks (`() => …`), not values.** The spec's own test
  `bodyIsNotRenderedWhileClosed` cannot pass with an eagerly built `HtmlElement`: building it is what
  starts its subscriptions and its requests. The same applies to `DataTable.empty` and to
  `EmptyState.default`, which is a method rather than a value because a DOM node can only be in one
  place at a time.
- **`NotificationBus`'s behaviour lives in a `Notifications` class that takes a clock and a
  scheduler.** The spec names cats-effect's `TestControl`, which is not available here: this is
  Scala.js, there is no cats-effect in the frontend, and the delays are `setTimeout`. Injecting the
  clock and the timer gives the same property — time is stepped by the test rather than waited on —
  with no new dependency. `object NotificationBus` remains the application-wide instance.
- **Deduplication remembers events, not what is on screen.** The spec says repeats "inside the
  window collapse into one". Deriving that from the visible list would let a repeat reappear the
  instant the user dismissed the first one, so the bus keeps a small `dedupKey -> timestamp` map,
  pruned to the window on every push.
- **`DataTable`'s loading state dims the existing rows rather than showing a skeleton.** The spec
  asks for "a skeleton and the previous row count". Keeping the real rows achieves the stated goal —
  no layout jump — and shows the user data that is still true, which a skeleton does not. `aria-busy`
  is what announces the state.
- **`Toast` has no timing of its own.** Automatic dismissal belongs to the bus, because a
  notification that is queued rather than visible still has to expire.
- **`FocusTrap` remembers one previously focused element rather than a stack.** KUI never opens a
  dialog from inside another dialog, and a stack would be state to keep correct for a case that does
  not arise. The comment in the source names the line that has to change if nested overlays ever
  become real.
- **The gallery extension is deferred to UI-009 with the rest of the gallery** (see UI-003's
  Deviations).
