# UI-011 — Error pages: 403, 404 and gateway-unreachable

- **ID:** UI-011
- **Title:** Error pages: 403, 404 and gateway-unreachable
- **Milestone / Feature:** M0 / KU-009
- **Owner role:** Frontend Architect
- **Size:** S
- **Dependencies / blocked by:** UI-009

## Goal (user value)

Three states a user will meet, each explaining what happened and offering the one useful next
action — instead of a blank page, a spinner forever, or a raw stack trace.

## Scope

1. **404** (`NotFoundPage`): "That page does not exist", the attempted URL, a link to the
   dashboard, and the nav stays usable.
2. **403** (`ForbiddenPage`): "You do not have permission to view X", who to ask (a
   configurable support contact from `AppInfo`, empty by default), and the nav stays usable.
   In M0 this page is reachable only through a direct URL since RBAC is M6, but it is built
   and tested now so M6 has nothing to design.
3. **Gateway unreachable**: the single full-screen state (feature matrix KU-009, "Screen 33").
   Shown when the shell's *own* calls (`/auth/me`, `/info`, the capability endpoints) fail with
   `ApiError.Unreachable` — not when a feature's call fails, which is the fallback panel's job.
   Contains: what happened, an automatic retry with visible countdown and exponential backoff
   (2 s, 4 s, 8 s, capped at 30 s), a manual "Try again", and the last successful contact time.
   It disappears automatically when a retry succeeds, with no reload.

## Non-goals

No offline mode, no service worker, no cached-page rendering. No error reporting to a server.

## Design references

Feature matrix KU-009 ("403, 404, feature fallback pages and the single full-screen 'cannot
reach gateway' state"), ADR-032 (the fallback panel is a *different* thing, for one feature),
ADR-024 (`EmptyState` primitive, `Messages` objects).

## Public Scala signatures to implement

```scala
package kui.ui.shell

enum ShellConnectivity:
  case Connected(lastContact: js.Date)
  case Lost(since: js.Date, nextRetryInSeconds: Int)

object ShellHealth:
  /** Fed by every shell-owned API call's outcome. A feature's failure never sets Lost. */
  val connectivity: Signal[ShellConnectivity]
  def reportSuccess(): Unit
  def reportUnreachable(): Unit
  def retryNow(): Unit

package kui.ui.shell.page

object GatewayUnreachable:
  def apply(state: Signal[ShellConnectivity], retry: Observer[Unit]): HtmlElement
```

## Tests required

- `ErrorPagesSuite` (DOM):
  - `notFoundShowsTheAttemptedUrlAndKeepsTheNavigation`.
  - `forbiddenNamesTheResourceAndDoesNotLeakWhetherItExists` — the message must be identical
    for a resource that exists and one that does not.
  - `bothPagesHaveALevelOneHeadingAndALinkHome` (accessibility and usability).
- `ShellHealthSuite` (unit + `TestControl`):
  - `aFeatureCallFailureDoesNotTriggerTheFullScreenState` — the distinction that matters.
  - `threeShellCallFailuresTriggerIt` (one transient failure must not flash the screen).
  - `backoffIsTwoFourEightCappedAtThirty`.
  - `aSuccessfulRetryRestoresTheAppWithoutAReload`.
  - `theCountdownIsVisibleAndDecrements`.

## Observability

Not applicable.

## Degraded behavior

The full-screen state is itself the degraded behaviour of last resort. It must render with no
API data at all — no version, no principal, no capabilities — because by definition nothing
answered.

## Docs to update

`docs/frontend/README.md`: when to use which of the three error surfaces (page-level 404/403,
feature fallback panel, full-screen gateway state). Getting this wrong is the most likely
future mistake, so the guidance is written down.
