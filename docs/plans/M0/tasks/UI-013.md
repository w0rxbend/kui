# UI-013 — Follow-up: re-derive design tokens from the Claude Design import

- **ID:** UI-013
- **Title:** Follow-up: re-derive design tokens from the Claude Design import
- **Milestone / Feature:** M0 / NX-007 (completion), TECH_DEBT TD-007
- **Owner role:** Frontend Architect
- **Size:** S (once unblocked)
- **Dependencies / blocked by:** UI-002, **and BLOCKERS.md B-001 — this task cannot start
  until the design import lands**

## Goal (user value)

The product looks like the design it was designed as. Until then, KUI ships with honest
placeholders rather than waiting.

## Scope

This task exists so the placeholder decision is tracked, not forgotten. **No M0 task depends
on it, and M0 is complete without it.**

When B-001 is resolved and `research/design/tokens.md` exists:

1. Replace every value in `frontend/ui-kernel/resources/css/10-tokens.css` with the imported
   token values, removing every `PLACEHOLDER` marker.
2. Add any token group the design defines that the placeholder set lacks; for a token the
   design does **not** define, keep the placeholder and list it in a "gaps" section for the
   design owner.
3. Re-run `ContrastSuite` (UI-002); any imported pair failing WCAG AA is reported back to the
   design owner as a gap rather than silently adjusted.
4. Visually diff the component gallery (UI-003) before and after; attach both screenshot sets.
5. Update `docs/frontend/tokens.md`, close TECH_DEBT TD-007, and set feature matrix NX-007
   to `DONE`.

## Non-goals

No component redesign. No new primitives. No Shoelace decision — ADR-024 defers that to a
separate, evidence-based reopening after the import; this task only records what the import
implies for it.
