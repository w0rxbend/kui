# UI-013 — Optional: reconcile tokens with a design import, if one ever lands

- **ID:** UI-013
- **Title:** Optional: reconcile the KUI token set with a design import
- **Milestone / Feature:** post-M0 improvement (NX-007 is already `DONE` via UI-002)
- **Owner role:** Frontend Architect
- **Size:** S
- **Dependencies / blocked by:** UI-002. **Nothing waits on this task and no milestone is
  gated by it.**

## Goal (user value)

If the Claude Design project is ever imported, KUI adopts its values cheaply — because UI-002
was built so that adopting them is a one-file edit.

## Status

**Not scheduled.** UI-002 took the token decision on KUI's own authority after analysing the
reference products; the token set is authoritative, NX-007 is `DONE`, and B-001 is closed as
decided-around. This file exists only so that *if* `research/design/tokens.md` ever appears,
the reconciliation work is already specified and nobody re-derives it.

## Scope (only if `research/design/tokens.md` appears)

1. Replace values in `frontend/ui-kernel/resources/css/10-tokens.css` where the import
   defines an equivalent token, updating each provenance comment to `/* design */`.
2. For a token the design does not define, **keep KUI's value** — the set is KUI's, and a gap
   in the import is not a reason to lose a token components depend on. List such tokens in
   `docs/frontend/tokens.md` under "not covered by the import".
3. Re-run `ContrastSuite`. **An imported pair that fails WCAG AA is adjusted, not adopted**,
   and the adjustment is recorded. Accessibility outranks fidelity to a mockup; this is a
   decision, not a question to send back.
4. Do not add a token group that no component needs, however many the import defines.
5. Visually diff the component gallery (UI-003) before and after; attach both screenshot sets.
6. Update `docs/frontend/tokens.md` and close TECH_DEBT TD-007.

## Non-goals

No component redesign. No new primitives. No reopening of the Shoelace question: ADR-024
decided against a third-party widget library, and an import of colour values is not new
evidence about component ownership. Reopening it would need a superseding ADR (PLAN §39).

## Design references

UI-002 (the token decision this would revise), TECH_DEBT TD-007, ADR-024,
PLAN §21 "Visual design reference", feature matrix NX-007 (already `DONE`).
