# UI-002 — KUI design tokens and three-state theme

- **ID:** UI-002
- **Title:** KUI design tokens and three-state theme
- **Milestone / Feature:** M0 / NX-007
- **Owner role:** Frontend Architect
- **Size:** M
- **Dependencies / blocked by:** UI-001

## Goal (user value)

Light and dark themes that work today, expressed entirely as CSS custom properties, so that
any future restyle changes **one file** and no component.

## Decision this task takes

The Claude Design import (BLOCKERS.md B-001) is owned outside this swarm and may never arrive.
Waiting would stall the entire frontend lane, so **KUI owns its token set**, decided here from
the two reference products already analysed:

| Question | Kafbat | Kouncil | KUI decision | Why |
| --- | --- | --- | --- | --- |
| Theme model | three-state light/dark/system in a ~1 600-line `theme.ts` object consumed by styled-components | one SCSS palette, no dark mode at all | three-state, as CSS custom properties | Dark mode is table stakes for an operator tool people stare at all day; Kouncil's omission is a gap, not a simplification |
| Token count | hundreds of component-scoped entries (`theme.button.primary.hover.background`, …) | a handful of SCSS variables | ~40 semantic tokens, **no component-scoped tokens** | Kafbat's per-component theming is why its theme file is 1 600 lines and why a palette change is a multi-day edit; semantic tokens (`--kui-color-surface-raised`) let one change propagate |
| Where values live | TypeScript object, needs a rebuild | SCSS, needs a rebuild | CSS custom properties, swappable at runtime | Enables the `data-theme` switch, and lets an operator override a colour in a deployment without rebuilding |
| Contrast | not enforced | not enforced | WCAG AA enforced by `ContrastSuite` | Neither reference checks it; several Kafbat muted-text pairs fail AA |

Values are seeded from Kafbat's palette because it is the closest visual reference for this
product category, but the **set, the naming and the constraints are KUI's own** and are not
provisional. `NX-007` closes on this work. If a design import ever lands, UI-013 reconciles
values only — it is an improvement, not a completion.

## Scope

1. `10-tokens.css` defining the token set as CSS custom properties on `:root`, redefined under
   `:root[data-theme="dark"]` and under `@media (prefers-color-scheme: dark)` guarded by
   `:root:not([data-theme="light"])`.

   Token groups: `--kui-color-*` (surface, surface-raised, border, text, text-muted, primary,
   primary-contrast, success, warning, danger, info, focus), `--kui-space-*` (0…8 on a 4 px
   scale), `--kui-font-*` (family-sans, family-mono, size-xs…xl, weight-regular/medium/bold,
   line-height-tight/normal), `--kui-radius-*` (sm, md, lg, pill), `--kui-shadow-*` (sm, md),
   `--kui-z-*` (dropdown, drawer, dialog, toast), `--kui-duration-*` (fast, normal).

2. **Every colour records its provenance**, so a future reconciliation knows what was
   deliberate. Each value carries a trailing comment: `/* seeded: kafbat */` for a value taken
   from the reference palette, `/* kui */` for one KUI chose (including every value adjusted to
   pass contrast). The file header states that this is the authoritative KUI token set, names
   the decision table above, and points at UI-013 as optional reconciliation — **not** as a
   pending completion.

3. `Theme` — the three-state switcher (`auto | light | dark`) persisted in a
   `WebStorageVar`, applied as `data-theme` on `<html>`, defaulting to `auto`.

4. A contrast check: a small test asserting every foreground/background token pair in both
   themes meets WCAG AA (4.5:1 for body text, 3:1 for large text and UI borders). Placeholder
   values that fail are adjusted — accessibility is not deferred to the design import.

## Non-goals

No component styling (UI-003). No component-scoped tokens, ever — that is the Kafbat trap this
decision exists to avoid. No theme editor, no per-user custom themes, no runtime palette
configuration (a deployment can override the custom properties with its own stylesheet; that
is enough and costs nothing).

## Public Scala signatures to implement

```scala
package kui.ui.kernel.theme

enum ThemeChoice { case Auto, Light, Dark }

object Theme:
  /** Persisted in localStorage under "kui.theme"; falls back to Auto when storage is
    * unavailable (private browsing) rather than throwing. */
  val choice: Var[ThemeChoice]
  val effective: Signal[ThemeChoice]        // Auto resolved against prefers-color-scheme
  def install(): Unit                        // binds `data-theme` on <html>, subscribes to the media query

/** The token names as constants so Scala code can read a computed value in tests and never
  * hard-codes a colour. */
object Tokens:
  object Color { val Surface = "--kui-color-surface"; /* ... */ }
  object Space { val S1 = "--kui-space-1"; /* ... */ }
  val all: List[String]
```

## Tests required

- `ThemeSuite` (unit + DOM under jsdom):
  - `defaultsToAuto`.
  - `autoFollowsPrefersColorScheme` — with a stubbed media query.
  - `explicitChoiceOverridesTheMediaQuery` in both directions.
  - `choiceSurvivesAReload` — write, re-create, read.
  - `unavailableLocalStorageFallsBackToAutoWithoutThrowing`.
  - `dataThemeAttributeIsSetOnTheHtmlElement`.
- `ContrastSuite` (unit): parses the token file, computes the contrast ratio for every
  documented foreground/background pair in both themes, asserts AA. The pair list lives in
  `docs/frontend/tokens.md` and is read by the test, so adding a token pair without checking
  its contrast is impossible.

Not applicable.

## Degraded behavior

If the token file fails to load (a broken deploy), the browser renders unstyled but legible
HTML — no component may depend on a token for its *function*, only for its appearance. State
this rule in `docs/frontend/README.md`.
