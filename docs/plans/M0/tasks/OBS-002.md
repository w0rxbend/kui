# OBS-002 — `libs/observability`: Tapir interceptors and metric names

- **ID:** OBS-002
- **Title:** `libs/observability`: Tapir interceptors and metric names
- **Milestone / Feature:** M0 / MT-007
- **Owner role:** Infrastructure Lead
- **Context / service:** `libs/observability`
- **Size:** M
- **Dependencies / blocked by:** OBS-001, KERN-004

## Goal (user value)

Every endpoint in every service is traced and measured identically without a single line of
per-endpoint instrumentation, so no feature can ship unobservable.

## Scope

1. `KuiInterceptors.serverInterceptors(telemetry, logger)` returning the ordered Tapir
   interceptor list: correlation-id extraction/generation → tracing
   (`tapir-otel4s-tracing`) → metrics (`tapir-opentelemetry-metrics`) → request logging.
2. `MetricNames` — the constant list of PLAN §30 plus the `ARCHITECTURE.md` §13 additions, as
   typed constants so no metric is ever emitted with an ad-hoc name.
3. Span naming: `kui.<context>.<operation>` (PLAN §30), derived from the endpoint's declared
   operation id, with a documented fallback for endpoints that do not set one — and a test
   that fails when an endpoint has no operation id, so the fallback is never used silently.
4. The client-side counterpart used by `libs/http`'s `UpstreamClient`: a span per upstream
   call, `traceparent` injection, and the `kui.upstream.*` metrics.

## Non-goals

No custom exporters. No sampling policy beyond the SDK default (revisit in M8). No business
metrics (`kui.kafka.*` names are declared here but emitted by `libs/kafka` in M1).

## Design references

ADR-009, PLAN §30 (the metric name list), `ARCHITECTURE.md` §13 (the additions:
`kui.stream.events`, `kui.stream.active`, `kui.cursor.rejected`, `kui.principal.rejected`,
`kui.config.version`), ADR-003 (interceptors come from `libs/http` consumers).

## Tests required

- `MetricNamesSuite` (unit): names are unique, all start with `kui.`, and the list matches
  PLAN §30 + `ARCHITECTURE.md` §13 exactly (a literal expected list — this test is the
  contract between the plan and the code).
- `KuiInterceptorsSuite` (unit, otel4s testkit + Tapir stub server):
  - `everyRequestProducesOneServerSpanNamedByOperationId`.
  - `correlationIdIsGeneratedWhenAbsentAndEchoedWhenPresent`.
  - `correlationIdAppearsInTheSpanTheLogAndTheResponseHeader` — the three-way correlation
    that makes an incident traceable.
  - `httpServerDurationIsRecordedWithRouteAndStatus`, including for a 500.
  - `interceptorOrderIsStable` — asserts the exact order, because tracing must wrap metrics
    so failed requests still record duration.
  - `endpointWithoutAnOperationIdFailsTheSuite` — the guard described in the scope.

## Observability

Self-referential: this task defines it. One rule for reviewers — a metric or span attribute
whose value could be user data (a topic name is fine; a message payload is not) must be
justified in the task spec that introduces it.

## Degraded behavior

If the meter or tracer cannot be created, interceptors degrade to no-ops and log one WARN.
A telemetry failure never fails a request.
