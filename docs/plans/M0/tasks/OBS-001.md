# OBS-001 — `libs/observability`: telemetry bootstrap and structured logger

- **ID:** OBS-001
- **Title:** `libs/observability`: telemetry bootstrap and structured logger
- **Milestone / Feature:** M0 / MT-007
- **Owner role:** Infrastructure Lead
- **Context / service:** `libs/observability`
- **Size:** M
- **Dependencies / blocked by:** KERN-002

## Goal (user value)

Every process emits traces, metrics and JSON logs that correlate with each other from the
first deployment, so the first production incident is diagnosable rather than archaeological.

## Scope

1. `Telemetry.resource` — an `otel4s` `OtelJava` provider built from `TelemetryConfig`, with
   OTLP export for traces and metrics and an optional Prometheus scrape endpoint, all as one
   `Resource[F, Telemetry[F]]` that shuts down cleanly.
2. `KuiLogger` — a `log4cats` `StructuredLogger[F]` wrapper that (a) always carries
   `service.name`, (b) merges a per-request context (`correlation.id`, `user.id`,
   `cluster.id`, `operation`), and (c) bridges the current span's `trace_id`/`span_id` into
   SLF4J MDC so a log line can be pasted into a trace search.
3. Logback configuration: JSON lines via `logstash-logback-encoder` when
   `telemetry.logFormat = json`, a human pattern otherwise. Shipped as a resource in this
   module and referenced by every `app`.
4. `Correlation` — generation and propagation of `CorrelationId` (a 16-hex-character value
   derived from the span id when a span exists, random otherwise).

## Non-goals

No Tapir interceptors (OBS-002). No `/metrics` product endpoint (that is `kui-metrics-service`,
M8; this module owns application telemetry only, ADR-009). No log shipping, no dashboards.

## Design references

ADR-009 (otel4s 1.1.0 with the oteljava backend, exporters, the two-Prometheus-endpoints
distinction), ADR-008 (log4cats over Logback, standard context keys, Fabric is dropped),
`ARCHITECTURE.md` §13, PLAN §30.

## Public Scala signatures to implement

```scala
package kui.observability

trait Telemetry[F[_]]:
  def tracer(name: String): F[org.typelevel.otel4s.trace.Tracer[F]]
  def meter(name: String): F[org.typelevel.otel4s.metrics.Meter[F]]

object Telemetry:
  def resource[F[_]: Async](serviceName: String, config: TelemetryConfig): Resource[F, Telemetry[F]]
  /** Used in tests and in modules that must not export anything. */
  def noop[F[_]: Applicative]: Telemetry[F]

final case class LogContext(
    correlationId: Option[CorrelationId],
    userId: Option[String],          // already hashed by the caller when hashUserIds is on
    clusterId: Option[ClusterId],
    operation: Option[String]
):
  def toMap: Map[String, String]

object LogContext:
  val empty: LogContext

object KuiLogger:
  /** `serviceName` becomes `service.name` on every entry. */
  def make[F[_]: Sync](serviceName: String): F[StructuredLogger[F]]
  /** Adds the request-scoped keys and the current span ids. */
  def withContext[F[_]](logger: StructuredLogger[F], ctx: LogContext): StructuredLogger[F]

object Correlation:
  def fromSpanOrRandom[F[_]: Sync: Tracer]: F[CorrelationId]
  val HeaderName: String = "X-Kui-Correlation-Id"
```

**Context key names are contract** (`ARCHITECTURE.md` §13): `correlation.id`, `user.id`,
`cluster.id`, `service.name`, `operation`. Any log entry from any module uses these exact
strings; a test in every service asserts it.

## Acceptance criteria

```

```

A manual check recorded once in the Implementation Report: run any `app` with
`KUI_TELEMETRY_LOGFORMAT=json` and confirm one line of output is valid JSON containing
`service.name`, `trace_id` and `span_id`.

## Tests required

- `TelemetrySuite` (unit, `munit-cats-effect` + otel4s testkit):
  - `resourceStartsAndShutsDownCleanly` — no non-daemon threads left behind.
  - `noopEmitsNothing`.
  - `spanCarriesServiceName`.
- `KuiLoggerSuite` (unit):
  - `everyEntryCarriesServiceName`.
  - `withContextAddsTheFiveStandardKeysAndNothingElse` — asserts the exact key set, so a typo
    like `correlationId` instead of `correlation.id` fails.
  - `mdcCarriesTraceAndSpanIdInsideASpan` and `mdcIsCleanOutsideOne` (no leakage between
    fibers — run two concurrent fibers with different contexts and assert no cross-talk).
  - `userIdIsNotLoggedWhenAbsent` — no `"user.id": null` noise.

## Observability

This module *is* the observability. Its own failures (exporter unreachable) must never fail a
request: exporter errors are logged at WARN once per minute and swallowed.

## Degraded behavior

If the OTLP endpoint is unreachable at startup, the process starts anyway with an exporter
that drops spans and logs one WARN. Telemetry is never a startup dependency — a monitoring
outage must not take KUI down.
