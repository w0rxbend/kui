# UI-012 — `frontend/ui-clusters` sample feature and bundle-shape check

- **ID:** UI-012
- **Title:** `frontend/ui-clusters` sample feature and bundle-shape check
- **Milestone / Feature:** M0 / KU-004
- **Owner role:** Frontend Architect
- **Size:** M
- **Dependencies / blocked by:** UI-010, SVC-002, BUILD-006

## Goal (user value)

The proof that the whole chain works end to end, on real code: a feature module that is
lazily downloaded, calls a typed client derived from the service's contract, renders a real
response, and shows its own fallback panel when the service is down.

## Scope

1. `frontend/ui-clusters` implementing `KuiFeature` with:
   - `id = FeatureId.Clusters`, a nav entry, one route `/ui/clusters`;
   - a page with a "Ping" button that calls `GET /api/v1/ping?message=...` through the
     cross-compiled `services/cluster/contract` client and renders the response in a
     `DataTable` of past pings (proving `ApiClient`, `QueryCache`, `DataTable` and the
     contract client all work);
   - `unavailableView` — the feature's own fallback content, which the shell renders through
     `FeatureFallbackPanel`;
   - no panels contributed (the `FeaturePanel` mechanism is exercised by its own unit test in
     UI-007; a real cross-feature panel arrives in M4).
2. Registration: the `FeatureId.Clusters` case, the registry thunk, and
   `"kui.ui.clusters"` added to `SmallModulesFor` in `build.mill`.
3. Turning on BUILD-006's `checkBundleShape` for real, and wiring it into CI (BUILD-004's
   bundle-shape stage), asserting:
   - a separate module file exists for `kui.ui.clusters`;
   - `main.js` does not contain the feature's classes;
   - `main.js` is under the size budget.

## Non-goals

No real cluster functionality — that is M1 (`ui-clusters` is filled in then; this task creates
the module and the ping page it will replace). No cluster switcher. No dashboard.

## Design references

ADR-012 (Option B, the thunk registry, the CI bundle-shape assertion), ADR-011,

## Degraded behavior

When the cluster service is down, the shell renders `unavailableView` and the feature module
is not downloaded at all (UI-010's `FeatureGate` test asserts this). If the module *is* already
loaded and the service then dies, the page keeps its previously fetched pings greyed with
their timestamp and disables the Ping button through `ActionPermissionWrapper` — the ADR-032
stale-data rule, demonstrated on real code so M1+ has a worked example.

## Deviations

### `grep -c 'ClustersFeature' main.js` is 1, not 0 — and that is correct

The acceptance criterion asks for zero occurrences of the string. The real number is one, and it is
not a leak. What is in `main.js` is a single mangled *method* name:

```
$ grep -o 'Lkui_ui_clusters_ClustersFeature[^"]\{0,40\}' out/frontend/uiShell/fullLinkJS.dest/main.js
Lkui_ui_clusters_ClustersFeature__page__Lcom_raquo_laminar_nodes_ReactiveHtmlElement(load.sv
```

The optimiser inlined a one-line private accessor across the module boundary. The class itself is
not there, which is the property that matters — `main.js` cannot construct the feature, so the
browser must fetch the feature's module first:

```
$ grep -c '\$c_Lkui_ui_clusters_ClustersFeature' out/frontend/uiShell/fullLinkJS.dest/main.js
0
$ grep -c '\$c_Lkui_ui_clusters_ClustersFeature' \
    'out/frontend/uiShell/fullLinkJS.dest/kui.ui.clusters.-Clusters-Feature.js'
6
```

`BundleShape`'s rule 2 was therefore tightened from "the mangled name appears anywhere" to "the
class-definition symbol `$c_` appears", with a unit test for the inlined-method case. The looser
rule flagged a one-line inlined accessor exactly as loudly as a feature that really had shipped with
the shell, and a check that cries wolf is a check somebody turns off.

### The browser's `ping` endpoint is a separate value from the service's

`ClusterEndpoints.ping` describes what the *service* serves: `/internal/v1/ping`, with the gateway's
signed principal header as a security input. A browser calls neither of those — the gateway rewrites
the prefix to `/api/v1` and supplies the principal itself — so the browser's client cannot be built
from that value. `ClustersApi.ping` is the browser's view of the same endpoint, built from the same
path segment, the same query parameter name and the same response DTO, all of which are now named
constants in the contract so the two cannot drift. `kui.contracts.PublicApi` holds the `/api/v1`
prefix, in `contracts-core`, so that the frontend can name it without any service's contract naming
it (a service contract must not know the public prefix; the browser must).

Verified against a running all-in-one:

```
$ curl "http://localhost:18080/api/v1/ping?message=hello-from-kui"
{"message":"hello-from-kui","at":"2026-09-03T17:53:55.282Z","service":"cluster"}
HTTP 200
```

### The client is based at the deployment root, not at `apiBase`

Every endpoint value KUI publishes to the browser already carries the full public path, `/api/v1`
included. A client based at `bootstrap.apiBase` would append one prefix to another and ask for
`/api/v1/api/v1/capabilities`. `Bootstrap.gatewayRoot` is the small helper that states this once,
and both the shell and this feature build their client from it.

### `HealthReporting` in the kernel, because a feature cannot call the shell

The spec asks for outcomes to be reported through `ShellHealth.report(CallScope.Feature, ...)`. A
feature cannot name `ShellHealth`: the shell depends on every feature, so the reverse edge is a
cycle and the end of lazy loading. `CallScope` and a one-function `HealthReporting` seam therefore
moved to `kui.ui.kernel.state`; the shell installs its tracker into it at start-up, and
`kui.ui.shell.CallScope` remains as an alias so no existing call site or suite changed. The rule the
task cares about is unaffected and asserted: this feature reports `CallScope.Feature` and never
`CallScope.Shell`.

### `ClustersPageId` is a sealed trait with a `case object`, not an `enum`

Waypoint's `Route.static` needs the page's *singleton type*. An `enum` case has the enum's type, and
the route does not compile. The shell's own `ShellPage` already uses this shape for the same reason.

### `FeatureRoutes.routes` takes the UI prefix

A feature's path patterns hang off `/ui`, or off `/kafka/ui` in a deployment mounted under a prefix.
Only the shell knows which, so it passes it in; a feature that hard-coded `/ui` would silently match
nothing under any other prefix.

### `frontend.uiClusters.test` runs on plain Node, not jsdom

`ClustersStateSuite` is about a state machine and touches no `document`. Running it without a DOM
keeps it fast and makes the absence of DOM assertions a fact about the module rather than a
convention somebody has to remember.

### CI runs `frontend.uiShell.checkBundleShape`, not `frontend.uiKernel`'s

BUILD-004's stage named the kernel's task. The kernel is a library with no entry point, so the
linker produces no `main.js` for it and it has no feature list — its check would skip and prove
nothing. The shell is the module the linker is run on, and it is the one with the feature list.
