# UI-012 — `frontend/ui-clusters` sample feature and bundle-shape check

- **ID:** UI-012
- **Title:** `frontend/ui-clusters` sample feature and bundle-shape check
- **Milestone / Feature:** M0 / KU-004
- **Owner role:** Frontend Architect
- **Size:** M
- **Dependencies / blocked by:** UI-010, SVC-002, BUILD-006

## Goal (user value)

The proof that the whole chain works end to end, on real code: a feature module that is
lazily downloaded, calls a typed client derived from the service's contract, renders a real
response, and shows its own fallback panel when the service is down.

## Scope

1. `frontend/ui-clusters` implementing `KuiFeature` with:
   - `id = FeatureId.Clusters`, a nav entry, one route `/ui/clusters`;
   - a page with a "Ping" button that calls `GET /api/v1/ping?message=...` through the
     cross-compiled `services/cluster/contract` client and renders the response in a
     `DataTable` of past pings (proving `ApiClient`, `QueryCache`, `DataTable` and the
     contract client all work);
   - `unavailableView` — the feature's own fallback content, which the shell renders through
     `FeatureFallbackPanel`;
   - no panels contributed (the `FeaturePanel` mechanism is exercised by its own unit test in
     UI-007; a real cross-feature panel arrives in M4).
2. Registration: the `FeatureId.Clusters` case, the registry thunk, and
   `"kui.ui.clusters"` added to `SmallModulesFor` in `build.mill`.
3. Turning on BUILD-006's `checkBundleShape` for real, and wiring it into CI (BUILD-004's
   bundle-shape stage), asserting:
   - a separate module file exists for `kui.ui.clusters`;
   - `main.js` does not contain the feature's classes;
   - `main.js` is under the size budget.

## Non-goals

No real cluster functionality — that is M1 (`ui-clusters` is filled in then; this task creates
the module and the ping page it will replace). No cluster switcher. No dashboard.

## Design references

ADR-012 (Option B, the thunk registry, the CI bundle-shape assertion), ADR-011,
`docs/ROADMAP.md` M0 exit criterion "Bundle-shape check", feature matrix KU-004.

## Public Scala signatures to implement

```scala
package kui.ui.clusters

/** Constructed only through `js.dynamicImport` in the shell's registry. Nothing in the shell
  * may name this type in a signature or a val. */
final class ClustersFeature extends KuiFeature:
  def id: FeatureId = FeatureId.Clusters
  def nav: NavEntry
  def routes: List[Route[? <: Page, ?]]
  def render(page: Page): HtmlElement
  def unavailableView(reason: DegradedReason, since: Option[Instant], retry: Observer[Unit]): HtmlElement
  def panels: List[PanelContribution] = Nil

/** Feature-local state: a plain class holding Vars, no global singleton (PLAN §21). */
final class ClustersState(api: ApiClient):
  val pings: Var[List[PingResponse]]
  val inFlight: Signal[Boolean]
  val lastError: Var[Option[ApiError]]
  def ping(message: String): Unit
```

## Degraded behavior

When the cluster service is down, the shell renders `unavailableView` and the feature module
is not downloaded at all (UI-010's `FeatureGate` test asserts this). If the module *is* already
loaded and the service then dies, the page keeps its previously fetched pings greyed with
their timestamp and disables the Ping button through `ActionPermissionWrapper` — the ADR-032
stale-data rule, demonstrated on real code so M1+ has a worked example.
