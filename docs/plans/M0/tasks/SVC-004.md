# SVC-004 — `services/cluster/app`: wiring, config slice and main

- **ID:** SVC-004
- **Title:** `services/cluster/app`: wiring, config slice and main
- **Milestone / Feature:** M0 / KU-005, KU-006
- **Owner role:** Domain Architect (Cluster Registry context)
- **Size:** M
- **Dependencies / blocked by:** SVC-003, CFG-001, OBS-001

## Goal (user value)

`./mill services.cluster.app.run` starts a real service with real telemetry and real
configuration validation — and the same wiring function is reused unchanged by the all-in-one
process, so the two shapes cannot drift (ADR-005).

## Scope

1. `ClusterWiring.make(config, telemetry): Resource[F, ClusterServer]` — the MacWire
   composition root returning **server logic without a listener** (ADR-010's exact
   requirement), so `apps/allinone` can mount it in-process.
2. `Main` — loads configuration, builds telemetry, calls `ClusterWiring.make`, binds the Netty
   listener from `libs/http`, installs a graceful-shutdown handler, and exits non-zero with the
   accumulated configuration errors when loading fails.
3. The service's configuration slice: `server`, `telemetry`, and the principal keys it accepts.
   A distributed-mode start with no principal keys configured **fails at startup** (KERN-006's
   degraded-behavior rule).
4. Logback resource selection by `telemetry.logFormat`.

## Non-goals

No Docker image (INFRA-001). No all-in-one composition (AIO-001). No cluster configuration
(`kui.clusters[]` is M1).

## Design references

ADR-010 (`object <Name>Wiring { def make(...): Resource[IO, <Name>Server] }`), ADR-005
(services expose wiring without starting a server), ADR-013 (config loading and failure),
ADR-002 (`IO` appears only here), `ARCHITECTURE.md` §3 (`app` layer) and §11.

## Public Scala signatures to implement

```scala
package kui.cluster.app

final case class ClusterServiceConfig(
    server: ServerConfig,
    telemetry: TelemetryConfig,
    principalKeys: List[PrincipalKeyConfig]
)

final case class ClusterServer[F[_]](
    routes: List[ServerEndpoint[Fs2Streams[F], F]],
    readiness: List[ReadinessCheck[F]],
    capabilities: F[ServiceCapabilities]
)

object ClusterWiring:
  /** Builds everything except the listener. Used by Main and by apps/allinone unchanged. */
  def make[F[_]: Async](
      config: ClusterServiceConfig,
      telemetry: Telemetry[F],
      principals: PrincipalCodec[F]
  ): Resource[F, ClusterServer[F]]

object Main extends IOApp:
  def run(args: List[String]): IO[ExitCode]
```

`Main`'s sequence, which every service copies:

1. Parse `--config <path>` flags (repeatable).
2. `KuiConfigSource.load` → on `Left`, print `ConfigErrors.render` to stderr and
   `ExitCode(1)`. No stack trace, no partial start.
3. Build `Telemetry.resource`, then `KuiLogger.make("cluster")`.
4. Build `PrincipalCodec`: `JwsPrincipalCodec` when keys are configured; **fail** when none
   are, unless `KUI_ALLOW_UNSIGNED=true` is set (a documented development-only escape hatch
   that logs a prominent WARN every 60 seconds while it is in effect).
5. `ClusterWiring.make` → `KuiServer.resource` → `IO.never` with graceful shutdown on
   SIGTERM/SIGINT, draining in-flight requests for up to 15 seconds.

## Tests required

- `ClusterWiringSuite` (integration, `munit-cats-effect`):
  - `wiringProducesEveryEndpointInTheContract` — count and names match
    `ClusterEndpoints.all` + health.
  - `wiringIsResourceSafe` — allocate and release twice; no leaked threads or open ports
    (there is no port: the wiring must not bind one — assert that too).
  - `readinessIsTrueAfterStartup`.
- `MainConfigFailureSuite` (failure):
  - `invalidConfigExitsWithCodeOneAndPrintsEveryProblem`.
  - `missingPrincipalKeysInDistributedModeIsAStartupFailure`.
  - `theUnsignedEscapeHatchLogsAWarning`.

## Observability

One INFO line at startup with the bound address, the base path, the resolved log format and
the git commit (from the build info of GW-010's mechanism, shared); one INFO line at shutdown
with the drain duration.

## Degraded behavior

A telemetry exporter that is unreachable does not prevent startup (OBS-001). A missing or
invalid configuration always does. Shutdown drains rather than dropping in-flight requests.
