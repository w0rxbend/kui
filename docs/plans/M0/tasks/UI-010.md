# UI-010 — Capability-driven navigation, `FeatureGate` and fallback panel

- **ID:** UI-010
- **Title:** Capability-driven navigation, `FeatureGate` and fallback panel
- **Milestone / Feature:** M0 / KU-002, KU-003
- **Owner role:** Frontend Architect
- **Size:** L
- **Dependencies / blocked by:** UI-008, UI-009, GW-005

## Goal (user value)

The milestone's visible promise: when a service dies, its sidebar entry dims within seconds,
clicking it explains what is wrong and when it started, offers a retry, and says what still
works — while the rest of KUI keeps working normally.

## Scope

1. **Sidebar rendering rules** (ADR-032, exactly):
   - `NotConfigured` → the entry is **hidden**.
   - `Forbidden` → shown, **disabled**, tooltip "You do not have permission to view X";
     hidden instead when `kui.ui.hideForbidden` is set.
   - `Unavailable` → shown **dimmed and clickable**; the route renders the fallback panel.
   - `Degraded` → shown normally with an **amber dot** and a tooltip carrying the reason.
   - `Ready` → shown normally.
2. `FeatureGate` — wraps a feature route: given the `FeatureState`, it renders the feature
   (loading it lazily first, UI-007) or the fallback panel, and it never renders a blank frame
   between states (a spinner with the feature's name).
3. `FeatureFallbackPanel` — the ADR-032 panel: the reason code rendered as human text, the
   message, `since` as both absolute and relative time, a **Retry now** button calling
   `POST /api/v1/capabilities/{service}/probe`, and a "what still works" list built from the
   other features' current states.
4. `CapabilityBanner` — a top-of-content banner when the capability stream is disconnected or
   when any feature is degraded, with the connection state from UI-006.
5. `ActionPermissionWrapper` (ADR-032): one wrapper that disables a write action for either
   an RBAC or a capability reason and shows **one merged tooltip**. In M0 only the capability
   half is live; the RBAC parameter exists.
6. Wiring the toast rule from UI-008 into the shell's toast host.

## Non-goals

No per-cluster navigation (M1). No RBAC (M6). No real feature content (UI-012).

## Design references

ADR-032 (this task is the ADR's implementation; every rendering rule above is quoted from it),
ADR-012 (loading is triggered when the capability is anything but `NotConfigured`),
feature matrix KU-002, KU-003, KU-009; PLAN §16.5 as amended by ADR-032.

## Public Scala signatures to implement

```scala
package kui.ui.shell.nav

object Navigation:
  /** Renders one item per registered feature, ordered by NavEntry.order, applying the
    * ADR-032 rules. Takes states as a Signal so a capability change re-renders exactly the
    * affected item. */
  def apply(
      features: List[(NavEntry, Signal[FeatureState])],
      current: Signal[Page],
      hideForbidden: Boolean
  ): HtmlElement

package kui.ui.shell.feature

object FeatureGate:
  def apply(
      feature: LazyFeature,
      state: Signal[FeatureState],
      page: Signal[Page],
      probe: Observer[Unit]
  ): Signal[HtmlElement]

object FeatureFallbackPanel:
  def apply(
      featureLabel: String,
      reason: DegradedReason,
      since: Option[Instant],
      retry: Observer[Unit],
      whatStillWorks: Signal[List[String]]
  ): HtmlElement

package kui.ui.kernel.component

object ActionPermissionWrapper:
  /** One merged tooltip for the two independent reasons an action can be unavailable. */
  def apply(
      action: HtmlElement,
      capability: Signal[FeatureState],
      permitted: Signal[Boolean] = Val(true),
      capabilityMessage: FeatureState => Option[String] = default
  ): HtmlElement
```

**Reason-code display text** is a `Messages` object (ADR-024: strings centralized per module,
no i18n runtime). Each `ReasonCode` gets one sentence written for an operator, e.g.
`UpstreamUnavailable` → "The cluster service is not responding." Add the table to
`docs/frontend/README.md`.

## Tests required

- `NavigationSuite` (DOM, exhaustive over `FeatureState`):
  - one assertion per ADR-032 rendering rule (hidden / disabled+tooltip / dimmed+clickable /
    amber dot / normal) — five rows, mirroring UI-008's derivation table.
  - `hideForbiddenHidesForbiddenEntries`.
  - `orderFollowsNavEntryOrderAndIsStableAcrossStateChanges` — an entry must not jump around
    when its state changes.
  - `aStateChangeRerendersOnlyTheAffectedItem`.
- `FeatureGateSuite` (DOM):
  - `loadsTheFeatureWhenTheStateBecomesAnythingButNotConfigured` — and **does not** load it
    while `NotConfigured` (the ADR-012 promise).
  - `rendersTheFallbackPanelWhenUnavailableWithoutLoadingTheFeature` — clicking a dimmed
    entry must not download the module.
  - `showsANamedSpinnerWhileLoadingAndNeverABlankFrame`.
  - `aFailedImportRendersTheFallbackWithARetryThatWorks`.
- `FallbackPanelSuite` (DOM):
  - `showsTheReasonTheMessageAndBothTimeFormats`.
  - `retryCallsProbeAndShowsProgress`; a failed probe shows an inline error, not a toast storm.
  - `whatStillWorksListsOnlyReadyFeatures`.

## Degraded behavior

This task *is* the degraded behaviour. Its own edge case: when the capability stream is
disconnected, entries keep their last known state, the banner says so, and nothing is
silently marked available — an unknown state must never be rendered as `Ready`.

## Deviations

Recorded during implementation. None of them changes what the user sees; each is either a
signature that could not work as written against the code UI-005 to UI-009 actually produced, or
a defect found while wiring the pieces together.

### The CSRF header name was wrong, and is now shared

`ApiClient` sent the token in `X-Kui-Csrf`. The gateway reads `X-Csrf-Token`, and it strips every
inbound `X-Kui-*` header at the edge by design (ADR-040), so **every** non-`GET` request from the
browser was rejected as a forgery. Fixed by moving the name into `kui.contracts.HttpHeaders.Csrf`,
which the gateway's `SessionMiddleware` and the browser's `ApiClient` now both read, so the two
cannot drift again without a change to the shared contract. Pinned by `HttpHeadersSuite` (both
platforms) and by `ApiClientSuite.theCsrfHeaderIsNamedExactlyWhatTheGatewayReads`, which asserts
the literal on a real outgoing request as well as on the constant. `CsrfCheck`'s denial messages
named the old header too and now interpolate the constant; ADR-019 gained an amendment, and
`ARCHITECTURE.md` §14 and `docs/frontend/README.md` were corrected.

### `Navigation` returns a list, not an element

The spec has `Navigation.apply(features, current, hideForbidden): HtmlElement`. UI-009 had already
shipped `Sidebar(router: Router[Page], items: Signal[List[NavItem]])`, and building a second
element that draws navigation would have left two components with the same job. So `Navigation`
decides *which* entries exist (`items`, a `Signal[List[NavItem]]`) and `Sidebar` applies the
ADR-032 rendering rules. Deciding is pure and its edge cases are about filtering and ordering;
drawing is about the DOM. `NavItem` moved from `layout` to `nav` and gained `state` and `order`.

`Sidebar` also had to change from `children <-- items.map(...)` to `children <-- items.split(...)`:
the former rebuilds every entry whenever any capability changes, which drops keyboard focus and
makes one service's outage rewrite the whole sidebar.

Two further signature changes for the same reason — the caller cannot supply what the spec assumes:

- `Navigation` takes `FeatureRoutes` rather than `NavEntry`, because a sidebar entry needs a
  destination and `NavEntry` carries none. `FeatureRoutes` is the new static half of a feature's
  registration (see below).
- `Navigation` takes the router through `Sidebar` rather than a `Signal[Page]`, because building an
  `href` needs the router and only the router knows the base path.

### `FeatureRoutes`: the static half of a feature's registration

ADR-012 amendment 2 requires route patterns to be registered before a feature is downloaded.
Nothing existed to carry them, or to carry the nav entry, the landing page and the `history.state`
codec — all of which have the same "known before the import" requirement. `FeatureRoutes` is that
type, and it is what UI-012 implements. `PageCodec` and `ShellRouter.make` now accept a list of
contributors, so a feature page survives Back instead of decoding to `NotFound`.

`FeatureRegistry.default` was replaced by `FeatureRegistry.install(thunks, staticRoutes)`, called
once by the shell. The kernel cannot name a feature class — `frontend.uiKernel` depending on
`frontend.uiClusters` is a cycle — so the map moved to `kui.ui.shell.FeatureRegistryImpl`, which is
the file UI-012's own spec already asks for.

### `FeatureGate` and `FeatureFallbackPanel` take more than the spec lists

`FeatureGate` needs the feature's label (for the named spinner and the panel heading) and the "what
still works" list, neither of which it can derive from a `LazyFeature`. `FeatureFallbackPanel` takes
`(reason: ReasonCode, message: String)` rather than `DegradedReason`, because that is what
`FeatureState.Unavailable` actually carries, plus `retryInFlight` and `retryError` signals — without
them the required "retry shows progress" and "a failed probe shows an inline error" behaviour has no
input. Its clock is a parameter so `"2 minutes ago"` is a fact about the panel and not about how long
the suite took to run.

### `ImportedFeature.retry` no longer passes through `NotLoaded`

Found by `FeatureGateSuite`: `retry()` set `NotLoaded` before starting, which published a frame
saying "nothing has been requested" to every observer — and `FeatureGate`, whose job is to start the
import when it sees `NotLoaded`, then started a second one alongside it. One retry press downloaded
the module twice. `retry()` now goes straight to `start()`, which sets `Loading` as its first act.

### `Shell.app` gained an `ApiClient` parameter

The retry button has to reach `POST /api/v1/capabilities/{service}/probe`, so the shell owns a
`CapabilityProbe` and hands the panel an `Observer[Unit]`. `frontend.uiShell` gained a `moduleDeps`
on `services.gateway.contract.js` for the endpoint definitions. The parameter is optional so a suite
can mount the frame without standing up a backend.

### Not done here

The toast rule (scope item 6) needed no work: `Capabilities.reportTransition` already pushes to
`NotificationBus`, and `Layout` already hosts `Toast` over it, so wiring the capability store into
start-up completed that path. Item 5's RBAC half is present and tested but always `true`; roles are
M6.
