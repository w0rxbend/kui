# GW-003 — Capability registry core

- **ID:** GW-003
- **Title:** Capability registry core (`CapabilityRegistry[F]`)
- **Milestone / Feature:** M0 / KU-001, KU-003
- **Owner role:** Chief Architect
- **Context / service:** `services/gateway/application`
- **Size:** L
- **Dependencies / blocked by:** GW-002, KERN-005

## Goal (user value)

The component that makes "a broken part of KUI never breaks the rest" observable: one place
that knows, per service and per cluster, whether a feature is available, degraded,
unavailable-since-when, or simply not configured — and publishes every change.

## Scope

1. `CapabilityRegistry[F]` exactly as sketched in `ARCHITECTURE.md` §4.5.
2. State storage: a `Ref[F, Map[CapabilityKey, CapabilityState]]` plus a `Topic[F,
   CapabilityChange]` for the delta stream, with a bounded subscriber queue so a slow SSE
   client cannot back-pressure the registry.
3. The **fold** — the decision function that combines the three inputs into one state, which
   is the heart of this task:

   | Input | Effect |
   | --- | --- |
   | readiness poll fails (GW-004) | `Unavailable(UpstreamUnavailable, msg, since = first failure)` |
   | circuit breaker open (HTTP-003) | `Unavailable(CircuitOpen, msg, since = open time)` |
   | service reports `configured = false` for a cluster | `NotConfigured` |
   | service reports `status = degraded` | `Degraded(reason)` with the service's payload |
   | p95 latency over the configured threshold | `Degraded(reason with p95Ms and suggestedPollIntervalMs)` |
   | all clear | `Available` |

   Precedence when several apply: `NotConfigured` > `Unavailable` > `Degraded` > `Available`.
   `since` is **sticky**: it is set on the transition into `Unavailable` and preserved while
   the state stays `Unavailable`, even if the reason code changes.
4. Debounce: a state change must persist for `debounce` (default 1 readiness interval, so
   10 s) before `Available → Unavailable` is published, but `Unavailable → Available` is
   published immediately. Recovery should feel instant; flapping should not spam the UI.
5. `probeNow(service)` — forces an immediate poll and returns when the state has been
   recomputed, so the UI's "Retry now" button is honest.

## Non-goals

No HTTP endpoints (GW-005). No polling loop (GW-004). No RBAC-derived `Forbidden` state —
that is a frontend derivation (ADR-032: the shell combines the registry state with the RBAC
decision), so the registry never returns `Forbidden`.

## Public Scala signatures to implement

Copied from `ARCHITECTURE.md` §4.5:

```scala
package kui.gateway.application.capability

trait CapabilityRegistry[F[_]]:
  def snapshot: F[Map[CapabilityKey, CapabilityState]]
  def state(key: CapabilityKey): F[CapabilityState]
  def changes: Stream[F, CapabilityChange]
  def report(key: CapabilityKey, state: CapabilityState): F[Unit]
  def probeNow(service: ServiceId): F[Unit]

object CapabilityRegistry:
  def resource[F[_]: Async](
      config: RegistryConfig,
      telemetry: Telemetry[F],
      logger: StructuredLogger[F]
  ): Resource[F, CapabilityRegistry[F]]

final case class RegistryConfig(
    debounce: FiniteDuration,          // default 10s
    subscriberQueueSize: Int,          // default 64
    degradedP95Threshold: FiniteDuration  // default 2s
)

/** The four raw inputs, kept separate so the fold is a pure function of all of them. */
final case class CapabilityInputs(
    readiness: Option[ReadinessSignal],
    circuit: Option[CircuitState],
    serviceReport: Option[ClusterCapability],
    p95: Option[FiniteDuration]
)

enum ReadinessSignal:
  case Ready
  case NotReady(reason: ReasonCode, message: String, since: Instant)
  case Unknown                        // never polled yet -> Degraded(Starting)

object CapabilityFold:
  /** Pure. Given the previous state and the current inputs, the new state. `now` is passed
    * in so `since` is testable without a clock. */
  def fold(previous: Option[CapabilityState], inputs: CapabilityInputs, now: Instant): CapabilityState
```

## Acceptance criteria

```
$ ./mill services.gateway.application.test.testOnly 'kui.gateway.application.capability.*'
```

The fold suite is a **table test with one row per input combination**; it is the specification
of KU-001 in executable form and reviewers should read it as such.

## Tests required

- `CapabilityFoldSuite` (unit + property):
  - `precedenceTable` — one assertion per row of the precedence table above.
  - `sinceIsStickyWhileUnavailable` — a reason change does not reset `since`.
  - `sinceIsClearedOnRecovery`.
  - `unknownReadinessIsDegradedStartingNotUnavailable` — a service that has never been polled
    must not be shown as down; this is the first-page-load correctness bug that would
    otherwise show every feature as broken for the first ten seconds.
  - `p95AboveThresholdProducesDegradedWithASuggestedPollInterval` — and the suggestion is at
    least the p95, so the UI does not poll faster than the service can answer.
  - `foldIsPure` — property: the same inputs always yield the same output.
- `CapabilityRegistrySuite` (concurrency, `TestControl`):
  - `publishesOneChangePerTransitionAndNoneForRepeatedIdenticalReports`.
  - `availableToUnavailableIsDebouncedButRecoveryIsImmediate`.
  - `aSlowSubscriberDoesNotBlockTheRegistry` — a subscriber that never reads still lets other
    subscribers and `report` proceed; the slow one drops events and is logged.
  - `probeNowReturnsAfterTheStateIsRecomputed`.
  - `snapshotIsConsistentWithTheDeltasASubscriberReceived` — property: subscribe, apply N
    random reports, assert `snapshot == replay(initialSnapshot, deltas)`. This is the
    invariant the SSE contract depends on (ADR-032: snapshot on connect, deltas afterwards).

## Observability

`kui.capability.state {service, cluster, state}` as an up-down counter or gauge, updated on
every transition; one INFO log per transition with `service`, `cluster`, `from`, `to`,
`reason`; **no log while a state is steady**.

## Degraded behavior

The registry itself must never fail: `report` is total, a fold that hits an impossible input
combination yields `Degraded(Unknown)` and logs at WARN rather than throwing. A registry that
crashed would take the shell's navigation with it.
