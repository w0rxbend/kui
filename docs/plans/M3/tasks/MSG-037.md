# MSG-037 — The table view and the JSON flattener

- **ID:** MSG-037
- **Title:** The table view and the JSON flattener
- **Milestone / Feature:** M3 / MS-003, MS-004
- **Owner role:** Frontend Architect
- **Context / service:** `frontend/ui-messages`
- **Size:** L
- **Dependencies / blocked by:** MSG-036

## Goal (user value)

Kouncil's defining feature, and one of the two things that make KUI a superset of Kafbat: a topic
read as a spreadsheet, with each record's headers, key and value flattened into columns you can scan
down.

## Scope

1. The view switch (a query parameter, so a table view is a link).
2. The flattener: JSON to dotted paths, with `H[]`, `K[]` and `V[]` prefixes for headers, key and
   value, to a bounded depth, with collapse thresholds and a row cap.
3. Dynamic columns: the union of the paths across the loaded rows, ordered stably, with a column
   picker that defaults to a sensible subset when the union is wide.
4. The page-based read path: `GET .../messages/page` (MSG-021) rather than the stream, with page
   navigation from `partitionOffsets` / `totalItems` / `pageCount`.
5. `FlattenLimits`: the one definition of the caps (DEVPLAN §10 D4).

## Non-goals

- No server-side flattening (ADR-029 rejects it; the service stays format-agnostic).
- No cell editing, no sorting by a flattened column across pages (sorting within a page only — a
  cross-page sort would require reading the whole topic).
- No CSV export of flattened columns in M3: `flatten=true` on the endpoint is reserved in the mapping
  document and not implemented (MSG-036's export exports the rendered rows).

## Design references

`research/kouncil/ui-analysis.md` (`json-grid.ts`: the flattening, the collapse limits, the hard row
cap; the observation that it is the single most-cited differentiator), DC-H8 (adopt the algorithm
with its caps, client-side, and default the column picker to a sensible subset), DC-H4 (two views over
one stream, switched by a query parameter), ADR-029, `research/design/REFERENCE.md` (density switch,
which matters most here).

## Public Scala signatures to implement

```scala
package kui.ui.messages.table

/** DEVPLAN §10 D4: the one definition of the caps. They are constructor parameters so the property
  * suite can drive the flattener at other values, and they appear in no other file. */
final case class FlattenLimits(maxDepth: Int, maxRows: Int, maxColumns: Int, maxArrayElements: Int)
object FlattenLimits:
  val Default: FlattenLimits = FlattenLimits(maxDepth = 3, maxRows = 1000,
                                             maxColumns = 120, maxArrayElements = 10)
```

```scala
package kui.ui.messages.table

final case class FlatCell(path: String, value: String)
final case class FlatRow(source: MessageDto, cells: Map[String, String])

object JsonFlattener:
  /** Dotted paths, `[i]` for array indices, prefixed `H`, `K` or `V`.
    *
    * Beyond `maxDepth`, the remaining subtree is one cell containing its compact JSON — truncated,
    * never dropped, so a user can see that there is more and switch to the list view.
    * Beyond `maxArrayElements`, the remainder is a single `+N more` cell.
    * A path component containing a dot or a bracket is escaped, and the escaping round-trips.
    */
  def flatten(row: MessageDto, limits: FlattenLimits): FlatRow

  /** The union of paths across rows, in first-seen order, capped at `maxColumns`; the columns that
    * do not fit are reachable through the picker. Stable: adding a row never reorders the columns
    * already on screen, because a table whose columns move as it loads is unreadable. */
  def columns(rows: Vector[FlatRow], limits: FlattenLimits): Vector[String]
```

## Tests required

- `JsonFlattenerPropertySuite` — exit criterion 4's second half
  - `depthCapIsRespected` (property over arbitrary JSON).
  - `rowCapIsRespected`.
  - `noValueIsSilentlyDropped` (property): every leaf of the input is reachable from some cell, either
    as its own cell or inside a truncated subtree cell. This is the property that separates a
    flattener from a lossy summary.
  - `pathEscapingRoundTrips` (property over keys containing dots, brackets, quotes and unicode).
  - `columnsAreStableUnderAppend` (property): `columns(rows)` is a prefix of `columns(rows ++ more)`.
  - `arrayCollapseKeepsTheFirstNAndCountsTheRest`.
  - `isTotal` (property) — every JSON value, including deeply nested and pathological ones, produces
    a `FlatRow` and never throws or hangs.
  - `nonJsonPayloadsProduceASingleValueColumn`.
- `MessageTableSuite` (jsdom)
  - `switchingViewsKeepsTheFilterStateAndTheUrl`.
  - `columnPickerDefaultsToASubsetWhenThePayloadIsWide`.
  - `pageNavigationUsesTheEndpointsPageCount`.
  - `densitySwitchChangesRowPaddingOnly` — the design's `compact` flag.
  - `athousandRowsRenderWithoutBlockingTheMainThreadForMoreThanTwoFrames` — measured with a
    performance mark; the table view is the screen where a naive render is most obviously wrong.

## Observability

None.

## Degraded behaviour

- A payload the flattener cannot usefully flatten (a plain string, a fallback-decoded blob): one
  `V` column with the text, and a note in the header that the payload is not JSON.
- Truncation at any cap shows a marker in the affected cell or column header, so what is missing is
  visible. A silent cap is a lie about the data.
- The page endpoint failing: the previous page stays on screen, dimmed and timestamped (ADR-032).

## Cancellation and shutdown

The table view uses the non-streaming page endpoint; the in-flight request is aborted on unmount and
on a page change, which is the same rule as the list view and is asserted the same way.
