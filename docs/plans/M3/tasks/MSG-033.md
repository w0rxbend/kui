# MSG-033 — `ui-kernel`: the typed `SseStream` client and `Drawer`

- **ID:** MSG-033
- **Title:** `ui-kernel`: typed SSE client and Drawer
- **Milestone / Feature:** M3 / KU-014, MS-005
- **Owner role:** Frontend Architect
- **Context / service:** `frontend/ui-kernel`
- **Size:** M
- **Dependencies / blocked by:** none. One of the five first-movers (DEVPLAN §6.4).

## Goal (user value)

Nothing on its own. It is the two kernel pieces every message screen needs: a stream client that
routes named events into typed Laminar signals and stops cleanly, and a right-hand drawer that
behaves the same way for produce, resend and the filter editor.

## Why this is a first-mover

M0's spike measured Netty's *server* side. Nothing in KUI has yet parsed named events with `id:` in a
browser, through an abortable fetch, with cancellation. The whole frontend lane sits on it, and the
alternative — the native `EventSource` — cannot send headers, cannot be aborted the same way, and
reconnects on its own schedule, which for a browse means silently re-reading a page.

## Scope

1. `SseStream`: an abortable-fetch-based named-event parser producing an `EventStream[SseEvent]`,
   with `Last-Event-ID` on reconnect and an explicit `close()` that aborts the request.
2. `Drawer`: the right-hand panel of DC-H9 — one component, stacking rules, focus trap, `Escape` to
   close, focus restored to the trigger.
3. Both under the design of `research/design/REFERENCE.md` (radii, the 272 px drawer alignment, the
   filled-chip status vocabulary).

## Non-goals

- No message-specific types. `SseStream` yields `(eventName, data: String)`; the message module
  decodes with the contract's codecs (MSG-034). A kernel that knew about `MessageDto` would make the
  kernel depend on a feature.
- No automatic reconnect loop. A browse that reconnects by itself re-reads records the user has
  already seen; reconnection is a decision the feature makes (MSG-035).
- No modal dialog. Drawers and expansion are the two patterns (DEVPLAN §10 D3).

## Public Scala signatures to implement

```scala
package kui.kernel.sse

final case class SseEvent(name: String, data: String, id: Option[String])

/** A named-event stream over an abortable fetch.
  *
  * `close()` aborts the underlying request, which is what makes cancellation reach the server: the
  * browser closing a connection is the first link of the chain the milestone's third exit criterion
  * asserts. A parser that merely stopped reading would leave the request open and the consumer with
  * it.
  */
final class SseStream private (...):
  val events: EventStream[SseEvent]
  val state:  Signal[SseState]
  def close(): Unit

object SseStream:
  def open(url: String, lastEventId: Option[String] = None): SseStream

enum SseState:
  case Connecting, Open
  case Closed(reason: ClosedReason)

enum ClosedReason:
  case Completed            // the server ended the stream normally
  case ClosedByClient
  case Failed(status: Option[Int], message: String)
```

```scala
package kui.kernel.sse

/** The parser, pure and platform-free, so it can be tested against the same byte fixture the JVM
  * side uses (MSG-043). */
object SseParser:
  /** Incremental: feed chunks, get complete events. Handles events split across chunk boundaries,
    * multi-line `data:`, comments, and `id:` fields. */
  def feed(state: ParserState, chunk: String): (ParserState, List[SseEvent])
```

  - `handlesEventsSplitAcrossChunks` (property over arbitrary chunk boundaries) — the single most

## Observability

None: the browser has no meter. `SseState` is the observable, and MSG-035 renders it.

## Degraded behaviour

- Stream ends normally: `Closed(Completed)`; the feature decides what to show.
- Stream fails: `Closed(Failed(status, message))`, with the message taken from the `error` event when
  one arrived and from the transport otherwise — so the two failure shapes reach the UI as one type.
- Network drops without a terminal event: `Closed(Failed(None, "connection lost"))`. The UI keeps the
  rows and offers retry (DEVPLAN §10 D13); it does not clear the table, which is what the reference
  does.

## Cancellation and shutdown

`close()` aborts the fetch. Laminar's `onUnmountCallback` calls it, so navigating away from the
screen closes the stream — and that is the first link of exit criterion 3. `DrawerSuite` and
`SseStreamSuite` both assert unmount behaviour, because a subscription that outlives its component is
invisible until a user has opened the screen forty times.
