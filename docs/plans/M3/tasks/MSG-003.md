# MSG-003 — `resolveRanges`: seek resolution, leaderless and empty filtering, compacted fallback, clamping

- **ID:** MSG-003
- **Title:** `resolveRanges`: seek resolution, leaderless and empty filtering, compacted fallback, clamping
- **Milestone / Feature:** M3 / MS-001, MS-003, ET-001
- **Owner role:** Principal Scala Engineer
- **Context / service:** `libs/kafka`
- **Size:** L
- **Dependencies / blocked by:** MSG-002

## Goal (user value)

"Show me this topic from three o'clock yesterday" turns into a concrete offset window per partition —
and it does so on a compacted topic whose log starts at offset 4 000 000, on a topic where one
partition is offline, and on a topic where half the partitions are empty, without any of those making
the screen hang or lie.

## Scope

1. `MessageBrowsePort.resolveRanges`: `SeekMode` + `Direction` + partition subset + isolation into
   `Map[TopicPartition, OffsetRange]`.
2. The five behaviours the research says every reference product had to learn:
   - empty partitions (`begin == end`) are **excluded**, not assigned;
   - **leaderless** partitions are excluded and reported, never passed to an offset lookup
     (`libs/kafka/PORT-INVARIANTS.md` §1 — the sixty-second timeout);
   - the **compacted-topic beginning fallback**: `offsetsForTimes(tp -> 0)` first, falling back to
     `beginningOffsets` when a result is `null` or the call throws `UnsupportedVersionException`;
   - explicit offsets are **clamped** into `[begin, end)`;
   - an unresolved `offsetsForTimes` means "start from end" backwards and "nothing to read" forwards.
3. A `ResolvedRanges` result that carries the excluded partitions with a reason, so the `phase` event
   can say *which* partitions were skipped rather than silently returning fewer records.
4. `SeekResolution`, a **pure** function over already-fetched offsets, so that every rule above is
   property-tested without a broker and so that MSG-021's page calculator uses the same code.

## Non-goals

- No polling (MSG-004). This task resolves; it does not read.
- No window splitting (MSG-005). `resolveRanges` returns the *whole* range to browse; the walker
  decides how to eat it.
- No topic existence check through `ClusterAdmin`. `partitionsFor` on an unknown topic returns an
  empty list, which this task maps to `KUI-TOPIC-NOT-FOUND` — one call, not two.

## Public Scala signatures to implement

```scala
package kui.kafka.consume

import kui.kernel.browse.*

/** Why a partition is not in the plan. It reaches the `phase` event, so it is an ADT and not a
  * string: the UI renders "3 partitions offline" differently from "3 partitions empty". */
enum ExcludedReason:
  case Empty
  case NoLeader
  case OutsideWindow          // a timestamp seek that resolved to nothing on this partition
  case NotRequested

final case class ResolvedRanges(
  ranges: Map[TopicPartition, OffsetRange],
  excluded: Map[TopicPartition, ExcludedReason],
  /** Log start and end as observed, kept because the page endpoint reports them (Kouncil's
    * `partitionOffsets` / `partitionEndOffsets`) and re-fetching them would be a second round trip. */
  bounds: Map[TopicPartition, OffsetRange]
):
  def isEmpty: Boolean
  def totalRecords: Long
```

```scala
package kui.kafka.consume

/** The pure core. Everything here is a function of numbers already fetched, so every rule in this
  * task is a property rather than an integration test.
  */
object SeekResolution:

  /** Offsets as observed per partition, before any rule is applied. */
  final case class Bounds(begin: Offset, end: Offset, leader: Boolean)

  /** @param atTime  the `offsetsForTimes` answer, `None` where the time index had nothing.
    */
  def plan(
    bounds:      Map[TopicPartition, Bounds],
    atTime:      Map[TopicPartition, Option[Offset]],
    seek:        SeekMode,
    direction:   Direction,
    requested:   Option[Set[PartitionId]]
  ): ResolvedRanges
```

```scala
package kui.kafka.consume

import cats.data.NonEmptySet
import fs2.Stream
import kui.kernel.cluster.ClusterProfile

trait MessageBrowsePort[F[_]]:
  /** Describes the topic, drops empty and leaderless partitions, resolves seek positions, clamps
    * into `[begin, end)`, applies the compacted-topic beginning fallback.
    *
    * Leaderless partitions are filtered **here, at the port** — never by the caller — because an
    * offset lookup naming a leaderless partition does not fail: the AdminClient retries metadata
    * until `default.api.timeout.ms`, sixty seconds with KUI's defaults, and then reports a timeout
    * that names nothing. (`libs/kafka/PORT-INVARIANTS.md` §1.)
    */
  def resolveRanges(
    profile:    ClusterProfile,
    topic:      TopicName,
    seek:       SeekMode,
    direction:  Direction,
    partitions: Option[NonEmptySet[PartitionId]],
    isolation:  IsolationLevel
  ): F[Either[KuiError, ResolvedRanges]]
```

## The resolution table

`SeekResolutionTableSuite` asserts it row by row; this table *is* the specification. `b` is the
partition's begin offset after the compacted fallback, `e` its end offset.

| `SeekMode` | `Direction` | Range | Notes |
| --- | --- | --- | --- |
| `Beginning` | Forward | `[b, e)` | |
| `Beginning` | Backward | `[b, b)` | empty: there is nothing before the beginning |
| `Latest` | Backward | `[b, e)` | the default browse; the walker eats it from the end |
| `Latest` | Forward | `[e, e)` | empty; the caller wanted `tail`, and MSG-006 is that call |
| `AtOffset(o)` | Forward | `[clamp(o), e)` | one offset applied to every selected partition |
| `AtOffset(o)` | Backward | `[b, clamp(o))` | `o` is exclusive: the record at `o` is *not* returned when reading backwards to it |
| `AtOffsets(m)` | Forward | `[clamp(m(p)), e)` | partitions absent from `m` are `NotRequested` |
| `AtOffsets(m)` | Backward | `[b, clamp(m(p)))` | the cursor's shape |
| `AtTimestamp(t)` | Forward | `[atTime.getOrElse(e), e)` | unresolved ⇒ empty range: everything is older than `t`, so there is nothing to read forward |
| `AtTimestamp(t)` | Backward | `[b, atTime.getOrElse(e))` | unresolved ⇒ read from the end: everything is older than `t`, so all of it qualifies |

Applied to every row, in this order:

1. a partition not in `requested` is `NotRequested`;
2. a partition with `leader = false` is `NoLeader` — **before** any offset call is made;
3. a partition with `begin == end` is `Empty`;
4. `clamp(o) = min(max(o, b), e)`;
5. a range that comes out empty after clamping is dropped with `OutsideWindow`.

// The invariant the port exists to hold (PORT-INVARIANTS §1)
val b = Map(tp0 -> Bounds(o(0), o(100), leader = true),
            tp1 -> Bounds(o(0), o(100), leader = false))
val plan = SeekResolution.plan(b, Map.empty, SeekMode.Latest, Direction.Backward, None)
assertEquals(plan.ranges.keySet, Set(tp0))
assertEquals(plan.excluded(tp1), ExcludedReason.NoLeader)

// A timestamp that matches nothing means opposite things in the two directions
assertEquals(
  SeekResolution.plan(b1, Map(tp0 -> None), SeekMode.AtTimestamp(t), Direction.Backward, None)
    .ranges(tp0).until, o(100))
assert(
  SeekResolution.plan(b1, Map(tp0 -> None), SeekMode.AtTimestamp(t), Direction.Forward, None)
    .ranges.isEmpty)

## Tests required

- `SeekResolutionTableSuite` — one case per row of the table, plus one per numbered rule.
- `SeekResolutionPropertySuite`
  - `everyRangeIsInsideItsPartitionBounds` (property over arbitrary bounds and modes) — the single
    most valuable property here: a resolved range that escapes `[b, e)` becomes an
    `OffsetOutOfRangeException` at seek time, which is a 500 for what is really a rounding error.
  - `clampingIsIdempotent`.
  - `noLeaderIsNeverInRanges` (property) — including when the caller explicitly requested it.
  - `emptyPartitionsAreNeverAssigned` (property).
  - `requestedSubsetIsHonoured` (property): `ranges.keySet ⊆ requested`.
  - `excludedAndRangesPartitionTheTopic` (property): every partition of the topic appears in exactly
    one of the two maps. A partition that appears in neither is a record set the user will never see
    and will never be told about.
  - `backwardAtOffsetIsExclusive` — pinned as its own case because it is the one off-by-one that
    would show a duplicated record on every page boundary.
- `MessageBrowseAdapterSuite` (Testcontainers, extended by MSG-008)
  - `compactedTopicUsesTheOffsetsForTimesZeroFallback` — a compacted topic whose head is far above
    zero resolves to the real first live record, not to 0.
  - `unknownTopicIsTopicNotFound` — `KUI-TOPIC-NOT-FOUND`, not an empty plan.
  - `offsetsForTimesUnsupportedFallsBackToBeginningOffsets` — a stubbed lease that throws
    `UnsupportedVersionException`.

## Observability

- `kui.message.resolve.duration` — histogram, attributes `cluster`, `topic`, `mode`, `direction`.
- One DEBUG line per resolution carrying the counts: assigned, empty, leaderless, out of window.
  Not the offsets themselves — a 1 000-partition topic would make one log line a kilobyte.
- Leaderless partitions are logged at **WARN once per resolution** with the count and the partition
  ids, because that is a real cluster problem the operator wants to see, and it is exactly the
  condition that used to look like a network timeout.

## Degraded behaviour

- Some partitions leaderless: the browse proceeds on the rest and the excluded set reaches the
  `phase` event, so the screen says "reading 7 of 8 partitions, 1 offline". It does **not** fail: a
  cluster with one broker down is the moment an operator most needs this screen.
- Every partition excluded: `ResolvedRanges.isEmpty`, and the use case ends the stream immediately
  with `done{reason:"exhausted"}` and a `phase` explaining why. Not an error — an empty topic is a
  legitimate answer.
- `offsetsForTimes` unsupported (broker below 0.10 message format): fall back and continue.
- Authorization failure on the topic: M1's mapper gives `KUI-FORBIDDEN`, which MSG-029 renders as a
  403 before the stream starts, not as an `error` event.

## Cancellation and shutdown

`resolveRanges` runs inside the consumer `Resource` of MSG-002; cancelling it releases the consumer.
`ResolveCancellationSuite` cancels a resolution against a broker made unreachable with a Toxiproxy
delay and asserts the consumer is released within the poll timeout rather than at the API timeout.
