# MSG-031 — Gateway: message routes, the streaming fan-in, the capability entry, the KU-016 hook

- **ID:** MSG-031
- **Title:** Gateway: message routes and streaming fan-in
- **Milestone / Feature:** M3 / MS-001, KU-014, KU-016
- **Owner role:** Chief Architect
- **Context / service:** `services/gateway`
- **Size:** L
- **Dependencies / blocked by:** MSG-028

## Goal (user value)

The browser talks to one origin. A stream travels from the message service through the gateway to an
`EventSource` without being buffered, without being cut off by a request timeout, and — when the tab
closes — is cancelled all the way back.

## Scope

1. `/api/v1` proxy routes for all eleven message endpoints, derived from `MessageEndpoints.all`.
2. **Streaming fan-in**: the gateway re-streams the SSE body with a bounded queue and honours
   backpressure (ADR-035), and does **not** apply the per-upstream request timeout to a stream body.
3. Cancellation propagation: browser abort → gateway stream cancellation → upstream request
   cancellation.
4. The `message` capability entry, per cluster, folded from the service's report (ADR-039).
5. The KU-016 permission hook on the filter-test endpoint: the check is declared and wired, and
   evaluates to "allow" while `auth.type=disabled`.

## Non-goals

- No aggregation. Every message endpoint is a proxy; there is no gateway-side merge, which is why
  the M1 dashboard defect cannot recur on these routes.
- No Kafka, no serde, no CEL on the gateway's classpath. Rules A8, A11 and A12 all say so and
  MSG-047's build test asserts it.
- No re-parsing of the SSE events. The gateway forwards bytes; a gateway that decoded and re-encoded
  would be a second place where the envelope is defined.

## Design references

ADR-035 ("service → gateway transport is the same SSE format over HTTP chunked; the gateway
re-streams without buffering beyond a bounded queue and honours backpressure"), ADR-037 (per-upstream
timeout, bulkhead, breaker — and the distinction this task must draw), ADR-039, ADR-040 (edge header
policy), ADR-043, `research/kafbat/api-analysis.md` mapping row for `messages/stream`
("streaming fan-in, cancellation propagated").

## Public Scala signatures to implement

```scala
package kui.gateway.api

/** Re-streams an upstream SSE body.
  *
  * Two rules that are easy to get wrong and are each a named test:
  *
  *  1. The per-upstream **request** timeout applies to the response *headers*, not to the body. A
  *     tail is supposed to stay open for hours; a 30-second timeout applied to the body would make
  *     live mode look like a Kafka problem every thirty seconds (DEVPLAN §8 R-8).
  *  2. The queue between upstream and downstream is bounded and **blocks** rather than dropping.
  *     Dropping here would silently lose records that the service has already counted as delivered,
  *     which is a discrepancy no client could detect.
  */
object StreamProxy:
  def relay[F[_]: Async](upstream: Stream[F, Byte], queueSize: Int): Stream[F, Byte]
```

## Tests required

- `StreamProxySuite`
  - `doesNotApplyTheRequestTimeoutToTheBody` — the acceptance snippet; R-8.
  - `cancellingTheDownstreamCancelsTheUpstream`.
  - `backpressuresRatherThanDropping` — a slow consumer makes the upstream slow, and no byte is lost
    (property over generated event streams).
  - `boundedQueueMemoryIsIndependentOfStreamLength` — a million events through a queue of 64.
  - `bytesAreForwardedUnchanged` (property) — the gateway is not allowed to reformat; asserted
    against MSG-043's byte fixtures.
- `MessageProxyRoutesSuite` (stub upstream)
  - `everyMessageEndpointHasAProxyRoute` — enumerated from `MessageEndpoints.all`, so an endpoint
    added without a route fails here rather than 404-ing.
  - `upstreamDownIsAnErrorEnvelopeNotAnEmptyStream` — a proxied stream whose upstream is unreachable
    must answer with an HTTP error before the stream opens, not with a zero-event stream that the UI
    would render as "no messages".
  - `theCapabilityEntryFollowsTheServiceReport` — `Available` / `Degraded` / `Unavailable`.
  - `filterTestDeclaresItsPermissionAndIsClusterScoped` (KU-016).
  - `lastEventIdIsForwarded`.

## Degraded behaviour

- Message service down: every message route answers `KUI-UPSTREAM-UNAVAILABLE` with a 503, the
  `message` capability is `Unavailable`, and the shell renders the fallback panel for the messages
  screens while every other screen keeps working. That is fault-injection scenario 1 and E2E
  criterion 8.
- Message service degraded: routes work, the capability is `Degraded`, and the UI shows the reason
  in the panel header.
- A stream that fails upstream mid-body: the bytes already forwarded stand, and the upstream's own
  `error` event is forwarded like any other. The gateway does not synthesise one — if the upstream
  died without sending one, the gateway appends an `error` event of its own naming
  `KUI-UPSTREAM-UNAVAILABLE`, because a truncated stream with no explanation is the reference
  behaviour this milestone exists to replace.

## Cancellation and shutdown

`cancellingTheDownstreamCancelsTheUpstream` is the middle link of the chain the milestone's criterion
3 asserts end to end; MSG-044 tests the whole chain and this suite tests this hop in isolation, so
that a regression names the hop that broke.
