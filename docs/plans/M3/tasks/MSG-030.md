# MSG-030 — Message `app`: the composition root and the cancellation-safe `Resource` chain

- **ID:** MSG-030
- **Title:** Message `app`: composition root, health, capabilities
- **Milestone / Feature:** M3 / KU-010, OT-003
- **Owner role:** Chief Architect
- **Context / service:** `services/message/app`, `apps/allinone`
- **Size:** L
- **Dependencies / blocked by:** MSG-029, MSG-026, MSG-041

## Goal (user value)

`kui-message-service` starts, reports what it can and cannot do, and stops without leaving a consumer
or a producer behind — including when it is stopped in the middle of forty open streams.

## Scope

1. The `services/message/app` module: macwire composition root, `main`, Netty server, health and
   capability endpoints.
2. The bootstrap order and its `Resource` chain: telemetry → configuration → HTTP client → profile
   source → serde registries → filter port → ports → use cases → routes → server.
3. Readiness: the service is ready when configuration is valid and the profile source has either a
   live upstream **or** a cached profile. It is not ready while it has neither, because a browse
   would fail anyway.
4. The `message` capability report (ADR-039): `Available`, `Degraded(reason)` when the profile
   source is serving last-known or a Schema Registry is unreachable, `Unavailable` when the service
   itself cannot serve.
5. Registration in `apps/allinone` (MSG-041 owns the configuration; this task owns the wiring).

## Non-goals

- No business logic of any kind in this module. It is the only module allowed to name `IO`
  (ADR-010), and that is all it does.
- No new endpoints.

## Design references

ADR-010 (macwire, one composition root), ADR-005 (the all-in-one shape), ADR-039 (the capability
fold's four inputs), ADR-041 A9 (`app` is the one module that may see `infrastructure`),
`ARCHITECTURE.md` §3; M1's `CLAPI-005` as the shape to copy.

## Public Scala signatures to implement

```scala
package kui.message.app

/** The whole service as one `Resource`. Every component with a lifetime is in this chain, in
  * dependency order, so that shutdown releases them in the reverse order without anybody having to
  * remember it.
  *
  * The ordering rule that is not obvious: the **server is last**, so it starts only after the
  * profile source and the serde registries are ready, and it stops **first**, so no new request
  * arrives while the things it needs are being torn down. Reversing either half produces a class of
  * failure that only shows up under load during a deployment.
  */
object MessageServiceModule:
  def resource[F[_]: Async: Meter: LoggerFactory](config: MessageServiceConfig)
    : Resource[F, MessageService[F]]

final case class MessageService[F[_]](
  routes: List[ServerEndpoint[Fs2Streams[F], F]],
  health: F[HealthReport],
  capabilities: F[List[CapabilityEntry]]
)
```

## Tests required

- `MessageServiceModuleSuite` (`munit-cats-effect`, Testcontainers)
  - `startsAndAnswersHealth`.
  - `readinessRequiresAProfileOrACache` — with the cluster service stubbed down and no cache, the
    service starts but is not ready, and the log says why. A service that reports ready and then
    fails every request is the failure shape M1's R-2 was about.
  - `capabilityIsDegradedWhenTheProfileSourceServesLastKnown`.
  - `capabilityIsDegradedWhenTheRegistryIsUnreachableAndAvailableWhenItIsUnconfigured` — the ADR-039
    distinction, pinned, because getting it backwards dims the UI for every deployment that simply
    has no Schema Registry.
  - **`shutdownWithFortyOpenStreamsReleasesEverything`** — open forty browse streams, cancel the
    service `Resource`, and assert `kui.message.consumers.active` is zero, no fiber is left, and
    shutdown completed within five seconds. This is the test that would have caught every
    teardown defect the M0 review found.
  - `theServerStopsBeforeItsDependencies` — asserted by ordering flags in the finalisers.
- `MessagePageReplicaSuite`
  - `aCursorMintedByOneInstanceIsHonouredByAnother` — two `MessageServiceModule` instances with the
    same `cursorKey`; exit criterion 11.
  - `withDifferentKeysTheCursorIsRejectedNotMisread`.
- `apps.allinone.test`
  - `theMessageServiceIsWiredAndItsConfigurationIsUsed` — the §6.6 configuration seam, owned by
    MSG-041 and asserted here as well because this is the module that does the wiring.

## Observability

- The standard service metrics from `libs/observability` (M0), plus everything the lower layers
  emit.
- Startup logs one INFO line naming the build, the configured clusters, whether a Schema Registry is
  configured per cluster, and the effective `kui.message.*` limits. That line is the first thing an
  operator reads when a browse behaves unexpectedly, and it is the cheapest possible defence against
  the "configuration parsed and discarded" defect.

## Degraded behaviour

- Cluster service unreachable at startup with no cache: not ready, with a reason; the gateway shows
  `message` as `Unavailable` and the messages screens show their fallback panel. Nothing else in KUI
  is affected, which is the fault-isolation property.
- One cluster's serde registry failing to build: that cluster is `Degraded`; every other cluster is
  `Available`.
- Configuration invalid: the process exits at startup with every error accumulated in one message
  (ADR-013).

## Cancellation and shutdown

The task's centre. The chain is one `Resource`; `shutdownWithFortyOpenStreamsReleasesEverything` is
the named test the definition of done requires. A `Supervisor` owns the profile-change listener and
is inside the chain, so a listener that is retrying a failed connection does not delay shutdown past
its cancellation.
