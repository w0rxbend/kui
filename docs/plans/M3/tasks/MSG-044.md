# MSG-044 — The cancellation suite: browser disconnect to consumer close

- **ID:** MSG-044
- **Title:** The cancellation suite
- **Milestone / Feature:** M3 / MS-001, MS-005 (exit criterion 3)
- **Owner role:** QA Engineer
- **Context / service:** `services/message/api`, `services/gateway/api`
- **Size:** M
- **Dependencies / blocked by:** MSG-029, MSG-030

## Goal (user value)

A closed tab does not leave a Kafka consumer running. The milestone's third exit criterion, asserted
at every hop rather than assumed at the ends.

## Why this task exists

The M0 review found cancellation and teardown systematically unconsidered, and M1 answered it with a
per-task requirement. M3 adds a suite of its own because this milestone's cancellation path crosses
four process boundaries — browser, gateway, service, broker — and a break at any hop looks identical
from the ends: the stream stops. Only a per-hop assertion names the hop.

## Scope

1. `StreamCancellationSuite`: cancel the SSE response body at the service and assert the consumer is
   released and the gauge is zero within one poll interval.
2. The same at the gateway: cancel the client, assert the upstream request was cancelled (MSG-031's
   own suite covers the mechanism; this asserts the composed path).
3. The teardown case: forty open streams, service shutdown, everything released within five seconds.
4. The **leak detector**: a helper that fails a test if `kui.message.consumers.active` is non-zero at
   the end of any suite that used it, applied to every integration suite in the message tree.

## Non-goals

- No browser-level assertion (MSG-046's Playwright spec does that).
- No new production code. If a hop cannot be asserted, that is a defect in the hop, not a reason to
  add a hook for the test.

## Design references

DEVPLAN §2 criterion 3, §10 D6 (why the assertion is a gauge **and** a finaliser flag), §8 R-3;
ADR-035 ("browser abort → gateway stream cancellation → service fiber cancellation → consumer
close"); `docs/spikes/M0-netty-sse.md` (Netty cancels the fs2 stream within 8 ms of the client
leaving — the measured basis for the one-poll-interval bound).

## Public Scala signatures to implement

package kui.message.api

/** Fails a suite that finished with a consumer or producer still open.
  *
  * Mixed into every integration suite in the message tree, because a leak introduced by a test that
  * was not about cancellation is exactly the leak nobody looks for. The check runs in
  * `afterAll`, reads the recording meter, and names the gauge and its value.
  */
trait LeakDetector extends CatsEffectSuite:
  def meter: RecordingMeter
  override def afterAll(): Unit

## Tests required

- `StreamCancellationSuite` (Testcontainers, real broker, real routes)
  - `cancellingTheResponseBodyReleasesTheConsumer` — the criterion. Both signals: the gauge and the
    finaliser flag.
  - `cancellingATailReleasesTheConsumer` — separately, because a tail has no natural end and its
    cancellation path is the one that matters most in practice.
  - `cancellingATrackScanReleasesTheCurrentConsumer`.
  - `cancellingDuringAPollDoesNotWaitForThePollToFinish` — asserted against `pollTimeout + 200 ms`;
    an implementation that waits for the poll would still pass a generous bound and would be wrong.
  - `aClientThatStopsReadingWithoutClosingIsBoundedByTheDeadline` — the half-open connection case:
    the budget's deadline is what stops it, and without this case that path is untested.
  - `fortyConcurrentStreamsCancelIndependently`.
- `StreamCancellationChainSuite` (gateway + stubbed service)
  - `cancellingTheClientCancelsTheUpstreamRequest`.
  - `theGatewayDoesNotBufferAfterTheClientIsGone` — asserted by memory-bounded queue behaviour, so a
    cancelled client does not leave the gateway draining a fast upstream.
- `LeakDetector` applied to: `MessageBrowseIntegrationSuite`, `KafkaAdapterSuite`,
  `MessageRoutesSuite`, `TrackStreamSuite`, `MessageServiceModuleSuite`, `ProducingSuite`.

## Observability

This suite is the consumer of `kui.message.consumers.active`, `kui.message.producers.active` and
`kui.stream.active`. If a future change removes one of those gauges, these tests stop compiling —
which is the right way for a metric that is load-bearing to be protected.

## Degraded behaviour

Not applicable; this is a test suite. Its degraded behaviour is that it must fail loudly and name the
hop: every assertion message includes which gauge, which value, and which hop was under test.
