# MSG-021 — `PageUseCase`: Kouncil per-partition newest-first paging

- **ID:** MSG-021
- **Title:** `PageUseCase`
- **Milestone / Feature:** M3 / MS-003
- **Owner role:** Domain Architect (message)
- **Context / service:** `services/message/application`
- **Size:** M
- **Dependencies / blocked by:** MSG-019

## Goal (user value)

The table view's read path: page 3 of a topic, newest first, per partition, with a total and page
count — a spreadsheet you can jump around in, which is the single most-cited thing Kouncil does that
Kafbat does not.

## Scope

1. `PageUseCase.page(request): F[Either[KuiError, MessagePage]]` — non-streaming, no server state.
2. Kouncil's arithmetic, unchanged: per partition,
   `position = end - pageSizePerPartition * (page - 1)`,
   `seekTo = max(position - pageSizePerPartition, beginning)`, then read up to
   `pageSizePerPartition` records.
3. The optional narrowing window (`from`/`to` timestamps, or an explicit `offset`) applied to
   `[beginning, end)` **before** paging.
4. `partitionOffsets`, `partitionEndOffsets` and `totalItems`, so the UI can render a page count.
5. The shared seek arithmetic: this task uses `SeekResolution` (MSG-003) and `RecordMapping`
   (MSG-019), and adds nothing of its own that the stream path does not also use — that sharing is
   what exit criterion 4 means by "the seek/offset math shared by the stream and the table endpoint".

## Non-goals

- No cursor (ADR-026 is explicit: the page mode needs none).
- No JSON flattening — client-side, MSG-037.
- No stability guarantee across pages while producers write. The offsets shift; the endpoint returns
  the ones it used, and the UI shows them. Documented, not hidden.

## Design references

as the sum of per-partition ranges), ADR-026 ("Kouncil's per-partition page mode needs no cursor …

## Public Scala signatures to implement

```scala
package kui.message.application.page

final case class MessagePage(
  items: List[DecodedRecord],
  partitionOffsets: Map[PartitionId, Offset],      // where each partition's page started
  partitionEndOffsets: Map[PartitionId, Offset],   // as observed at request time
  totalItems: Long,                                // sum of the per-partition ranges
  pageCount: Int
)

/** Pure, and therefore property-tested. Every off-by-one in the table view is a bug in this
  * object and nowhere else. */
object PageArithmetic:
  def rangeFor(bounds: OffsetRange, page: Int, pageSizePerPartition: Int): OffsetRange
  def pageCount(bounds: Map[PartitionId, OffsetRange], pageSizePerPartition: Int): Int
  def totalItems(bounds: Map[PartitionId, OffsetRange]): Long

trait PageUseCase[F[_]]:
  def page(request: PageRequest): F[Either[KuiError, MessagePage]]
```

             OffsetRange.unsafe(o(0), o(0)))

## Tests required

- `PageArithmeticSuite`
  - `theFormulaTable` — the three cases above plus page 0 and a negative page (both are validation
    errors from `PageRequest`, asserted here as unreachable).
  - `pagesTileTheRangeWithoutGapsOrOverlap` (property) — concatenating every page's range in order
    reproduces the whole range exactly. The property that makes "the table view skips a record every
    few pages" impossible.
  - `pageCountMatchesTheNumberOfNonEmptyPages` (property) — the reference has a known off-by-filter
    bug here (`ARCHITECTURE.md` §8: "the reference `pageCount` bug is not reproduced"), so this is
    asserted rather than copied.
  - `clampsAtTheBeginning` (property).
  - `emptyPartitionContributesNothing`.
- `PageUseCaseSuite` (fake ports)
  - `narrowsByTimestampWindowBeforePaging`.
  - `narrowsByExplicitOffset`.
  - `returnsTheObservedOffsetsNotTheRequestedOnes` — what the UI needs to show the truth about a
    moving topic.
  - `usesTheSameSeekResolutionAsTheStream` — asserted by calling both paths with the same inputs and
    comparing the resolved ranges. This is exit criterion 4's "shared" made into a test, rather than
    a claim about which function was called.
  - `masksExactlyAsTheStreamDoes` — the same distinctive-token assertion.

## Degraded behaviour

- A partition that is leaderless or empty is excluded by `SeekResolution`, so it contributes zero
  records and zero to `totalItems`, and the response's `partitionEndOffsets` omits it — the UI shows
  the partition as unavailable rather than as empty.
- A page beyond the end returns an empty `items` with a correct `pageCount`, not a 404.

## Cancellation and shutdown

The whole page is one consumer `Resource`; cancelling the request (the client disconnecting from a
plain HTTP call) releases it. `PageUseCaseSuite.cancellationReleasesTheConsumer` asserts it — a
non-streaming endpoint is the one people forget, and a table view that a user clicks away from is
exactly as capable of leaking a consumer as a stream.
