# MSG-046 — Fault-isolation E2E: the message service stopped, the registry stopped

- **ID:** MSG-046
- **Title:** Fault-isolation E2E
- **Milestone / Feature:** M3 / (exit criterion 8), KU-010
- **Owner role:** QA Engineer
- **Context / service:** `e2e`, `deployment/compose`
- **Size:** L
- **Dependencies / blocked by:** MSG-030, MSG-037, MSG-041

## Goal (user value)

The milestone's headline resilience claim, proved by driving a real browser: stopping the message
service stops live mode with a toast and keeps the fetched rows on screen, while topics and brokers
carry on; stopping the Schema Registry leaves browsing working on non-SR serdes with an honest chip.

## Scope

1. `MessagesE2ESpec`: the happy path first — browse a seeded topic, expand a row, switch to the table
   view, produce a record and see it arrive in live mode, resend a range and see it in the
   destination, track a planted header across three topics.
2. `MessagesFaultIsolationSpec`: `docker stop kui-message` mid-session; assert the toast, the greyed
   rows with their timestamp, and that the topic and broker screens still work; `docker start` and
   assert recovery **without a page reload**.
3. `SchemaRegistryOutageSpec`: `docker stop schema-registry`; assert browsing continues on non-SR
   serdes and the serde chip reads `SR unavailable`.
4. `MessagesCancellationSpec`: close the tab during a tail and assert the service's
   `kui.message.consumers.active` returns to zero — the browser end of exit criterion 3.

## Non-goals

- No visual regression testing.
- No performance assertions (MSG-045).
- No new production code. Every affordance these specs drive already exists, and if one does not, the
  gap belongs to the task that owns the screen.

## Design references

DEVPLAN §2 criterion 8, §7's fault-injection list; `docs/DELIVERY.md` (point six: any part failing
without the rest becoming unusable, tested rather than asserted); M1's `CFGOP-007` as the shape to
copy — **including its lesson**: M1's E2E ran against stale images for the whole milestone because
the suite depended on the all-in-one jar but not on the container images the Compose topology runs.
This task's first act is to check that `e2e.test` depends on the images it drives, and to fix it if
it does not.

## Observability

The specs read the service's metrics endpoint, which makes them the only tests that assert the
metric is exposed as well as recorded.

## Degraded behaviour

The suite **is** the degraded-behaviour test. One rule for writing it: every assertion is on what the
user sees — a toast's text, a row's class, a chip's label — not on an internal state, because the
claim being tested is about the user's experience of a failure.

## Cancellation and shutdown

`MessagesCancellationSpec` is the outermost link of the chain that MSG-044 tests hop by hop. Between
them, every link is covered, and a failure names the link.
