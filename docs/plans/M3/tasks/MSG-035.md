# MSG-035 — The filter bar: seek and polling modes, partitions, serdes, string filter, live toggle

- **ID:** MSG-035
- **Title:** The filter bar
- **Milestone / Feature:** M3 / MS-001, MS-005, MS-006, MS-009, MS-014
- **Owner role:** Frontend Architect
- **Context / service:** `frontend/ui-messages`
- **Size:** L
- **Dependencies / blocked by:** MSG-034, MSG-031

## Goal (user value)

The control strip that makes the screen useful: pick where to start, which partitions, which serdes,
type a search, or turn on live — and the URL always says exactly what you are looking at, so it can
be sent to a colleague.

## Scope

1. The seek-mode selector, with the reference's vocabulary because users already know it: Newest,
   Oldest, Live, From offset, To offset, Since time, To time — mapped onto KUI's `SeekMode` +
   `Direction` pair.
2. The conditional input: an offset field for the offset modes, a date-time field for the time
   modes, nothing for the rest. Changing the mode clears the other.
3. Partition multi-select, serde selectors (key and value) from `GET .../serdes`, a debounced string
   filter, a limit selector, an isolation toggle, and the live play/pause.
4. The stream lifecycle: opening on a parameter change, aborting the previous one first, and showing
   `phase` / `consumed` progress.
5. Everything in the URL (MSG-034's route), with per-topic recall in `localStorage` when the URL has
   no parameters — the reference's behaviour, which is what makes the screen usable on a second
   visit.

## Non-goals

- No smart-filter editor (MSG-039); the bar shows the active filter chip and a button that opens it.
- No table/list view switch behaviour beyond setting the query parameter (MSG-037 renders).
- No auto-refresh timer. The reference's 5-second broker poll is not copied for messages either: a
  browse is an explicit action, and live mode is the streaming answer (M1's D10, same reasoning).

## Public Scala signatures to implement

```scala
package kui.ui.messages

/** One browse, as a state machine: parameters in, events out, exactly one stream open at a time.
  *
  * The rule that is easy to get wrong: a parameter change **aborts the previous stream before
  * opening the next**. Two open streams means two consumers on the broker and two interleaved
  * result sets on screen, and it happens the moment a user edits a filter while a page is loading.
  */
final class BrowseSession(api: MessagesApi, initial: BrowseParams):
  val rows:      Signal[Vector[MessageDto]]
  val phase:     Signal[Option[String]]
  val consumed:  Signal[Option[ConsumedDto]]
  val status:    Signal[BrowseStatus]
  val cursor:    Signal[Option[String]]
  def update(params: BrowseParams): Unit
  def stop(): Unit
  def nextPage(): Unit

enum BrowseStatus:
  case Idle, Loading, Live
  case Ended(reason: String)
  case Failed(code: String, message: String, retryable: Boolean)
```

## The mode table

| Label | `mode` | `direction` | Extra input |
| --- | --- | --- | --- |
| Newest | `Latest` | `Backward` | none |
| Oldest | `Beginning` | `Forward` | none |
| Live | — | — | none (`live=true`) |
| From offset | `AtOffset` | `Forward` | offset |
| To offset | `AtOffset` | `Backward` | offset |
| Since time | `AtTimestamp` | `Forward` | date-time |
| To time | `AtTimestamp` | `Backward` | date-time |

KUI's `seekTo[]` (per-partition offsets) has no control in the bar; it is reachable through the URL
and is what a cursor produces. That is deliberate: a control for it would need a row per partition.

## Degraded behaviour

- Capability `Degraded`: the bar works, with a banner naming the reason (typically a stale cluster
  profile or an unreachable registry).
- Capability `Unavailable`: the bar is replaced by the fallback panel; the rows already fetched stay
  on screen, greyed, with their fetch time (ADR-032's DC-H3 and E2E criterion 8).
- A stream that fails: `BrowseStatus.Failed` with the code and message, a retry button, and the rows
  kept.

## Cancellation and shutdown

`BrowseSession.stop()` and the unmount hook both call `SseStream.close()`, which aborts the fetch.
`unmountClosesTheStream` is the assertion; without it, every navigation away from a live tail would
leave a consumer open on the broker.
