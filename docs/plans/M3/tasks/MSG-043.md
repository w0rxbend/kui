# MSG-043 — The wire seam suite: one byte fixture, two decoders

- **ID:** MSG-043
- **Title:** The wire seam suite
- **Milestone / Feature:** M3 / KU-014 (exit criteria 9 and 10)
- **Owner role:** QA Engineer with the Chief Architect
- **Context / service:** `services/message/contract`, `libs/http`, `frontend/ui-kernel`
- **Size:** M
- **Dependencies / blocked by:** MSG-027, MSG-033

## Goal (user value)

The M1 defect cannot happen again. The bytes the service writes and the bytes the browser reads are
one committed file, asserted by a JVM suite and a Scala.js suite, so a change on either side that the
other does not follow fails the build instead of producing an empty screen.

## Why this task exists

The M0 review found that nothing tested the seams between components, and that is where the worst
defects lived. M1 found two more of exactly that kind, and one of them was this seam one layer up:
the dashboard decoded `ClustersResponse` against a `ClusterOverviewDto` body, both suites green, the
screen empty under a "last updated just now" timestamp. This task is the structural answer for the
milestone whose entire value travels over a stream.

## Scope

1. A committed fixture per named event — `phase`, `message`, `consumed`, `done`, `error`,
   `heartbeat` — as **raw SSE bytes**, including field order (`event`, then `id`, then `data`) and
   the blank-line terminator.
2. A JVM suite asserting the service's renderer produces exactly those bytes.
3. A Scala.js suite asserting `SseParser` + the contract's decoders turn exactly those bytes into
   exactly the expected values.
4. The negative fixtures: an event with an unknown name, an event with a field the decoder does not
   know, and a `message` missing a required field — each with the behaviour it must produce.
5. A cursor fixture: a cursor minted with a fixed key decodes to a known value, so a change to the
   cursor's encoding is caught here as well.

## Non-goals

- No new test framework, no golden-file library. `assertNoDiff` on a string read from a resource is
  the whole mechanism, and its simplicity is the point.
- No coverage of the transport (that is MSG-044's).

```
frontend/ui-messages/test/src/kui/ui/messages/SseDecoderSeamSuite.scala
```

The fixtures live in the **contract** module's resources because that is the module both sides
already depend on. A fixture in either the service's or the browser's tree would belong to one side,
and the side that owned it would be the side that was always right.

## Files to change

- `build.mill` — the contract's JS test module gains the resource directory (Scala.js test resources
  need the explicit `resources` entry; if that proves impossible under Mill 1.1.8, the fixture is
  generated into a Scala `object` by a build task, and the deviation is recorded).

## Public Scala signatures to implement

```scala
package kui.message.contract

/** The fixtures, addressable by name from both platforms. */
object SseFixtures:
  val names: List[String]
  def bytes(name: String): String        // exact, including trailing blank line
  def expected(name: String): SseEvent   // name, id, and the decoded payload
```

## ADRs this task must obey

ADR-035 (the format is normative), ADR-007 (the codecs are explicit, so a fixture is a real check on
them rather than a check on a derivation), ADR-018.

## Acceptance criteria

```
$ ./mill services.message.contract.jvm.test
$ ./mill services.message.contract.js.test      # separate invocation
$ ./mill services.message.api.test
$ ./mill frontend.uiMessages.test
```

All four must be green, and the deliberate-break check must fail:

```
$ sed -i 's/"partition"/"partitionId"/' .../MessageDtos.scala && ./mill services.message.contract.jvm.test
... FAILED: SseWireSeamSuite.messageMatchesItsFixture
```

Run that check while writing the task and paste the output into the Implementation Report. A seam
test that has never been seen to fail is a seam test nobody can trust.

## Tests required

- `SseWireSeamSuite` (cross-compiled, runs on both platforms)
  - `everyFixtureDecodesToItsExpectedValue`.
  - `everyFixtureReEncodesToItselfByteForByte` — round-trip, so encoder and decoder are both pinned.
  - `fieldOrderIsEventThenIdThenData`.
  - `anUnknownEventNameIsYieldedNotDropped` — forward compatibility: a server that adds an event must
    not break an older browser.
  - `anUnknownFieldInAKnownEventIsIgnored`.
  - `aMissingRequiredFieldIsADecodeFailureNotADefault` — **the M1 defect**, named: a decoder that
    defaults a missing list to empty turns a wrong document into an empty screen.
- `SseEncoderSeamSuite` (JVM) — the real renderer over real domain events produces the fixtures.
- `SseDecoderSeamSuite` (Scala.js) — `SseParser` over the fixture bytes produces the contract types,
  including a run where the bytes are fed in one-character chunks.
- `CursorFixtureSuite` — a cursor minted with a fixed key equals the committed string, and decodes
  back.

## Degraded behaviour

Not applicable; this task adds no runtime code. Its contribution to degradation is the negative
fixtures: they define what a client does with a document it does not fully understand, which is what
decides whether a future version of either side breaks the other.
