# MSG-042 — `libs/testkit`: seeded topic fixtures and a Schema Registry container

- **ID:** MSG-042
- **Title:** `libs/testkit`: seeded topic fixtures and a Schema Registry container
- **Milestone / Feature:** M3 / (test infrastructure for every row)
- **Owner role:** QA Engineer
- **Context / service:** `libs/testkit`
- **Size:** L
- **Dependencies / blocked by:** none. One of the five first-movers (DEVPLAN §6.4).

## Goal (user value)

Nothing directly. Every integration assertion in this milestone needs a topic of a known shape, and
this is the task that makes those shapes cheap enough to assert against rather than expensive enough
to skip.

## Why this is a first-mover

Exit criterion 2 needs a partition with a million records. Finding out in week three that seeding it
takes eleven minutes per suite run is finding out too late — the suite gets disabled and the criterion
is lost (DEVPLAN §8 R-10). The fixture's cost is a fact to be measured now.

## Scope

1. `SeededTopics`: named fixtures, created once per container and reused by every suite.
2. The shapes, each existing because a specific behaviour needs it:
   - `simple` — 8 partitions, 800 records, JSON values, string keys.
   - `large` — 1 partition, **1 000 000** records, small values; the over-fetch bound.
   - `bigRecords` — 20 records of about 1 MiB; the byte budget.
   - `compacted` — `cleanup.policy=compact`, log start far above zero; the `offsetsForTimes(0)`
     fallback.
   - `transactional` — records written in transactions with aborted batches; control records inflate
     `end - begin`, which is what breaks a count-based loop.
   - `mixed` — tombstones, empty values, invalid UTF-8, and two records whose value is Avro; the
     serde fallback path.
   - `hundredPartitions` — the benchmark shape.
   - `tracked` — three topics with a planted `orderId` header, for the tracking criterion.
3. `SchemaRegistryContainer`: pinned, wired to the Kafka container, with helpers to register an Avro,
   a Protobuf and a JSON schema.
4. `CountingLease` (also used by MSG-008) and a `RecordingMeter` helper for asserting the gauges the
   cancellation criteria rest on.

## Non-goals

- No new security topologies. M1's PLAINTEXT / SASL-SCRAM / SSL fixtures are reused unchanged.
- No fake broker. Everything here is a real container; the fakes live in the modules that need them
  and are held to the contract suite of MSG-025.

## Public Scala signatures to implement

```scala
package kui.testkit.kafka

final case class SeededTopic(
  name: TopicName, partitions: Int, records: Long,
  /** What was written, per partition, so a suite can assert exact offsets rather than counts. */
  offsets: Map[PartitionId, OffsetRange],
  timestamps: Map[PartitionId, (Instant, Instant)]
)

object TopicShapes:
  val simple, large, bigRecords, compacted, transactional, mixed, hundredPartitions: TopicShape
  val tracked: List[TopicShape]

object SeededTopics:
  /** Creates and fills the shapes once per broker. Idempotent: a shape that already exists with the
    * right record count is not rewritten, so a suite re-run inside one container is fast.
    *
    * Seeding uses one producer with `linger.ms=50` and `batch.size=1MiB`; the million-record shape
    * must seed in **under 60 seconds**, and `SeededTopicsSuite` asserts that bound. If it cannot be
    * met, the shape is tagged `Slow`, moved to the nightly job, and the decision is recorded in
    * `TECH_DEBT.md` — in this task, not later by whoever finds the suite too slow.
    */
  def ensure(bootstrap: String, shapes: List[TopicShape]): Resource[IO, Map[String, SeededTopic]]
```

## Tests required

- `SeededTopicsSuite`
  - `everyShapeHasTheRecordCountAndPartitionCountItClaims`.
  - `theReportedOffsetsMatchTheBroker` — the fixture's own `offsets` map is what suites assert
    against, so a wrong map would make every downstream assertion wrong in the same direction and
    all of them green.
  - `compactedShapeHasALogStartAboveZero` — asserted after a forced compaction, because a fixture
    that quietly failed to compact would make MSG-003's fallback test vacuous.
  - `transactionalShapeHasMoreOffsetsThanRecords` — the property that makes it useful.
  - `mixedShapeContainsATombstoneAnEmptyValueAndInvalidUtf8`.
  - `ensureIsIdempotentAndFast`.
  - `theMillionRecordShapeSeedsUnderTheBound` — with the measured time printed, so the number is in
    the CI log rather than in somebody's memory.
- `SchemaRegistryContainerSuite`
  - `registersAndReadsBackAllThreeSchemaTypes`.
  - `theContainerIsReachableFromTheKafkaNetwork`.

## Observability

`RecordingMeter` is the observability *of the tests*: an in-memory otel4s meter whose gauge values
can be read back, which is what turns "the consumer gauge returns to zero" from a claim into an
assertion (DEVPLAN §10 D6).

## Degraded behaviour

If a container cannot start (no Docker), the suites that need it must **fail with a clear message
naming Docker**, not hang and not silently pass. `SeededTopics.ensure` checks Docker availability
first and produces that message.

## Cancellation and shutdown

`ensure` returns a `Resource`; the fixture is `ResourceSuiteLocalFixture`, so a cancelled suite tears
down its container. A leaked container per aborted test run makes a developer's machine unusable
within a day, which is the practical version of this milestone's theme.
