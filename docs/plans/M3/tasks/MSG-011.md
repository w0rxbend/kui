# MSG-011 — `SerdeRegistry` / `ClusterSerdes`: resolution order, suggestions, the `kui.clusters[].serde` slice

- **ID:** MSG-011
- **Title:** `SerdeRegistry` / `ClusterSerdes`: resolution order, suggestions, configuration
- **Milestone / Feature:** M3 / SD-001, SD-003, MS-009
- **Owner role:** Principal Scala Engineer
- **Context / service:** `libs/serde`, `libs/config`
- **Size:** L
- **Dependencies / blocked by:** MSG-010

## Goal (user value)

An operator writes `topicValuesPattern: "orders.*"` once and every orders topic decodes correctly for
everyone. A user who wants something else picks from a list that only offers serdes that can actually
work right now — no Schema Registry entries when the registry is unreachable.

## Scope

1. `SerdeRegistry[F].forCluster(profile): Resource[F, ClusterSerdes[F]]`, built in configuration
   order and closed when the profile changes.
2. `ClusterSerdes.resolve`: **pattern → explicit config → cluster default → String**, with `Fallback`
   as the terminal case that always resolves.
3. `ClusterSerdes.suggest(topic, target, use)`: the MS-009 picker list, ordered, marking one as
   `preferred`, and **omitting serdes whose backing service is unavailable** (the SR chip case).
4. The `kui.clusters[].serde` configuration slice, keeping Kafbat's key shape (ADR-028): `name`,
   `className`, `filePath`, `properties`, `topicKeysPattern`, `topicValuesPattern`,
   `defaultKeySerde`, `defaultValueSerde`.
5. Validation at startup: an unknown serde name, an invalid regex, or a `defaultValueSerde` naming a
   serde that is not configured are configuration errors accumulated with every other one (ADR-013),
   not runtime surprises.

## Non-goals

- No `className` / `filePath` **loading**. The keys are accepted and validated so that a Kafbat
  configuration file does not fail to parse, and a configured `className` produces a named
  `KUI-UNSUPPORTED` error at startup pointing at M7. Silently ignoring it would be the M1
  `AllInOneConfig` defect again.
- No registry client (MSG-012 registers itself into this registry).
- No masking (MSG-016).

## Design references

ADR-028 (resolution order and the config key shape, both taken from Kafbat so that a migrating

## Public Scala signatures to implement

```scala
package kui.serde

trait SerdeRegistry[F[_]]:
  /** Built in configuration order, closed on profile change. A `Resource` because a
    * Schema-Registry serde owns an HTTP client and a cache, and because a profile change must not
    * leave the old one running. */
  def forCluster(profile: ClusterProfile): Resource[F, ClusterSerdes[F]]

trait ClusterSerdes[F[_]]:
  def all: List[Serde[F]]
  /** pattern → explicit → default → String; `Fallback` always exists, so this never fails for
    * lack of a serde — only for an explicitly requested name that is not configured. */
  def resolve(topic: TopicName, target: Target, explicit: Option[SerdeName])
    : F[Either[KuiError, Serde[F]]]
  def suggest(topic: TopicName, target: Target, use: SerdeUse): F[List[SerdeSuggestion]]
  def fallback: Serde[F]

final case class SerdeSuggestion(
  name: SerdeName, description: String, preferred: Boolean,
  schema: Option[SchemaDescription], parameters: List[SerdeParameter],
  /** `false` with a reason when the serde exists but cannot work now (registry unreachable).
    * The picker renders it disabled with the reason rather than hiding it, so a user is not left
    * wondering where Avro went (ADR-032). */
  available: Boolean, unavailableReason: Option[String]
)
```

```scala
package kui.serde

/** The resolution order, as a pure function, so that it is a table test and not four `if`s in an
  * effect. */
object SerdeResolution:
  final case class Rules(
    patterns: List[(Regex, SerdeName, Target)],
    defaultKey: Option[SerdeName], defaultValue: Option[SerdeName]
  )
  def resolve(rules: Rules, available: Set[SerdeName], topic: TopicName,
              target: Target, explicit: Option[SerdeName]): Either[KuiError, SerdeName]
```

## Tests required

- `SerdeResolutionSuite`
  - `theOrderTable` — one case per step, including "explicit beats everything" and "the fallback is
    the terminal case".
  - `anExplicitUnknownNameIsAnError` — not a silent fallback: the user asked for something specific.
  - `patternsAreEvaluatedInConfigurationOrder` (property) — first match wins, and it is the
    configured order, not the map iteration order, which is the classic silent difference between a
    developer's machine and production.
  - `resolveNeverFailsWithoutAnExplicitName` (property).
- `ClusterSerdesSuite`
  - `suggestMarksExactlyOnePreferred` (property).
  - `suggestMarksAnUnavailableSerdeUnavailableRatherThanOmittingIt`.
  - `theResourceIsClosedWhenTheProfileChanges` — a `Ref` finaliser flag; this is the ADR-016
    invalidation contract, and without it a rotated Schema Registry credential is never picked up.
  - `builtInsAreAlwaysPresentEvenWithNoConfiguration`.
- `SerdeConfigSuite`
  - `unknownSerdeNameIsAccumulatedWithOtherErrors` — asserted alongside a second, unrelated
    configuration error in one message (ADR-013).
  - `invalidRegexNamesTheKeyAndThePattern`.
  - `defaultSerdeMustExist`.
  - `classNameIsRefusedWithAPointerToM7`.
  - **`theSectionIsActuallyUsed`** — the M1 seam defect, pinned: a configuration with a
    `topicValuesPattern` is loaded through the real composition path and asserted to change what
    `resolve` returns. A section that parses and is then discarded passes every other test here.

## Observability

- `kui.serde.registry.built` — counter, attribute `cluster`; a number that climbs on a stable
  configuration means profile churn is rebuilding registries.
- One INFO line per cluster registry build listing the serde names in resolution order. It is short,
  it happens once per profile version, and it is the line an operator needs when a topic decodes
  unexpectedly.

## Degraded behaviour

- A serde whose backing service is down stays in `all` and in `suggest`, marked unavailable with the
  reason. `resolve` will not choose it implicitly; asking for it explicitly returns
  `KUI-SERDE-UNAVAILABLE`, which MSG-029 renders as a 503 **before** the stream starts.
- The registry `Resource` failing to build for one cluster must not stop the service: the cluster's
  serdes degrade to the built-ins and the `message` capability reports `Degraded` with the reason.

## Cancellation and shutdown

`forCluster` is a `Resource`; a profile change cancels the old one, and the suite asserts the
finaliser ran. The registry itself holds a `Ref` of open registries keyed by `(clusterId, version)`
and closes the previous version **after** the new one is built, so an in-flight browse never loses
its serdes mid-stream.
