# MSG-007 — `produce` and `deleteRecords` (purge)

- **ID:** MSG-007
- **Title:** `produce` and `deleteRecords` (purge)
- **Milestone / Feature:** M3 / MP-001, MP-003, MS-008
- **Owner role:** Principal Scala Engineer
- **Context / service:** `libs/kafka`
- **Size:** M
- **Dependencies / blocked by:** MSG-002

## Goal (user value)

Publishing a record and emptying a partition, as two port methods that report exactly what happened —
the partition, offset and timestamp the broker assigned, and the new low watermark per partition —
rather than a bare success.

## Scope

1. `MessageBrowsePort.produce`: one `RawProducerRecord` through a producer `Resource`, returning
   `ProducedAt`.
2. `MessageBrowsePort.produceAll`: a batch through **one** producer, for MP-002's `count` and for
   MP-003's resend. Producing 500 records through 500 producers is 500 connections.
3. `MessageBrowsePort.deleteRecords`: `listOffsets(earliest)` + `listOffsets(latest)`, then
   `deleteRecords(tp -> beforeOffset(latest))` for non-empty partitions only, returning the new low
   watermark per partition as a `BatchResult` (M1's type).
4. Partition validation: a produce naming a partition the topic does not have is a `KUI-VALIDATION`
   error naming the partition count, not an `UnknownTopicOrPartitionException` at send time.

## Non-goals

- No serialization. The port takes and returns bytes; `libs/serde` turns a user's text into them
  (MSG-011, MSG-022).
- No templating, no `{{count}}` placeholders — those are a frontend feature (ADR-029) and a `count`
  parameter here.
- No transactions and no idempotent producer. A UI produce is one record.
- No read-only-mode check. That is an application concern (MSG-022) because it depends on the cluster
  profile and the principal, neither of which this port has.

## Design references

`research/kafka/admin-capabilities.md` §2 "Purge" (the two `listOffsets` calls, the per-partition new
low watermark, `PolicyViolationException` on a compacted topic without `delete`) and §4 "Produce";
`research/kafbat/api-analysis.md` Finding 10 (Kouncil's resend reads a range and re-produces).

## Public Scala signatures to implement

```scala
trait MessageBrowsePort[F[_]]:
  ...
  def produce(profile: ClusterProfile, record: RawProducerRecord): F[Either[KuiError, ProducedAt]]

  /** One producer for the whole batch. Results are in input order, and a failure in the middle is
    * reported per record rather than aborting the ones that already landed — a resend that copies
    * 400 of 500 records must say which 400. */
  def produceAll(profile: ClusterProfile, records: List[RawProducerRecord])
    : F[Either[KuiError, List[Either[KuiError, ProducedAt]]]]

  /** Purge. Returns the new low watermark per partition; a partition that was already empty is
    * `Skipped(NoLeader | Failed)` rather than absent (M1's `BatchResult` invariant). */
  def deleteRecords(profile: ClusterProfile, topic: TopicName, partitions: Option[Set[PartitionId]])
    : F[Either[KuiError, BatchResult[TopicPartition, Offset]]]
```

## Tests required

- `ProducingSuite` (Testcontainers)
  - `roundTripsKeyValueAndHeaderBytesExactly` (property over arbitrary byte arrays including empty
    ones, `null` keys and multi-valued headers).
  - `nullValueIsATombstone` — `None` produces a record whose value is `null`, which is what a
    compacted topic needs and what a "produce an empty value" form must not turn into `""`.
  - `partitionOutOfRangeIsAValidationError` — with the partition count in the message.
  - `produceAllUsesOneProducer` — asserted through `kui.message.producers.active` peaking at 1 for a
    100-record batch.
  - `produceAllReportsPerRecordFailures`.
  - `cancellationReleasesTheProducer`.
- `RecordDeletionSuite` (Testcontainers)
  - `movesTheLowWatermark`.
  - `skipsEmptyPartitionsWithAReason`.
  - `compactedTopicWithoutDeleteIsAValidationError` — `PolicyViolationException` mapped, message
    naming `cleanup.policy`.
  - `noPartitionDisappearsFromTheResult` (property, over M1's `BatchResult` invariant).

## Observability

- `kui.message.produced` — counter, attributes `cluster`, `topic`, `outcome`.
- `kui.message.produce.duration` — histogram.
- `kui.message.records.deleted` — counter with the partition count, attributes `cluster`, `topic`.
- Purge logs at **INFO** with cluster, topic, partitions and the watermarks: it destroys data, and an
  operator must be able to find out when it happened even before audit exists (M5). Produce logs at
  DEBUG, without the payload — a payload in a log is a masking bypass (ADR-023).

## Degraded behaviour

- A broker that refuses the produce (quota, authorization, message too large) returns a mapped
  `KuiError`; the produce drawer shows it and keeps the user's text (MP-001's "keep contents").
- A partial `produceAll`: the successful records stay produced. There is no rollback, this is stated
  in the return type, and MSG-022's resend UI reports "copied 400 of 500" rather than pretending.
- `deleteRecords` unsupported (a managed service that disables it): `KUI-UNSUPPORTED`, which
  ADR-039 renders as `NotConfigured` — the action is hidden rather than shown broken.

## Cancellation and shutdown

The producer is a `Resource`; cancelling a produce closes it. A record already accepted by the broker
is **not** un-produced — the test `cancellationReleasesTheProducer` asserts release, not rollback,
and the scaladoc says so, because a caller that expects otherwise will write a retry that duplicates.
