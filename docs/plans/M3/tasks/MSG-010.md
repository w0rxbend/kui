# MSG-010 — Built-in serdes: String, Int32/64, UInt32/64, UUID, Base64, Hex, JSON, with auto-detection

- **ID:** MSG-010
- **Title:** Built-in serdes and auto-detection
- **Milestone / Feature:** M3 / SD-001
- **Owner role:** Principal Scala Engineer
- **Context / service:** `libs/serde`
- **Size:** L
- **Dependencies / blocked by:** MSG-009

## Goal (user value)

The formats that cover most topics without any configuration: text, numbers, UUIDs, and JSON pretty
enough to read and structured enough for the table view to flatten. And the topic nobody configured
still shows something sensible, because auto-detection picks the serde that can actually decode the
bytes.

## Scope

1. The eight non-registry built-ins of SD-001: `String`, `Int32`, `Int64`, `UInt32`, `UInt64`,
   `UUID`, `Base64`, `Hex`, `Json`.
2. Auto-detection: `preferable` per serde, and `SerdeAutodetect.rank`, which orders the candidates
   for a payload. This is the "magic byte" row of SD-001 for the non-registry serdes; the Schema
   Registry magic byte is MSG-012's.
3. Serializers for each, so the produce form can send an integer or a UUID as bytes.
4. `Json`'s `properties`: nothing. Its contribution is `kind = Json`, which is what unlocks MSG-037's
   flattener.

## Non-goals

- No `ProtobufFile`, `ProtobufRaw`, `AvroEmbedded`, `MessagePack`, `Struct`, MirrorMaker2 or
  `__consumer_offsets` serdes. Those are KU-023 in M5 (DEVPLAN §10 D9), even though ADR-028 lists
  them among the eventual built-ins.
- No Schema Registry (MSG-012).
- No per-topic configuration or patterns (MSG-011).

## Public Scala signatures to implement

```scala
package kui.serde.builtin

object BuiltinSerdes:
  /** In resolution order — the order a `preferable` tie is broken in, and the order the picker
    * lists them in. `Fallback` is not here: it is the terminal case, not a candidate. */
  def all[F[_]: Sync]: List[Serde[F]]

object NumberSerdes:
  /** Big-endian, exactly `n` bytes, or a `DeserializeFailure`. A four-byte serde that accepted
    * eight bytes and read the first four would render half a number and look plausible, which is
    * worse than failing. */
  def int32[F[_]: Sync]: Serde[F]
  def int64[F[_]: Sync]: Serde[F]
  def uint32[F[_]: Sync]: Serde[F]
  def uint64[F[_]: Sync]: Serde[F]   // rendered through `java.lang.Long.toUnsignedString`
```

```scala
package kui.serde

/** Which serde to try for a payload nobody configured.
  *
  * Ranking, not guessing: every candidate is asked `preferable`, and the first that says yes in
  * `BuiltinSerdes.all` order wins. `Json` says yes only when the bytes parse as a JSON object or
  * array — a bare `123` is a number, not JSON, which is why the number serdes come first.
  */
object SerdeAutodetect:
  def rank[F[_]: Monad](candidates: List[Serde[F]], topic: TopicName, target: Target,
                        sample: Option[Array[Byte]]): F[List[SerdeName]]
```

## The detection table

`SerdeAutodetectSuite.detectionTable` asserts it row by row.

| Payload | Detected | Why |
| --- | --- | --- |
| `{"a":1}` | `Json` | parses as an object |
| `[1,2]` | `Json` | parses as an array |
| `123` | `Int32`/`Int64` by length, not `Json` | a bare number is ambiguous and the number serdes are earlier |
| 4 bytes, not printable | `Int32` | |
| 16 bytes | `UUID` **only if** it round-trips to a canonical UUID | a 16-byte blob is not automatically a UUID |
| valid UTF-8, no control characters | `String` | |
| anything else | `Fallback` | the terminal case |

## Acceptance criteria

```
$ ./mill libs.serde.test
```

```scala
// Round-trip, for every serde that has a serializer
forAll(validInputFor(serde)) { s =>
  val bytes = serde.serializer(t, Value, Map.empty).flatMap(_.serialize(s, Nil)).rethrow
  val back  = serde.deserializer(t, Value).flatMap(_.deserialize(Nil, bytes)).rethrow
  assertEquals(back.text, s)
}

// A four-byte serde refuses eight bytes rather than reading half of them
assert(NumberSerdes.int32[IO].deserializer(t, Value)
         .flatMap(_.deserialize(Nil, Array.fill(8)(0.toByte))).unsafeRunSync().isLeft)
```

## Tests required

- `BuiltinSerdesSuite`
  - `roundTripsForEverySerde` (property, per serde, with a generator of that serde's valid inputs).
  - `wrongLengthIsAFailureNotATruncation` — for all four number serdes.
  - `uint64RendersAboveLongMaxValue` — the case that a signed rendering gets wrong and nobody
    notices until an operator reads a negative sequence number.
  - `jsonKindIsJsonAndTextIsCompactNotPretty` — the browser pretty-prints (MSG-036); the service
    sends compact, because pretty-printing on the server multiplies the bytes on the wire by three.
  - `jsonSerdeRejectsNonJson`.
  - `uuidRejectsSixteenBytesThatAreNotAUuid`.
  - `hexAndBase64AreCaseAndPaddingExact` (property).
  - `emptyBytesAreHandledByEverySerde` — `Right("")` or `Left`, never a crash (property over all).
- `SerdeAutodetectSuite`
  - `detectionTable` — one case per row.
  - `rankIsDeterministic` (property) — two calls with the same sample give the same order. A picker
    whose order changes between refreshes is a picker the user cannot trust.
  - `neverRanksASerdeThatCannotDecodeTheSample` (property).

## Observability

Reuses MSG-009's `kui.serde.deserialize.failures`. Adds `kui.serde.autodetected` — counter with a
`serde` attribute, so the operator can see what their unconfigured topics actually contain.

## Degraded behaviour

Every serde here returns `Left` rather than throwing, and `Deserializers.withFallback` turns that
into a rendered record plus an error annotation. A user browsing a Protobuf topic with no registry
sees the bytes and a marker naming the serde that failed — which is exactly what tells them to
configure a registry.

## Cancellation and shutdown

None of these serdes has a lifetime or performs I/O.
