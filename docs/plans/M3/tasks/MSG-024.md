# MSG-024 — `PurgeUseCase` and the serde suggestion use case

- **ID:** MSG-024
- **Title:** `PurgeUseCase` and the serde suggestion use case
- **Milestone / Feature:** M3 / MS-008, MS-009, SD-003
- **Owner role:** Domain Architect (message)
- **Context / service:** `services/message/application`
- **Size:** S
- **Dependencies / blocked by:** MSG-017, MSG-011

## Goal (user value)

Two small things the browse screen needs: emptying a topic's partitions, and the serde picker's list
with the right one already selected.

## Scope

1. `PurgeUseCase.purge(request)`: read-only check, then the port's `deleteRecords`, returning the new
   low watermark per partition.
2. `SerdeSuggestionUseCase.suggest(cluster, topic, target, use)`: the picker list, with `preferred`
   set by the same resolution the browse uses, and unavailable serdes marked with a reason.

## Non-goals

- No purge on the topic page (DEVPLAN §10 D11 — that entry point is M5, with audit).
- No audit record (M5). The INFO log line of MSG-007 is the only trace in M3, and MSG-048 documents
  that.
- No serde *configuration* editing.

## Public Scala signatures to implement

```scala
package kui.message.application.admin

final case class PurgeRequest(cluster: ClusterId, topic: TopicName,
                              partitions: Option[NonEmptySet[PartitionId]])
final case class PurgeResult(newLowWatermarks: Map[PartitionId, Offset],
                             skipped: Map[PartitionId, String])

trait PurgeUseCase[F[_]]:
  /** Refused with `KUI-READ-ONLY` on a read-only cluster, before anything is read. */
  def purge(request: PurgeRequest): F[Either[KuiError, PurgeResult]]

trait SerdeSuggestionUseCase[F[_]]:
  def suggest(cluster: ClusterId, topic: TopicName, target: Target, use: SerdeUse)
    : F[Either[KuiError, List[SerdeSuggestion]]]
```

## ADRs this task must obey

ADR-034 (`KUI-READ-ONLY`; `KUI-VALIDATION` for a compacted topic without `delete`), ADR-028
(resolution order decides `preferred`), ADR-032 (an unavailable serde is listed and disabled with a
reason, never hidden), ADR-041 A3.

## Tests required

- `PurgeUseCaseSuite`
  - `readOnlyClusterIsRefused`.
  - `everyRequestedPartitionAppearsInTheResultOrTheSkippedMap` (property) — M1's `BatchResult`
    invariant carried through to the response, so no partition silently vanishes.
  - `compactedTopicWithoutDeleteIsAValidationErrorNamingTheSetting`.
  - `noPartitionsRequestedMeansAllPartitions`.
- `SerdeSuggestionUseCaseSuite`
  - `exactlyOnePreferred` (property).
  - `preferredMatchesWhatResolveWouldChoose` (property) — the picker and the browse must agree, and
    the only way to guarantee it is to derive one from the other.
  - `unavailableSerdesAreListedWithAReason`.
  - `serializeAndDeserializeListsCanDiffer` — a serde that can decode but not encode appears in one
    list only.

## Observability

- `kui.message.purge` — counter, attributes `cluster`, `topic`, `outcome`. Purge is destructive and
  its rate is worth alerting on even before audit exists.
- No metric for suggestions; it is a read of already-loaded state.

## Degraded behaviour

- `deleteRecords` unsupported on a managed service: `KUI-UNSUPPORTED`, rendered by ADR-039 as
  `NotConfigured`, so the action is hidden rather than shown and broken.
- A partition offline: skipped with a reason, the rest are purged, and the result says so.
- Serde registry unavailable for a cluster: `suggest` returns the built-ins with a `Degraded` note
  rather than an error — a user must still be able to pick `String` while the registry is down.

## Cancellation and shutdown

Both are short, single-request operations inside the adapters' `Resource`s; cancellation releases
them. A purge cancelled after the broker accepted the call is **not** undone, and the scaladoc says
so.
