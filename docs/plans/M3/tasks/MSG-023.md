# MSG-023 — `TrackUseCase`: the bounded multi-topic scan

- **ID:** MSG-023
- **Title:** `TrackUseCase`
- **Milestone / Feature:** M3 / ET-001, ET-002
- **Owner role:** Domain Architect (message)
- **Context / service:** `services/message/application`
- **Size:** L
- **Dependencies / blocked by:** MSG-019

## Goal (user value)

"Where did order 4471 go?" — one header value, three topics, a two-hour window, results streamed as
they are found, sorted by time, with a hard stop. Neither Kafbat nor Provectus has this at all.

## Scope

1. `TrackUseCase.stream(query): Stream[F, BrowseEvent]` — the SSE variant (ET-002).
2. `TrackUseCase.run(query): F[Either[KuiError, List[DecodedRecord]]]` — the capped synchronous
   variant (ET-001), which is the same stream compiled to a list under the same budget.
3. Per topic, per partition: `[offsetForTime(from), offsetForTime(until))`, then scan **topics
   smallest-range-first** with one consumer at a time, so a small topic's hits arrive quickly.
4. The matcher of MSG-017: `value | key | header(name)` against
   `contains | notContains | equals | notEquals | regex`, with a per-record regex timeout.
5. `correlationKey`: a `group` string per event, from a header or a JSON path. No join.
6. One `done{reason}` at the end, replacing Kouncil's empty-array sentinel.

## Non-goals

- No STOMP, no WebSocket (ADR-029, DR-12).
- No server-side correlation or graph building — M9.
- No cross-cluster tracking.
- No progress estimate as a percentage: the events report topics done and records scanned. A
  percentage over an offset range is wrong on a compacted topic, and a wrong progress bar is worse
  than none.

## Design references

ADR-029 (every rule of this task), `research/kafbat/api-analysis.md` Finding 10 (Kouncil's algorithm:
per-topic ranges, sorted by total range size, sequential scan with a single consumer, five empty
polls per topic, 1 000-event sanity limit, and that "tracking" is a scan and not a join),
`research/kouncil/ui-analysis.md` DC-H11 (bounded, with the same budgets as browse).

## Public Scala signatures to implement

```scala
package kui.message.application.track

trait TrackUseCase[F[_]]:
  /** Emits `phase` per topic, `message` per hit (with `group` when a correlation key is set),
    * `consumed` progress, and exactly one `done{reason}`.
    *
    * Topics are scanned smallest-range-first (Kouncil's ordering) so that the cheap answers arrive
    * first — on a scan that will hit its budget, which topics were finished decides what the user
    * actually gets.
    */
  def stream(query: TrackQuery): Stream[F, BrowseEvent]

  /** The capped synchronous form: the same stream, compiled, with the same budget. There is one
    * implementation, so the two variants cannot disagree about what "found" means. */
  def run(query: TrackQuery): F[Either[KuiError, List[DecodedRecord]]]

object EventMatching:
  /** Pure. `Left` only for a regex that exceeds its match budget. */
  def matches(m: TrackMatch, record: DecodedRecord): Either[FilterError, Boolean]
  def group(key: CorrelationKey, record: DecodedRecord): Option[String]

object TrackPlan:
  final case class TopicPlan(topic: TopicName, ranges: Map[PartitionId, OffsetRange], size: Long)
  /** Smallest range first, ties broken by topic name so a plan is deterministic. */
  def order(plans: List[TopicPlan]): List[TopicPlan]
```

## ADRs this task must obey

ADR-029, ADR-035 (the envelope, and the `done` that replaces the sentinel), ADR-017 (a `filterId`
may be used instead of a matcher, with the same error counting), ADR-023 (results go through
`RecordMapping`, so they are masked), ADR-041 A3, PLAN §22.

## Library coordinates

None new. The regex engine is `java.util.regex` with a match budget enforced by an interruptible
block — **not** re2j, which is only on `libs/filter`'s classpath (rule A12). Record this in the
Implementation Report: if the budget proves unreliable in practice, moving the matcher behind
`MessagePredicate` and using CEL's re2j is a one-file change.

    decided.
  - `regexRespectsItsMatchBudget` — a catastrophic-backtracking pattern against a long value.
  - `groupExtractsFromHeaderAndJsonPath`, and yields `None` rather than failing when the path misses.
  - `matchingIsPureAndTotal` (property).
- `TrackUseCaseSuite` (fake ports, `TestControl`)
  - `scansSmallestTopicFirst`.
  - `stopsAtTheLimitWithDoneLimit`.
  - `stopsAtTheDeadlineWithDoneBudget`.
  - `emitsExactlyOneTerminalEvent` (property).
  - `resultsAreTimestampSortedWithinABatch`.

## Observability

- `kui.message.track.duration` — histogram, attributes `cluster`, `topics` (count, not names — a
  metric attribute per topic name is unbounded cardinality), `outcome`.
- `kui.message.track.scanned` and `.hits` — counters. The ratio is what tells an operator their
  window is too wide.

## Degraded behaviour

- A topic the principal cannot read: a `phase` event naming it and the scan continues.
- A window that resolves to nothing on every topic: `done{reason:"exhausted"}` with no messages,
  which the UI renders as "no events found in this window" — not an error.
- The budget reached: `done{reason:"budget"}` and the UI says which topics were finished, so the user
  can narrow the window rather than guess.

## Cancellation and shutdown

One consumer at a time, each a `Resource`, released when the scan moves to the next topic or when the
stream is cancelled. `cancellationStopsTheScanAndReleasesTheConsumer` asserts the release flag; a
track that leaked one consumer per topic would leak three per abandoned search.
