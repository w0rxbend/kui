# MSG-034 — `ui-messages`: the module, the typed clients, the routes and the topic-tab seam

- **ID:** MSG-034
- **Title:** `ui-messages`: module, clients, routes, the topic-tab seam
- **Milestone / Feature:** M3 / KU-013, MS-001
- **Owner role:** Frontend Architect
- **Context / service:** `frontend/ui-messages`, `frontend/ui-shell`
- **Size:** M
- **Dependencies / blocked by:** MSG-027, MSG-033

## Goal (user value)

The messages screen exists, is reachable from the topic page and from a URL, and its client is
generated from the same contract the service compiles — so the M1 defect where a browser decoded a
document nobody sends cannot be repeated.

## Scope

1. The `frontend/ui-messages` Mill module, depending on `frontend.uiKernel` and
   `services.message.contract.js`.
2. Typed clients derived from `MessageEndpoints` with `tapir-sttp-client4`; **no hand-written URL
   anywhere in this module**, which is the rule that makes the seam hold.
3. Routes: `/ui/clusters/:c/topics/:t/messages` (with the view, filter state and cursor in the URL)
   and `/ui/clusters/:c/events/track`.
4. The topic-tab seam: the messages tab is contributed through the kernel `FeaturePanel` slot
   (KU-013, DC-H6), keyed by a **slot id declared in `frontend/ui-kernel`** and used by both
   `ui-topics` and `ui-messages`. No file in `frontend/ui-topics` is edited by this milestone.
5. The shell registration: route entries and the drawer host, in one commit.

## Non-goals

- No screens (MSG-035 onward). This task ends with a page that renders its heading, its breadcrumb
  and an empty state.
- No changes to `ui-topics` or `ui-clusters` (DEVPLAN §3, §6.5).
- No client-side state library. Airstream is the state model (ADR-011).

## Design references

ADR-012 (microfrontend loading; `ui-messages` is a split module), ADR-032 (navigation state and the
URL-as-state rule), `research/kafbat/ui-analysis.md` "Messages" (the URL parameter names, which KUI
keeps where they are already right: `mode`, `limit`, `offset`, `timestamp`, `partitions`,
`stringFilter`, `keySerde`, `valueSerde`, `cursor`), DC-H6 (a cross-feature panel is a slot, never an
import), `research/design/REFERENCE.md`.

## Public Scala signatures to implement

```scala
package kui.ui.messages

/** The typed client. Every call is derived from an endpoint value in `services.message.contract`,
  * so a path or a DTO that changes on the server changes here at compile time.
  *
  * This is the M1 lesson made structural: the dashboard decoded `ClustersResponse` against a
  * `ClusterOverviewDto` body and every suite on both sides was green, because each tested itself
  * against its own idea of the payload. There is no idea here — there is one type.
  */
object MessagesApi:
  def page(cluster: ClusterId, topic: TopicName, params: PageParams): EventStream[Either[ErrorEnvelope, MessagePageDto]]
  def produce(...): EventStream[Either[ErrorEnvelope, ProduceResultDto]]
  def serdes(...): EventStream[Either[ErrorEnvelope, List[SerdeSuggestionDto]]]
  /** The stream endpoints are `SseStream` (MSG-033) plus the contract's decoders, not sttp: an
    * abortable fetch is what carries cancellation. The URL is still built from the endpoint value. */
  def browseUrl(cluster: ClusterId, topic: TopicName, params: BrowseStreamParams): String
```

```scala
package kui.ui.messages

/** Filter state lives in the URL, so a browse is a link somebody can send.
  * `history.state` carries only what the URL cannot: the fetched rows, for back-navigation. */
final case class MessagesRoute(cluster: ClusterId, topic: TopicName, view: View, params: BrowseParams)
enum View { case List, Table }
```

## Tests required

- `MessagesApiSuite`
  - `everyCallIsDerivedFromAnEndpointValue` — asserted by grepping the module's sources for a string
    literal beginning `/api/`, which must find none. A crude test, and the one that would have caught
    the M1 defect.
  - `decodesTheContractsGoldenFiles` — the browser decodes the same fixtures the JVM suite encodes
    (the seam; MSG-043 makes it exhaustive).
  - `anErrorEnvelopeIsDecodedAsAnError` — not as a successful empty payload. This is the exact M1
    failure: a decoder that defaults a missing field turns a wrong document into an empty screen, so
    every list field is required (MSG-027) and this asserts the browser half.
- `MessagesRoutesSuite`
  - `roundTripsEveryParameterThroughTheUrl` (property).
  - `anUnknownViewParameterFallsBackToListRatherThanFailing`.
  - `theMessagesTabIsContributedThroughTheSlotNotAnImport` — asserted by the absence of any
    `ui-topics` symbol in this module's dependency graph.

## Observability

None.

## Degraded behaviour

- `message` capability `Unavailable`: the route still resolves and renders the kernel's fallback
  panel with the reason (ADR-032, DR-15 — an unavailable entry is clickable and explains itself).
- `NotConfigured`: the messages tab is not shown on the topic page at all, per ADR-032.

## Cancellation and shutdown

Every subscription in this module is bound to Laminar's mount lifecycle; navigating away closes the
`SseStream`. `MessagesRoutesSuite.navigatingAwayClosesTheStream` asserts it in jsdom, which is the
browser end of the milestone's third exit criterion.
