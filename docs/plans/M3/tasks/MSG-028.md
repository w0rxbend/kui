# MSG-028 — Message endpoints: stream, page, produce, resend, purge, serdes, filters, track

- **ID:** MSG-028
- **Title:** Message endpoints
- **Milestone / Feature:** M3 / MS-001 … MS-009, MP-001 … MP-003, ET-001, ET-002, KU-016
- **Owner role:** Chief Architect
- **Context / service:** `services/message/contract`
- **Size:** M
- **Dependencies / blocked by:** MSG-027

## Goal (user value)

Every address the milestone offers, declared once, so that the gateway derives its routes, the
browser generates its client and the OpenAPI document is regenerated from the same values.

## Scope

The eleven endpoints, on `KuiEndpoint.internal` (`/internal/v1`), from the KUI mapping of
`research/kafbat/api-analysis.md`:

| Method | Path | Feature |
| --- | --- | --- |
| GET | `/clusters/{c}/topics/{t}/messages/stream` | MS-001, MS-002, MS-005, MS-006, MS-007 |
| GET | `/clusters/{c}/topics/{t}/messages/page` | MS-003 |
| POST | `/clusters/{c}/topics/{t}/messages` | MP-001, MP-002 |

| GET | `/clusters/{c}/topics/{t}/messages/schema` | SD-004 |

## Non-goals

- No `messages/v1` shape. Kafbat disabled its own (`ValidationException("Not supported")`); the
  stream endpoint plus `seekTo[]` covers everything it did.
- No server logic (MSG-029), no gateway routes (MSG-031).
- No `PUT`/`PATCH` of anything: nothing here edits an existing record, because Kafka has no such
  operation and an endpoint that implied one would be answered by a bug report.

## Design references

`research/kafbat/api-analysis.md` "Proposed KUI `/api/v1` mapping" (the paths, kebab-case, plural
nouns, explicit sub-resources) and Finding 5.2 (the parameter set); ADR-029 (the track and page
parameters); ADR-017 (`filterId` **and** `filterSource` on browse and track); ADR-035 (SSE responses);
ADR-026 (`cursor` accepted as a parameter and as `Last-Event-ID`).

## Tests required

- `MessageEndpointsSuite` (both platforms)
  - `everyEndpointIsUnderInternalV1`.
  - `everyEndpointDeclaresASignedPrincipal`.
  - `everyEndpointDeclaresAPermission` — enumerated, so a new endpoint without one fails the build
    rather than shipping unprotected in M6.
  - `pathsAreKebabCaseAndPluralNouns` (property over the templates).
  - `noTwoEndpointsShareAMethodAndPathTemplate`.
  - `browseParamsRoundTripThroughTheQueryString` (property) — a request built by the browser's
    generated client parses back to the same value; this is half of the wire seam, and MSG-043 is
    the other half.
  - `cursorMayArriveAsAParameterOrAsLastEventId` — both, and they agree.
  - `allContainsEveryEndpointDeclaredInThisModule` — by reflection over the objects, so an endpoint
    that is written and then forgotten in `all` fails here rather than 404-ing in production.

## Degraded behaviour

Endpoint declarations carry `ErrorEnvelope` as their error output, which is what makes every failure
mode of this milestone expressible as a typed response instead of an untyped 500. Streaming
endpoints additionally carry ADR-035's `error` event **inside** the stream, and the two are
different: a failure before the stream starts is an HTTP error envelope; a failure after it starts is
an `error` event. MSG-029 implements the split and its suite asserts both.

## Cancellation and shutdown

Not applicable to declarations. The streaming endpoints' output type is an fs2 `Stream`, which is
what makes cancellation expressible at all — a `List` output would have forced the service to
materialise a topic, which is the thing this milestone must never do.
