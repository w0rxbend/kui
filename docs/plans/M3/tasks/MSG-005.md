# MSG-005 — The backward window walker

- **ID:** MSG-005
- **Title:** The backward window walker
- **Milestone / Feature:** M3 / MS-001, MS-002
- **Owner role:** Principal Scala Engineer
- **Context / service:** `libs/kafka`
- **Size:** M
- **Dependencies / blocked by:** MSG-004

## Goal (user value)

"Show me the newest hundred records" on a topic with a million of them reads a hundred and a bit,
not a million. This is the exit criterion the milestone is judged on second, and it is the difference
between a tool that works on a real topic and one that only works on a demo.

## Scope

1. `BackwardWindows`: a pure iterator from a set of ranges and a `limit` to a sequence of *rounds*,
   each round being one `Map[TopicPartition, OffsetRange]` sized `ceil(limit / partitionCount)` per
   partition, walking down from `until` toward `from`.
2. `MessageBrowsePort.pollBackward`: rounds fed to `pollRanges` in order, stopping as soon as the
   caller's `limit` is satisfied or the ranges are exhausted.
3. The guarantee, stated as an assertion rather than an intention: **records fetched never exceed
   `limit + windowSize * partitionCount`**.

## Non-goals

- No sorting and no `limit` trimming across partitions (MSG-019 does that: the walker over-fetches by
  at most one window and the use case takes the newest `limit`).
- No forward walking. Forward browsing reads `[from, end)` in one range and stops at the limit, which
  MSG-004 already does.

## Public Scala signatures to implement

```scala
package kui.kafka.consume

/** Splits a backward browse into rounds. Pure, and therefore property-tested rather than measured.
  *
  * The window size is `ceil(limit / partitionCount)` per partition, not `limit`: reading `limit`
  * records from each of eight partitions to show `limit` of them is the over-fetch this type
  * exists to prevent.
  */
object BackwardWindows:
  final case class Round(ranges: Map[TopicPartition, OffsetRange])

  def windowSize(limit: Int, partitionCount: Int): Long        // ceil, minimum 1

  /** Lazily, newest first. `remaining` shrinks as the caller reports what it kept, so a round that
    * returned nothing (a compacted gap) does not end the walk. */
  def rounds(ranges: Map[TopicPartition, OffsetRange], limit: Int): LazyList[Round]
```

```scala
trait MessageBrowsePort[F[_]]:
  ...
  /** Newest-first browse that never loads a whole partition.
    *
    * Emits the same `PollEvent`s as `pollRanges`, one round at a time, and stops as soon as
    * `limit` records have been emitted or the ranges are exhausted. The over-fetch bound is
    * `limit + windowSize * partitionCount`, asserted by `MessageBackwardWindowSuite`.
    */
  def pollBackward(
    profile: ClusterProfile, topic: TopicName,
    ranges: Map[TopicPartition, OffsetRange], limit: Int,
    budget: PollBudget, isolation: IsolationLevel
  ): Stream[F, PollEvent]
```

```scala
// The milestone's second exit criterion, as an assertion over a counting lease
val fetched = countingLease.recordsFetched
assert(fetched <= limit + BackwardWindows.windowSize(limit, 8) * 8,
       s"over-fetched: $fetched")
```

Run against the 1 000 000-record fixture of MSG-042, with `limit = 100` and 8 partitions the bound is
`100 + 13 * 8 = 204`.

## Tests required

- `BackwardWindowsSuite` (pure)
  - `windowsTileTheRangeWithoutGapsOrOverlap` (property) — built directly on `OffsetRange.tail` /
    `dropTail`, whose tiling property MSG-001 already proves.
  - `windowsAreNewestFirst` (property).
  - `terminatesForEveryInput` (property over `(limit, partitionCount, ranges)` including
    `limit = 1`, a single-record range, and an empty range) — with a bound on the number of rounds,
    so a non-terminating walker fails rather than hanging the suite.
  - `windowSizeIsCeilingAndNeverZero` (property).
  - `aRoundThatYieldsNothingDoesNotEndTheWalk` — the compacted-gap case.
- `MessageBackwardWindowSuite` (Testcontainers, the 1 M fixture)
  - `readsAtMostLimitPlusOneWindow` — the acceptance snippet.
  - `returnsTheNewestRecords` — the offsets returned are the highest ones, and are contiguous per
    partition.
  - `walksToTheBeginningWhenTheTopicIsSmallerThanTheLimit` — a 3-record topic with `limit = 100`
    returns 3 records and `done{reason:"exhausted"}`, not an infinite walk.

## Observability

- `kui.message.backward.rounds` — histogram of rounds per browse. A distribution whose tail grows
  is how a regression to over-fetching shows up in production before a user reports it.
- Reuses MSG-004's poll metrics; adds no per-round log line.

## Degraded behaviour

- A round that returns nothing (every offset in the window was compacted away) continues to the next
  round rather than ending the browse; the budget's deadline is what bounds a topic that is entirely
  holes.
- A partition exhausted mid-walk is dropped from subsequent rounds, so the remaining partitions get
  larger effective windows for the same `limit` — which is what the user wants and what the
  reference does.

## Cancellation and shutdown

The walk is one `Stream` over one consumer `Resource`; cancelling between rounds or inside a poll
releases it. `MessageBackwardWindowSuite.cancellingMidWalkReleasesTheConsumer` asserts it with the
`Ref` finaliser flag of MSG-002.
