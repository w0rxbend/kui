# MSG-006 — `tail`: seek-to-end, endless poll, throttle hook, cancellation

- **ID:** MSG-006
- **Title:** `tail`: seek-to-end, endless poll, throttle hook, cancellation
- **Milestone / Feature:** M3 / MS-005
- **Owner role:** Principal Scala Engineer
- **Context / service:** `libs/kafka`
- **Size:** M
- **Dependencies / blocked by:** MSG-004

## Goal (user value)

Live mode: records appear as they are produced, the browser stays responsive under a topic doing
thousands a second, and the consumer stops the moment the user presses pause or leaves the page.

## Scope

1. `MessageBrowsePort.tail`: assign every partition (including empty ones — a partition with nothing
   in it is exactly where the next record may land), seek to `endOffsets`, poll forever.
2. Byte and deadline budget still apply; the record budget does not (there is no `limit` in live
   mode).
3. The throttle hook: `PollBudget.throttleBytesPerSecond` is honoured here as in `pollRanges`. The
   *event-rate* throttle of 20/s is a use-case concern (MSG-020), not a port concern, because it is
   about what the UI can render, not about what the broker can serve.

## Non-goals

- No `done` event and no cursor — a tail has no end (ADR-035).
- No rate limiting to the UI (MSG-020).
- No automatic switch to tailing when a backward browse catches up. Live is a mode the user chooses.

## Design references

`research/kafka/admin-capabilities.md` §4 "Tailing" (seek to `endOffsets` of **all** partitions, poll
forever, throttle to ~20 msg/s to the UI); `research/kafbat/api-analysis.md` Finding 5.1
(`TailingEmitter`: infinite `PHASE`/`CONSUMING`/`MESSAGE`, no `DONE`, client disconnect is the only
exit); ADR-035.

## Public Scala signatures to implement

```scala
trait MessageBrowsePort[F[_]]:
  ...
  /** Endless. The only exits are cancellation, the byte budget and the deadline; there is no
    * record limit and no `Exhausted`.
    *
    * Every partition is assigned, including empty ones, because the next record may be produced
    * into any of them — this is the one place where the empty-partition exclusion of
    * `resolveRanges` must not be applied.
    */
  def tail(
    profile: ClusterProfile, topic: TopicName,
    partitions: Option[NonEmptySet[PartitionId]],
    budget: PollBudget, isolation: IsolationLevel
  ): Stream[F, PollEvent]
```

## ADRs this task must obey

ADR-035 (no `done` for a tail; heartbeats keep the connection alive during quiet periods — the
`Idle` events this stream emits are what MSG-020 turns into them), ADR-016, ADR-041 A10.

## Tests required

- `TailingSuite` (Testcontainers)
  - `seesRecordsProducedAfterItStarted`.
  - `doesNotReplayHistory` — a topic with 100 existing records yields nothing until something new is
    produced. Live mode that starts by dumping the whole topic is the bug this pins.
  - `assignsEmptyPartitions` — produce only into a partition that was empty at start and assert the
    record arrives.
  - `emitsIdleWhileNothingIsProduced` — so that MSG-020 has something to build heartbeats on.
  - `neverEmitsExhausted` (property over a run of arbitrary length).
  - `stopsAtTheDeadline` with `done` suppressed — the stream simply ends; the use case decides what
    the client is told.
  - `cancellationClosesTheConsumerWithinOnePollInterval` — the milestone's criterion 3 at port level:
    cancel the fiber, assert the `Resource` finaliser ran and `kui.message.consumers.active` is zero
    within `pollTimeout + 100 ms`.

## Observability

- `kui.message.tail.active` — up-down counter of live tails, attributes `cluster`, `topic`. It is the
  number an operator looks at when a broker complains about connections.
- Reuses MSG-004's poll and byte counters.

## Degraded behaviour

- A partition that goes leaderless mid-tail: fs2-kafka's consumer retries internally; if the failure
  surfaces, it propagates as a mapped `KuiError` and MSG-029 emits `event: error` and ends the
  stream. Live mode that silently stops delivering while looking connected is the failure this
  milestone exists to avoid.
- The byte budget spent on a very loud topic: the stream ends with a reason and the UI shows "live
  mode stopped: byte budget reached", with a resume button. A tail is not exempt from PLAN §22.

## Cancellation and shutdown

The whole task is a cancellation story: `tail` is `Stream.repeatEval` inside the consumer `Resource`,
and every exit path is the `Resource` closing. The named test above is the one the milestone's exit
criterion cites at the port level.
