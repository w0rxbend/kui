# MSG-048 — Milestone documentation, operator pages, feature matrix, ADR amendments

- **ID:** MSG-048
- **Title:** Milestone documentation, operator pages, feature matrix, ADR amendments
- **Milestone / Feature:** M3 / all rows
- **Owner role:** Infrastructure Lead with the Chief Architect
- **Context / service:** `docs/`, `ARCHITECTURE.md`, `docs/adr/`, `STATUS.md`, `TECH_DEBT.md`
- **Size:** M
- **Dependencies / blocked by:** everything

## Goal (user value)

An operator can configure serdes, masking and filters from a document rather than from the source,
and the project's own record says what M3 actually shipped — including what it did not.

## Scope

1. **New operator pages**
   - `docs/operations/serdes.md`: the built-in catalogue generated from the `SerdeDescription`s, the
     resolution order, the configuration keys, the Schema Registry section with the Confluent
     Community Licence position and the statement that deployments can run without the module, the
     numeric-header table generated from `HeaderDecoding.NumericHeaders`, and a coverage column
     marking any serde that has no integration test.
   - `docs/operations/masking.md`: the rule model, the application order, worked examples, the
     statement that produce is never masked, and the warning that until M5 the only record of a
     produce, resend or purge is a log line.
   - `docs/operations/filters.md`: the CEL variables (from `CelEnvironment`'s scaladoc), the limits
     table, and the three worked examples.
2. **Updated pages**: `docs/operations/configuration.md` (the `kui.message.*` table),
   `docs/operations/services.md` (the message service's row), `docs/testing.md` (the fixture
   catalogue and the leak detector), `docs/domain/message.md` (final pass).
3. **Feature matrix**: the 27 M3 rows flipped to `DONE`, from the evidence the tasks left. No task
   flips its own row (DEVPLAN §6.5).
4. **ADR amendments**, each one a recorded consequence rather than a new decision:
   - ADR-035: the browse vocabulary lives in `libs/kernel` (DEVPLAN §10 D1); the message events'
     byte fixtures are normative alongside `libs/http`'s.
   - ADR-026: the **measured** cursor size per partition, replacing the estimate.
   - ADR-017: the measured CEL evaluation cost per record, and whether the 10 ms budget was ever hit.
   - ADR-029: what tracking cost in practice on the benchmark shapes.
   - ADR-014: the licence review outcome and the packaging decision it produced.
5. **`libs/kafka/PORT-INVARIANTS.md`**: §1's text has moved into `resolveRanges`' scaladoc (MSG-003);
   §2's owner is corrected from M3 to M4, with a sentence saying why (DEVPLAN §10 D5).
6. `STATUS.md`: the M3 acceptance section, with the CI run id, and — following the M1 precedent —
   **an explicit list of what was not proved**, because a criterion nobody checked is not a criterion
   that passed.
7. `TECH_DEBT.md`: every debt taken.

## Non-goals

- No new features, no code changes other than generated documentation.
- No rewriting of an ADR's decision. An amendment records what was learned; a changed decision is a
  new ADR.

## Degraded behaviour

The section of `STATUS.md` this task writes has one rule, taken verbatim from the M1 pass: **be
specific about what was not proved.** A milestone record that lists only successes is the document
that makes the next milestone's review start from a false position. If a criterion was demonstrated
only on a developer's machine, it says so.
