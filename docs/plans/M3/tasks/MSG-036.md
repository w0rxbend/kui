# MSG-036 — The list view: rows, expand-in-place detail, the fallback-serde marker, copy and export

- **ID:** MSG-036
- **Title:** The list view and message detail
- **Milestone / Feature:** M3 / MS-001, MS-010, MS-011, MS-014, MS-002
- **Owner role:** Frontend Architect
- **Context / service:** `frontend/ui-messages`
- **Size:** L
- **Dependencies / blocked by:** MSG-035

## Goal (user value)

The screen people came for: a table of records, one row each, that expands in place to show
pretty-printed JSON, its headers and its metadata — with the record's serde named, a marker when the
fallback was used, copy, save and export.

## Scope

1. The rows: offset, partition, timestamp (absolute or relative, in the user's timezone), key and
   value, with ellipsis and a full-text title.
2. **Expansion in place** (DEVPLAN §10 D3, from `research/design/REFERENCE.md`): tabs for Key, Value
   and Headers; the value pretty-printed when `kind = Json`; a metadata column with timestamp type,
   serde names and sizes.
3. The fallback marker: a warning icon with the reason when a `deserializeErrors[]` entry exists, so
   "this is not what the topic really contains" is visible rather than inferred from mojibake.
4. `Next` paging from the `done` cursor, and the `consumed` progress strip.
5. Row actions: copy to clipboard, save as a file, "produce like this" (opens MSG-038's drawer
   prefilled), and "track this header value" (opens MSG-040 prefilled).
6. Export the rendered rows to JSON or CSV, client-side, with the formula-injection guard the
   reference has.

## Non-goals

- No drawer for detail (D3: expansion, per the design).
- No table view (MSG-037).
- No server-side export.
- No infinite scroll: the reference's single `Next` is kept, because a browse is bounded and a
  cursor-based infinite scroll hides how much has been read.

## Design references

`research/design/REFERENCE.md` ("a message row expands in place to show pretty-printed JSON and its
headers, rather than opening a drawer or a dialog"; quantities as bars; filled status chips),
`research/kafbat/ui-analysis.md` "Messages table", "Message row" and "Expanded message" (the columns,
the actions, the fallback marker, the export payload and the CSV injection guard, the timestamp
formatting with milliseconds and the relative-time option), ADR-032 (stale data stays on screen).

## ADRs this task must obey

ADR-032 (stale rows stay, dimmed and timestamped, and the reason is rendered verbatim after the state
word), ADR-024 (the design system), ADR-023 (the browser never unmasks: what it receives is what it
shows, and there is no "show original" affordance — the pre-masking value does not exist on the
wire).

## Library coordinates

None new. Pretty-printing is circe's; the CodeMirror viewer of ADR-025 is **not** used here — a
read-only JSON view is a `<pre>` with syntax highlighting classes, and pulling an editor into a row
would cost more than the feature.

None.

## Degraded behaviour

- Stream failed after some rows: rows stay, dimmed, with the error and a retry. Never cleared.
- A record whose value is 5 MiB: the row shows the first 2 KiB with an "expand to load" affordance;
  the full value is already in memory but rendering it inline freezes the tab.
- Masked fields render as their masked value with a small marker in the detail's metadata column
  saying a masking policy applied — so a user does not report a data-corruption bug.

## Cancellation and shutdown

Row-level subscriptions are bound to the row's mount; a list re-render on a new page does not leak
them. `MessageListSuite.rerenderingDoesNotLeakSubscriptions` asserts the count returns to the row
count after two pages.
