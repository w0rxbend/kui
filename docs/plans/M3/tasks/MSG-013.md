# MSG-013 — `libs/serde-confluent`: serializers and the SD-004 JSON Schema for the produce form

- **ID:** MSG-013
- **Title:** Registry serializers and produce-form schema generation
- **Milestone / Feature:** M3 / SD-004, MP-004
- **Owner role:** Principal Scala Engineer
- **Context / service:** `libs/serde-confluent`
- **Size:** M
- **Dependencies / blocked by:** MSG-012

## Goal (user value)

Publishing to an Avro topic works from the browser: the produce form validates what the user typed
against the topic's schema **before** anything is sent, and says which field is wrong.

## Scope

1. Serializers for the three registry formats: user JSON text to registry-encoded bytes, with the
   subject resolved by the configured naming strategy (`TopicNameStrategy` by default).
2. `SchemaDescription` for a topic and target: the registry schema plus the **JSON Schema** the
   produce form validates against (SD-004), generated from Avro or Protobuf where the registry does
   not already hold JSON Schema.
3. Validation before send, in the serializer, so a malformed payload is a `SerializeFailure` naming
   the field, not a broker rejection or a corrupt record.

## Non-goals

- No client-side validation logic (the browser uses the JSON Schema this task produces; the form is
  MSG-038).
- No schema **registration**. KUI never writes to the registry in M3.
- No subject naming strategies beyond `TopicNameStrategy` and `RecordNameStrategy`; a third is a
  configuration key nobody in the references offers.

## Design references

ADR-014 (`tapir-apispec-docs` + `sttp.apispec:jsonschema-circe` for JSON Schema generation in the
produce dialog; `networknt json-schema-validator` for validating produced JSON-Schema messages),
`research/kafbat/ui-analysis.md` "Produce" (Ajv validation against the selected serde's schema, the
exact error strings, and that all errors are shown in one list).

## Public Scala signatures to implement

```scala
package kui.serde.confluent

/** Avro / Protobuf / JSON Schema projected to a JSON Schema the produce form can validate against.
  *
  * Total: an Avro union, a Protobuf `oneof` and a recursive record all have a projection, because a
  * form that cannot describe a schema must still let the user type into it. Where the projection
  * loses precision it says so in `x-kui-approximate`, and the serializer's own validation, which
  * uses the real schema, is what actually decides.
  */
object JsonSchemaProjection:
  def fromAvro(schema: String): Either[String, Json]
  def fromProtobuf(descriptor: String): Either[String, Json]
  def fromJsonSchema(schema: String): Json      // identity

object RegistrySerializers:
  enum SubjectStrategy { case TopicName, RecordName }
  def subjectFor(strategy: SubjectStrategy, topic: TopicName, target: Target,
                 recordName: Option[String]): String
```

## Observability

- `kui.serde.serialize.failures` — counter, attributes `serde`, `topic`, `reason`
  (`validation` | `registry` | `encode`), so an operator can tell a user's typo from a broken
  registry.

## Degraded behaviour

- Registry unreachable while producing: `KUI-SERDE-UNAVAILABLE` **before** the record is sent. A
  produce that cannot validate must not be sent unvalidated — a corrupt record in a topic outlives
  the outage that caused it.
- A schema the projection cannot express: the form falls back to a free JSON editor with a note, and
  the serializer still validates against the real schema. The user is never blocked by our inability
  to draw their schema.
