# MSG-039 — The smart-filter editor and saved filters

- **ID:** MSG-039
- **Title:** The smart-filter editor and saved filters
- **Milestone / Feature:** M3 / MS-007, KU-016
- **Owner role:** Frontend Architect
- **Context / service:** `frontend/ui-messages`
- **Size:** M
- **Dependencies / blocked by:** MSG-035

## Goal (user value)

Write a CEL predicate, test it against a sample record before running it over a topic, save it under
a name, and reuse it — with the compile error pointing at the character that is wrong.

## Scope

1. The filter editor drawer: a source field, the variable reference the reference product shows in a
   modal, a "Test" button calling `POST /clusters/{c}/message-filters/test`, and "Apply".
2. Registration: `POST /clusters/{c}/message-filters` returns the id; the browse request then carries
   **both** `filterId` and `filterSource` (ADR-017), so a replica that has not compiled it can.
3. Saved filters in `localStorage`, per cluster: name, source, and where it is active, with edit,
   delete and "clear all" — and a warning listing the `cluster:topic` pairs where a filter being
   deleted is currently active.
4. The active-filter chip in the filter bar, with the source on hover and one click to edit.

## Non-goals

- No server-side filter storage (ADR-017: filters remain client-stored, as in the reference).
- No CEL syntax highlighting beyond bracket matching unless the kernel editor already exists.
- No sharing of saved filters between users — that would be a stored object with an owner, which is
  M6 territory.

## Design references

ADR-017 (the id scheme, `filterId` **and** `filterSource`, the test endpoint's cluster scope),
`research/kafbat/ui-analysis.md` "Filters bar" — `InfoModal`'s variable list and its three examples,
`SavedFilters`' behaviour including the deletion warning listing active `cluster:topic` pairs, and
the localStorage key shapes; KU-016.

## Public Scala signatures to implement

```scala
package kui.ui.messages.filters

final case class SavedFilter(id: String, name: String, source: String, cluster: ClusterId)

object SavedFilters:
  /** `kui.message-filters[<clusterId>]`. Cluster-scoped because a filter that references a field of
    * one cluster's payloads is meaningless on another, and because deleting "all filters" should
    * not reach across clusters. */
  def load(cluster: ClusterId): List[SavedFilter]
  def save(f: SavedFilter): Unit
  def delete(id: String): Unit
  /** Where this filter is currently applied, so deletion can warn rather than surprise. */
  def activeIn(id: String): List[(ClusterId, TopicName)]

object FilterHelp:
  /** The variable list, taken from the contract's own documentation of the CEL environment rather
    * than retyped here — a help text that lists a variable the server does not expose is the most
    * annoying kind of wrong. MSG-015's `theEnvironmentExposesExactlyTheDocumentedVariables`
    * asserts the other half. */
  val variables: List[(String, String)]
```

the *source* is not, because it may be long and it is available from the id), ADR-021 (the test
action declares `Topic.MessagesRead`).

None.

## Degraded behaviour

- Filter capability unsupported (CEL failed to initialise — R-5): the editor is not offered at all
  and the bar shows only the string filter. The screen does not advertise a feature the server
  cannot run.
- The test endpoint failing: the error is shown in the editor and "Apply" stays enabled, because a
  filter that could not be tested may still be correct and the browse will report its own errors.
- An applied filter whose id the server no longer knows: the request carries the source, so it
  recompiles. This is the failure the reference product has (`4002` on an evicted cursor id) and the
  one ADR-017 designed away; `applyRegistersAndThenBrowsesWithBothIdAndSource` is what keeps it away.

## Cancellation and shutdown

The editor's in-flight test request is aborted on close.
