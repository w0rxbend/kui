# MSG-002 — `libs/kafka`: consumer and producer factories with a per-request `Resource`

- **ID:** MSG-002
- **Title:** `libs/kafka`: consumer and producer factories with a per-request `Resource`
- **Milestone / Feature:** M3 / MS-001, MP-001, OT-001
- **Owner role:** Principal Scala Engineer
- **Context / service:** `libs/kafka`
- **Size:** M
- **Dependencies / blocked by:** MSG-001

## Goal (user value)

Every browse and every produce gets its own Kafka client, configured the way the reference products
learned to configure them, and every one of those clients is closed — including when the user closes
the tab in the middle of a stream. This is the task that makes the milestone's cancellation criterion
possible at all; the tests that assert it are MSG-044's.

## Scope

1. `ConsumerFactory[F]`: an fs2-kafka `KafkaConsumer` as a `Resource`, built from a
   `ClusterProfile`'s connection settings plus the per-request knobs (`isolation.level`,
   `max.poll.records`).
2. `ProducerFactory[F]`: the same for `KafkaProducer[Array[Byte], Array[Byte]]`.
3. The settings both share: byte-array deserializers, `enable.auto.commit=false`, **no `group.id`**,
   a `client.id` that names KUI, the cluster and the operation, and the security properties
   `libs/kafka-auth` already renders (M1).
4. `kui.message.consumers.active` and `kui.message.producers.active`: up-down counters incremented on
   acquire and decremented on release, which are one half of DEVPLAN §10 D6's cancellation assertion.
5. A `ConsumerLease[F]` wrapper exposing only what the port needs — `assign`, `seek`, `position`,
   `pause`, `resume`, `poll`, `partitionsFor`, `beginningOffsets`, `endOffsets`, `offsetsForTimes` —
   so that no caller can `subscribe` or commit by accident.

## Non-goals

- No seek logic, no polling loop, no windowing (MSG-003 … MSG-006).
- No consumer **pooling** or reuse across requests. Every browse gets its own consumer and closes it,
  which is what all three reference products do (`research/kafka/admin-capabilities.md` §4) and what
  makes cancellation a `Resource` release rather than a bookkeeping problem. If profiling later says
  the connection setup dominates, that is a `TECH_DEBT.md` row with a measurement attached, not a
  guess made now.
- No `group.id`, no `subscribe`, no offset commits, ever. See "Degraded behaviour".
- No admin calls. `ClusterAdmin` is M1's and is not touched.

## Design references

`research/kafka/admin-capabilities.md` §4 (manual assignment, `enable.auto.commit=false`,
`BytesDeserializer`, one client per request, closed after use; `wakeup`/`InterruptException` on
cancellation and that both must close the consumer), ADR-006 Amendment 1 (**fs2-kafka for consumers
and producers**, raw `Admin` for admin work — this task is on the fs2-kafka side of that line),
ADR-022 (the security properties, rendered by `libs/kafka-auth`), ADR-016 (metric naming),
`ARCHITECTURE.md` §4.3.

## Public Scala signatures to implement

```scala
package kui.kafka.consume

import cats.effect.{Resource, Temporal}
import fs2.kafka.*
import kui.kernel.browse.{IsolationLevel, PartitionId, Offset}
import kui.kernel.cluster.ClientProperties

/** What a single browse needs beyond the cluster's connection settings. */
final case class ConsumeSettings(
  isolation: IsolationLevel,
  maxPollRecords: Int,
  pollTimeout: FiniteDuration,
  clientIdSuffix: String
)

trait ConsumerFactory[F[_]]:
  /** One consumer, for one request, released when the caller's scope ends — which includes the
    * caller being cancelled. There is deliberately no `use`-free variant. */
  def consumer(props: ClientProperties, settings: ConsumeSettings): Resource[F, ConsumerLease[F]]

object ConsumerFactory:
  def make[F[_]: Async: Meter]: F[ConsumerFactory[F]]

  /** The properties this factory always sets, exposed for the test that asserts them and for
    * `docs/operations/serdes.md`. `group.id` is absent from this map and there is no code path
    * that adds it. */
  val Fixed: Map[String, String]
```

```scala
package kui.kafka.consume

/** The only consumer surface the rest of KUI may touch.
  *
  * It is a wrapper and not a type alias because the fs2-kafka `KafkaConsumer` also offers
  * `subscribe`, `commitSync` and the group protocol, none of which is legal here: a browse that
  * joined a group would move a real application's committed offsets, which is the single most
  * damaging thing a read-only tool can do to a production cluster.
  */
trait ConsumerLease[F[_]]:
  def partitionsFor(topic: TopicName): F[List[PartitionInfo]]
  def beginningOffsets(tps: Set[TopicPartition]): F[Map[TopicPartition, Offset]]
  def endOffsets(tps: Set[TopicPartition]): F[Map[TopicPartition, Offset]]
  /** `None` for a partition whose time index has nothing at or after `millis`. Never `-1`. */
  def offsetsForTimes(targets: Map[TopicPartition, Long]): F[Map[TopicPartition, Option[Offset]]]
  def assign(tps: Set[TopicPartition]): F[Unit]
  def seek(tp: TopicPartition, offset: Offset): F[Unit]
  def position(tp: TopicPartition): F[Offset]
  def pause(tps: Set[TopicPartition]): F[Unit]
  def resume(tps: Set[TopicPartition]): F[Unit]
  def poll: F[Chunk[RawRecord]]
```

## The fixed client properties, stated exactly

`ConsumerFactory.Fixed` is the specification; `ConsumerFactorySuite.fixedProperties` is the test.

| Key | Value | Why |
| --- | --- | --- |
| `key.deserializer`, `value.deserializer` | `ByteArrayDeserializer` | decoding is `libs/serde`'s job and happens after the poll |
| `enable.auto.commit` | `false` | a browse must never move anyone's offsets |
| `group.id` | **absent** | assign-only; see `ConsumerLease` |
| `auto.offset.reset` | `none` | every position is explicit; a silent reset would show the wrong records |
| `client.id` | `kui-<clusterId>-<suffix>-<random 6>` | so a broker operator can see which tool is connected and which screen opened it |
| `isolation.level` | from `ConsumeSettings` | `read_uncommitted` by default, matching the references (ADR/DC-D8) |
| `max.poll.records` | from `ConsumeSettings` (`= limit`) | Kafbat's behaviour: a page never over-fetches by a whole poll |
| `default.api.timeout.ms` / `request.timeout.ms` | from `AdminTuning` | one place owns timeouts (M1) |

The producer's fixed set: byte-array serializers, `acks=all`, `enable.idempotence=false` (a UI
produce is a single record, and idempotence would require a producer id per request),
`max.block.ms` from the tuning, `client.id` as above.

## ADRs this task must obey

ADR-006 Amendment 1, ADR-022 (never assemble a JAAS string here — `libs/kafka-auth` renders it and
this task consumes `ClientProperties`), ADR-016 (metric names), ADR-041 A10 (this is one of the
modules allowed a Kafka client; nothing it exposes may leak a Kafka type — `ConsumerLease` is the
boundary, and `RawRecord` is KUI's own type, not `ConsumerRecord`).

Expected: green, including `ClientLifecycleSuite`, which is the one that matters.

```scala
// The lifecycle assertion the milestone's criterion 3 rests on
for
  released <- Ref[IO].of(false)
  factory  <- ConsumerFactory.make[IO]
  fiber    <- factory.consumer(props, settings).use(_ => IO.never).guarantee(released.set(true)).start
  _        <- IO.sleep(50.millis)
  _        <- fiber.cancel
  r        <- released.get
  active   <- meter.gaugeValue("kui.message.consumers.active")
yield
  assert(r)                 // the Resource finalised
  assertEquals(active, 0L)  // and the counter agrees
```

```scala
// group.id is not merely unset by default; there is no path that sets it
assert(!ConsumerFactory.Fixed.contains("group.id"))
```

## Tests required

- `ConsumerFactorySuite`
  - `fixedProperties` — one assertion per row of the table above.
  - `noGroupIdOnAnyPath` — the rendered property map for a randomly generated `ClusterProfile` and
    `ConsumeSettings` never contains `group.id` (property).
  - `clientIdNamesTheClusterAndTheOperation` (property): the id contains the cluster id and the
    suffix, and is unique across two calls.
  - `securityPropertiesComeFromKafkaAuth` — the rendered map contains exactly what
    `libs/kafka-auth` produced for the profile, with the fixed keys added and nothing removed.
  - `isolationLevelIsPassedThrough` — both values.
- `ClientLifecycleSuite` (`munit-cats-effect`)
  - `cancellationReleasesTheConsumer` — the snippet above.
  - `anExceptionInsideUseStillReleases`.
  - `theGaugeReturnsToZeroAfterManyConcurrentLeases` — 50 parallel acquire/release cycles, gauge back
    to zero. A gauge that is only ever incremented and a gauge that is never incremented both read
    zero at rest, which is why DEVPLAN §10 D6 pairs it with the finaliser flag.
  - `producerReleasesOnCancellation` — the same three cases for `ProducerFactory`.

## Observability

- `kui.message.consumers.active` and `kui.message.producers.active` — up-down counters, attributes
  `cluster`, `operation`.
- `kui.kafka.client.created` — counter, same attributes, so that a leak shows as created rising while
  active stays flat.
- One log line per client at DEBUG on acquire and release, carrying the `client.id`. Not INFO: a busy
  UI creates one consumer per page of records and would drown an operator's log.

## Degraded behaviour

- A cluster KUI cannot connect to fails at `Resource` acquisition and the error is mapped by M1's
  `KafkaErrorMapper` — no new mapping is written here.
- A connection that dies mid-stream surfaces from `poll` as a mapped `KuiError`, which MSG-029 turns
  into an `event: error`. It never becomes a dropped connection, which is the reference product's
  behaviour this milestone exists to improve on.
- **The rule that has no error path:** nothing may ever set `group.id`. There is no configuration
  key for it, no parameter carrying it, and `ConsumerFactorySuite.noGroupIdOnAnyPath` is what
  enforces it. If a future task needs group-aware consumption, it adds a different factory rather
  than a flag on this one.

## Cancellation and shutdown

The whole point of the task. `Resource.make(acquire)(release)` with the release closing the
fs2-kafka consumer; fs2-kafka handles the `wakeup`/`InterruptException` dance internally, which is
the reason ADR-006 chose it for the consumer side. `ClientLifecycleSuite` asserts it under
cancellation, under an exception and under concurrency.
