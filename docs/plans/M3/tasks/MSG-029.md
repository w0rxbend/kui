# MSG-029 — Message `api`: server logic, the SSE wiring, the error envelope

- **ID:** MSG-029
- **Title:** Message `api`: server logic and the SSE wiring
- **Milestone / Feature:** M3 / all message rows, KU-014
- **Owner role:** Chief Architect
- **Context / service:** `services/message/api`
- **Size:** L
- **Dependencies / blocked by:** MSG-028, MSG-019, MSG-020, MSG-021, MSG-022, MSG-023, MSG-024

## Goal (user value)

The endpoints answer. Domain events become the named SSE events an `EventSource` can route,
failures become codes an operator can search for, and the milestone's central promise — a mid-stream
failure arrives as an `error` event rather than as a connection that stops — is implemented here.

## Scope

1. Server logic for all eleven endpoints of MSG-028, mapping DTOs to domain requests with Chimney
   (ADR-033) and domain results back.
2. `BrowseEvent` to `libs/http`'s `Sse`: `Phase → phase`, `Message → message`, `Consumed → consumed`,
   `Done → done` (with the cursor in `data` **and** in `id:`), `Failed → error`.
3. The split between a pre-stream failure (an HTTP error envelope with a status) and an in-stream
   failure (an `error` event), and the rule that validation and permission failures are always the
   former.
4. Heartbeats every 15 s idle, from `Sse` (M0), configured here.
5. `MaskingBoundarySuite`: the enumerated assertion that no endpoint leaks an unmasked payload.

## Non-goals

- No use-case logic. If a rule needs deciding, it belongs in `application` (ADR-041 A3 forbids the
  reverse anyway).
- No new SSE primitives. `kui.http.sse.Sse` exists and is used as it is; anything missing is a
  `TECH_DEBT.md` row, not a rewrite (DEVPLAN §3).
- No gateway concerns (MSG-031).

## Design references

ADR-035 and `ARCHITECTURE.md` §7 (the envelope, and that `SseSuite.goldenWireFormat` in `libs/http`
is the normative example, field order included), ADR-034 (`ErrorEnvelope.statusOf`), ADR-033
(Chimney, in this layer), `research/kafbat/api-analysis.md` Finding 5.1 (what Kafbat does instead,
and why: `sink.error` becomes an abrupt close after the headers are sent).

## Public Scala signatures to implement

```scala
package kui.message.api

/** Domain events to wire events.
  *
  * The one rule that is not obvious and is asserted twice: `Failed` renders as `event: error` and
  * **terminates the stream normally** — the HTTP response completes rather than aborting. A client
  * that sees a completed stream with an `error` event knows what happened; a client that sees a
  * dropped connection has to guess, which is exactly what
  * `research/kafbat/api-analysis.md` Finding 5.1 records as the reference behaviour.
  */
object StreamRendering:
  def render[F[_]](events: Stream[F, BrowseEvent], cursorCodec: CursorCodec[F]): Stream[F, SseEvent]

  /** The name of every event, in one place, so that the browser's `addEventListener` names and the
    * server's come from the same file through the contract module. */
  object EventNames:
    val Phase = "phase"; val Message = "message"; val Consumed = "consumed"
    val Done = "done";   val Error = "error";     val Heartbeat = "heartbeat"
```

- `kui.stream.active` and `kui.stream.events` come from `libs/http`'s `Sse` (M0) — this task adds a

  per event.

## Degraded behaviour

The split, stated once and enforced by tests:

| When | What the client gets |
| --- | --- |
| Bad parameter, unknown topic, missing permission, unusable cursor | an HTTP status and `ErrorEnvelope`; no stream is opened |
| Kafka failure, serde registry failure, budget exhaustion after the stream opened | `event: error` (or `done` for a budget), then a normal completion |
| Client disconnects | nothing; the stream is cancelled and no terminal event is written |

## Cancellation and shutdown

- The Netty SSE body's cancellation propagates into the fs2 stream (measured in M0:
  `docs/spikes/M0-netty-sse.md`, cancelled within 8 ms of the client leaving), which cancels the use
  case, which releases the consumer.
- `StreamCancellationSuite` (MSG-044) is the named test of exit criterion 3; this task provides the
  route it runs against and asserts here that cancelling the response body cancels the use-case
  fiber.
