# MSG-041 — The `kui.message.*` configuration slice and every environment that carries it

- **ID:** MSG-041
- **Title:** The `kui.message.*` configuration slice and the environments
- **Milestone / Feature:** M3 / OT-001, MS-013, KU-015
- **Owner role:** Infrastructure Lead
- **Context / service:** `libs/config`, `apps/allinone`, `deployment/*`
- **Size:** M
- **Dependencies / blocked by:** MSG-001

## Goal (user value)

Every limit in this milestone is a documented setting with a default that works, and an operator who
changes one sees the change take effect — which is the specific defect M1 shipped and had to find by
running the product.

## Scope

1. The `kui.message.*` Ciris slice with the defaults of DEVPLAN §10 D7.
2. `kui.streaming.cursorKey` (a `Secret`), generated when absent with a WARN naming the consequence
   for multi-replica deployments (MSG-018).
3. Wiring the slice into `apps/allinone`, `deployment/docker`, `deployment/compose` and the
   quickstart, plus a Schema Registry service in the Compose topology.
4. The configuration seam test (DEVPLAN §6.6): a non-default value is asserted to change observed
   behaviour, not merely to parse.
5. The three example configuration files gain a message section.

## Non-goals

- No serde or masking configuration (MSG-011 and MSG-016 own those sub-slices).
- No new secrets mechanism.

## Design references

ADR-013 (Ciris, accumulated errors, no silent defaults), DEVPLAN §10 D7 (the numbers and where each
comes from), ADR-026 (`cursorKey`), `docs/DELIVERY.md` (the quickstart must keep working with one
command).

## Public Scala signatures to implement

```scala
package kui.config.message

final case class MessageConfig(
  defaultPageSize: Int,             // 100
  maxPageSize: Int,                 // 500
  pollTimeout: FiniteDuration,      // 1 s
  maxEmptyPolls: Int,               // 5
  maxBytesPerRequest: Long,         // 50 MiB
  deadline: FiniteDuration,         // 60 s
  tailEventsPerSecond: Int,         // 20
  tailMaxRows: Int,                 // 500 (the browser's bound, published so both agree)
  throttleBytesPerSecond: Option[Long],   // none
  cursorTtl: FiniteDuration,        // 1 h
  maxCursorBytes: Int,              // 8 KiB
  produceMaxCount: Int,             // 1000
  filter: FilterConfig,
  track: TrackConfig
)
final case class FilterConfig(maxSourceBytes: Int, maxAstNodes: Int,
                              evaluationDeadline: FiniteDuration, cacheSize: Int, cacheTtl: FiniteDuration)
final case class TrackConfig(defaultLimit: Int, maxLimit: Int,
                             maxWindow: FiniteDuration, deadline: FiniteDuration)

object MessageConfig:
  val Default: MessageConfig
  /** Cross-field validation, accumulated: `defaultPageSize <= maxPageSize`, deadlines positive,
    * `maxCursorBytes` large enough for a single-partition cursor, `tailEventsPerSecond >= 1`. */
  def config: ConfigValue[Effect, MessageConfig]
```

## Acceptance criteria

```
$ ./mill libs.config.test
$ ./mill apps.allinone.test
$ ./scripts/quickstart.sh          # still one command, still prints one URL
```

```
$ KUI_MESSAGE_MAX_PAGE_SIZE=7 ./mill apps.allinone.run &

7
```

That last pair of commands is the whole point of the task: the number a user typed changed what the
API did.

## Tests required

- `MessageConfigSuite`
  - `defaultsMatchTheDevplanTable` — one assertion per field, so a default that drifts from the
    documentation fails here.
  - `crossFieldErrorsAccumulate` — three bad values produce one message naming all three (ADR-013).
  - `anUnknownKeyUnderKuiMessageIsAnError` — a typo in a limit must not be silently ignored.
  - `cursorKeyIsGeneratedWhenAbsentAndTheWarningNamesIt`.
  - `theSecretNeverAppearsInAToStringOrTheStartupLog` (property).
- `MessageConfigSeamSuite` (`apps.allinone.test`, Testcontainers) — **the M1 defect, pinned**
  - `aNonDefaultMaxPageSizeChangesTheApiResponse` — the acceptance snippet, run in-process.
  - `aNonDefaultTailRateChangesTheObservedEventRate` (`TestControl`).
  - `everyFieldOfMessageConfigIsReachableFromTheCompositionRoot` — by reflection over the case class,
    asserting each field is read somewhere in the wiring. Crude, and it is exactly the check that
    would have caught `ClusterServiceConfig.Default` being handed to a service whose configuration
    had just been parsed.

## Observability

The startup log line of MSG-030 prints the effective limits. This task's contribution is that the
line is generated from the case class, so a field added without being logged is a field nobody can
verify in production.

## Degraded behaviour

- Any invalid value: the process refuses to start, with every error in one message. There is no
  "fall back to the default" path — a limit that silently reverted is how an operator concludes the
  product ignores its configuration.
- A missing `cursorKey` with a single replica: generated, warned, works.
- A missing Schema Registry in Compose: the stack still comes up and browsing works on non-SR serdes,
  which is E2E criterion 8 and is also what a developer's laptop should do.

## Cancellation and shutdown

Not applicable to configuration; the Compose changes must leave `docker compose down` removing every
container, volume and network, which the quickstart teardown test already asserts.
