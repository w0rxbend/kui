# MSG-018 — The signed cursor codec

- **ID:** MSG-018
- **Title:** The signed cursor codec
- **Milestone / Feature:** M3 / MS-002, KU-015
- **Owner role:** Domain Architect (message)
- **Context / service:** `services/message/application`
- **Size:** M
- **Dependencies / blocked by:** MSG-017

## Goal (user value)

"Next page" works — behind a load balancer, after a restart, on any replica, an hour later — because
the cursor carries its own state instead of naming a row in a cache that a different process owns.

## Scope

1. `CursorCodec`: encode and decode ADR-026's payload as
   `base64url(payload) "." base64url(HMAC-SHA256(payload, cursorKey))`.
2. The payload of `ARCHITECTURE.md` §8, versioned (`v`), bound to cluster and topic, carrying the
   per-partition next offset, direction, serdes, limit, isolation, filter id and expiry.
3. The three rejections, each with its own code: expired (`KUI-CURSOR-EXPIRED`), signature or shape
   invalid (`KUI-CURSOR-INVALID`), too large to mint (`KUI-CURSOR-TOO-LARGE`).
4. `cursorKey` from `kui.streaming.cursorKey` (a `Secret`), generated at startup when absent.

## Non-goals

- No encryption. Offsets are not secret and the cursor is bound to a cluster and topic the caller
  already named. ADR-026 says "must be encrypted if offsets are sensitive"; they are not, and adding
  a cipher would make the key rotation story worse for no gain. Recorded here so the decision is
  visible rather than assumed.
- No server-side cursor store, of any kind, ever (ADR-026 rejects it explicitly).
- No filter **source** in the cursor: the browse request carries it (ADR-017), because a cursor that
  embedded an 8 KiB program would be a URL nobody can send.

## Design references

ADR-026 (the format, the fields, the expiry, the codes), `ARCHITECTURE.md` §8 (the payload, field by
field), `research/kafbat/api-analysis.md` Finding 5.2 "Cursor paging" (the process-local Guava cache
this replaces, and its failure mode: an id that means nothing on another replica).

## Public Scala signatures to implement

```scala
package kui.message.application.cursor

/** ADR-026's payload. Field names are one or two characters because this value travels in a query
  * string and grows with the partition count. */
final case class BrowseCursor(
  v: Int,                                   // 1
  cluster: ClusterId, topic: TopicName,
  direction: Direction,
  perPartitionNext: Map[PartitionId, Offset],
  filterId: Option[FilterId],
  keySerde: Option[SerdeName], valueSerde: Option[SerdeName],
  limit: Int, isolation: IsolationLevel,
  expiresAt: Instant
)

object BrowseCursor:
  /** Forward cursors carry `lastOffset + 1`; backward cursors carry the next `until`. The two are
    * different numbers for the same boundary, and confusing them duplicates or skips exactly one
    * record per page — which is why this is a constructor and not a caller's arithmetic. */
  def afterForward(request: BrowseRequest, lastSeen: Map[PartitionId, Offset], now: Instant,
                   ttl: FiniteDuration): BrowseCursor
  def beforeBackward(request: BrowseRequest, firstSeen: Map[PartitionId, Offset], now: Instant,
                     ttl: FiniteDuration): BrowseCursor
```

```scala
package kui.message.application.cursor

trait CursorCodec[F[_]]:
  /** `Left(KUI-CURSOR-TOO-LARGE)` above `maxCursorBytes` (default 8 KiB, about 400 partitions),
    * with a hint to browse a partition subset — ADR-026's documented behaviour, not a truncation. */
  def encode(cursor: BrowseCursor): F[Either[KuiError, String]]

  /** Verifies the signature **before** parsing the payload, checks the version, then the expiry,
    * then the cluster and topic binding against the request. A cursor for another topic is
    * `KUI-CURSOR-INVALID`, not a browse of that other topic. */
  def decode(raw: String, expected: (ClusterId, TopicName), now: Instant)
    : F[Either[KuiError, BrowseCursor]]

object CursorCodec:
  def hmacSha256[F[_]: Sync](key: Secret[Array[Byte]], maxBytes: Int): CursorCodec[F]
```

## ADRs this task must obey

ADR-026 (every rule), ADR-034 (the three codes), ADR-044 (the `Secret` type and the rule that a key
never appears in a `toString` or a log), ADR-041 A3 — this is `application`, so no Tapir, no circe
codecs for the wire; the payload is encoded with a hand-written, explicitly versioned serialisation
in this file. That is deliberate: a cursor is a compatibility surface, and a derived codec would let
a field rename silently invalidate every outstanding cursor.

## Library coordinates

None new: `javax.crypto.Mac` from the JDK, and `java.util.Base64`'s URL encoder.

## Tests required

- `CursorCodecSuite`
  - `roundTripsForArbitraryPayloads` (property, including 0, 1 and 400 partitions).
  - `decodesOnASecondCodecInstanceWithTheSameKey` — the replica property, which is the whole reason
    this type exists.
  - `aDifferentKeyRejects`.
  - `tamperedPayloadRejects` (property over single-character mutations of the encoded string).
  - `signatureIsVerifiedBeforeParsing` — asserted by feeding a payload that would throw if parsed:
    a codec that parses first is a codec that can be attacked with a malformed payload.
  - `expiryIsEnforcedAndIsItsOwnCode`.
  - `clusterAndTopicBindingIsEnforced`.
  - `unknownVersionIsInvalidNotIgnored`.
  - `oversizeIsRejectedAtEncodeNotTruncated`.
  - `forwardAndBackwardBoundariesDifferByExactlyOne` — the off-by-one that duplicates a record on
    every page boundary, pinned as its own case.
  - `keyNeverAppearsInAToStringOrAnErrorMessage` (property).

## Observability

- `kui.message.cursor.rejected` — counter, attribute `reason` (`expired` | `invalid` | `too-large`).
  A spike in `invalid` is either a rotated key or something worth looking at; a spike in `expired` is
  a UI that is holding cursors too long.
- Nothing logs a cursor. It contains no secret, but it is long, per-request and useless in a log.

## Degraded behaviour

- An expired cursor returns `KUI-CURSOR-EXPIRED`, and MSG-036's UI re-issues the browse from the
  filter bar's current state rather than showing an error — the user sees a refreshed page, which is
  what they wanted from "next".
- A key rotation invalidates every outstanding cursor. That is one refresh for the user, and it is
  documented in `docs/operations/configuration.md` beside the key.
- No key configured in a multi-replica deployment: a generated key differs per replica, so cursors
  break behind a load balancer. **The service logs a WARN at startup naming the key** when it
  generates one and more than one replica is possible; a silent generation is how this becomes an
  intermittent bug report.

## Cancellation and shutdown

Nothing here has a lifetime. The `Mac` instance is created per call — it is not thread-safe, and a
shared one guarded by a lock would be a contention point on the hottest path in the service.
