# MSG-022 — `ProduceUseCase` (with `count`) and `ResendUseCase`

- **ID:** MSG-022
- **Title:** `ProduceUseCase` and `ResendUseCase`
- **Milestone / Feature:** M3 / MP-001, MP-002, MP-003, MP-004
- **Owner role:** Domain Architect (message)
- **Context / service:** `services/message/application`
- **Size:** L
- **Dependencies / blocked by:** MSG-017, MSG-011

## Goal (user value)

Publish a record — with the right serde, validated before it is sent — and copy a range of records
from one topic into another, byte for byte, optionally without their headers. The second is the
Kouncil feature neither other product has.

## Scope

1. `ProduceUseCase.produce(request)`: resolve serdes, serialize key and value, validate, send, return
   the assigned partition, offset and timestamp.
2. `count` (MP-002): the same record produced `n` times through **one** producer. Placeholder
   expansion (`{{count}}`, `{{timestamp}}`, `{{uuid}}`) is a browser feature (ADR-029); the server
   takes `count` and produces what it was given, `n` times.
3. `ResendUseCase.resend(request)`: read `[fromOffset, toOffset)` of **one** source partition and
   produce each record into the destination topic, **as bytes**, with no deserialization at any
   point, optionally stripping headers.
4. Read-only enforcement: both are alter actions, refused with `KUI-READ-ONLY` when the cluster
   profile says so.
5. Range validation against the source partition's real bounds before anything is read.

## Non-goals

- No masking on produce or resend (ADR-023 — masking a value on the way in corrupts the topic; the
  resend path never decodes at all, which makes it structurally impossible).
- No audit record (M5).
- No cross-cluster resend. Source and destination are the same cluster in M3; a second profile is a
  second client and a second failure mode, and no reference product offers it.
- No transactional resend and no rollback: a partial copy is reported, not undone (MSG-007).

## Public Scala signatures to implement

```scala
package kui.message.application.produce

final case class ProduceRequest(
  cluster: ClusterId, topic: TopicName, partition: Option[PartitionId],
  key: Option[String], value: Option[String], headers: List[(String, String)],
  keySerde: Option[SerdeName], valueSerde: Option[SerdeName],
  keySerdeProperties: Map[String, String], valueSerdeProperties: Map[String, String],
  count: Int      // 1..kui.message.produce.maxCount (default 1000)
)

trait ProduceUseCase[F[_]]:
  /** One result per produced record, in order. A batch that fails halfway reports what landed. */
  def produce(request: ProduceRequest): F[Either[KuiError, List[ProducedAt]]]
```

```scala
package kui.message.application.produce

final case class ResendRequest(
  cluster: ClusterId,
  source: SourceRange, destination: Destination, keepHeaders: Boolean
)
final case class SourceRange(topic: TopicName, partition: PartitionId,
                             fromOffset: Offset, toOffset: Offset)   // half-open
final case class Destination(topic: TopicName, partition: Option[PartitionId])

final case class ResendResult(read: Long, produced: Long, failures: List[ResendFailure])
final case class ResendFailure(sourceOffset: Offset, error: KuiError)

trait ResendUseCase[F[_]]:
  /** Copies bytes. The records are never deserialized, so a topic KUI cannot decode can still be
    * copied — which is the case an operator most often needs a resend for.
    *
    * Bounded by the same `PollBudget` as a browse: a resend of ten million records is refused by the
    * budget rather than attempted.
    */
  def resend(request: ResendRequest): F[Either[KuiError, ResendResult]]
```

## Tests required

- `ProduceUseCaseSuite` (fake ports)
  - `resolvesSerdesTheSameWayBrowsingDoes` — the produce form's serde list and the browse serde list
    come from one resolution (MSG-011); two resolutions would let a user produce with a serde they
    cannot read back.
  - `validationFailureNamesTheField` and does not send.
  - `countProducesExactlyNRecordsThroughOneProducer`.
  - `countIsBounded` — above `maxCount` is a validation error naming the limit.
  - `readOnlyClusterIsRefusedBeforeAnythingIsSerialized`.
  - `aTombstoneIsProducibleAndIsNotAnEmptyString` — `value = None` produces a null value; this is the
    case a form that maps "empty" to `""` gets wrong and that breaks compaction.
  - `neverMasks` — a value matching a masking rule is produced verbatim, asserted by reading it back.
- `ResendUseCaseSuite`
  - `copiesBytesExactly` (property over generated payloads including invalid UTF-8) — exit
    criterion 6.
  - `stripsHeadersWhenAsked` and keeps them otherwise.
  - `rangeOutsideThePartitionBoundsIsAValidationError` naming the bounds.
  - `reversedRangeIsAValidationError`.
  - `partialFailureIsReportedPerOffset`.
  - `neverDeserializes` — asserted with a `SerdeSource` that fails on every call: the resend must
    still succeed, which proves no decode happens on this path.
  - `budgetBoundsTheCopy`.
  - `readOnlyClusterIsRefused`.

## Observability

- `kui.message.produced` (from MSG-007) with an added `source` attribute (`form` | `bulk` | `resend`),
  so a spike is attributable.
- `kui.message.resend.records` — counter, attributes `cluster`, `source_topic`, `destination_topic`.
- Both log at **INFO** with cluster, topic, partition, count and outcome, and no payload. Until audit
  exists (M5), this log line is the only record that a write happened, and MSG-048 says so in
  `docs/operations/masking.md`'s neighbourhood.

## Degraded behaviour

- Destination topic missing: `KUI-TOPIC-NOT-FOUND` before anything is read, because reading a
  million records and then discovering there is nowhere to put them is the expensive failure.
- Destination partition out of range: validation error naming the partition count.
- Producer failure mid-batch: the copy stops, the result reports `produced` and `failures`, and the
  UI shows "copied 4 812 of 10 000, from offset X" so the operator can resume from a known point.

## Cancellation and shutdown

- Both use cases run inside a producer `Resource` (and, for resend, a consumer `Resource` as well);
  cancelling releases both. A resend cancelled halfway leaves what it produced — stated in the
  scaladoc, asserted by `resendCancellationLeavesWhatWasProduced`, and reported in the UI, because a
  caller that assumes atomicity will write a retry that duplicates.
