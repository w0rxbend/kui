# MSG-015 — `libs/filter`: the CEL port, `BoundedCache`, the id scheme, the string filter, budgets

- **ID:** MSG-015
- **Title:** `libs/filter`: CEL smart filters and the string filter
- **Milestone / Feature:** M3 / MS-006, MS-007, KU-016
- **Owner role:** Principal Scala Engineer
- **Context / service:** `libs/filter`, `libs/cache`
- **Size:** L
- **Dependencies / blocked by:** none. One of the five first-movers (DEVPLAN §6.4).

## Goal (user value)

"Show me only the records where `record.value.status == 'FAILED'`" — evaluated safely, on every
replica, without the user registering anything twice, and without a filter that loops taking the
service down.

## Why this is a first-mover

ADR-017 records that `dev.cel:cel:0.14.0` brings roughly a 10 MB transitive graph including
protobuf-java and re2j. Whether it resolves, compiles under `-Werror`, and agrees with the
protobuf-java version `libs/serde-confluent` pins is a dependency question, not a coding one, and it
must surface while there is time to react. The documented fallback is in DEVPLAN §8 R-5: MS-006's
string filter ships, MS-007 moves to M5, and the browse pipeline is unaffected because it takes a
`MessagePredicate` rather than a CEL program.

## Scope

1. `libs/cache`'s `BoundedCache[F, K, V]` over Caffeine — ADR-016's second primitive, deferred by M1
   to its first caller, which is this task (DEVPLAN §10 D14).
2. `MessageFilterPort[F]`: compile, cache, evaluate.
3. The CEL environment: Kafbat's `record` variable, unchanged, so that a user's existing filters
   work — `partition`, `offset`, `timestampMs`, `keyAsText`, `valueAsText`, `headers` and
   `key` / `value` as `dyn` parsed from JSON when possible.
4. The id scheme: `sha256(source)` first 16 hex characters, **no process salt**, so an id minted by
   one replica is the same id on every other one.
5. Budgets: a source-size limit before compilation, and a per-record evaluation deadline.
6. `StringContainsFilter`: MS-006's case-insensitive contains over key, value and header values, as
   the other instance of the same `MessagePredicate`.

## Non-goals

- No Groovy, no JavaScript, no expression language of KUI's own (ADR-017, DR-1).
- No stored filters. Saved filters live in the browser's `localStorage` (MSG-039).
- No RBAC enforcement. KU-016 fixes the *shape* of the permission check on the test endpoint
  (MSG-031); enforcement is M6.
- No filtering inside `libs/kafka`. A filter runs on decoded records, which is above the port.

## Public Scala signatures to implement

```scala
package kui.filter

/** A record, as a filter sees it: decoded text plus the metadata. Deliberately not the wire DTO and
  * not `RawRecord` — a filter must not depend on either, and both would drag a module edge. */
final case class FilterableRecord(
  partition: Int, offset: Long, timestampMs: Long,
  keyAsText: String, valueAsText: String, headers: Map[String, String]
)

/** The one shape the browse pipeline knows. CEL is an instance; so is the string filter; so is
  * `MessagePredicate.always`. This is what makes R-5's fallback a configuration change rather than
  * a redesign. */
trait MessagePredicate[F[_]]:
  def test(record: FilterableRecord): F[Either[FilterError, Boolean]]

enum FilterError:
  case Runtime(message: String)      // counted as a `filterError`, never fatal
  case Timeout(afterMs: Long)
```

```scala
package kui.filter

opaque type FilterId = String
object FilterId:
  /** `sha256(source)` first 16 hex characters. No salt: an id must mean the same thing on every
    * replica, which is exactly what Kafbat's process salt made impossible. */
  def of(source: String): FilterId

trait MessageFilterPort[F[_]]:
  /** Compiles and caches. Returns the id, which is a pure function of the source, so registering
    * the same filter twice is free and idempotent. */
  def register(source: String): F[Either[KuiError, FilterId]]
  /** `filterSource` is accepted alongside `filterId` so a replica that has never seen the id can
    * compile it on demand (ADR-017). */
  def predicate(id: FilterId, source: Option[String]): F[Either[KuiError, MessagePredicate[F]]]
  /** The test endpoint's pure function: run against a synthetic record. */
  def test(source: String, sample: FilterableRecord): F[Either[KuiError, Boolean]]
```

```scala
package kui.cache

/** ADR-016's bounded cache: a maximum size, an optional TTL, and the metrics every KUI cache
  * publishes. */
trait BoundedCache[F[_], K, V]:
  def get(key: K): F[Option[V]]
  def getOrLoad(key: K)(load: => F[V]): F[V]
  def put(key: K, value: V): F[Unit]
  def invalidate(key: K): F[Unit]
  def stats: F[CacheStats]

object BoundedCache:
  def make[F[_]: Sync: Meter, K, V](name: String, maxSize: Long, ttl: Option[FiniteDuration])
    : Resource[F, BoundedCache[F, K, V]]
```

## The limits, stated exactly

| Limit | Value | Where it comes from |
| --- | --- | --- |
| Compiled-program cache | 10 000 entries, TTL 1 h | ADR-017 |
| Maximum filter source length | 8 KiB | KUI's own; a CEL predicate longer than that is a program, not a filter |
| Maximum AST node count | 1 000 | KUI's own; the cheap half of the "complexity limit" ADR-017 requires |
| Per-record evaluation deadline | 10 ms | KUI's own; at 20 000 records a page it bounds the worst case to 200 s, which the browse deadline then cuts to 60 s |
| Regex engine | re2j, through CEL's default | linear time; the reason a regex filter cannot backtrack the service to a halt |

All five are `kui.message.filter.*` configuration keys with these defaults (MSG-041).

## Observability

- `kui.filter.compile` — counter, attributes `outcome`.
- `kui.filter.evaluate.duration` — histogram; the p99 of this is what tells an operator a user's
  filter is the reason browsing is slow.
- `kui.filter.errors` — counter, attribute `kind` (`runtime` | `timeout`). It is the same number the
  `consumed` event reports as `filterErrors`, and the suite asserts they agree.
- `kui.cache.*` from `BoundedCache`, per ADR-016.

## Degraded behaviour

- A filter that fails on a record: the record is **excluded**, the error is counted, and the stream
  continues. Excluded rather than included, because a filter is a narrowing and a user who asked for
  failures does not want successes when the predicate breaks. The count is on screen, so a filter
  that fails on every record is visible rather than silent.
- A filter that times out: identical treatment, with its own counter, and after a configurable number
  of consecutive timeouts (default 100) the browse ends with `done{reason:"filter"}` rather than
  spending the whole deadline on a program that cannot finish.
- CEL failing to initialise at startup (R-5): the port reports `NotConfigured`, MS-007's UI is
  hidden, MS-006's string filter still works, and the service starts.

## Cancellation and shutdown

`BoundedCache` is a `Resource`. Filter evaluation is a `Sync[F].interruptible` block so that
cancelling a browse cancels an in-flight evaluation rather than waiting for its 10 ms deadline per
record — with 20 000 records queued that difference is three minutes.
