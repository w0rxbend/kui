# MSG-008 — `MessageBrowsePort` Testcontainers matrix: every seek mode, both directions, 1 M records

- **ID:** MSG-008
- **Title:** `MessageBrowsePort` Testcontainers matrix
- **Milestone / Feature:** M3 / MS-001 (exit criteria 1 and 2)
- **Owner role:** Principal Scala Engineer with QA Engineer
- **Context / service:** `libs/kafka`
- **Size:** L
- **Dependencies / blocked by:** MSG-005, MSG-006, MSG-007, MSG-042

## Goal (user value)

The milestone's first two exit criteria, as one command. Every seek mode and every polling mode is
demonstrated against a real broker, and backward browsing is demonstrated not to read a partition it
was not asked to read.

## Scope

1. `MessageBrowseIntegrationSuite`: the matrix — `{Beginning, Latest, AtOffset, AtOffsets,
   AtTimestamp} × {Forward, Backward}` plus `tail`, against the seeded fixtures of MSG-042.
2. The over-fetch bound on the 1 000 000-record fixture.
3. The three shapes that break naive implementations, each as a named case: a compacted topic, a
   transactional topic under `read_committed`, and a topic with one leaderless partition.
4. A `CountingLease` decorator in `libs/testkit` that counts records fetched and polls issued, so the
   bound is an assertion over a number rather than over elapsed time.

## Non-goals

- No security matrix. M1 proved PLAINTEXT / SASL-SCRAM / SSL parity for admin calls, the consumer
  uses the same `ClientProperties` renderer, and re-running three broker configurations here would
  double the suite time for no new information. One case (`sasl-scram`) is kept as a smoke test that
  the properties reach the consumer at all.
- No performance assertions. Timings are MSG-045's, in `docs/benchmarks/`, where a slow machine is a
  recorded number rather than a red build.

package kui.testkit.kafka

/** Wraps a `ConsumerLease` and counts what it fetched. The bound assertion of DEVPLAN §2.2 is a
  * statement about this counter, not about a stopwatch. */
final class CountingLease[F[_]](underlying: ConsumerLease[F], counter: Ref[F, CountingLease.Counts])

## Acceptance criteria

```
$ ./mill libs.kafka.test
```

Expected: `MessageBrowseIntegrationSuite` reports one green case per `BrowseMatrix.all` entry plus
the named shape cases, and the whole suite completes in under four minutes on CI hardware with the
fixture seeded once per container.

```
+ browse: Latest/Backward returns the newest 100 offsets            1.2s
+ browse: AtTimestamp/Forward starts at the first record at or after ts   0.9s
+ browse: backward over 1M records fetched 204 <= 204               3.1s
+ browse: read_committed terminates on a transactional topic        2.0s
```

## Tests required

- `MessageBrowseIntegrationSuite`
  - one case per `BrowseMatrix.all` entry, asserting the **exact offset list**, not a count: a browse
    that returns the right number of the wrong records passes a count assertion.
  - `backwardOverAMillionRecordsStaysWithinTheBound` — the milestone criterion, using `CountingLease`.
  - `compactedTopicStartsAtTheFirstLiveRecord`.
  - `transactionalTopicTerminatesUnderReadCommitted` — with an explicit `IO.timeout(30.seconds)` so
    the regression fails instead of hanging.
  - `leaderlessPartitionIsExcludedAndReported` — the broker hosting one partition is stopped; the
    browse returns the other partitions' records and names the excluded one. This is the case that
    would otherwise take sixty seconds to fail (`PORT-INVARIANTS.md` §1) and it asserts a bound of
    ten seconds on the whole call.
  - `saslScramSmokeTest` — one browse against the M1 SASL topology.
  - `tailSeesANewRecordAndStopsOnCancel`.
- Every case runs against the same container; the fixture is created once (MSG-042's
  `ResourceSuiteLocalFixture`).

## Observability

None of its own. The suite asserts on the metrics MSG-002 and MSG-004 emit, using the otel4s
in-memory testkit, which is how "the gauge returns to zero" becomes a test rather than a claim.

## Degraded behaviour

If the 1 M fixture takes longer than 60 seconds to seed on CI, the two cases that need it are tagged
`Slow` and moved to the nightly job **in this task**, with the tag and the reason recorded in
`TECH_DEBT.md` — rather than the whole suite being quietly disabled later, which is R-10.

## Cancellation and shutdown

`cancellationDuringEveryModeReleasesTheConsumer` — a parameterised case over the same matrix that
cancels mid-stream and asserts the `Resource` finaliser flag and the gauge, for each mode. This is
the port-level half of exit criterion 3.
