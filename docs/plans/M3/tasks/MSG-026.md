# MSG-026 — The cluster profile source and the serde registry adapter, with the SR probe

- **ID:** MSG-026
- **Title:** Cluster profile source, serde registry adapter, Schema Registry probe
- **Milestone / Feature:** M3 / SD-001, SD-003, OT-003
- **Owner role:** Domain Architect (message)
- **Context / service:** `services/message/infrastructure`
- **Size:** L
- **Dependencies / blocked by:** MSG-025, MSG-012

## Goal (user value)

The message service knows about clusters without owning their configuration, keeps working while the
cluster service restarts, and rebuilds a cluster's serdes the moment its profile changes — so a
rotated Schema Registry password takes effect without a restart.

## Scope

1. `ClusterProfileSource`: a **thin adapter over M2's shared `services/cluster/client`** (ADR-046),
   which already implements the conditional `GET /internal/v1/clusters/{id}/profile` with its ETag,
   the `GET /internal/v1/clusters/stream` subscription, the fallback poll, the last-known cache and
   the cancellation path. This task writes **no HTTP profile protocol of its own**: it depends on
   `services.cluster.client`, which rule A11 permits, and adapts that module's output to the domain
   port declared in MSG-017. If `services/cluster/client` does not exist when this task starts
   (DEVPLAN §3a P1), build it **in that module** and raise this task to XL — never a private copy
   under `services/message/infrastructure`.
2. A **last-known-profile cache** that answers while the cluster service is unreachable, with the age
   of the answer, and a `Degraded` capability while it is being used.
3. `SerdeRegistryAdapter`: `libs/serde`'s registry, per cluster, rebuilt on a profile version change,
   old registry closed after the new one is built.
4. `SchemaRegistryProbe`: the health input the capability fold reads (ADR-039).
5. `MessageCacheSuite`: the assertion that the only caches in this service are the three ADR-016
   names, and that no payload is in any of them.

## Non-goals

- No cluster **list** endpoint consumption: the message service resolves one cluster at a time, by
  id, because that is all any of its endpoints needs.
- No second hop: if the cluster service answers `Degraded`, this service reports `Degraded`; it does
  not go looking for the data elsewhere (ADR-043's "no chains").
- No profile writing.

## Design references

ADR-043 (the four conditions: published contract, cached last-known fallback, capability reporting,
no chains), ADR-036 (ETag plus SSE distribution), ADR-016 (`ARCHITECTURE.md` §9's `message` row: the
serde registry `Resource` rebuilt on profile change; payloads never cached), ADR-039 (what dims the
capability), DEVPLAN §10 D8.

## Public Scala signatures to implement

```scala
package kui.message.infrastructure

trait ClusterProfileSource[F[_]]:      // declared in the domain (MSG-017), implemented here
  def profile(cluster: ClusterId): F[Either[KuiError, Versioned[ClusterProfile]]]
  /** Emits on every version change, so the serde registry can be rebuilt. Never fails: a broken
    * subscription becomes a retry with backoff and a `Degraded` status. */
  def changes: Stream[F, ClusterId]
  def status: F[SourceStatus]

final case class Versioned[A](value: A, version: String, fetchedAt: Instant, stale: Boolean)

enum SourceStatus:
  case Live
  case ServingLastKnown(since: Instant, reason: String)
  case Unavailable(reason: String)     // no cached profile and no upstream: the only fatal case
```

```scala
package kui.message.infrastructure

/** Per-cluster serde registries, keyed by profile version.
  *
  * A version change builds the new registry **first** and closes the old one after, so a browse
  * that is halfway through a page does not lose its deserializer. The old registry is closed after
  * a grace period (`kui.message.serde.closeGrace`, default 60 s) rather than immediately, for the
  * same reason.
  */
final class SerdeRegistryAdapter[F[_]: Async](...) extends SerdeSource[F]:
  def forCluster(cluster: ClusterId): Resource[F, ClusterSerdes[F]]
```

## Observability

- `kui.message.profile.age` — gauge in seconds, attribute `cluster`. The number an operator looks at
  to know how stale the service's view is.
- `kui.message.profile.source` — up-down counter with a `status` attribute.
- `kui.serde.registry.built` (MSG-011) gains a `reason` attribute (`initial` | `version-change`).
- One INFO line per profile version change per cluster: old version, new version, and what was
  rebuilt.

## Degraded behaviour

This task **is** fault-injection scenario 5. The contract:

- Cluster service down, profile cached: browsing works, `stale = true`, capability `Degraded` with
  the age. Nothing on the message screens breaks.
- Cluster service down, profile never fetched (a cold start during an outage): that cluster's
  endpoints answer `KUI-UPSTREAM-UNAVAILABLE`; other clusters are unaffected.
- Cluster service returns a profile whose cluster no longer exists: `KUI-CLUSTER-NOT-FOUND`, and the
  cached entry is dropped.
- Schema Registry down: `Degraded`, serdes fall back, browsing continues (MSG-012).

## Cancellation and shutdown

- The SSE subscription is a supervised fiber in a `Resource`; shutdown cancels it and the suite
  asserts nothing is left running.
- The registry map's `Resource`s are all released on shutdown, including any old version still inside
  its grace period — a shutdown that waited 60 seconds for a grace timer would make every deployment
  a minute slower.
