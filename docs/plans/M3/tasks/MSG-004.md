# MSG-004 — `pollRanges`: assign / seek / pause / resume, position-based termination, budgets

- **ID:** MSG-004
- **Title:** `pollRanges`: assign / seek / pause / resume, position-based termination, budgets
- **Milestone / Feature:** M3 / MS-001, MS-013
- **Owner role:** Principal Scala Engineer
- **Context / service:** `libs/kafka`
- **Size:** L
- **Dependencies / blocked by:** MSG-003. One of the five first-movers (DEVPLAN §6.4).

## Goal (user value)

A resolved set of offset windows becomes a stream of records that **ends**: on a transactional topic
whose control records leave gaps, on a partition that answers three empty polls in a row, and on a
topic that is still being written to. A browse that does not terminate is a spinner that never stops
and a consumer that never closes, and it is the worst failure this milestone can ship.

## Why this is a first-mover

Two facts from `research/kafka/admin-capabilities.md` §4 make the naive loop wrong, and both are
invisible in a happy-path test: **an empty poll does not mean end-of-partition**, and **control
records occupy offsets but are never returned**, so `end − begin` overstates the record count and a
loop that counts records never reaches its target. Termination must be on `position >= until` per
partition. Proving that against a real transactional topic early is the point of this task.

## Scope

1. `MessageBrowsePort.pollRanges`: assign every partition in the plan, seek each to its `from`, poll,
   emit, `pause` a partition when `position >= until`, and complete when every partition is paused.
2. `PollEvent` as the stream element: `Polled(chunk, stats)` and `Exhausted(tp)`, so the use case can
   emit `consumed` and `phase` events without knowing how polling works.
3. Budget enforcement: records, bytes and deadline from `PollBudget`, plus the optional bytes/second
   throttle (MS-013), each ending the stream with the reason that ended it.
4. The empty-poll rule: an empty poll advances nothing and is not a termination signal; a partition
   is finished only by its position. A safety net of `maxEmptyPolls` (default 5, Kouncil's number)
   ends a stream whose partitions are all paused-but-not-progressing, with
   `done{reason:"exhausted"}` rather than a hang.
5. Filtering out records at or beyond `until` — a poll can return records past a window's end.

## Non-goals

- No window splitting: `pollRanges` reads the ranges it is given (MSG-005 splits them).
- No merge-sort across partitions and no `limit` enforcement in record order — that is application
  logic (MSG-019), because "the newest hundred across eight partitions" is a product decision, not a
  Kafka one.
- No deserialization. Records leave here as bytes.
- No tailing (MSG-006).

## Public Scala signatures to implement

```scala
package kui.kafka.consume

final case class PollStats(records: Int, bytes: Long, elapsed: FiniteDuration, polls: Int)

enum PollEvent:
  /** A non-empty batch, already trimmed to the windows. */
  case Polled(records: Chunk[RawRecord], stats: PollStats)
  /** This partition has reached its `until`. Emitted once per partition, before the stream ends. */
  case Exhausted(tp: TopicPartition)
  /** No records this round. Carried rather than swallowed so the use case can emit `consumed`
    * updates and keep a slow browse's heartbeat honest. */
  case Idle(stats: PollStats)

enum StopReason:
  case Exhausted, RecordLimit, ByteLimit, Deadline, Cancelled
```

```scala
package kui.kafka.consume

trait MessageBrowsePort[F[_]]:
  ...
  /** One consumer per stream; assign, seek, pause; terminates when `position >= until` for every
    * partition, when the budget is spent, or when the caller cancels.
    *
    * **Never terminates on an empty poll.** An empty `poll` means "nothing arrived within the poll
    * timeout", which on a live topic is the normal case; treating it as end-of-partition truncates
    * a page. The safety net for a partition that can neither progress nor finish is
    * `maxEmptyPolls`, and it ends the stream with `Exhausted`, not with an error.
    */
  def pollRanges(
    profile:   ClusterProfile,
    topic:     TopicName,
    ranges:    Map[TopicPartition, OffsetRange],
    budget:    PollBudget,
    isolation: IsolationLevel
  ): Stream[F, PollEvent]
```

```scala
package kui.kafka.consume

/** The loop, as a function of a `ConsumerLease` so it can be tested against a fake lease with no
  * broker at all. Every termination rule of this task is asserted here first and against a
  * container second. */
object RangePolling:
  final case class Settings(pollTimeout: FiniteDuration, maxEmptyPolls: Int)

  def run[F[_]: Temporal](
    lease:    ConsumerLease[F],
    ranges:   Map[TopicPartition, OffsetRange],
    budget:   PollBudget,
    settings: Settings
  ): Stream[F, PollEvent]
```

## The loop, stated exactly

1. `assign(ranges.keySet)`; for each `tp`, `seek(tp, range.from)`.
2. Repeat:
   a. if every partition is paused → emit `Exhausted` for any not yet emitted, stop with `Exhausted`;
   b. if the budget is exhausted → stop with the dimension that ran out;
   c. `poll`;
   d. drop records whose offset is `>= until` for their partition (a poll may overshoot);
   e. emit `Polled` (or `Idle` when the trimmed chunk is empty) with cumulative stats;
   f. for each assigned partition, if `position(tp) >= until` then `pause(tp)` and emit `Exhausted`;
   g. if the poll was empty, increment the empty-poll counter; otherwise reset it. At
      `maxEmptyPolls`, stop with `Exhausted`.
3. On every exit path the consumer `Resource` closes. There is no other exit path.

The throttle, when configured, is applied between (e) and (f) as a `Temporal.sleep` computed from the
bytes just delivered — in the port, not in the use case, so that a caller cannot forget it.

## ADRs this task must obey

ADR-035 (`consumed` needs cumulative counters and the remaining budget: `PollStats` carries the first
and `PollBudget` the second), ADR-016 (metrics), ADR-041 A10.


```scala
// The rule an empty poll must not break
val lease = FakeLease(polls = List(Chunk.empty, Chunk.empty, chunkOf(recordsUpToUntil)))
val events = RangePolling.run[IO](lease, ranges, budget, Settings(1.second, maxEmptyPolls = 5))
  .compile.toList.unsafeRunSync()
assert(events.exists(_.isInstanceOf[PollEvent.Polled]))   // it did not stop at the first empty poll

// Termination is on position, not on record count
val transactional = FakeLease(polls = List(chunkOfSize(9)), positionAfter = until)  // 10 offsets, 1 control record
assert(RangePolling.run[IO](transactional, ranges, budget, s).compile.toList
         .unsafeRunSync().exists(_ == PollEvent.Exhausted(tp0)))
```

## Tests required

- `RangePollingSuite` (fake lease, no broker, `TestControl`)
  - `assignsAndSeeksEveryPartitionOnce`.
  - `pausesAPartitionWhenItsPositionReachesUntil`.
  - `stopsWhenEveryPartitionIsPaused`.
  - `emptyPollDoesNotTerminate` — the snippet above.
  - `maxEmptyPollsIsASafetyNetNotTheNormalPath` — asserts the counter resets after any non-empty
    poll, so a slow topic never hits it.
  - `trimsRecordsBeyondUntil` (property): no emitted record has `offset >= until` for its partition.
  - `budgetStopsWithTheRightReason` — one case per `StopReason`, each asserting the stream ended and
    the consumer was released.
  - `throttleDelaysProportionallyToBytes` (`TestControl`, virtual time — a wall-clock assertion here
    would be flaky and would prove nothing about the arithmetic).
  - `statsAreCumulativeAndMonotone` (property).
- `PollTerminationSuite` (Testcontainers, extended by MSG-008)
  - `terminatesOnATransactionalTopicUnderReadCommitted` — the case R-1 exists for: control records
    make `end − begin` larger than the number of records, so a count-based loop hangs. Written with
    an explicit 30-second `IO.timeout` so a regression **fails** rather than hanging the suite.
  - `terminatesWhileAProducerIsStillWriting` — `until` was fixed at resolution time; new records do
    not extend the browse.
  - `terminatesOnACompactedTopicWithGaps`.

## Observability

- `kui.message.poll.duration` — histogram per poll, attributes `cluster`, `topic`.
- `kui.message.records.consumed`, `kui.message.bytes.consumed` — counters, same attributes.
- `kui.message.browse.stopped` — counter with a `reason` attribute taken from `StopReason`. This is
  the metric an operator reads to find out whether users are hitting budgets, and it is the only
  cheap way to know that `maxEmptyPolls` is firing in production.
- No log line per poll. One DEBUG line per stream at completion with the totals and the stop reason.

## Degraded behaviour

- A partition that stops progressing: the empty-poll net ends the stream with `Exhausted`; the user
  sees fewer records and a `done` event, not a spinner.
- A broker that fails mid-stream: the mapped `KuiError` propagates out of the stream and MSG-029
  turns it into `event: error`, after which everything already sent stands (DEVPLAN §10 D13).
- The budget spent: `done{reason:"budget"}`, and the UI offers "continue" with the cursor. Truncation
  is always visible; it is never silent.

## Cancellation and shutdown

- Cancelling the fiber running the stream releases the consumer `Resource`, which closes the client.
  fs2-kafka performs the `wakeup` internally.
- `RangePollingSuite.cancellationMidPollReleasesTheConsumer` cancels while a poll is in flight (a
  fake lease whose `poll` never completes) and asserts release within 100 ms of virtual time.
- No `IO.uncancelable` anywhere in the loop. If a future change needs one, it belongs around the
  seek sequence only, and it needs a comment saying why.
