# TOP-028 — `ui-topics`: the module, its registration, its routes and its typed clients

- **ID:** TOP-028
- **Title:** `ui-topics`: the module, its registration, its routes and its typed clients
- **Milestone / Feature:** M2 / TP-001, KU-001
- **Owner role:** Frontend Architect
- **Context / module:** `frontend/ui-topics`, `frontend/ui-shell`
- **Size:** M
- **Dependencies / blocked by:** TOP-020, TOP-023

## Goal (user value)

Topics appear in the sidebar, its screens are downloaded only when somebody opens them, and the
browser decodes exactly the documents the gateway sends.

## Scope

1. The Mill module `frontend.uiTopics`, its CSS resource directory and its jsdom test module.
2. `TopicsFeature` (the dynamic half) and `TopicsRoutes` (the static half: nav entry, route
   patterns, `history.state` codec).
3. Registration: `FeatureId.Topics`, the thunk in `FeatureRegistryImpl`, and `TopicsRoutes` in
   `staticRoutes`.
4. `TopicsApi` and `TopicsQueries`: the typed client over the **gateway's** `/api/v1` shapes, and
   the per-feature query caches.
5. Recorded-response tests for every document this client decodes.

## Non-goals

- No screens. TOP-029 and TOP-030.
- No fix for TD-016 (the clusters feature being statically imported by `main.js`). That is an
  existing debt with its own owner; this task must not make it worse and TOP-037 asserts the topics
  module specifically is not fetched on first paint.
- No shared state with `ui-clusters`. The current cluster is the shell's, through
  `CurrentCluster`.

## Design references

- `frontend/ui-clusters/` — the whole module is the pattern: `ClustersFeature`'s doc comment about
  the split border, `ClustersRoutes`' page-as-data rule, `ClustersApi` and `ClustersQueries`.
- **The comment in `build.mill` above `object uiClusters`**, which records M1's second integration
  defect verbatim: the dashboard decoded `ClustersResponse` while the gateway sends
  `ClusterOverviewDto`, every response decoded successfully into zero rows, and the page rendered
  "No clusters yet" against a working broker. This task's module declares
  `services.gateway.contract.js` for the same reason and its suite asserts against recorded bytes.
- ADR-012 and its amendment 2 (the dynamic import is a split border; the static half is data),
  ADR-011, ADR-032.
- `docs/frontend/features.md` — the registration steps, which TOP-031 updates from what this task
  learns.

## Public Scala signatures to implement

```scala
package kui.ui.topics

/** The pages this feature owns. A page is data: what the URL is built from and parsed into, and
  * nothing about how anything is drawn (ADR-012 amendment 2).
  */
sealed trait TopicsPageId extends Page

object TopicsPageId {
  final case class List(clusterId: String) extends TopicsPageId
  final case class Detail(clusterId: String, topic: String, tab: TopicTab) extends TopicsPageId
}

/** The tab is part of the page and therefore part of the URL: a configuration listing is what an
  * operator pastes into a ticket, and a link that always opened on the overview would make the
  * recipient hunt for what they were sent.
  */
enum TopicTab { case Overview, Settings }
```

```scala
package kui.ui.topics

/** The typed client. Every method names the **gateway's** shape, which for the overview is the
  * gateway's own DTO and for everything else is the topic service's, proxied unchanged.
  */
final class TopicsApi(client: ApiClient) {
  def list(cluster: String, params: TopicListParams): EventStream[Either[ApiError, TopicsResponse]]
  def overview(cluster: String, topic: String): EventStream[Either[ApiError, TopicOverviewDto]]
  def config(cluster: String, topic: String): EventStream[Either[ApiError, TopicConfigResponse]]
  def partitions(cluster: String, topic: String): EventStream[Either[ApiError, PartitionsResponse]]
  def refresh(cluster: String): EventStream[Either[ApiError, RefreshAcceptedDto]]
}
```

## Decisions this task takes (no ADR covers them)

1. **The detail page reads the gateway's `overview`, not the topic service's `getTopic`.** One
   request fills the page including its future tabs, and it is the endpoint M4 extends. The
   proxied `getTopic` stays available and is what a script or an MCP tool would use.
2. **The tab is in the URL.** Stated above; it also makes the Settings tab's data a separate query
   that is not fetched until the tab is opened.
3. **The feature holds no capability signal.** M2's topic screens are read-only, the shell already
   draws the banner and the fallback panel from the capability store, and a second subscription
   would be a second opinion about one state on one screen. This repeats `ClustersFeature`'s
   recorded deviation 5 deliberately, because it is now a pattern and TOP-031 writes it down.

the feature class anywhere in the shell destroys the split border and nothing about the source

With the stack running, the sidebar shows Topics, and stopping `kui-topic` dims it.

## Tests required

`TopicsApiSuite` (jsdom, recorded responses) — **the browser half of the seam**:

- **`theRecordedListResponseDecodes`** — `recorded/topics-200.json` is the same bytes the gateway
  proxy suite (TOP-023) records. Not a hand-written fixture: a hand-written fixture is a
  description of what the author believed the server sends, and M1's second defect was exactly
  that belief being wrong.
- `theRecordedStaleResponseDecodesAndKeepsItsScrapedAt`.
- **`theRecordedOverviewResponseDecodes`** — against the gateway's DTO, with four `not_configured`
  sections.
- `theRecordedConfigResponseDecodes`, including a sensitive entry with a null value.
- `aMissingItemsFieldIsAFailureNotAnEmptyList` — the specific decoder behaviour that turned M1's
  wrong document into a silently empty page. A decoder that defaults a missing list to `Nil` cannot
  tell a wrong document from an empty one.
- `queryParametersAreEncodedIntoTheUrl` (property) — including that an absent parameter is absent
  rather than empty.

`TopicsRoutesSuite`:

- `everyPageRoundTripsThroughItsHistoryStateCodec` (property).
- `theRoutePatternsEndOfSegments` — without it a pattern claims its own sub-paths and a mistyped
  URL never 404s.
- `theNavEntryNamesTheTopicFeatureId`.
- `anUnknownTabInAUrlFallsBackToOverview` — a bookmark can outlive a tab.

## Observability

- Every call reports to `HealthReporting` with `CallScope.Feature`. A topic-service failure must
  never be reported as a shell failure; that is the difference between a dimmed feature and a
  full-screen "cannot reach the gateway" (ADR-032).
- No client-side metric is sent to the server (M0's rule).

## Degraded behaviour

- **Topic service unavailable**: the shell never routes here and renders the feature's
  `unavailableView`, whose sentence names what still works — the dashboard, the brokers page and
  the settings page.
- **Topic service not configured**: the sidebar entry is hidden and the module is never
  downloaded.
