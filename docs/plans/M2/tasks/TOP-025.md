# TOP-025 — OpenAPI regeneration, error-code table, contract snapshot

- **ID:** TOP-025
- **Title:** OpenAPI regeneration, error-code table, contract snapshot
- **Milestone / Feature:** M2 / OT-005, KU-001
- **Owner role:** Chief Architect
- **Context / service:** `services/gateway`, `services/topic/api`, `docs/api`
- **Size:** S
- **Dependencies / blocked by:** TOP-024, TOP-021

## Goal (user value)

The published API document describes what KUI actually serves, so somebody writing a client
against it does not discover a missing endpoint at runtime.

## Scope

1. Regenerate `services/topic/api/openapi.json` and the merged
   `docs/api/openapi.json`, and commit both.
2. `docs/api/error-codes.md` gains every code the topic service can return, with its status and
   what an operator does about it.
3. The OpenAPI style check passes for the new endpoints: every operation has an id, a summary, a
   tag and a described error response.
4. The committed snapshot is checked in CI, so a contract change that is not regenerated fails the
   build rather than being noticed by a client.

## Non-goals

- No contract changes. If the style check finds a missing summary, the fix belongs in the task that
  owns the endpoint (TOP-020 or TOP-024) and this task waits for it. A contract edited to satisfy
  a document generator is a contract nobody reviewed.
- No client generation.
- No new error codes. `ErrorCode` already carries `TopicNotFound`; if a genuinely new code is
  needed, the task that needs it adds it, together with its row in the table.

## Design references

- `services/gateway/api/src/kui/gateway/api/openapi/` — `OpenApiMerge`, `OpenApiDocument` and
  `OpenApiStyleCheck`, all of which exist and none of which changes.
- `docs/api/error-codes.md` — the existing table and its columns.
- ADR-003 (the contract is the source), ADR-034 (the envelope and its codes).
- PLAN §46's common exit criterion: "OpenAPI regenerated and committed".

## Acceptance criteria

```
$ ./mill services.topic.api.openApi
$ ./mill services.cluster.api.openApiCheck
$ ./mill services.topic.api.openApiCheck
$ ./mill services.gateway.api.openApi
$ ./mill services.gateway.api.openApiCheck
$ git diff --stat -- services/topic/api/openapi.json docs/api/openapi.json    # non-empty, then committed
```

And with the stack running:

```
$ curl -s localhost:8080/api/v1/openapi.json | jq -r '.paths | keys[]' | grep topics
/api/v1/clusters/{clusterId}/topics
/api/v1/clusters/{clusterId}/topics/refresh
/api/v1/clusters/{clusterId}/topics/{topicName}
/api/v1/clusters/{clusterId}/topics/{topicName}/config
/api/v1/clusters/{clusterId}/topics/{topicName}/overview
/api/v1/clusters/{clusterId}/topics/{topicName}/partitions
```

Six paths and no others. A seventh means a mutation endpoint has appeared, which is risk R-11
arriving.

## Tests required

- `OpenApiMergeSuite` gains `theTopicServicesPathsAreMerged` and
  `noPathIsDeclaredByTwoServices`.
- `OpenApiStyleCheckSuite` runs unchanged over the enlarged document; if it fails, the fix is in the
  contract task, not here.
- `ErrorCodeTableSuite` (new, in `libs.contractsCore.jvm.test` or wherever the existing table test
  lives): **every `ErrorCode` case appears as a row in `docs/api/error-codes.md`**, asserted by
  parsing the markdown. A documented table that nothing checks is the third M0 finding — a
  documented rule nothing enforces — and this is its enforcer.
