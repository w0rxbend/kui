# TOP-013 — Topic snapshot use case: per-cluster scrape, staleness, forced refresh, capability report

- **ID:** TOP-013
- **Title:** Topic snapshot use case: per-cluster scrape, staleness, forced refresh, capability report
- **Milestone / Feature:** M2 / TP-001, TP-003, CL-005
- **Owner role:** Domain Architect (topics)
- **Context / service:** `services/topic/application`
- **Size:** L
- **Dependencies / blocked by:** TOP-012, TOP-006

## Goal (user value)

Opening the topic list of a cluster with ten thousand topics costs no admin call: the answer is a
snapshot taken in the background, stamped with when it was taken, kept while the cluster is
unreachable, and refreshable on demand by a button that returns immediately.

## Scope

1. The Mill module `services.topic.application` and its test module.
2. `TopicSnapshots`: a `SnapshotRegistry[F, ClusterId, TopicSnapshot]` with the scrape as its
   loader, the interval from configuration, and retention driven by `ClusterProfiles`.
3. The scrape itself: `TopicAdmin.scrape`, the internal-topic union rule, the `NameIndex` build,
   and the `scrapedAt` stamp from `ClockPort`.
4. Forced refresh: returns immediately with "accepted", deduplicated, and never blocks on a dead
   cluster.
5. `TopicCapabilityUseCase`: the topic service's own capability report, per cluster, folding the
   snapshot's status and the profile client's health.
6. A per-scrape timeout, so a cluster that answers slowly cannot hold a refresh fiber forever.

## Non-goals

- No list filtering, searching, sorting or paging. TOP-014 — this task produces the snapshot the
  pipeline reads.
- No HTTP, no DTO, no Tapir, no Circe. Rule A3.
- No second cache primitive. `SnapshotRegistry` is TOP-006's and this task is its first caller.
- No cross-cluster aggregation. Each cluster is independent, including in failure.

## Public Scala signatures to implement

```scala
package kui.topic.application

import cats.effect.kernel.Resource
import kui.cache.SnapshotCell
import kui.kernel.ClusterId
import kui.topic.domain.TopicSnapshot

/** One topic snapshot per cluster, refreshed on a timer, released when the cluster goes away. */
trait TopicSnapshots[F[_]] {

  /** The snapshot for a cluster, starting its scrape if this is the first ask. `None` when the
    * cluster is not configured — which is a 404 at the edge, not an empty list.
    */
  def of(cluster: ClusterId): F[Option[SnapshotCell[F, TopicSnapshot]]]

  /** Starts a refresh and returns immediately; `false` when the cluster is unknown. */
  def requestRefresh(cluster: ClusterId): F[Boolean]
}

object TopicSnapshots {
  def resource[F[_]: Temporal](
      admin: kui.topic.domain.TopicAdmin[F],
      profiles: kui.topic.domain.ClusterProfiles[F],
      clock: kui.topic.domain.ClockPort[F],
      config: TopicSnapshotConfig,
      metrics: kui.cache.CacheMetrics[F],
      logger: org.typelevel.log4cats.StructuredLogger[F]
  ): Resource[F, TopicSnapshots[F]]
}

final case class TopicSnapshotConfig(
    refreshInterval: FiniteDuration,
    /** A whole scrape's budget. Past it the scrape is cancelled and the previous snapshot is kept
      * as stale — a scrape that runs longer than the interval would otherwise overlap the next
      * one and double the load on a cluster that is already struggling. */
    scrapeTimeout: FiniteDuration,
    internalPrefix: String
)
```

```scala
package kui.topic.application

/** The topic service's capability, per cluster, for the gateway's registry (ADR-039). */
trait TopicCapabilityUseCase[F[_]] {
  def report: F[List[(ClusterId, TopicCapability)]]
}

enum TopicCapability {
  case Available(scrapedAt: Instant)
  case Degraded(reason: String, since: Instant, lastScrapedAt: Option[Instant])
  case Unavailable(reason: String, since: Instant)
}
```

## Behaviour it must have

- **Retention.** `ClusterProfiles.onChange` drives `SnapshotRegistry.retain`, so a cluster removed
  from configuration has its snapshot released and its refresh fiber cancelled within one change
  event. This is the reason `SnapshotRegistry` exists.
- **Never a partial replacement.** A failed scrape leaves the previous snapshot in place, reported
  stale; it never writes a snapshot containing only the topics it managed to read before failing.
- **The scrape is one logical unit with a timeout.** Cancelled at `scrapeTimeout`, with a WARN
  naming the cluster and the elapsed time.
- **`scrapedAt` comes from `ClockPort`**, so a suite can assert exact instants.
- **The capability fold** is `Available` when the last scrape succeeded, `Degraded` when a scrape
  is failing but a previous snapshot is being served, and `Unavailable` when there is no snapshot
  at all. Per DEVPLAN §10 D11 this is reported per **cluster**; the *service's* capability is
  reported by the gateway's readiness poller and is not this use case's business.

## Cancellation and shutdown

Releasing the resource cancels every refresh loop, every in-flight scrape and the profile-change
subscription, in that order. Asserted by `releasingTheSnapshotsLeavesNothingRunning`.

## Observability

- The `SnapshotRegistry` metrics, with `cache = topic.snapshot` and a `cluster` label.
- `kui.topic.scrape.duration` histogram and `kui.topic.scrape.topics` gauge per cluster — the two
  numbers that answer "is the scrape keeping up", which is the operational question this whole
  design creates.
- `kui.topic.scrape.incomplete` gauge: how many topics the last scrape could not read.
- INFO per successful scrape at DEBUG level in steady state, INFO on the first success after a
  failure; WARN on failure, rate-limited to one per cluster per interval.
- Span `topic.scrape` with `cluster`, `topics`, `incomplete` and `outcome`.

## Degraded behaviour

- **Cluster unreachable**: previous snapshot served, `Section.Stale` at the edge, capability
  `Degraded` for that cluster only.
- **Cluster unreachable and never scraped**: no snapshot; the edge answers
  `Section.Unavailable(reason)` and the list screen shows its error state with a retry.
- **Partly authorized cluster**: the snapshot exists, `incomplete` names the topics that could not
  be read, and the list renders a note rather than silently showing fewer rows.
- **Scrape slower than the interval**: the timeout cancels it, a WARN says so, and the interval is
  the operator's dial (TOP-032). The snapshot ages visibly rather than the service piling up
  overlapping scrapes.
