# TOP-020 — Topic contract: list, detail, config, partitions, refresh

- **ID:** TOP-020
- **Title:** Topic contract: list, detail, config, partitions, refresh
- **Milestone / Feature:** M2 / TP-001, TP-003, TP-004, PA-001, SF-001
- **Owner role:** Chief Architect
- **Context / service:** `services/topic/contract` (cross-compiled)
- **Size:** M
- **Dependencies / blocked by:** TOP-019

## Goal (user value)

Every address the topic feature uses is declared once, so the gateway derives its routes, the
browser generates its client and the OpenAPI document is regenerated — all from the same five
endpoint values.

## Scope

1. The Mill module `services.topic.contract` with its `.jvm` and `.js` halves.
2. Five endpoints on the `KuiEndpoint.internal` base, under `/internal/v1`.
3. The query parameters of the list endpoint, with their codecs and their validation: `q`, `mode`,
   `showInternal`, `sort`, `page`, `pageSize`.
4. The response envelopes, composing `PageDto`, the topic fragments and `Section`.
5. The contract suite: every path, every name, every security input, and — the one that matters for
   this milestone — that **no mutating endpoint is declared**.

## Non-goals

- No server logic. TOP-021.
- No mutation endpoints. Not `POST /topics`, not `PATCH /topics/{topic}`, not
  `DELETE /topics/{topic}`, not `/partitions`, not `/replication-factor`. M5, with read-only mode
  and audit. A declared endpoint is one somebody implements (DEVPLAN §3 and risk R-11).
- No CSV. TP-017 is M5, and content negotiation on an endpoint that has one representation is a
  branch with no second case.
- No overview endpoint. That is a gateway aggregation and TOP-024 declares it on the gateway.
- No `/messages`, `/consumer-groups`, `/analysis`, `/producers`, `/acls` or `/connectors`.

```scala
package kui.topic.contract

/** The list query, validated at the edge.
  *
  * `sort` is an `Option` and not a defaulted value, because "no sort given" is meaningful:
  * `mode=fts` orders by relevance only when the caller did not ask for an order (DEVPLAN §10 D4,
  * TOP-014 decision 2). Defaulting here would make an explicit sort silently ignored.
  */
final case class TopicListParams(
    q: Option[String],
    mode: SearchMode,
    showInternal: Boolean,
    sort: Option[Sort[TopicSortField]],
    page: PageRequest
)
```

```scala
package kui.topic.contract.dto

/** The list response. `topics` is a `Section` so a cluster that could not be scraped is a 200 with
  * a stale or unavailable section — never a 5xx (DEVPLAN §10 D11).
```

## Decisions this task takes (no ADR covers them)

1. **`sort` is one parameter, `field:direction`, not two.** ADR-026 writes it that way, and two
   parameters admit the state "direction given, field not", which a codec then has to invent a
   meaning for.
2. **`topicPartitions` exists separately from `getTopic` even though the detail contains
   partitions.** A topic with two thousand partitions makes the detail document large, and the
   partition table is the part a screen re-fetches when the user hits refresh. The detail endpoint
   caps its embedded partition list at the first 500 and says so in the response; the dedicated
   endpoint returns all of them.
3. **`refresh` is per cluster, not per topic**, and answers 202. The snapshot is per cluster, so a
   per-topic refresh would either refresh everything under a misleading name or invent a second
   caching level. 202 because the response does not mean the data is new (D5's snapshot is
   asynchronous), and the body carries `requestedAt` so the button has something to say.
4. **`showInternal` defaults to `false`.** Both reference products do, and the alternative shows
   every operator `__consumer_offsets` and KUI's own metadata topics on first load.

## Tests required

`TopicEndpointsSuite` (cross-compiled):

- `everyEndpointIsUnderInternalV1` — the precondition `ContractRouting.derive` fails construction
  on, asserted in the module that can fix it.
- `everyEndpointCarriesTheSignedPrincipalSecurityInput`.
- `everyEndpointHasAUniqueNameASummaryAndATag`.
- `theEndpointListIsExactlyTheFiveDeclared` — a sixth must be a deliberate edit.
- **`noEndpointMutates`** — every endpoint's method is `GET`, except `refresh`, which is a `POST`
  that changes nothing on the cluster. This is risk R-11's enforcer and DEVPLAN §9 item 10's named
  check: the rule "no mutations in M2" is stated in three documents and this is the thing that
  makes it true.
- `aMalformedTopicNameIsADecodeFailure` — a 400 naming the field, not a 404.

`TopicQueryCodecsSuite` (cross-compiled, unit + property):

- `sortParsesFieldColonDirection` (table).
- `anUnknownSortFieldIsADecodeFailure` — not a default. A silently ignored sort is how a user
  concludes sorting is broken.
- `anUnknownModeIsADecodeFailure`.
- `pageSizeAboveTheMaximumIsADecodeFailure` — ADR-026's 500.
- `pageZeroOrNegativeIsADecodeFailure` — the reference resets these to defaults silently; naming
  the problem is better than guessing what was meant.
- `defaultsAreTwentyFivePlainNotInternalAndNoSort` (property over absent parameters).

`TopicResponsesSuite`: golden decode and round-trip for each response, including a `TopicsResponse`
whose section is `Stale` and one whose section is `Unavailable`.

## Observability

None: this module has no runtime. The endpoint `name`s it fixes are what TOP-021's metrics and the
gateway's access log label their spans with, so a rename here is an observability change and the
Implementation Report should say so.

## Degraded behaviour

Every response wraps its payload in a `Section`, so a cluster that cannot be scraped is a 200 with
a stale or unavailable section. `incompleteTopics` sits outside the section deliberately: it is a
fact about the data that *is* there.
