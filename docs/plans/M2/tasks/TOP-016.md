# TOP-016 — Topic configuration use case

- **ID:** TOP-016
- **Title:** Topic configuration use case
- **Milestone / Feature:** M2 / TP-004
- **Owner role:** Domain Architect (topics)
- **Context / service:** `services/topic/application`
- **Size:** S
- **Dependencies / blocked by:** TOP-013

## Goal (user value)

A topic's Settings tab lists every configuration key with its value, its default and where the
value came from, marks the ones that were overridden, and shows that a sensitive key has a value
without showing the value.

## Scope

1. `TopicConfigUseCase`: one topic's configuration, read live, with the "not authorized is an
   empty list" rule surfaced as a renderable state rather than an error.
2. The default-value derivation: `defaultValue` comes from the synonym whose source is `Default`,
   which is the only way a screen can say "this was overridden".
3. Ordering: entries sorted by name, ascending, always — the tab is a reference list somebody
   scans alphabetically and a broker-dependent order would make two clusters look different for no
   reason.

## Non-goals

- No editing (TP-006, M5). No diff, no `incrementalAlterConfigs`, no validation of a proposed
  value.
- No unit formatting. `retention.ms` as "7 days" and `segment.bytes` as "1 GiB" are rendering, and
  TOP-030 does it next to the table that shows it.
- No filtering to "only overridden". A client-side toggle over a list of forty entries needs no
  server support.

## Design references

- `research/kafbat/ui-analysis.md` "Settings tab" — the three columns, the bolding of an overridden
  key, the masked value with the title "Sensitive Value", and that the default column is blank when
  value equals default.
- `research/kafbat/feature-matrix.md` TP-4 — "name, value, defaultValue, source, isSensitive,
  isReadOnly, synonyms. Sensitive sanitized."
- `research/kafka/admin-capabilities.md` §2, row "Topic configs" — and the reference behaviour that
  a visible topic without `DESCRIBE_CONFIGS` is an empty config rather than an error.
- TOP-004's decision 1, which is the port half of the same rule.

## Public Scala signatures to implement

```scala
package kui.topic.application

import kui.kernel.{ClusterId, TopicName}
import kui.topic.domain.{TopicConfigEntry, TopicError}

trait TopicConfigUseCase[F[_]] {

  /** One topic's configuration.
    *
    * An empty list is a **valid answer** and means one of two things the caller must be able to
    * tell apart, which is why the result is not a bare `List`: the topic genuinely has no dynamic
    * configuration the broker will report, or the caller may see the topic but not its
    * configuration.
    */
  def config(cluster: ClusterId, topic: TopicName): F[Either[TopicError, TopicConfigView]]
}

/** What the Settings tab renders. */
enum TopicConfigView {
  /** Entries, sorted by name. Possibly empty, which the screen renders as "no overrides". */
  case Entries(values: List[TopicConfigEntry])

  /** The topic exists and the caller may not read its configuration. The screen says so, rather
    * than showing an empty table that reads as "this topic has no settings". */
  case NotPermitted(detail: String)
}
```

## Decisions this task takes (no ADR covers them)

1. **"Not permitted" is a case of the result, not an error.** The topic page still renders; only
   one tab says why it is empty. Making it a `TopicError.Forbidden` would give the whole page a
   403, and the partitions the user is allowed to see would disappear with it.
2. **`defaultValue` is derived from the synonyms, not from a hard-coded table.** KUI carrying its
   own table of Kafka defaults would be a table that is wrong on the next broker release, and the
   broker already knows.
3. **A sensitive entry's `defaultValue` is also `None`.** The default of a sensitive key is not
   itself a secret, but showing a default beside a masked value invites the reader to conclude the
   value equals it. Absence is the honest rendering.

## Tests required

`TopicConfigUseCaseSuite`:

- `entriesAreSortedByName` (property).
- **`aSensitiveEntryHasNeitherAValueNorADefault`**.
- `overriddenIsValueDifferentFromDefault` (property) — and is always false for a sensitive entry,
  because "overridden" is not knowable without the value and a bolded row would be a guess.
- `defaultComesFromTheDefaultSourceSynonym`.
- `noSynonymsMeansNoDefault` — `None`, not the value itself.
- `anUnauthorizedReadIsNotPermittedNotAnError`.
- `anUnknownTopicIsNotFound`.
- `cancellingTheRequestCancelsTheAdminCall`.

## Observability

- Span `topic.config` with `cluster`, `topic`, `entries` and `permitted`.
- No metric of its own: the admin call underneath is already measured by
  `kui.kafka.admin.duration` with `operation = describeConfigs`, and a second timer over the same
  call would be two numbers for one fact.

## Degraded behaviour

- **Not authorized**: `NotPermitted`, with the tab explaining it.
- **Cluster unreachable**: `TopicError.Unreachable`; the tab shows its error state with a retry,
  and the rest of the topic page — served from the snapshot — keeps working.
- **Documentation absent** (broker older than 2.6): tooltips are absent; nothing else changes.
