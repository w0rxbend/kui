# TOP-004 — `libs/kafka`: `topicConfigs` with synonyms, documentation and sensitivity

- **ID:** TOP-004
- **Title:** `libs/kafka`: `topicConfigs` with synonyms, documentation and sensitivity
- **Milestone / Feature:** M2 / TP-004
- **Owner role:** Principal Scala Engineer
- **Context / module:** `libs/kafka`
- **Size:** M
- **Dependencies / blocked by:** TOP-003

## Goal (user value)

The Settings tab of a topic shows every configuration key, what it is set to, where that value
came from, and — for a sensitive key — that there is a value without showing it.

## Scope

1. `TopicAdmin.topicConfigs` implemented on `KafkaTopicAdmin`.
2. `ConfigSource` and `ConfigSynonym` types, if `ClusterTypes.scala`'s broker-config equivalents
   are not reusable verbatim; if they are, reuse them and say so.
3. The sensitivity rule: a sensitive entry has `value = None` and `isSensitive = true`, and there
   is no code path anywhere in this module that can produce a sensitive entry carrying a value.
4. The "visible topic without `DESCRIBE_CONFIGS`" rule: an empty config list plus a
   `NotAuthorized` skip, never an error.

## Non-goals

- No config **editing** (TP-006, M5). No `incrementalAlterConfigs`, no `validateOnly` dry run.
- No interpretation of values: no formatting of `retention.ms` as a duration, no `bytes` humanising.
  That is a rendering concern and belongs to TOP-030, where the unit table can be seen next to the
  screen that uses it.
- No default-value inference beyond what the broker reports in `source` and `synonyms`.

## Public Scala signatures to implement

```scala
package kui.kafka.admin

/** Where a configuration value came from, mapped from
  * `org.apache.kafka.clients.admin.ConfigEntry.ConfigSource` so nothing above `libs/kafka`
  * imports a Kafka enum. `Unknown` exists because a newer broker can name a source this enum does
  * not have, and an unhandled value must be a value rather than an exception.
  */
enum ConfigSource {
  case DynamicTopic, DynamicBroker, DynamicDefaultBroker, StaticBroker, Default, Unknown
}

/** One of the layers a value could have come from, with the value that layer holds. */
final case class ConfigSynonym(name: String, value: Option[String], source: ConfigSource)
```

```scala
// on KafkaTopicAdmin
def topicConfigs(connection: ClusterConnection, topics: List[TopicName], includeDocs: Boolean)
    : F[Either[KuiError, BatchResult[TopicName, List[TopicConfigEntry]]]]
```

### Behaviour it must have

- One `describeConfigs` per chunk of `AdminTuning.describeChunkSize` topics, with
  `includeSynonyms(true)` always and `includeDocumentation(includeDocs)` from the parameter.
- `includeDocs` defaults to `false` at every caller: documentation roughly doubles the response
  and only the Settings tab of a single topic asks for it. Asking for it on a broker older than
  2.6 is never an error — the field is simply `None`.
- **`isSensitive` ⇒ `value = None`.** Enforced in the conversion, not by the caller. Kafka already
  returns `null` for these, so the rule is "never invent a value", and the test asserts it against
  an entry the fake reports with both a value and the sensitive flag — because a future client
  version could.
- `UnknownServerException`, which some managed services return here for no discernible reason, is
  a `SkipReason.Failed(ErrorCode.UpstreamUnavailable, …)` for that topic and not a whole-call
  failure. This is the one place a generic server error is downgraded, and it is downgraded
  because the reference product learned to.
- `TopicAuthorizationException` → an **empty list** as the value and a `NotAuthorized` skip is
  **not** produced: the topic is present in `values` with `Nil`. That is deliberate and it is the
  opposite of `describeTopics`' rule. `admin-capabilities.md` §2 records the reference's behaviour,
  and the reason it is right here is that "this topic has no configuration you may see" is a
  renderable fact about a topic that exists, whereas "this topic has no description" is not.

## Decisions this task takes (no ADR covers them)

1. **An unauthorized config read is a present-but-empty value, not a skip.** Stated above with its
   reasoning. It is written down here rather than left to the implementer because the two adjacent
   methods do the opposite thing, and an inconsistency that is deliberate must be documented or it
   will be "fixed".
2. **Synonyms are always requested.** They cost one field per entry and they are the only way to
   answer "why is this value what it is", which is the question the tab exists for. TD-019 records
   that M1 carried broker-config synonyms and rendered none; M2 renders topic synonyms (TOP-030),
   so this is not a repeat.

## Tests required

`TopicConfigsSuite` (unit, fake pool):

- **`aSensitiveEntryNeverCarriesAValue`** — the fake reports `("password", "hunter2", sensitive =
  true)` and the conversion yields `value = None`. The one assertion that keeps a password off a
  screen.
- `anUnauthorizedTopicIsPresentWithAnEmptyConfig` — in `values`, not in `skipped`.
- `unknownServerExceptionIsAPerTopicSkip`.
- `documentationIsNoneWhenNotRequested` and `whenTheBrokerDoesNotSupportIt`.
- `synonymsAreOrderedFromMostToLeastSpecific` — the order Kafka returns them in, preserved, since
  the screen renders the first one as "the default".
- `unknownConfigSourceBecomesUnknown` rather than throwing.
- `chunksAtTheConfiguredSize` (property).
- `cancellingTheCallCancelsOutstandingChunks`.

## Observability

Inherited span and duration sample with `operation = describeConfigs`. One WARN, rate-limited per
cluster per scrape, when any topic returned `UnknownServerException`: it is a managed-service
symptom an operator should be able to correlate with a support ticket, and an unlimited WARN on a
10 000-topic scrape would be 10 000 lines.

## Degraded behaviour

- **No `DESCRIBE_CONFIGS`**: an empty config list; the tab renders "you are not permitted to see
  this topic's configuration" rather than an empty table.
- **Documentation unsupported**: `None`; the tooltip is simply absent.
- **Broker unreachable**: `Left`, and the snapshot serves its previous value as `Stale`.
