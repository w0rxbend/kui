# TOP-015 — Topic detail and partition use cases

- **ID:** TOP-015
- **Title:** Topic detail and partition use cases
- **Milestone / Feature:** M2 / TP-003, PA-001
- **Owner role:** Domain Architect (topics)
- **Context / service:** `services/topic/application`
- **Size:** M
- **Dependencies / blocked by:** TOP-013

## Goal (user value)

Opening one topic shows its partitions with their leaders, replicas and in-sync replicas, its
offsets and sizes, and — when a partition is offline — says so instead of showing a zero.

## Scope

1. `TopicDetailUseCase`: one topic's detail for one cluster, read live rather than from the
   snapshot, with the snapshot as the fallback.
2. The aggregate arithmetic: message count per partition and for the topic, under-replicated and
   offline partition counts, replication factor.
3. The refusal rule, implemented once: a topic with any partition whose offsets are missing has no
   topic-level message count.
4. Not-found handling: a topic that is not in the cluster is `TopicError.NotFound`, and a cluster
   that is not configured is `ClusterError.ClusterNotFound` — two different 404s, because the
   remedies differ.

## Non-goals

- No configuration. TOP-016 — the Settings tab is a separate call because it is a separate admin
  call with a separate failure mode, and joining them would make a config refusal hide the
  partitions.
- No consumer groups, connectors, ACLs or schemas. Those are the gateway's aggregation (TOP-024)
  and other milestones' services.
- No analysis, no active producers (M5).
- No mutation.

## Public Scala signatures to implement

```scala
package kui.topic.application

import kui.kernel.{ClusterId, TopicName}
import kui.topic.domain.{TopicDetail, TopicError}

trait TopicDetailUseCase[F[_]] {

  /** One topic's detail.
    *
    * Read **live** rather than from the snapshot, and this is the one place in M2 where a request
    * costs an admin call. A list is a thousand rows a user scans; a detail page is one topic a
    * user is looking at because something is wrong with it, and showing them a sixty-second-old
    * partition assignment during an incident is the wrong trade. The snapshot's row is the
    * fallback when the live read fails, marked stale with the snapshot's own `scrapedAt`.
    */
  def detail(cluster: ClusterId, topic: TopicName): F[Either[TopicError, Fresh[TopicDetail]]]
}

/** A value plus whether it was read now or recovered from the snapshot. The edge turns this into
  * `Section.Ok` or `Section.Stale`; making it explicit here stops the api layer from guessing.
  */
enum Fresh[+A] {
  case Live[A](value: A) extends Fresh[A]
  case FromSnapshot[A](value: A, scrapedAt: Instant, reason: String) extends Fresh[A]
}
```

```scala
package kui.topic.application

/** The arithmetic every screen in the milestone depends on, in one testable place.
  *
  * The refusal rule is the whole reason it is not inline: a per-topic message count computed from
  * a partial set of partitions is wrong rather than merely incomplete
  * (`libs/kafka/PORT-INVARIANTS.md` §1), and a rule implemented at three call sites is a rule
  * implemented at two.
  */
object PartitionAggregates {

  /** `None` if **any** partition's count is missing. */
  def messageCount(partitions: List[PartitionView]): Option[Long]

  /** `None` if any partition's size is missing — the same refusal, for the same reason. */
  def sizeBytes(partitions: List[PartitionView]): Option[Long]

  def outOfSyncReplicas(partitions: List[PartitionView]): Int
  def offlinePartitions(partitions: List[PartitionView]): Int
  def replicationFactor(partitions: List[PartitionView]): Option[Int]
}
```

## Decisions this task takes (no ADR covers them)

1. **The detail page reads live; the list reads the snapshot.** Stated in the signature's doc
   comment with its reasoning. The cost is one admin call per detail view, which is bounded by the
   number of humans looking at topic pages, not by the topic count.
2. **A live read failure falls back to the snapshot row rather than to an error**, and says which
   it did. The alternative — a red page when the snapshot has a perfectly good answer thirty
   seconds old — is the behaviour ADR-032's stale rule exists to prevent.
3. **Size and count refuse independently.** A cluster that reports offsets but refuses log
   directories shows counts and an em dash for size. Coupling them would lose a number the operator
   can have.

## ADRs this task must obey

ADR-027 (staleness is explicit and carries `scrapedAt`), ADR-032 (stale data is shown, greyed and
timestamped, not hidden), ADR-034, ADR-041 A1/A3.

## Tests required

`PartitionAggregatesSuite` (unit + property):

- **`messageCountIsNoneIfAnyPartitionIsMissing`** (property) — the invariant, at the level that
  owns it.
- `messageCountSumsWhenEveryPartitionIsPresent` (property).
- `anEmptyPartitionContributesZeroNotNothing` — `min == max` is a count of zero and must not be
  confused with an absent count.
- `sizeRefusesIndependentlyOfCount`.
- `outOfSyncCountsReplicasNotPartitions` — the reference's own column is "out of sync replicas",
  and counting partitions instead is an easy and invisible mistake.
- `offlinePartitionsCountsLeaderlessOnes`.
- `replicationFactorIsNoneForNoPartitions`.

`TopicDetailUseCaseSuite` (`munit-cats-effect` + fakes):

- `aLiveReadIsReportedAsLive`.
- **`aFailedLiveReadFallsBackToTheSnapshotAndSaysSo`** — `FromSnapshot` with the snapshot's
  `scrapedAt` and a reason.
- `aFailedLiveReadWithNoSnapshotIsAnError`.
- `anUnknownTopicIsNotFoundEvenWhenTheSnapshotIsStale` — a topic deleted since the scrape must not
  be resurrected by the fallback.
- `anUnknownClusterIsClusterNotFound`.
- `partitionsAreOrderedByPartitionId` (property).
- `cancellingTheRequestCancelsTheAdminCall`.

## Observability

- Span `topic.detail` with `cluster`, `topic` and `source = live | snapshot`.
- `kui.topic.detail.fallback` counter — how often the live read failed and the snapshot saved the
  page. A rising count is an early warning of a cluster going bad, before any list is affected.
- No log line per request.

## Degraded behaviour

- **Live read fails, snapshot present**: the page renders from the snapshot with a stale badge and
  its timestamp.
- **Live read fails, no snapshot**: `Section.Unavailable` with the reason and a retry.
- **Offsets refused, description fine**: partitions render with leaders and replicas, counts as em
  dashes.
- **One partition offline**: that row shows "offline" in place of a leader, the topic's count cell
  is an em dash, and the indicator strip shows the offline count — three consistent statements of
  one fact, which is what stops an operator from thinking the topic is empty.
