# TOP-019 — `libs/contracts-core`: `PageDto` and the topic DTO fragments

- **ID:** TOP-019
- **Title:** `libs/contracts-core`: `PageDto` and the topic DTO fragments
- **Milestone / Feature:** M2 / TP-001, TP-003, PA-001
- **Owner role:** Chief Architect
- **Context / module:** `libs/contracts-core` (cross-compiled)
- **Size:** M
- **Dependencies / blocked by:** TOP-011

## Goal (user value)

The shape of a paged list and the shape of a topic row are written once and compiled by both the
service that produces them and the browser that renders them, so the two cannot disagree.

## Scope

1. `kui.contracts.paging.PageDto[A]` — the wire form of `libs/kernel`'s `Page`: `{items, page:
   {page, pageSize, totalItems, pageCount, nextPageToken}}`, with explicit Circe codecs and a Tapir
   schema.
2. `kui.contracts.topic.*` — the DTO fragments shared by the topic service's contract **and** the
   gateway's topic-overview aggregation: `TopicRowDto`, `TopicDetailDto`, `PartitionDto`,
   `ReplicaDto`, `TopicConfigEntryDto`.
3. `pageCount` derived, never carried independently: it is computed from `totalItems` and
   `pageSize` in one place.
4. Golden documents for each, committed, and decoded by the cross-compiled suite so the JVM and
   Scala.js codecs are proven identical.

## Non-goals

- No endpoints. TOP-020.
- No second page type. `PageDto` is a *rendering* of `libs/kernel`'s `Page`; it does not compute
  totals, cut pages or sort. If it ever needs to, something upstream is broken.
- No topic mutation DTOs.
- No `Section` changes. `Section` exists and topic responses compose it.

## Design references

- ADR-026 — the response shape (`{items, page}`) and the reason offset paging is kept for these
  lists.
- `research/kafbat/api-analysis.md` "Proposed KUI `/api/v1` mapping": "responses carry `{ items,
  page: { totalItems?, pageCount?, nextPageToken? } }`" and, for topics specifically, "Fix
  `pageCount` bug; add `page.totalItems`".
- ADR-007 (explicit Circe codecs, no automatic derivation), ADR-003.
- `libs/contracts-core/src/kui/contracts/cluster/ClusterDtos.scala` is the shape to copy, including
  the rule that a field which is permanently `None` is not put on the wire at all (CLAPI-001's
  decision 3).

## Public Scala signatures to implement

```scala
package kui.contracts.paging

/** One page of a list on the wire.
  *
  * `totalItems` is the size of the list **after every filter**, and `pageCount` is derived from it
  * here rather than sent independently by the producer. That is not tidiness: the implementation
  * this project is modelled on sends a `pageCount` computed before its internal-topic filter runs,
  * so its page count disagrees with its own rows whenever the filter removes anything
  * (`research/kafbat/api-analysis.md` §3.3). One number, derived from another, cannot disagree
  * with it.
  */
final case class PageInfo(page: Int, pageSize: Int, totalItems: Option[Long], nextPageToken: Option[String]) {
  /** Ceiling division, and at least 1 so an empty list is "page 1 of 1" rather than "1 of 0". */
  def pageCount: Option[Int]
}

final case class PageDto[A](items: List[A], page: PageInfo)

object PageDto {
  given [A: {Encoder, Decoder}] => Codec[PageDto[A]]
  given [A: Schema] => Schema[PageDto[A]]

  /** The only constructor from the kernel type, so the mapping happens once. */
  def of[A, B](page: kui.kernel.Page[A])(f: A => B): PageDto[B]
}
```

package kui.contracts.topic

import kui.kernel.{PartitionId, TopicName}

## Decisions this task takes (no ADR covers them)

1. **`pageCount` is derived on the DTO, not sent.** Above, with the citation.
2. **`nextPageToken` is on `PageInfo` and is always `None` in M2.** ADR-026 puts cursors on
   messages and tracking, not on sorted lists, and this is the one permanently-`None` field the
   plan admits — because it is `PageDto`'s field, shared with the endpoints of M3 that *will* fill
   it, and a second page shape for cursors would be exactly the duplication this module exists to
   prevent. The topic contract's documentation says it is unused.
3. **`TopicDetailDto` embeds the row rather than repeating its fields.** The list row and the
   detail header show the same numbers, and two flat records would let them drift.
4. **`source` on a config entry is a `String`, not an enum, on the wire.** A broker can name a
   source KUI's enum does not have, and a decode failure on an unknown config source would fail a
   whole page over a cosmetic field. The service maps its enum to a stable lowercase spelling.

## ADRs this task must obey

ADR-003 (the contract is the single source of the wire shape), ADR-007 (explicit codecs), ADR-026,
ADR-041 A6 (no JVM-only dependency on the shared or `.js` halves).

The golden document `page.json` must read exactly:

```json
{"items":[],"page":{"page":1,"pageSize":25,"totalItems":0,"pageCount":1,"nextPageToken":null}}
```

An empty list is page 1 of 1. A `pageCount` of 0 would make a client render "page 1 of 0".

## Tests required

`PageDtoSuite` (cross-compiled, unit + property):

- **`pageCountIsDerivedFromTotalItems`** (property) — over generated totals and page sizes,
  including 0 and exact multiples.
- `anEmptyListIsPageOneOfOne`.
- `pageCountIsAbsentWhenTotalItemsIs` — a cursor-paged response of M3 will have neither.
- `ofPreservesPaginationAndMapsItems` (property) — `PageDto.of` over `libs/kernel`'s `Page`.
- `goldenRoundTrip`.

`TopicDtosSuite` (cross-compiled):

- `everyGoldenDecodesAndReEncodesIdentically` — for all four goldens.
- **`aMissingMessageCountIsNullNotZero`** — asserted on the JSON text, because this is the field
  whose wrong rendering makes an operator think a topic is empty.
- `anOfflinePartitionHasANullLeader` — on the JSON text, for the same reason.
- `aSensitiveConfigEntryHasNoValueOnTheWire`.
- `unknownConfigSourceStringsDecode` — a source KUI has never heard of does not fail the document.
- `theJvmAndJsEncodersAgree` — the golden files are the mechanism: both platforms' suites decode
  and re-encode the same bytes, and M1's second integration defect is the reason this is asserted
  rather than assumed.

## Degraded behaviour

The DTOs are the vocabulary degradation is expressed in: `Section` wraps them at the endpoint
level, and every unknowable value is an `Option` that renders as an em dash. Nothing here can fail.
