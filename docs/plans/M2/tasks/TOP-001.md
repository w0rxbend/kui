# TOP-001 — `libs/kernel`: `NameIndex`, `SearchMode` and the ranking contract

- **ID:** TOP-001
- **Title:** `libs/kernel`: `NameIndex`, `SearchMode` and the ranking contract
- **Milestone / Feature:** M2 / SF-001, TP-001
- **Owner role:** Principal Scala Engineer
- **Context / module:** `libs/kernel` (cross-compiled)
- **Size:** M
- **Dependencies / blocked by:** —

## Goal (user value)

Typing part of a topic name finds the topic, on a cluster with ten thousand of them, without a
Lucene dependency and without a second definition of "matches" in the browser.

## Scope

1. `kui.kernel.search.SearchMode`: `Plain | Fts`, with its wire spelling.
2. `kui.kernel.search.NameIndex`: built once from a list of names, answering a query with the
   matching names in ranked order.
3. The two matchers: `Plain` is a case-insensitive substring test; `Fts` is a trigram score.
4. The ranking contract, stated as tests: stable ordering on equal scores, an empty query matches
   everything in input order, and `Plain` is exactly equivalent to a naive substring filter.
5. Cross-compilation: the same code links and runs on Scala.js, because the browser matches
   favourites and client-side filters with it.

## Non-goals

- **No Lucene, no persistent index, no analyzer configuration.** ADR-038 defers all of it behind a
  benchmark; TP-002 and SF-002 are M9. This task must not add a dependency of any kind.
- No configuration of n-gram sizes. One trigram size, chosen here, documented here.
- No index over anything but names: not configs, not values. Kafbat indexes configs too; nothing
  in M2's criteria needs it and an index of values is a much larger memory claim.
- No topic knowledge. `NameIndex` indexes strings and does not know what they name.

## Design references

- ADR-038 (in-memory index first, `NameIndex` in `libs/kernel`, `q` plus `mode`, Lucene deferred
  behind a benchmark, "property tests cover ranking stability and the equivalence of `plain` with
  a naive substring filter" — those two sentences are this task's acceptance criteria).
- `research/kafbat/api-analysis.md` Finding 2 "Full-text search", for the semantics being
  replaced, and DEVPLAN §10 D4 for why the boolean flag becomes a two-value mode.
- `research/kafbat/feature-matrix.md` SF-1 and SF-2.

## Public Scala signatures to implement

```scala
package kui.kernel.search

/** How a `q` parameter is matched.
  *
  * Two values rather than the reference product's boolean `fts`, whose meaning depended on two
  * server-side settings a client could not see (DEVPLAN §10 D4).
  */
enum SearchMode {
  case Plain
  case Fts

  /** The lowercase name the query string uses. Spelled out rather than derived from the case
    * name, so renaming a case cannot silently change the wire contract.
    */
  def wire: String = this match {
    case Plain => "plain"
    case Fts => "fts"
  }
}

object SearchMode {
  val Default: SearchMode = Plain
  def fromWire(raw: String): Option[SearchMode]
  given CanEqual[SearchMode, SearchMode] = CanEqual.derived
}
```

```scala
package kui.kernel.search

/** A searchable set of names, built once and queried many times.
  *
  * It is built inside a per-context snapshot (ADR-027) and thrown away with it, so construction
  * cost is paid once per scrape rather than once per request. `Plain` needs no index at all and
  * is answered by a scan; the trigram map exists for `Fts` and is built lazily so that a
  * deployment that never uses `fts` never pays for it.
  */
final class NameIndex private (names: Vector[String]) {

  /** The names matching `query` under `mode`, best first.
    *
    * Ties keep the order the index was built in, which is the caller's order — so a caller that
    * built the index from an already sorted list gets a deterministic result, and a later `sort`
    * is stable over it.
    *
    * A blank query matches every name in build order. That is not a special case bolted on: an
    * empty search box means "no filter", and returning nothing would make the list vanish when
    * the user deletes their query.
    */
  def search(query: String, mode: SearchMode): List[String]

  def size: Int
}

object NameIndex {

  /** The trigram width. Three, not two or four: two is noise on names that share `__`, four
    * misses three-character queries entirely, and the reference product's own n-gram range
    * (1..4) exists to support prefix queries KUI answers with a substring test instead.
    */
  val NGram: Int = 3

  def of(names: List[String]): NameIndex

  /** The scoring function, exposed so a suite can assert ranking without building an index. The
    * score is the fraction of the query's trigrams present in the name, in [0.0, 1.0]; a query
    * shorter than [[NGram]] falls back to the substring test and scores 1.0 or 0.0.
    */
  def score(name: String, query: String): Double
}
```

## Decisions this task takes (no ADR covers them)

1. **A query shorter than three characters falls back to substring matching in `Fts` mode.** A
   trigram index cannot answer a two-character query at all, and the honest choices are "no
   results" or "substring". A search box that returns nothing after two keystrokes reads as
   broken.
2. **Scores are not returned.** The API is "the matching names, best first". A relevance number
   on the wire is a number somebody will render, and its scale is an implementation detail that
   ADR-038's deferred Lucene switch would change.
3. **The index is case-insensitive by lowercasing both sides with `Locale.ROOT` semantics.** On
   Scala.js `toLowerCase` is already locale-independent; on the JVM the default locale would make
   a Turkish deployment match differently from a British one, which is the kind of bug that is
   found once a year.

## Tests required

`SearchModeSuite`:

- `wireSpellingsAreStable` — a table of both values.
- `fromWireRejectsAnythingElse` — `Some`/`None`, never a default, so an unknown `mode` becomes a
  400 at the edge instead of silently searching the wrong way.

`NameIndexSuite` (unit + property, cross-compiled):

- **`plainIsExactlyASubstringFilter`** (property) — for any list of names and any query, the
  result equals `names.filter(_.toLowerCase.contains(query.toLowerCase))`, in input order. This is
  ADR-038's stated property and the one that makes `plain` explainable to a user.
- `anEmptyQueryMatchesEverythingInBuildOrder` (property).
- **`rankingIsStableForEqualScores`** (property) — shuffle names with identical scores and assert
  the result follows build order, not hash order.
- `ftsFindsATransposition` — the case `plain` cannot.
- `ftsIsASupersetOfPlainForQueriesOfThreeOrMore` (property) — every plain match is also an fts
  match, so switching the toggle never *loses* a result.
- `shortQueriesFallBackToSubstringInFtsMode`.
- `caseIsIgnoredInBothDirections`.
- `scoreIsBoundedToZeroOne` (property).
- `buildingTenThousandNamesIsUnderTheBudget` — construct 10 000 generated names and assert the
  build and one query complete; the assertion is on completion, not on a stopwatch reading, and
  the measured figure is printed for TOP-035's benchmark to quote.

## Observability

None. `libs/kernel` has no runtime and takes no logger; this is a pure data structure. The cost
of building it is observed one layer out, by the snapshot that builds it (TOP-013), which records
it under the cache metrics ADR-016 requires.

## Degraded behaviour

There is none to speak of, and that is the point of putting the matcher here: a search cannot
fail, cannot time out and cannot be unavailable. A query that matches nothing returns an empty
list, and the screen renders its empty state rather than an error.

10 000 names, which is the number that decides whether Lucene is ever revisited.
