# TOP-032 — The `kui.topics.*` configuration slice

- **ID:** TOP-032
- **Title:** The `kui.topics.*` configuration slice
- **Milestone / Feature:** M2 / OT-003
- **Owner role:** Infrastructure Lead
- **Context / module:** `libs/config`
- **Size:** S
- **Dependencies / blocked by:** TOP-013

## Goal (user value)

An operator whose cluster has fifty thousand topics can slow the scrape down, widen the chunks and
lengthen the interval, without a rebuild — and every one of those dials has a documented default
that works.

## Scope

1. `TopicsConfig` in `libs/config`: the typed slice, decoded with Ciris, with accumulated errors.
2. The keys: refresh interval, scrape timeout, internal prefix, search defaults, chunk sizes and
   parallelism, and the profile-client block.
3. Validation with real bounds, so an impossible value is a startup error naming the key rather
   than a mystery at runtime.
4. Documentation of every key in `docs/operations/configuration.md`, with its default and the
   consequence of changing it.

## Non-goals

- No `kui.clusters[]` for the topic service. It holds no cluster list; the profile client is the
  only source (DEVPLAN §10 D1, risk R-7). A key that looked like a cluster list here would be the
  drift that risk names.
- No store configuration. The topic service is not a store client.
- No per-cluster overrides of the topic settings in M2. `AdminTuning` is already per cluster and
  arrives in the profile; these are the topic service's own process-level dials.
- No hot reload of these keys. They are process configuration and a restart is the documented way
  to change them (ADR-036: process-local sections are owned by each process).

## Design references

- ADR-013 (Ciris, typed configuration, every error accumulated into one message), ADR-036 (who owns
  which section).
- `libs/config/src/kui/config/ClusterConfig.scala` and `StoreConfig.scala` — the existing slices and
  their validation style.
- `research/kafka/admin-capabilities.md` DC-D4 — the chunk sizes and their defaults (200 for
  describes and offsets, parallelism 4) and the reason they are configurable per cluster.
- DEVPLAN §10 D3 (the internal prefix), D5 (the interval and why it is 60 s rather than the cluster
  service's 30).

## Public Scala signatures to implement

```scala
package kui.config

import scala.concurrent.duration.FiniteDuration

/** The topic service's own dials.
  *
  * Every default here is a number with a reason, and the reasons are in
  * `docs/operations/configuration.md` rather than only in this file, because the person who needs
  * to change one is reading the operator documentation and not the source.
  */
final case class TopicsConfig(
    /** How often a cluster's topic snapshot is rebuilt. Sixty seconds, twice the cluster service's
      * thirty, because a topic scrape is an order of magnitude more expensive than a cluster one
      * and its data changes an order of magnitude less often. */
    refreshInterval: FiniteDuration,

    /** A whole scrape's budget. Past it the scrape is cancelled and the previous snapshot kept: a
      * scrape that outlives its interval would otherwise overlap the next one and double the load
      * on a cluster that is already struggling. Default 45 s, deliberately shorter than the
      * interval. */
    scrapeTimeout: FiniteDuration,

    /** A topic is internal if Kafka says so **or** its name starts with this. Default `__`. Both
      * conditions, never one: `__kui_config` is an ordinary topic to Kafka and noise to an
      * operator (DEVPLAN §10 D3). */
    internalPrefix: String,

    /** What `mode` means when a request omits it. Default `plain`. */
    defaultSearchMode: SearchMode,

    /** Default and maximum page size, bounded by ADR-026's 500. */
    defaultPageSize: Int,
    maxPageSize: Int
)

object TopicsConfig {
  val Default: TopicsConfig
  def config: ConfigValue[Effect, TopicsConfig]
}
```

Keys, exactly:

| Key | Type | Default | Bounds |
| --- | --- | --- | --- |
| `kui.topics.refreshInterval` | duration | `60s` | 5 s … 1 h |
| `kui.topics.scrapeTimeout` | duration | `45s` | 1 s … `refreshInterval` |
| `kui.topics.internalPrefix` | string | `__` | 1 … 16 characters |
| `kui.topics.defaultSearchMode` | `plain \| fts` | `plain` | — |
| `kui.topics.defaultPageSize` | int | `25` | 1 … `maxPageSize` |
| `kui.topics.maxPageSize` | int | `500` | 1 … 500 (ADR-026) |
| `kui.clusterProfiles.url` | uri | — (required) | the cluster service's base |
| `kui.clusterProfiles.pollInterval` | duration | `60s` | 5 s … 1 h |
| `kui.clusterProfiles.startupTimeout` | duration | `10s` | 1 s … 60 s |

## Decisions this task takes (no ADR covers them)

1. **`scrapeTimeout` must be less than `refreshInterval`, and it is validated as such.** Two dials
   whose combination is nonsense should fail at startup, not produce overlapping scrapes at three
   in the morning. The cross-field check is why this is a validated case class rather than six
   independent values.
2. **`maxPageSize` cannot exceed ADR-026's 500.** An operator raising it to 100 000 would be
   configuring an outage, and `PageSize`'s own doc comment already says so.
3. **The chunk sizes are not here.** They live in `AdminTuning`, per cluster, and arrive in the
   profile — because the right chunk size depends on the broker, not on the KUI process.

## ADRs this task must obey

ADR-013 (accumulated errors; unknown keys rejected), ADR-026 (the page bounds), ADR-036 (process-local
sections are the process's own), ADR-038 (mode names).

## Library coordinates

`is.cir::ciris` 3.15.0, already on `libs.config` (`DEPENDENCY_MATRIX.md`).

## Acceptance criteria

```
$ ./mill libs.config.test
$ ./mill libs.config.compile
```

And, against the topic service:

```
$ KUI_TOPICS_REFRESHINTERVAL=10s KUI_TOPICS_SCRAPETIMEOUT=30s ./mill services.topic.app.run
… startup fails, exiting 1, with:
  kui.topics.scrapeTimeout (30s) must be shorter than kui.topics.refreshInterval (10s)
```

One message, naming both keys and both values. An error that names only the field is an error that
sends the reader back to the documentation.

## Tests required

`TopicsConfigSuite` (MUnit + ScalaCheck):

- `defaultsAreTheDocumentedOnes` — asserted against the table above, so the code and the operator
  documentation cannot drift.
- **`everyProblemIsReportedTogether`** — an out-of-range interval, an unknown mode and a page size
  above the maximum produce one message containing all three.
- `anUnknownKeyUnderKuiTopicsIsRejected` — ADR-013's rule, which is what turns a typo into a startup
  error instead of a silently ignored setting.
- **`scrapeTimeoutMustBeShorterThanTheInterval`** — both directions.
- `maxPageSizeAboveFiveHundredIsRejected`.
- `anEmptyInternalPrefixIsRejected` — an empty prefix would make every topic internal.
- `theProfileUrlIsRequiredAndMustBeAValidUri`.
- `boundsAreInclusiveAtTheDocumentedEdges` (property).

## Observability

The startup configuration summary logs the resolved values, redacted where relevant. There is
nothing secret in this slice, and logging it is what lets an operator confirm which file actually
took effect — the question M1's all-in-one defect made unanswerable.

## Degraded behaviour

None at runtime: a configuration that parses is a configuration that works. A configuration that
does not parse stops the process before anything binds, with every problem named.

## Docs to update

`docs/operations/configuration.md` — the table above, each row with the consequence of changing it,
and a short paragraph on tuning for a large cluster: raise the interval before raising the timeout,
and remember that the chunk sizes are per cluster and live with the cluster's configuration.
