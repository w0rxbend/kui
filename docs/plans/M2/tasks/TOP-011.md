# TOP-011 — Topic domain: the model and its invariants

- **ID:** TOP-011
- **Title:** Topic domain: the model and its invariants
- **Milestone / Feature:** M2 / TP-001, TP-003, TP-004, PA-001
- **Owner role:** Domain Architect (topics)
- **Context / service:** `services/topic/domain`
- **Size:** M
- **Dependencies / blocked by:** —

## Goal (user value)

The topic service has its own words for what a topic is, so that every rule about counting,
sorting and rendering is stated once, in a module that no Kafka client and no HTTP library can
reach.

## Scope

1. The Mill module `services.topic.domain` and its test module.
2. `TopicSummary` — the row a list shows.
3. `TopicDetail` and `PartitionView` — the detail page's aggregate.
4. `TopicConfig` and `TopicConfigEntry` — the settings tab's aggregate.
5. `TopicSnapshot` — every summary of one cluster at one instant, plus the `NameIndex` built over
   the names and the `scrapedAt` that every screen shows.
6. The invariants, as smart constructors returning `Either[ValidationError, _]` or as types that
   cannot express the invalid state.

## Non-goals

- **No ports.** TOP-012.
- **No use cases, no `F[_]`, no cats-effect.** Rule A1 allows this module `libs/kernel` and
  cats-core only.
- No DTOs, no Circe, no Tapir. Rule A2 and A3.
- No mutation model: no `TopicCreation`, no `TopicUpdate`, no reassignment plan. M5.
- No `Ping`-style placeholder. This module is created with its real model or not at all.

## Public Scala signatures to implement

```scala
package kui.topic.domain

import java.time.Instant
import kui.kernel.{PartitionId, TopicName}

/** One row of the topic list.
  *
  * Three fields are `Option` and each absence means something specific:
  *
  *   - `messageCount` is `None` when the count could not be computed **for the whole topic** —
  *     which is what happens when any partition is leaderless or its offsets were skipped. A count
  *     summed over a partial set of partitions would be wrong rather than incomplete, and a wrong
  *     number is worse than no number because only one of them starts an investigation
  *     (`libs/kafka/PORT-INVARIANTS.md` §1, DEVPLAN §10 D6).
  *   - `sizeBytes` is `None` when the broker would not report log directories.
  *   - `replicationFactor` is `None` for a topic with no partitions, which Kafka permits
  *     transiently after a create.
  */
final case class TopicSummary(
    name: TopicName,
    isInternal: Boolean,
    partitionCount: Int,
    replicationFactor: Option[Int],
    outOfSyncReplicas: Int,
    offlinePartitions: Int,
    messageCount: Option[Long],
    sizeBytes: Option[Long]
) {
  def hasOfflinePartitions: Boolean = offlinePartitions > 0
  def isUnderReplicated: Boolean = outOfSyncReplicas > 0
}

/** One partition on the detail page. `leader` is `None` for an offline partition — never `-1`,
  * which the reference products use and which sorts and sums as a number.
  */
final case class PartitionView(
    partition: PartitionId,
    leader: Option[BrokerId],
    replicas: List[Replica],
    earliestOffset: Option[Long],
    latestOffset: Option[Long],
    sizeBytes: Option[Long]
) {
  /** `None` when either offset is missing: the same refusal as `TopicSummary.messageCount`, one
    * level down, and the level the aggregate is computed from. */
  def messageCount: Option[Long]
  def isLeaderless: Boolean = leader.isEmpty
}

/** A replica, with the two flags the partition table renders as chips. */
final case class Replica(broker: BrokerId, isLeader: Boolean, isInSync: Boolean)

final case class TopicDetail(
    summary: TopicSummary,
    partitions: List[PartitionView],
    cleanupPolicy: Option[String],
    segmentCount: Option[Int]
)

/** The whole configuration of one topic. A sensitive entry has no value, ever. */
final case class TopicConfigEntry(
    name: String,
    value: Option[String],
    defaultValue: Option[String],
    source: ConfigSource,
    isSensitive: Boolean,
    isReadOnly: Boolean,
    documentation: Option[String]
) {
  /** What the screen bolds: a value that is not the default. */
  def isOverridden: Boolean = !isSensitive && value != defaultValue
}

/** Every topic of one cluster, at one instant, with the index the list searches. */
final case class TopicSnapshot(
    topics: Vector[TopicSummary],
    index: kui.kernel.search.NameIndex,
    scrapedAt: Instant,
    /** Topics the scrape could not describe, with the reason, so the list can say "9 998 of
      * 10 000 topics; 2 could not be read" instead of quietly showing fewer. */
    incomplete: Map[TopicName, String]
) {
  def byName: Map[TopicName, TopicSummary]
  def size: Int = topics.size
}

/** The fields a topic list may be sorted by. An enum and not a string, so an unknown `sort` is a
  * decode failure at the edge instead of a silently ignored parameter.
  */
enum TopicSortField {
  case Name, Partitions, ReplicationFactor, OutOfSyncReplicas, Size, MessageCount
}
```

## Decisions this task takes (no ADR covers them)

1. **`TopicSnapshot.topics` is a `Vector`, not a `List`.** The list pipeline slices it by index for
   every page of every request on a 10 000-element collection; a `List` makes that O(n) per page
   for no reason. It is a domain type and the choice is a data-structure one, so it is recorded
   here rather than argued in a review.
2. **`TopicSummary` carries counts, not the partitions.** The detail page loads partitions; a list
   of 10 000 topics × 50 partitions each would be half a million objects held in a snapshot to
   render six columns.
3. **`offlinePartitions` is a count on the summary, and the reason the count exists is rendering,
   not arithmetic.** It is what lets the list say "the count is missing *because* two partitions
   are offline" instead of showing an unexplained em dash.

## Tests required

`TopicSummarySuite` (unit + property):

- `messageCountIsNoneWhenAnyPartitionIsMissing` — constructed from partitions, asserted at the
  aggregate.
- `underReplicatedIsDerivedNotStored` (property).
- `internalIsWhateverItWasConstructedWith` — the union rule lives in the application layer, and
  this suite asserts the domain does **not** apply a prefix rule of its own, so there is one place
  the rule can be got wrong.

`PartitionViewSuite`:

- **`aLeaderlessPartitionHasNoLeaderAndNoCount`**.
- `isrIsASubsetOfReplicas` (property) — a constructed value that violates it is refused with a
  named `ValidationError`, because an ISR larger than the replica set is a broker bug and rendering
  it as "5 of 3 in sync" would be KUI's.
- `exactlyOneReplicaIsLeaderWhenThereIsALeader` (property).
- `messageCountIsNeverNegative` (property).

`TopicSnapshotSuite`:

- `byNameIsConsistentWithTopics` (property).
- `theIndexContainsExactlyTheTopicNames` (property) — the assertion that stops a snapshot whose
  index and rows have drifted apart, which would make search silently wrong.
- `anIncompleteTopicIsStillCounted` — `incomplete` explains, it does not remove.

## Observability

None: this module has no runtime and takes no logger. The counts it exposes — `offlinePartitions`,
`incomplete` — are what the application layer turns into metrics in TOP-013.

## Degraded behaviour

Expressed in the types rather than in code: every field that a cluster can refuse to answer is an
`Option`, every aggregate over such fields refuses rather than guesses, and `incomplete` carries
the reason so a screen can explain a short list.
