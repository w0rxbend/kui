instead of copying a ping button, and the eight microfrontends still to come are the same shape as
each other.

This task closes `TECH_DEBT.md` **TD-015**, whose remedy is written as: "the pattern is decided
against a real screen in M2 grooming and `docs/frontend/features.md` records it".

## Scope

1. Rewrite `docs/frontend/features.md` from what `ui-clusters` and `ui-topics` actually do.
2. The registration checklist: `FeatureId`, the thunk, `staticRoutes`, the Mill module, the CSS
   directory, the test module.
3. The page-composition pattern: a feature class holding its own `Queries`; pages as pure functions
   of signals; a row model as a pure function; screens taking `navigate` and `hrefFor` rather than
   a router.

## What the document must contain

Written for someone who has never seen the project, per the explanation style the repository uses.

1. **What a microfrontend is here** — a Scala.js class in its own Mill module, linked into its own
   JavaScript file, fetched the first time somebody navigates to it, and registered in exactly one
   place.
2. **The registration checklist**, as six numbered steps with the file for each.
3. **The split border, and how it is destroyed.** The thunk's body is
   `js.dynamicImport(new kui.ui.<f>.<F>Feature())` and nothing else; assigning it to a `val`,
   naming the type in a signature, or mentioning the class anywhere outside the import puts the
   whole feature into `main.js`, where every user downloads it on first paint — including users
   whose deployment does not have that service. Nothing about the source looks different when that
   happens, which is why `checkBundleShape` asserts the shape of the linked output. **And**: the
   check passes today while the promise is broken, because `main.js` statically *imports* the split
   file (TD-016) — the document says so, so a reader does not conclude from a green build that the
   promise is kept.
4. **The static half.** Nav entry, route patterns and the `history.state` codec are ordinary data,
   linked normally, because all of it must be known before anything is downloaded.
5. **State.** A feature builds its own client and its own `Queries` in its constructor, because a
   dynamic import cannot be passed arguments; feature state is a class holding `Var`s, never a
   global (PLAN §21).
6. **Pages.** A page is a function from signals to an element; a row model is a **pure function**
   from the response to the values the table draws, so every rendering rule is a test row instead
   of a screenshot to squint at. Both real features do this and it is the single highest-value
   convention in the frontend.
7. **Navigation.** A page takes `navigate` and `hrefFor` rather than reaching for a router, so it
   is drivable from a suite; and a row is a real `<a>` with a real `href`, so copy, bookmark and
   open-in-new-tab work. TD-020 records what is still missing (a navigation port on `KuiFeature`).
8. **Failure rendering.** The four states of ADR-032 and which one each response shape produces,
   with the topic list's row-model table as the worked example.
9. **Testing.** jsdom by default; pure suites for row models; `domtestutils` for the DOM;
   **recorded responses, not hand-written fixtures**, for anything that crosses a process boundary
   — with the M1 incident stated: the dashboard decoded `ClustersResponse` while the gateway sends
   `ClusterOverviewDto`, the decoder defaulted a missing `items` to `Nil`, every response decoded
   successfully into zero rows, and the page rendered "No clusters yet" under a "last updated just
   now" timestamp against a working broker.
10. **Two Scala.js test modules cannot be named in one Mill invocation** — a harness limitation
    recorded in `STATUS.md`, and the reason every frontend command in this repository is its own
    line.

## Decisions this task takes (no ADR covers them)

1. **The pattern is what `ui-topics` does, and `ui-clusters` is described as the earlier
   approximation of it.** Two examples that disagree need a tiebreak, and the newer one was written
   with the older one's deviations in front of it.
2. **The document names the open debts rather than describing an ideal.** A reader who follows an
   idealised document and then finds `history.pushState` in the code concludes the document is
   wrong about everything.
