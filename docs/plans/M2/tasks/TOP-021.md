# TOP-021 — Topic `api`: server logic, envelope, `Section` staleness, query validation

- **ID:** TOP-021
- **Title:** Topic `api`: server logic, envelope, `Section` staleness, query validation
- **Milestone / Feature:** M2 / TP-001, TP-003, TP-004, PA-001
- **Owner role:** Chief Architect
- **Context / service:** `services/topic/api`
- **Size:** L
- **Dependencies / blocked by:** TOP-020, TOP-014, TOP-015, TOP-016

## Goal (user value)

The topic service answers HTTP: every endpoint of the contract, with domain values mapped to DTOs,
failures mapped to one error envelope, and stale data marked as stale rather than hidden or
faked.

## Scope

1. The Mill module `services.topic.api` and its test module.
2. `TopicRoutes`: server logic for the five endpoints, over the use cases.
3. `TopicMapping` (Chimney, per ADR-033): domain → DTO, in this layer and nowhere else.
4. `TopicErrors`: `TopicError` → `ErrorEnvelope`, with the status codes and the `KUI-*` codes.
5. `Section` assembly: `Ok`, `Stale` (with `scrapedAt` and a reason) or `Unavailable`, from the
   snapshot's status and the use cases' `Fresh` values.
6. The service's OpenAPI document, generated and committed beside the module as the cluster
   service's is.
7. Health and readiness endpoints, and the capability report the gateway polls.

## Non-goals

- No business rules. If a rule needs writing here, it belongs in `application`. The one thing this
  layer decides is *presentation of failure*.
- No page construction. `Page` arrives from the use case and is mapped with `PageDto.of`; this
  layer never slices, sorts or counts. Risk R-4 is precisely a page rebuilt at this layer.
- No mutation routes.
- No wiring. TOP-022.

## Design references

- `services/cluster/api/` — the whole module is the worked example: the envelope mapping, the
  `Section` assembly from `SnapshotFreshness`, the stub-interpreter suite and the OpenAPI task.
  Note CLAPI-004's recorded deviation 2 — `SnapshotFreshness` loses the error's code, so every
  failing scrape reports `UPSTREAM_UNAVAILABLE` — and **do not reproduce it**: this task carries
  the `ErrorCode` through to the section's `reason`.
- ADR-033 (Chimney, mapping at the `api` boundary), ADR-034 (the envelope and `statusOf`),
  ADR-032 (how the three states render), ADR-039 §6.
- `ARCHITECTURE.md` §6 (the degraded-response envelope).

## Decisions this task takes (no ADR covers them)

1. **A cluster that is configured but has never been scraped answers `Section.Unavailable`, not an
   empty page.** An empty list from a cluster that has ten thousand topics is a lie that looks
   like data, and it is the exact failure M1's second integration defect produced on the
   dashboard.
2. **`incompleteTopics` is reported even when the section is `Stale`.** It describes the data being
   shown, and the data being shown is the stale snapshot.
3. **The detail endpoint's embedded partition list is capped at 500 with a
   `partitionsTruncated: true` flag**, per TOP-020's decision 2. The flag is on the response and
   not implied by the count, because a topic with exactly 500 partitions is not truncated.

## Observability

- One span per endpoint, named from the contract's endpoint `name` (`topic.list`, `topic.get`, …),
  with `cluster`, and for the list `mode`, `page` and `matched`.
- `kui.http.server.duration` inherited from `libs/http`; no second timer.
- INFO on a 5xx only. A 404 for a topic name a user mistyped is not an event.
- The capability route reports per-cluster states from `TopicCapabilityUseCase`, which is what the
  gateway polls (TOP-023).

## Degraded behaviour

- **Snapshot stale**: 200, `Section.Stale`, `scrapedAt`, the real reason code.
- **Snapshot absent**: 200, `Section.Unavailable(reason, message, since)`.
- **Detail live read failed, snapshot present**: 200, `Section.Stale` — the `Fresh.FromSnapshot`
  case mapped straight through, which is why TOP-015 made it explicit rather than letting this
  layer guess.
- **Config not permitted**: 200 with a `TopicConfigView.NotPermitted` payload, not a 403 — the rest
  of the topic page must keep working (TOP-016 decision 1).
- **Cluster service down**: the topic service still answers from the profiles it holds; the
  capability report says `Degraded` and names the reason.
