# TOP-036 — Property suites for paging, sorting and search

- **ID:** TOP-036
- **Title:** Property suites for paging, sorting and search
- **Milestone / Feature:** M2 / TP-001, SF-001
- **Owner role:** QA Engineer
- **Context / modules:** `services/topic/application`, `libs/kernel`
- **Size:** M
- **Dependencies / blocked by:** TOP-014, TOP-001

## Goal (user value)

The milestone's first exit criterion, met: the arithmetic behind "page 3 of 40, sorted by size,
matching 'ord'" is proven over generated data rather than checked on three examples.

## Scope

1. The generators: `TopicSnapshot`s of realistic and adversarial shapes, and `TopicListQuery`s
   across the whole parameter space.
2. The properties, stated as laws rather than as examples.
3. A **differential** property: the pipeline against an obvious, slow, obviously correct reference
   implementation written in the test tree.
4. Shrinking that produces readable counterexamples, so a failure names a snapshot a person can
   read.

## Non-goals

- No new production code. If a property cannot be expressed, the finding goes back to TOP-014.
- No performance assertions. TOP-035 measures; this proves correctness.
- No RBAC properties beyond the ordering one; there is no RBAC to test.

## Public signatures to implement

```scala
package kui.topic.application

/** The obvious implementation: filter with a `for` comprehension, sort with `sortBy`, slice with
  * `drop`/`take`, count with `length`. Slow, unoptimised, and clearly correct by inspection.
  *
  * It exists so that `ListTopics` can be tested against something other than a restatement of
  * itself. A property that asserts the pipeline equals a re-implementation of the pipeline proves
  * only that it was typed twice; a property that asserts it equals code a reader can verify at a
  * glance proves the optimised version.
  */
object ReferenceListing {
  def apply(snapshot: TopicSnapshot, query: TopicListQuery): (List[TopicSummary], Int)
}
```

```scala
package kui.topic.application

/** Generators tuned to produce the shapes that break paging, not the shapes that are easy to
  * generate: empty snapshots, snapshots that are entirely internal, snapshots where every row ties
  * on the sort key, page numbers past the end, queries that match nothing and queries that match
  * everything.
  */
object ListGenerators {
  given Arbitrary[TopicSnapshot]
  given Arbitrary[TopicListQuery]
  /** A snapshot where every topic ties on every sortable field except the name. The stability
    * properties are vacuous without it. */
  val allTies: Gen[TopicSnapshot]
  /** A snapshot that is entirely internal topics. `showInternal=false` over it is the exact case
    * the reference product's page count gets wrong. */
  val allInternal: Gen[TopicSnapshot]
}
```

## The properties

`ListLawsSuite`:

1. **`totalItemsEqualsTheFilteredSize`** — over every generated snapshot and query.
2. **`theResultEqualsTheReferenceImplementation`** — rows and total, differentially.
3. `everyPageIsAtMostPageSize`.
4. `theUnionOfEveryPageIsTheFilteredSetExactlyOnce` — no row appears on two pages, none is lost.
5. `pagesAreContiguous` — page *n* + 1 begins where page *n* ended.
6. **`sortingIsStable`** — over `allTies`, the order within a tie group is the name order and does
   not vary between runs.
7. `reversingTheSortReversesTheRowsExceptForMissingValues` — missing values are last in both
   directions, which is the one place a sort is deliberately not an involution, and the property
   states it exactly rather than excluding the case.
8. **`filteringHappensBeforePaging`** — a visibility predicate that hides half the topics halves
   the total, not just the page.
9. **`hidingInternalTopicsChangesTheTotal`** — over `allInternal`, `totalItems` is 0 and `pageCount`
   is 1. This is the reference product's defect, expressed as a law.
10. `anEmptySnapshotIsAnEmptyFirstPage`.
11. `aPagePastTheEndIsEmptyWithTheCorrectTotal`.
12. `plainSearchEqualsANaiveSubstringFilter` — ADR-038's stated property, at the pipeline level.
13. `ftsIsASupersetOfPlain` for queries of three characters or more.
14. `theQueryIsIdempotent` — running it twice on the same snapshot gives the same rows, which
    catches a hidden dependency on hash order or on wall-clock time.

`PagingLawsSuite` (in `libs/kernel`, because `Page` is where the arithmetic lives):

- `pageOfIsTotalOverEveryInput` (property) — including page numbers near `Int.MaxValue`, which
  `PageRequest.offset` already clamps and which is the overflow its doc comment describes.
- `offsetNeverGoesNegative` (property).
- `pageCountAndTotalItemsAgree` (property).

## Decisions this task takes (no ADR covers them)

1. **A differential test against a deliberately naive reference.** Written above. It is the
   difference between a property suite that documents the implementation and one that checks it.
2. **The generators are biased towards adversarial shapes.** Uniformly random topic sets almost
   never tie, almost never are entirely internal and almost never ask for a page past the end —
   which are three of the four places this code can be wrong.
3. **The suite runs 200 cases by default and 2 000 under the nightly flag.** Enough to catch a
   systematic error on every commit, and enough to catch a rare one within a day.

ADR-041 §3 applies to the architecture check.

## Degraded behaviour

- **A failing property must produce a readable counterexample.** Shrinking is configured so a
  failure names a snapshot of two or three topics rather than of two hundred; a counterexample
  nobody can read is a failure nobody can fix, and the suite is verified against that by the
  deliberate-break exercise above.
