# TOP-005 — `libs/kafka`: `listOffsets` — leaderless filtering, whole-topic refusal, chunking

- **ID:** TOP-005
- **Title:** `libs/kafka`: `listOffsets` — leaderless filtering, whole-topic refusal, chunking
- **Milestone / Feature:** M2 / TP-001, TP-003, PA-001
- **Owner role:** Principal Scala Engineer
- **Context / module:** `libs/kafka`
- **Size:** L
- **Dependencies / blocked by:** TOP-003

## Goal (user value)

A cluster with one offline partition answers the topic list in milliseconds with an em dash in one
cell, instead of failing after sixty seconds with a message that names nothing.

This is the task the whole `PORT-INVARIANTS.md` file was written for. Read TOP-002's doc comment
before writing a line of it.

## Scope

1. `TopicAdmin.listOffsets` on `KafkaTopicAdmin`: describe first, filter leaderless partitions,
   then ask, in chunks of `AdminTuning.listOffsetsChunkSize` (default 200 partitions).
2. `TopicAdmin.partitionSizes` on `KafkaTopicAdmin`, from `describeLogDirs`, with per-broker
   refusals as per-partition skips.
3. A short-lived description cache inside the adapter, so a caller that asks for offsets of many
   topics in one scrape does not pay a `describeTopics` round trip per topic
   (`admin-capabilities.md` DC-D3: "cache descriptions for a few seconds inside the adapter").
4. The `SkipReason.NoLeader` case — which has existed since KAFKA-005 with nothing producing it —
   finally gets its producer.

## Non-goals

- No `deleteRecords`, no purge (MS-008, M3/M5).
- No `forTimestamp`, `maxTimestamp`, `earliestLocal` or `latestTiered` specs. M2 needs earliest and
  latest; the seek modes are M3's and belong to `MessageBrowsePort`, not here.
- No aggregation into a per-topic count. The port returns per-partition offsets and skips; the
  refusal to aggregate is a **rule stated here and enforced one layer up** (TOP-014), because
  aggregation is a domain decision and the port must not invent an `Option[Long]` for a topic.
- No `isolation.level` choice. `read_uncommitted` is the AdminClient default and M2 shows
  positions, not transactional visibility; ADR's `read_committed` opt-in is DC-D8 and is M3's.

## Design references

- **The doc comment TOP-002 wrote on this method.** It is the specification. If the implementation
  and the comment disagree, one of them is a bug and the comment is not it.
- `research/kafka/admin-capabilities.md` §2, row "Topic offsets / message counts", including the

- DC-D3 in the same document — the decision, its evidence, its tradeoff (one extra `describeTopics`

## Public Scala signatures to implement

```scala
package kui.kafka.admin

import kui.kafka.{BatchResult, SkipReason}
import kui.kernel.TopicPartition

/** The rule of `PORT-INVARIANTS.md` §1, as a pure function, so that it is testable without a
  * broker and impossible to forget in a second caller.
  */
object LeaderFilter {

  /** Splits requested partitions into the ones it is safe to ask about and the ones that must be
    * reported as `NoLeader`.
    *
    * A partition whose topic is **not in the descriptions at all** is also unsafe: not knowing
    * whether it has a leader is exactly the state that produces the sixty-second retry, so an
    * unknown topic is skipped with `NotFound` rather than optimistically included.
    */
  def partition(
      requested: List[TopicPartition],
      descriptions: Map[TopicName, TopicDescription]
  ): (List[TopicPartition], Map[TopicPartition, SkipReason])
}
```

### Behaviour `listOffsets` must have, in order

1. Group the requested partitions by topic. Fetch descriptions for those topics — from the
   adapter's cache when an entry is younger than `AdminTuning.descriptionCacheTtl` (default 5 s),
   otherwise through `describeTopics`.
2. Run `LeaderFilter.partition`. **Nothing leaderless reaches the client.**
3. Chunk the safe partitions and issue `listOffsets(earliest)` and `listOffsets(latest)` per
   chunk, with bounded parallelism from `AdminTuning`.
4. A returned `offset < 0` is `SkipReason.NotFound("the broker reported no offset")`, not a value:
   a negative offset rendered as a count is a number that cannot be true.
5. Merge: `values` are the partitions that answered both calls, `skipped` is everything else, and
   the invariant `values.keySet ++ skipped.keySet == requested.toSet` holds — asserted by a
   property test, because a partition that silently vanishes is how a wrong total is born.
6. A reconnect-class failure fails the whole call with a `Left`.

### Behaviour `partitionSizes` must have

- One `describeLogDirs` per broker holding a replica, batched by `AdminTuning`, summing each
  partition's size across the log directories that hold it.
- A broker that refuses (`ClusterAuthorizationException`) or errors per directory contributes
  `NotAuthorized` or `Failed` skips for the partitions it holds, and never fails the call: a
  ten-broker cluster where one broker is down still knows nine brokers' sizes.

## Decisions this task takes (no ADR covers them)

1. **The description cache is inside the adapter and its TTL is five seconds, configurable.** DC-D3
   proposes exactly this. Five seconds is short enough that a partition that just lost its leader
   is noticed within one scrape and long enough that a 10 000-topic scrape pays the describe once
   rather than per chunk. It is `AdminTuning.descriptionCacheTtl` so a cluster with pathological
   metadata churn can turn it off with `0.seconds`.
2. **The cache is keyed by `(ClusterId, TopicName)` and bounded.** Unbounded, it would be a memory
   leak proportional to topics seen; the bound is `AdminTuning.descriptionCacheMaxTopics` (default
   20 000) with the oldest evicted first, and exceeding it is a DEBUG line, not an error.
3. **`listOffsets` does not aggregate and does not return an `Option[Long]` per topic.** Stated in
   Non-goals; repeated as a decision because it is the natural thing to add here and the reason not
   to is one layer away.

## ADRs this task must obey

ADR-006 Amendment 1 (per-key futures; the `all()` shape cannot express this), ADR-016 (the
description cache publishes the name, bound, TTL and hit-rate metric every cache must),
ADR-034, ADR-041 A5 and A10.

## Library coordinates

None new. The bounded description cache is a `Ref`-held map with an insertion-ordered eviction, not
Caffeine: `BoundedCache` does not exist yet (ADR-016 ties it to its first real consumer), and
adding a dependency for a twenty-line map inside one adapter would be the wrong end of that trade.

```scala
val partitions = List(tp("orders", 0), tp("orders", 1), tp("orders", 2))   // partition 1 offline
val result = admin.listOffsets(connection, partitions).unsafeRunSync().toOption.get

assertEquals(result.values.keySet, Set(tp("orders", 0), tp("orders", 2)))
assertEquals(result.skipped(tp("orders", 1)), SkipReason.NoLeader)
assertEquals(recorder.partitionsAskedAbout, Set(tp("orders", 0), tp("orders", 2)))
```

And the timing assertion that is the whole point:

```scala

// exactly as a real AdminClient does
TestControl.executeEmbed(admin.listOffsets(connection, partitions)).timeout(1.second)
```

## Observability

- Inherited span and duration per admin call.
- `kui.kafka.admin.skipped` with `reason = no_leader` — the metric that lets an operator see
  "seventeen partitions are offline" without opening a screen.
- INFO, once per call, when any partition was filtered: the count and the first five partitions.
  This is the line somebody will paste into a bug report when the count column shows an em dash,
  and it is what converts "the UI is broken" into "partition 3 of orders has no leader".
- DEBUG on a description-cache hit and miss with the cluster id.

## Degraded behaviour

- **One partition leaderless**: that partition is `NoLeader`; every other partition answers; the
  caller refuses to aggregate the topic (TOP-014) and the cell is an em dash with an offline
  marker.
- **Every partition of a topic leaderless**: the topic has no offsets at all and no count; the
  topic still lists, with its partition count and replication factor, which come from the
  description.
- **`describeLogDirs` refused**: sizes are `None`; the size column is an em dash. It does not
  affect counts, which come from a different call — a deliberate separation, so that losing one
  does not lose both.
- **Broker unreachable**: `Left`, snapshot serves `Stale`.
