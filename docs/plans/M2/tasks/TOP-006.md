# TOP-006 — `libs/cache`: `SnapshotRegistry`, a keyed collection of supervised cells

- **ID:** TOP-006
- **Title:** `libs/cache`: `SnapshotRegistry`, a keyed collection of supervised cells
- **Milestone / Feature:** M2 / TP-001, TP-003
- **Owner role:** Principal Scala Engineer
- **Context / module:** `libs/cache`
- **Size:** M
- **Dependencies / blocked by:** —

## Goal (user value)

A KUI with forty configured clusters holds forty topic snapshots, creates each one the first time
somebody looks at that cluster, refreshes each on its own timer, and — the part that matters —
releases the snapshot and stops its timer the moment a cluster is removed, so a decommissioned
cluster does not keep a Kafka client authenticating every minute forever.

## Scope

1. `SnapshotRegistry[F, K, A]` in `kui.cache`: a keyed, lazily populated collection of
   `SnapshotCell`s over a supervisor.
2. On-demand creation: `getOrCreate(key)` builds a cell with a loader derived from the key, starts
   its refresh loop, and returns it. Concurrent callers for the same key get one cell.
3. `retain(keys)`: the set of keys that should exist. Anything outside it is released — its refresh
   fiber cancelled, its cell dropped — and anything inside it that does not exist yet is *not*
   created (creation stays on demand; retention only removes).
4. A cancellation path: releasing the registry's `Resource` cancels every refresh loop.
5. The cache metrics ADR-016 requires, one set per registry, labelled by key.

## Non-goals

- **No `BoundedCache`, no Caffeine.** ADR-016's second primitive still has no consumer; adding it
  here would mean a TTL policy with nothing to test it against.
- No refactor of `services/cluster`'s `ClusterSnapshots` onto this (DEVPLAN §10 D12 and
  `TECH_DEBT.md`). This task must not touch `services/cluster`.
- No eviction by size or by idleness. Retention is driven by the caller's key set, which is the
  configured cluster set, and a bound on "how many clusters may be configured" is a configuration
  question, not a cache question.
- No persistence and no cross-process sharing.

## Design references

- ADR-016 — the caching contract: every cache publishes a name, a bound, a TTL or invalidation
  rule, a staleness contract and metrics; `SnapshotCell` is the primitive this composes.
- ADR-027 — per-context snapshots, `status`, `scrapedAt`, atomic replacement.
- `services/cluster/application/src/kui/cluster/application/ClusterSnapshots.scala` is the working
  example to read first. Its doc comments about supervised refresh, deduplicated forced refresh
  and the cost of a leaked refresh fiber apply here verbatim; DEVPLAN §10 D12 says why this is a
  new type rather than that one made generic.

## Public Scala signatures to implement

```scala
package kui.cache

import scala.concurrent.duration.FiniteDuration

import cats.effect.kernel.{Resource, Temporal}

/** A collection of [[SnapshotCell]]s keyed by something the caller owns — in M2, a `ClusterId`.
  *
  * The lifetime rule is the reason this type exists rather than a `Ref[Map[K, SnapshotCell]]`: a
  * cell owns a refresh fiber, and a map does not release what it drops. A cluster removed from
  * configuration must stop costing a Kafka connection, and "must stop" is a `Resource` finalizer,
  * not a hope.
  */
trait SnapshotRegistry[F[_], K, A] {

  /** The cell for this key, created and started if it does not exist. Concurrent callers for the
    * same key receive the same cell; creation is serialised per registry, not per key, because a
    * registry holds tens of keys and a lock per key would cost more than it saves.
    */
  def getOrCreate(key: K): F[SnapshotCell[F, A]]

  /** The cell for this key if it already exists. Never creates one — this is what a read path
    * that must not start a scrape uses.
    */
  def get(key: K): F[Option[SnapshotCell[F, A]]]

  /** Releases every key outside `keys`, cancelling its refresh. Returns the keys released, which
    * is what the caller logs.
    */
  def retain(keys: Set[K]): F[Set[K]]

  /** Every live cell, in key order. */
  def all: F[List[(K, SnapshotCell[F, A])]]

  /** Starts a refresh of one key and returns immediately — `false` when the key is unknown.
    *
    * It must not await completion: a forced refresh against a dead cluster would otherwise block
    * for the full admin timeout and hang the button that triggered it. Deduplication is the
    * cell's, so twenty presses are one scrape.
    */
  def requestRefresh(key: K): F[Boolean]
}

object SnapshotRegistry {

  /** @param name     the cache name published in metrics and in `docs/operations/observability.md`
    * @param load     how one key's value is produced; failures are values, per ADR-034
    * @param interval the refresh period for every cell in this registry
    */
  def resource[F[_]: Temporal, K, A](
      name: String,
      load: K => F[Either[SnapshotLoadFailure, A]],
      interval: FiniteDuration,
      metrics: CacheMetrics[F],
      logger: org.typelevel.log4cats.StructuredLogger[F]
  ): Resource[F, SnapshotRegistry[F, K, A]]
}
```

## Tests required

`SnapshotRegistrySuite` (MUnit + `munit-cats-effect` + `TestControl`):

- `getOrCreateIsIdempotentUnderConcurrency` — a thousand concurrent calls for one key produce one
  cell and one loader invocation.
- `getDoesNotCreate`.
- `eachCellRefreshesOnItsOwnSchedule` — advance virtual time, assert the loader ran once per
  interval per key.
- **`retainReleasesTheCellsItDrops`** — the dropped key's loader is never called again after the
  release completes, asserted by advancing several intervals.
- **`retainCancelsTheRefreshFiberAndDoesNotWaitForIt`** — a key whose loader is blocked forever is
  still released promptly.
- `retainDoesNotCreateMissingKeys`.
- `staleReadsAreServedWhileTheLoaderFails` — the `SnapshotCell` contract, asserted through the
  registry so a wiring mistake cannot lose it.
- `requestRefreshReturnsImmediately` — with a loader that takes the full admin timeout, the call
  returns in virtual zero time.
- `requestRefreshIsDeduplicated` — twenty presses, one load.
- `requestRefreshOnAnUnknownKeyIsFalse`.
- **`releasingTheRegistryCancelsEveryRefresh`** — after the resource is released, advancing an hour
  of virtual time invokes no loader; this is the definition-of-done item 9 assertion for this
  module.
- `metricsAreLabelledByKey` — read back from a recording meter, not from a fake that could agree
  with a bug.

## Observability

- The instruments ADR-016 names, one set per registry, with `cache` (the registry name) and `key`
  labels: hits, misses, loads, load failures, load duration, and the age of the current value.
- INFO when a key is released by `retain`, naming the key and why (the caller's reason string).
  An operator removing a cluster should see KUI let go of it.
- WARN on a load failure, rate-limited to one per key per interval, so a cluster that has been
  down for a week does not produce a line every minute.

## Degraded behaviour

- **A loader that always fails**: the cell holds no value and reports `Offline(lastError)`; reads
  see `None` and the caller renders `Unavailable`.
- **A loader that starts failing after succeeding**: the cell keeps the previous value and reports
  it as stale with its `scrapedAt`. This is the behaviour every "greyed and timestamped" screen in
  the milestone rests on.
- **A loader that never returns**: the refresh fiber is supervised and the next tick does not
  start a second one; the value ages visibly. The loader's own timeout is the caller's
  responsibility and TOP-013 sets one.
