# TOP-017 — `services/topic/infrastructure`: the module and the `TopicAdmin` adapter

- **ID:** TOP-017
- **Title:** `services/topic/infrastructure`: the module and the `TopicAdmin` adapter
- **Milestone / Feature:** M2 / TP-001, TP-003, TP-004, PA-001
- **Owner role:** Domain Architect (topics)
- **Context / service:** `services/topic/infrastructure`
- **Size:** L
- **Dependencies / blocked by:** TOP-012, TOP-005, TOP-004

## Goal (user value)

The topic service's rules are connected to a real Kafka cluster, with every shape a real cluster
can produce — a deleted topic, an unauthorized one, an offline partition, a broker that will not
report its disks — turned into a value the domain already knows how to render.

## Scope

1. The Mill module `services.topic.infrastructure` and its test module.
2. `TopicAdminAdapter`: the domain's `TopicAdmin` implemented over `libs/kafka`'s `TopicAdmin`,
   `ClusterProfiles` for the connection, and the `KafkaErrorMapper` for failures.
3. `KafkaToTopicDomain`: the pure conversions, in their own object, exhaustively matched.
4. The scrape composition: `listTopics` → `describeTopics` → `topicConfigs` (skipped: the list does
   not need configs) → `listOffsets` → `partitionSizes`, assembled into `ScrapeResult`.
5. Running `PortContractSuite` (TOP-012) against the live adapter, so the fake and the adapter are
   held to one contract.

## Non-goals

- No profile client wiring. TOP-018 supplies `ClusterProfiles`; this task takes it as a
  constructor parameter and its tests pass a fake.
- No HTTP, no DTO. Rule A9 keeps `api` out of here and this module out of `api`.
- No caching. The snapshot is the application layer's.
- No mutation.

## Design references

- `services/cluster/infrastructure/src/kui/cluster/infrastructure/` — the whole directory is the
  worked example: `ClusterAdminAdapter`, `KafkaToDomain`, `ClusterAdminClients`,
  `ReconnectPolicy`. `KafkaToDomain`'s doc comment on why duplicate types either side of the

- `research/kafka/admin-capabilities.md` §2 and DC-D4.
- DEVPLAN §10 D3 (the internal union is the **application's** rule — this adapter reports Kafka's

```scala
package kui.topic.infrastructure

/** The translation between `libs/kafka`'s vocabulary and the topic domain's.
  *
  * Pure, total, and in its own file so that the shapes a real cluster produces — a `null` leader,
  * an ISR the broker reports as larger than the replica set, a topic that vanished between two
  * calls, a config entry with the sensitive flag and no value, a broker that refused its log
  * directories — are unit-testable without a broker in each of those states.
  *
  * The duplicate types on either side (`libs/kafka`'s `TopicDescription` and the domain's
  * `TopicDetail`, `SkipReason` and the domain's incompleteness reasons) are deliberate: rule A5
  * forbids `libs/kafka` from depending on a service and rule A1 forbids the domain from depending
  * on `libs/kafka`, so one definition is not available without breaking the layering. Every pair
  * is bridged by an exhaustive match, which the compiler checks, and that is what this file is.
  */
object KafkaToTopicDomain {
  def summary(
      listing: TopicListing,
      description: Option[TopicDescription],
      offsets: Map[TopicPartition, PartitionOffsets],
      sizes: Map[TopicPartition, PartitionSize],
      skipped: Map[TopicPartition, SkipReason]
  ): dom.TopicSummary

  def partition(
      info: TopicPartitionInfo,
      offsets: Option[PartitionOffsets],
      size: Option[PartitionSize]
  ): dom.PartitionView

  def configEntry(entry: kui.kafka.admin.TopicConfigEntry): dom.TopicConfigEntry

  /** Every `SkipReason` becomes a sentence a screen can show. Exhaustive: a new case fails to
    * compile here, which is the whole point of the pair. */
  def incompleteness(reason: SkipReason): String

  def error(e: kui.kernel.error.KuiError): dom.TopicError
}
```

```scala
package kui.topic.infrastructure

/** One scrape, composed from four admin calls, with the order and the failure rules stated once.
  *
  *   1. `listTopics(includeInternal = true)` — always true. The internal filter is a display rule
  *      that the application layer applies with its own definition (DEVPLAN §10 D3), so filtering
  *      here would make `showInternal=true` unable to show anything.
  *   2. `describeTopics` over every name.
  *   3. `listOffsets` over every partition of every described topic — which is where the port's
  *      leaderless filtering happens, and why this step cannot be reordered before (2).
  *   4. `partitionSizes`.
  *
  * A failure in (1) fails the scrape. A failure in (2), (3) or (4) contributes `incomplete`
  * entries and does not: a cluster that answers three of four calls still produces a useful list,
  * and blanking the screen over a refused `describeLogDirs` would be the M1 lesson unlearned.
  */
object TopicScrape {
  def run[F[_]: Async](kafka: KafkaTopicAdmin[F], connection: ClusterConnection)
      : F[Either[KuiError, dom.ScrapeResult]]
}
```

## Tests required

`KafkaToTopicDomainSuite` (unit + property) — the nineteen-shapes suite, the reason this file
exists:

- `nullLeaderBecomesNoLeaderAndNoCount`.
- `aSkippedPartitionMakesTheTopicCountNone` (property) — for every `SkipReason`.
- `aTopicWithNoDescriptionIsStillARowWithAnIncompletenessReason` — a topic that vanished mid-scrape
  is reported, not dropped silently, because a list that quietly shrinks is a list nobody trusts.
- `everySkipReasonHasASentence` — an exhaustive match, asserted case by case.
- `isrLargerThanReplicasIsReportedNotCorrected`.
- `aSensitiveConfigEntryStaysValueless`.
- `errorMappingIsTotalOverTheKuiErrorCases`.

`TopicAdminAdapterSuite` (unit, `StubTopicAdmin` for `libs/kafka`'s port):

- `anUnknownClusterIsClusterNotFoundWithoutCallingKafka`.
- `aFailedListTopicsFailsTheScrape`.
- **`aFailedDescribeLogDirsDoesNotFailTheScrape`** — sizes are `None`, counts are intact.
- `aFailedListOffsetsDoesNotFailTheScrape`.
- `internalTopicsAreAlwaysListedByTheAdapter` — the filter is the application's.
- `cancellingTheScrapeCancelsEveryOutstandingAdminCall`.

`TopicAdminLiveSuite` (Testcontainers, seeded from `libs/testkit`'s `TopicFixtures`) — and it runs
**`PortContractSuite`**, so the live adapter and the application layer's fake satisfy one contract:

- the contract suite in full;
- `aLeaderlessPartitionYieldsNoCountAgainstARealBroker` — the invariant, end to end, against a
  broker;
- `aScrapeOfTheRealisticSeedProducesTheExpectedRows`;
- `describeConfigsOfEveryTopicSucceedsOrIsEmpty`.

## Observability

- Span `topic.scrape.step` per admin call within a scrape, child of the application layer's
  `topic.scrape` span, with `step`, `cluster` and `outcome`. When a scrape is slow, this is what
  says which of the four calls it was.
- `kui.topic.scrape.skipped` counter with `step` and `reason`, fed from the `BatchResult`s. It is
  the same fact `libs/kafka`'s counter records one layer down, labelled by the step that asked —
  and the two disagreeing is itself a useful signal.
- WARN, once per scrape per cluster, listing the first five incomplete topics with their reasons.

## Degraded behaviour

- **`listTopics` fails**: the scrape fails, the snapshot keeps its previous value as stale.
- **`describeTopics` partly fails**: those topics appear with an incompleteness reason and no
  counts.
- **`listOffsets` partly fails**: those topics have no message count; everything else is intact.
- **`describeLogDirs` fails entirely**: no sizes anywhere; counts, partitions and replicas
  unaffected.
- **The profile is missing**: `ClusterNotFound`, which the snapshot registry turns into a released
  cell rather than a retry loop.
