# TOP-012 — Topic domain ports: `TopicAdmin`, `ClusterProfiles`, `ClockPort`

- **ID:** TOP-012
- **Title:** Topic domain ports: `TopicAdmin`, `ClusterProfiles`, `ClockPort`
- **Milestone / Feature:** M2 / TP-001, TP-003
- **Owner role:** Domain Architect (topics)
- **Context / service:** `services/topic/domain`
- **Size:** S
- **Dependencies / blocked by:** TOP-011

## Goal (user value)

The topic service's use cases are written against three narrow interfaces, so they can be tested
without a broker and without an HTTP client, and so the adapters can be replaced without touching
a rule.

## Scope

1. `TopicAdmin[F]` — the **domain's** port, in the domain's vocabulary. Not `libs/kafka`'s trait
   of the same name.
2. `ClusterProfiles[F]` — the domain's view of "which clusters exist and what are they called".
3. `ClockPort[F]` — `now`, because `scrapedAt` is domain data and a use case that reaches for the
   system clock is a use case that cannot be tested at a fixed instant.
4. The failure vocabulary: `TopicError`, mapped from `KuiError` by the adapter.

## Non-goals

- No implementations. TOP-017 and TOP-018.
- No `fs2.Stream` in any signature. ADR-041 Amendment 3 refused to widen A1 for exactly this, and
  its answer applies here: change notification is a callback returning its deregistration, and the
  stream, if one is wanted, is built in `application`.
- No mutation methods.
- No leaking of `libs/kafka` types. The domain port speaks `TopicSummary`, `PartitionView` and
  `TopicConfigEntry`; the adapter does the translating, exactly as `KafkaToDomain` does for the
  cluster service.

## Design references

- `services/cluster/domain/src/kui/cluster/domain/ClusterAdmin.scala` and `ClusterConfigStore.scala`
  — the existing domain ports and, importantly, the shape ADR-041 Amendment 3 settled for change
  notification (`onChange(handler): F[F[Unit]]`).
- `services/cluster/infrastructure/src/kui/cluster/infrastructure/KafkaToDomain.scala` — its doc
  comment explains why the duplicate types on either side of the boundary are deliberate and why
  an exhaustive match is the mitigation. The same applies here and TOP-017 writes the match.
- DEVPLAN §10 D1 — where the connection material comes from.
- `research/kafka/admin-capabilities.md` DC-D1 — one narrow port per bounded context.

`PortContractSuite` holds the **shared contract** every implementation must satisfy — the fake in
`application`'s tests and the live adapter in `infrastructure`'s tests both run it. It is written
here, with the port, because a contract written after the second implementation is a description
of the first one.

## Public Scala signatures to implement

```scala
package kui.topic.domain

import kui.kernel.{ClusterId, PartitionId, TopicName}

/** Everything the topic context needs from a Kafka cluster, in the topic context's words.
  *
  * The parameter is a `ClusterId` and not a connection: resolving an id to connection material is
  * an adapter's job, and a domain port that took a `ClusterConnection` would put `libs/kernel`'s
  * security ADT — and therefore the shape of a Kafka client — into a business rule.
  */
trait TopicAdmin[F[_]] {

  /** Every topic of a cluster, with its counts. One call, because this is a scrape and the
    * chunking, parallelism and offset arithmetic are the adapter's business (DC-D4).
    */
  def scrape(cluster: ClusterId): F[Either[TopicError, ScrapeResult]]

  def detail(cluster: ClusterId, topic: TopicName): F[Either[TopicError, TopicDetail]]

  def config(cluster: ClusterId, topic: TopicName): F[Either[TopicError, List[TopicConfigEntry]]]
}

/** What one scrape produced: the summaries, and what it could not read.
  *
  * `incomplete` is not an error channel. A scrape that read 9 998 of 10 000 topics succeeded, and
  * a caller that treated it as a failure would blank a screen over two unreadable topics.
  */
final case class ScrapeResult(topics: List[TopicSummary], incomplete: Map[TopicName, String])
```

```scala
package kui.topic.domain

import kui.kernel.ClusterId

/** Which clusters this KUI knows about, from the topic service's point of view.
  *
  * It carries no connection material: the adapter behind it holds that, and a use case that could
  * see a password would be a use case that could log one.
  */
trait ClusterProfiles[F[_]] {
  def all: F[List[ClusterRef]]
  def get(id: ClusterId): F[Option[ClusterRef]]

  /** Registers a handler for the set changing and returns its deregistration.
    *
    * A callback and not an `fs2.Stream`, per ADR-041 Amendment 3: a domain that imports a concrete
    * runtime type can no longer be read, tested or moved without that runtime.
    */
  def onChange(handler: Set[ClusterId] => F[Unit]): F[F[Unit]]
}

/** A cluster's identity as a topic screen shows it. */
final case class ClusterRef(id: ClusterId, name: String, readOnly: Boolean)
```

```scala
package kui.topic.domain

/** Why a topic operation could not answer.
  *
  * Four cases, because the caller renders four different things: a 404, a "you may not", a greyed
  * stale screen and a red one. Mapped from `KuiError` in the adapter, so no `libs` error type
  * reaches a use case.
  */
enum TopicError {
  case NotFound(topic: TopicName)
  case ClusterNotFound(cluster: ClusterId)
  case Forbidden(detail: String)
  case Unreachable(detail: String, retryable: Boolean)
}
```

## Tests required

`PortContractSuite` — an abstract suite, parameterised by a `TopicAdmin[IO]` and a fixture, listing
the behaviours **every** implementation must have. It is run by `application`'s fake and by
`infrastructure`'s live adapter (TOP-017), which is what makes it a contract rather than a
description:

- `scrapeOfAnUnknownClusterIsClusterNotFound`.
- `detailOfAnUnknownTopicIsNotFound`.
- `configOfATopicWithoutPermissionIsAnEmptyListNotForbidden` — the rule TOP-004 decided, asserted
  once for both implementations so the fake cannot drift from the adapter.
- `scrapeReportsIncompleteRatherThanFailing`.
- `aLeaderlessPartitionYieldsNoTopicMessageCount` — the invariant, asserted at the domain boundary
  as well as at the port, deliberately: two assertions at two levels is how a rule survives a
  refactor of either one.

Plus a trivial `ClockPortSuite` asserting the fixed-clock fake used by every later suite.

## Observability

None: interfaces. Their implementations carry the spans, and TOP-017 names them.

## Degraded behaviour

The ports are total: every failure is a `TopicError` value. There is no throwing path, and
`PortContractSuite` asserts that a failing implementation returns a `Left` rather than raising —
which is the assertion that keeps an adapter's exception from reaching a use case.
