## Goal (user value)

The second port in KUI's admin family exists, and the sixty-second timeout that
`libs/kafka/PORT-INVARIANTS.md` warned about is written down on the method that has to prevent it
— so the next person to add an offset lookup reads the rule in their editor rather than
rediscovering it as a bug report.

## Scope

1. The `TopicAdmin[F]` **port trait** in `kui.kafka.admin`, declaring the five read methods M2
   needs, and no others.
2. The result types: `TopicListing`, `TopicDescription`, `TopicPartitionInfo`, `PartitionOffsets`,
   `TopicConfigEntry`, `PartitionSize`.
3. **The move.** `libs/kafka/PORT-INVARIANTS.md` §1 becomes the doc comment on
   `TopicAdmin.listOffsets`, and is **deleted from that file in this same commit**.
4. The trait's methods are declared here and implemented by TOP-003 (`listTopics`,
   `describeTopics`), TOP-004 (`topicConfigs`) and TOP-005 (`listOffsets`, `partitionSizes`). No
   adapter is written here.

## Non-goals

- **No mutations. Not one.** No `createTopic`, `deleteTopic`, `alterConfigs`, `createPartitions`,
  `alterPartitionReassignments` or `deleteRecords` — not even declared, not even returning
  `Unsupported`. Those are M5 and they ship with read-only mode and the audit trail (DEVPLAN §3).
  A declared method is a method somebody implements.
- No `describeProducers` (TP-013, M5), no analysis (TP-012, M5), no transactions.
- No adapter, no `AdminClientPool` usage, no Kafka imports beyond the ones the conversions need —
  and the conversions are TOP-003's.
- No `GroupAdmin`, no `SecurityAdmin`, no `MessageBrowsePort`. `PORT-INVARIANTS.md` §2 stays where
  it is: M4 owns it.

## Design references

- **`libs/kafka/PORT-INVARIANTS.md` §1** — the text this task moves, and its instruction: "If you
  are the person creating `TopicAdmin` … move the relevant section into a doc comment on the
  method, delete it from here, and leave this file with only what is still homeless."
- `research/kafka/admin-capabilities.md` §2 — every row of it, and DC-D1 (one narrow port per
  bounded context), DC-D3 (no-leader filtering is a port invariant), DC-D4 (batching in the

- ADR-006 Amendment 1 — admin work uses the raw `Admin` client through `AdminClientPool`, so the

- The existing `ClusterAdmin` in `libs/kafka/src/kui/kafka/admin/ClusterAdmin.scala` is the shape
  to copy: `F[Either[KuiError, A]]` for whole-call failures, `BatchResult[K, A]` for per-key ones.

## Public Scala signatures to implement

```scala
package kui.kafka.admin

import kui.kernel.{PartitionId, TopicName}

/** What `listTopics` returns: cheap, name-level facts about every topic.
  *
  * `isInternal` is Kafka's own flag. It is **not** the whole definition of an internal topic in
  * KUI — a name-prefix rule is unioned with it one layer up (DEVPLAN §10 D3) — and this type
  * deliberately reports only what the broker said, so that the union happens in one place instead
  * of being half-applied here.
  */
final case class TopicListing(name: TopicName, isInternal: Boolean, topicId: Option[String])

/** One partition, as `describeTopics` reports it. */
final case class TopicPartitionInfo(
    partition: PartitionId,
    /** `None` when the partition has no leader. Kafka reports `null`; the reference products
      * render `-1`, which sorts and sums as a number and is therefore worse than nothing. */
    leader: Option[BrokerId],
    replicas: List[BrokerId],
    inSyncReplicas: List[BrokerId]
) {
  def isLeaderless: Boolean = leader.isEmpty
  def isUnderReplicated: Boolean = inSyncReplicas.size < replicas.size
}

final case class TopicDescription(
    name: TopicName,
    isInternal: Boolean,
    topicId: Option[String],
    partitions: List[TopicPartitionInfo]
) {
  def replicationFactor: Option[Int] = partitions.headOption.map(_.replicas.size)
  def leaderlessPartitions: List[PartitionId]
}

/** Earliest and latest offsets for one partition. */
final case class PartitionOffsets(partition: PartitionId, earliest: Long, latest: Long) {
  /** Never negative: a partition whose earliest offset has moved past its latest during a
    * deletion is reported as empty rather than as a negative count. */
  def messageCount: Long = math.max(0L, latest - earliest)
}

/** One entry of a topic's configuration.
  *
  * `value` is an `Option` because a sensitive entry has no value: Kafka returns `null` for it and
  * KUI must render "hidden", never an empty string that reads as "unset".
  */
final case class TopicConfigEntry(
    name: String,
    value: Option[String],
    source: ConfigSource,
    isSensitive: Boolean,
    isReadOnly: Boolean,
    documentation: Option[String],
    synonyms: List[ConfigSynonym]
)

final case class PartitionSize(partition: PartitionId, bytes: Long)
```

```scala
package kui.kafka.admin

import kui.kafka.BatchResult
import kui.kernel.error.KuiError
import kui.kernel.cluster.ClusterConnection
import kui.kernel.{PartitionId, TopicName}

/** The topic context's window onto a Kafka cluster (`research/kafka/admin-capabilities.md`
  * DC-D1). Read-only in M2: every mutation is M5, and this trait declares none of them, because a
  * declared method is one somebody implements before its safety net exists (DEVPLAN §3).
  */
trait TopicAdmin[F[_]] {

  def listTopics(connection: ClusterConnection, includeInternal: Boolean)
      : F[Either[KuiError, List[TopicListing]]]

  /** Descriptions for the named topics, chunked. A topic that vanished between the listing and
    * this call is `SkipReason.NotFound`, not a failed batch: on a busy cluster a topic is deleted
    * during a scrape often enough that failing the scrape would make the screen flicker. */
  def describeTopics(connection: ClusterConnection, topics: List[TopicName])
      : F[Either[KuiError, BatchResult[TopicName, TopicDescription]]]

  /** A topic visible without `DESCRIBE_CONFIGS` yields an **empty** config list, not an error
    * (`admin-capabilities.md` §2). The caller renders "not authorized" from the skip reason. */
  def topicConfigs(connection: ClusterConnection, topics: List[TopicName], includeDocs: Boolean)
      : F[Either[KuiError, BatchResult[TopicName, List[TopicConfigEntry]]]]

  /** Earliest and latest offsets for the given partitions.
    *
    * ==Leaderless partitions are filtered here, at the port, and never by the caller==
    *
    * If any partition named in a `listOffsets` request has no leader, the AdminClient does not
    * fail the call. It retries metadata, quietly, until `default.api.timeout.ms` expires — sixty
    * seconds with KUI's defaults — and only then reports a timeout naming nothing useful. A
    * single offline partition therefore turns a millisecond call into a one-minute failure on a
    * cluster that is 99% healthy, and it does so only while a broker is down, which is exactly
    * when the operator most needs the screen.
    *
    * So this method describes the topics first and removes every leaderless partition before it
    * asks. Each removed partition appears in the returned `BatchResult` as `SkipReason.NoLeader`,
    * so a caller can render "offline" for that partition instead of a number, and so that a
    * per-topic aggregate can refuse to compute rather than report a wrong total — a message count
    * summed over a partial set of partitions is wrong rather than merely incomplete.
    *
    * The rule is the port's and not the caller's because there will be four callers by M5 and
    * three of them will not know it exists. Evidence:
    * `research/kafka/admin-capabilities.md` §2 "Topic offsets / message counts" and DC-D3.
    */
  def listOffsets(connection: ClusterConnection, partitions: List[TopicPartition])
      : F[Either[KuiError, BatchResult[TopicPartition, PartitionOffsets]]]

  /** Per-partition on-disk sizes, from `describeLogDirs`. A broker that refuses is a skip for its
    * partitions, never a failure for the topic. */
  def partitionSizes(connection: ClusterConnection, topics: List[TopicName])
      : F[Either[KuiError, BatchResult[TopicPartition, PartitionSize]]]
}
```

## Observability

None: this task adds no runtime. The port's implementations (TOP-003 … TOP-005) inherit
`AdminClientPool.run`'s span and `kui.kafka.admin.duration` sample, with `operation` set to the
method name, and each of those tasks names its own log lines.

## Degraded behaviour

Declared here, implemented downstream, and stated now so that the three implementing tasks agree:

- A topic that disappears mid-scrape is a per-key `NotFound` skip, never a failed call.
- A topic the caller may see but not read configs for is an empty config list plus a
  `NotAuthorized` skip.
- A leaderless partition is a `NoLeader` skip and a refusal to aggregate, never a partial sum.
- A whole-cluster failure — unreachable, timed out, authentication refused — is a `Left`.
