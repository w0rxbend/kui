# STORE-001 — `StoreRecord` envelope, `StoreKey`, explicit codecs and golden files

- **ID:** STORE-001
- **Title:** `StoreRecord` envelope, `StoreKey`, explicit codecs and golden files
- **Milestone / Feature:** M1 / OT-004 (dynamic configuration store), ADR-042
- **Owner role:** Principal Scala Engineer
- **Context / service:** `libs/config`, package `kui.config.store`
- **Size:** M
- **Dependencies / blocked by:** —

## Goal (user value)

Everything KUI ever stores about itself — a registered cluster, a setting, a role, a masking
policy — is one record shape on the wire, with a version, a timestamp and a schema number. An
operator can `kafka-console-consumer` the topic and read it; a future KUI can read a record an
older KUI wrote, or refuse it by name instead of silently skipping it. Nothing else in the store
can be built until this shape exists, because the crypto, the replay, the writer and the file
adapter all speak it.

## Scope

The pure data layer of the metadata store. No Kafka, no files, no I/O of any kind — this task
adds no dependency to `libs/config`.

1. `StoreKey`: the typed form of the record key ADR-042 §2 describes as "a section path such as
   `cluster/<clusterId>`, `settings/global`, `rbac/roles`, `masking/<clusterId>`", with
   `render`/`parse` that round-trip, and a `StoreSection` enum naming the sections M1 knows about.
2. `StoreRecord`: the JSON envelope — `envelopeVersion`, `key`, `version`, `updatedAt`,
   `updatedBy`, `deleted`, `payload`.
3. Hand-written Circe codecs (ADR-007: no `circe-generic` automatic derivation outside
   `services/*/contract`), plus the `envelopeVersion` compatibility rule.
4. The **secret marker** convention: how a payload says "this string is a secret" *before* it is
   encrypted and after it is decrypted, so that STORE-002 can encrypt without knowing the schema
   of any section.
5. Two committed golden files and the suite that asserts against them.

## Non-goals

**No encryption** — STORE-002 owns `FieldCrypto` and the `$enc` node; this task only reserves the
marker names and asserts that a payload containing a `$enc` node round-trips through the envelope
untouched. **No port, no adapter** (STORE-003). **No Kafka**, no configuration keys (STORE-004).
**No section payload types**: `payload` is `io.circe.Json` here and stays `Json` at the port. The
cluster section's own DTO is CLADP-003's business and lives in `services/cluster/infrastructure`;
`libs/config` must not learn what a cluster is (rule A5 works both ways — the store is generic
infrastructure, and a store that knows its sections would have to change for every new one).

## Design references

ADR-042 §2 (topics, key shape, "a versioned JSON envelope, Circe"), §3 (`version`, tombstones),
§4 (the `keyId` that STORE-002 puts inside the payload, not the envelope). ADR-007 (Circe,
explicit codecs). ADR-034 (`ErrorCode`, one code per named failure).
`docs/operations/metadata-store.md` §2 and §5 — the console-consumer dump in §5 is a promise
about this format: keys are printable text and values are one-line JSON.
DEVPLAN §7 row "Store envelope" is the acceptance shape.

## Public Scala signatures to implement

```scala
package kui.config.store

import io.circe.{Decoder, Encoder, Json}
import java.time.Instant
import kui.kernel.Secret

/** The sections of `__kui_config` KUI knows about. Unknown sections are not an error on read —
  * a newer KUI writing a section this one does not model must not break this one's replay — so
  * `StoreSection` has an `Other(name)` case rather than a parse failure. */
enum StoreSection(val name: String):
  case Cluster  extends StoreSection("cluster")
  case Settings extends StoreSection("settings")
  case Rbac     extends StoreSection("rbac")
  case Masking  extends StoreSection("masking")
  case File     extends StoreSection("file")
  case Other(raw: String) extends StoreSection(raw)

object StoreSection:
  def fromName(raw: String): StoreSection
  given CanEqual[StoreSection, StoreSection] = CanEqual.derived

/** A record key: `<section>/<id>`, e.g. `cluster/prod-eu`, `settings/global`, `rbac/roles`.
  *
  * Exactly two segments. Not three: a hierarchy invites a "list everything under x/y/z" query
  * that a compacted topic replayed into a `Map` answers no faster than a prefix scan, and every
  * extra segment is one more thing two writers can disagree about. */
final case class StoreKey(section: StoreSection, id: String):
  def render: String                       // s"${section.name}/$id"
  override def toString: String = render

object StoreKey:
  val IdPattern: String                    // "^[a-z0-9]([a-z0-9-_.]{0,126}[a-z0-9])?$"
  /** Rejects an empty section, an id that is not `IdPattern`, more or fewer than two segments,
    * and any key longer than 255 characters. */
  def parse(raw: String): Either[StoreError, StoreKey]
  def cluster(clusterId: String): Either[StoreError, StoreKey]
  val SettingsGlobal: StoreKey
  val RbacRoles: StoreKey
  given CanEqual[StoreKey, StoreKey] = CanEqual.derived

/** One record as it sits in `__kui_config`, decoded.
  *
  * `version` is the record's own version, starting at 1 and incremented by one per accepted
  * write (STORE-007 defines "accepted"). `deleted` marks a logical tombstone; a physical
  * tombstone (a `null` Kafka value) is also honoured on read and is what compaction eventually
  * removes, but KUI writes the logical form because a `null` value carries no `updatedAt`,
  * no `updatedBy` and no version, which makes an audit of "who deleted this cluster"
  * impossible to answer from the log. */
final case class StoreRecord(
    envelopeVersion: Int,
    key: StoreKey,
    version: Long,
    updatedAt: Instant,
    updatedBy: String,
    deleted: Boolean,
    payload: Json
)

object StoreRecord:
  /** The only version this KUI writes. */
  val CurrentEnvelopeVersion: Int = 1
  /** The versions this KUI can read. Widening it is a compatible change; narrowing it is not. */
  val SupportedEnvelopeVersions: Set[Int] = Set(1)

  def create(key: StoreKey, payload: Json, updatedBy: String, at: Instant): StoreRecord
  def tombstone(key: StoreKey, version: Long, updatedBy: String, at: Instant): StoreRecord

  given Encoder[StoreRecord]     // hand-written, field order fixed as in the golden files
  given Decoder[StoreRecord]     // fails with StoreError.UnsupportedEnvelope for an unknown version
  given CanEqual[StoreRecord, StoreRecord] = CanEqual.derived

/** How a payload says "this string is a secret" before STORE-002 encrypts it and after
  * STORE-002 decrypts it.
  *
  * A plaintext secret is the object `{"$secret": "hunter2"}` and never a bare string. The
  * marker exists so that the crypto layer can walk any section's JSON and find every secret
  * without a per-section list of field paths — a list that would have to be extended, and
  * forgotten, every time a section gains a field. Encryption replaces the whole marker object
  * with `{"$enc": {...}}` (STORE-002); decryption puts it back. Nothing outside `kui.config.store`
  * ever sees a `$enc` node. */
object SecretJson:
  val PlaintextField: String = "$secret"
  val CipherField: String    = "$enc"

  def encoder: Encoder[Secret[String]]     // Secret("x") => {"$secret":"x"}
  def decoder: Decoder[Secret[String]]     // {"$secret":"x"} => Secret("x")

  /** Every JSON path in `payload` holding a plaintext secret marker, in document order.
    * Used by STORE-002 and by the STORE-009 leak test. */
  def plaintextPaths(payload: Json): List[String]

  /** True when no `$secret` marker survives anywhere in the tree. The write path asserts this
    * after encryption, so a section that gains a secret field can never reach the topic in the
    * clear because someone forgot to register it. */
  def isFullyEncrypted(payload: Json): Boolean

/** Failures of the store that are not failures of a request. Each maps to one `ErrorCode`. */
enum StoreError(val code: ErrorCode, val message: String) extends Product, Serializable:
  case InvalidKey(raw: String, why: String)
  case UnsupportedEnvelope(found: Int, supported: Set[Int])
  case MalformedRecord(key: String, why: String)

object StoreError:
  def toKuiError(e: StoreError): KuiError    // InfrastructureError-side; see ErrorCode table
```

### `ErrorCode` cases added by this task

Added to `kui.kernel.error.ErrorCode` in the enum's existing style, each with its description
sentence (KERN-008 makes the description a constructor parameter, so a case without one does not
compile):

| Case | wire | status | retryable | description |
| --- | --- | --- | --- | --- |
| `StoreUnavailable` | `KUI-STORE-UNAVAILABLE` | 503 | true | "KUI's metadata store could not be reached; reads are served from the last replayed state and writes are rejected." |
| `StoreReplayTimeout` | `KUI-STORE-REPLAY-TIMEOUT` | 503 | true | "The metadata store's log could not be replayed to its end within the configured timeout." |
| `StoreTopicIncompatible` | `KUI-STORE-TOPIC-INCOMPATIBLE` | 500 | false | "An existing metadata-store topic has settings KUI cannot use, and KUI never rewrites an existing topic's configuration." |
| `StoreEnvelope` | `KUI-STORE-ENVELOPE` | 500 | false | "A record in the metadata store is not a readable envelope for this version of KUI." |
| `StoreCrypto` | `KUI-STORE-CRYPTO` | 500 | false | "An encrypted field in the metadata store could not be decrypted with any configured key." |
| `StoreNotConfigured` | `KUI-STORE-NOT-CONFIGURED` | 501 | false | "No metadata store is configured, so this change cannot be persisted; configure kui.store.kafka.* to enable it." |

`ErrorCode.area` derives `STORE` from the wire string for free, so the generated document groups
them without further work. `StoreUnavailable`, `StoreReplayTimeout` and `StoreCrypto` are **not**
added to `KuiError.InfrastructureCodes` — that set is keyed by `ErrorCode` and already contains
`UpstreamUnavailable`/`Timeout`/`Internal`; STORE-008 adds `StoreUnavailable` and
`StoreReplayTimeout` to it when it wires the capability fold, because until there is a capability
to dim, changing that set has no observable effect and would be untestable. Record that here so
the next reader does not think it was forgotten.

## Envelope format, decided here

```json
{"envelopeVersion":1,"key":"cluster/prod-eu","version":3,"updatedAt":"2026-09-03T10:15:30Z","updatedBy":"kui-cluster/7f3a","deleted":false,"payload":{"displayName":"Production EU","bootstrapServers":["kafka-1:9092"],"security":{"protocol":"SASL_SSL","mechanism":"SCRAM-SHA-512","username":"kui","password":{"$enc":{"keyId":"k1","iv":"...","ct":"..."}}}}}
```

Rules a worker must not vary:

- **The key is the Kafka record key**, as UTF-8 text, and is `StoreKey.render`. It is duplicated
  inside the envelope so that an exported file (metadata-store.md §5) is self-describing when
  the key column is lost. Replay asserts the two agree and treats a mismatch as
  `StoreError.MalformedRecord`.
- **`updatedAt` is ISO-8601 UTC with second precision**, `Instant.truncatedTo(SECONDS)`. Not
  millis: the field is for a human reading a diff, and a millisecond difference between two
  replicas writing "the same" record is noise in a golden file.
- **`updatedBy` is `<service-name>/<instance-suffix>`** while `kui.auth.type = disabled` (M1);
  when identity arrives it becomes the principal id. It is free text to a reader, never parsed.
- **Field order in the encoder is the order above.** Golden files are compared as parsed JSON
  (`assertEquals(parse(actual), parse(golden))`) so ordering is not load-bearing for correctness,
  but a stable order keeps the committed files diffable.
- **Unknown envelope fields are ignored on read.** Unknown `envelopeVersion` is not: it fails with
  `StoreError.UnsupportedEnvelope`, which is the "never a silent skip" requirement of DEVPLAN §7.
  The difference is deliberate — an added field is compatible by construction, a bumped version
  number is the writer saying "you cannot understand this".

## Tests required

- `StoreKeySuite` (unit + property):
  - `renderParseRoundTrips` — property over generated valid sections and ids.
  - `rejectsWrongSegmentCount` — `"cluster"`, `"cluster/a/b"`, `""`, `"/x"` each give
    `StoreError.InvalidKey` naming the raw input.
  - `rejectsIdsThatAreNotSlugs` — uppercase, spaces, leading dash, 200 characters.
  - `unknownSectionParsesToOther` — `"connect/foo"` is `StoreSection.Other("connect")`, not a
    failure, with a comment pointing at the forward-compatibility argument above.
- `StoreRecordSuite` (unit):
  - `encodesToTheCommittedGoldenFile` / `decodesTheCommittedGoldenFile` for both fixtures.
  - `tombstoneGoldenFileHasDeletedTrueAndAnEmptyPayload`.
  - `unknownEnvelopeVersionIsANamedError` — `{"envelopeVersion":99,...}` decodes to
    `StoreError.UnsupportedEnvelope(99, Set(1))`, and the failure message contains both numbers.
  - `unknownEnvelopeFieldIsIgnored` — the same golden file plus `"futureField": 1` decodes equal
    to the original.
  - `updatedAtIsSecondPrecision` — a record created from an `Instant` with nanos encodes without
    them.
  - `payloadWithACipherNodeRoundTripsUntouched` — the envelope never inspects `$enc`.
  - `secretMarkerRedactsInToString` — `SecretJson.decoder` produces a `Secret[String]` whose
    `toString` is `Secret(***)`; a `StoreRecord`'s own `toString` is not asserted, because its
    payload is `Json` and a payload with a plaintext marker in it is exactly what STORE-002
    forbids from reaching a log line.
  - `plaintextPathsFindsEveryMarker` — a nested payload with three markers, one inside an array,
    yields three paths in document order.
  - `isFullyEncryptedIsFalseWhenOneMarkerRemains`.

## Observability / Degraded behavior

Nothing runs at runtime in this task. One rule the codecs must respect and which STORE-006 and
STORE-008 depend on: **no code in `kui.config.store` ever puts a `payload` into a log message.**
Log the key, the version and the offset; those identify the record completely and none of them
can hold a secret. The suites do not assert this (there is nothing logging yet) — STORE-009 does,
against a real replay.
