# GRP-018 — `MutationGuard` and `AuditSink[F]`: the pre-M5 safety net

- **ID:** GRP-018
- **Title:** `MutationGuard` and `AuditSink[F]`: the pre-M5 safety net
- **Milestone / Feature:** M4 / CG-003, CG-004, CG-005 (safety), forward to AD-001, OT-002 (M5)
- **Owner role:** Domain Architect (Consumer Group Management context)
- **Context / module:** `services/consumer/application` (+ `services/consumer/domain` for the record)
- **Size:** M
- **Dependencies / blocked by:** GRP-012

## Goal (user value)

M4 ships the first operation in KUI that changes a customer's system, and it ships it in a milestone
where read-only mode, RBAC and the audit trail do not yet exist. This task is the reason that is
acceptable: every mutation is refused on a read-only cluster before a Kafka client is touched, every
mutation is classified so M5's enumeration test finds it already classified, and every mutation —
successful, refused or failed — leaves one structured record with what it did.

## Scope

1. `MutationKind`: the closed set of mutations this service performs, with the resource each one
   names. M5's read-only enumeration test reads this.
2. `MutationGuard[F]`: `guard(cluster, kind, resource)(op)` — the one function every mutation goes
   through. It checks read-only, runs the operation, writes the audit record, and cannot be
   bypassed because the use cases take the guard rather than the port.
3. `MutationRecord`: the audit shape. Declared in `domain` so the port (GRP-012) can name it.
4. `AuditSink[F]`'s contract: never fails the operation it records.

## Non-goals

- **No global read-only policy.** M5 (`libs/security-core` gains it). M4 reads the `readOnly` flag on
  the cluster profile the cluster service already serves, which is a per-cluster setting that exists
  today.
- **No RBAC.** M6. `MutationRecord.principal` is the anonymous principal M5's plan already says it
  will be until M6.
- **No `__kui_audit` topic.** M5 (D7 of the M1 plan: the topic is created by the milestone that first
  writes a record — and a *log* sink is not a record in that topic). GRP-023 ships the log sink.
- **No audit viewer.** M6.
- **No mutation of anything but consumer groups.** This guard lives in the consumer service; M5
  generalises it or replaces it, and either is fine because it is behind a port.

## Design references

- DEVPLAN §10 D2 — the three substitutes, in full, and why they ship with the operation.
- `docs/ROADMAP.md` M5: *"Read-only mode: every mutating operation in every service introduced so far
  returns `KUI-READ-ONLY`; the check is on the operation's `Mutation` marker, verified by a test that
  enumerates all endpoints and asserts each is classified"* — `MutationKind` is that marker's
  application-layer half, built now so M5's test has something to enumerate.
- ADR-023 (audit and masking) — the record's field set, which M4 implements the subset of that it can
  know without an identity service.
- `ErrorCode.ReadOnly` (`KUI-READ-ONLY`, 405) already exists in `libs/kernel`.

## Public Scala signatures to implement

```scala
package kui.consumer.domain

import java.time.Instant
import kui.kernel.{ClusterId, GroupId}

enum MutationOutcome:
  case Succeeded
  case Refused(code: String, reason: String)
  case Failed(code: String, reason: String)
  /** The operation was cancelled or timed out after the request was sent. Kafka gives no guarantee
    * that it was not applied, and a record that claimed either would be a lie. An operator seeing
    * this knows to go and look. */
  case Unknown(reason: String)

/** One line in the audit trail.
  *
  * Deliberately flat and deliberately free of anything that could carry a credential: there is no
  * profile, no connection, no properties map. GRP-023's suite asserts that against a profile whose
  * every secret is a distinctive token.
  */
final case class MutationRecord(
    at: Instant,
    cluster: ClusterId,
    /** "consumer.group.offsets.reset", "consumer.group.delete", "consumer.group.offsets.delete" */
    operation: String,
    /** The group id. A resource string rather than a typed id because M5's sink is generic. */
    resource: String,
    /** Anonymous until M6 (ROADMAP M5, "audit records carry an anonymous principal until M6"). */
    principal: String,
    /** What changed, as `partition -> (before, after)`. Empty for a delete. Offsets are not
      * credentials and an audit record without them answers nothing. */
    before: Map[String, Long],
    after: Map[String, Long],
    outcome: MutationOutcome,
    /** The trace id, so a record can be joined to the request that produced it. */
    traceId: Option[String]
)
```

```scala
package kui.consumer.application

/** Every mutation this service can perform. M5's enumeration test reads this set.
  *
  * Adding a mutation without adding a case here does not compile, because `MutationGuard.guard`
  * takes one. That is the enforcement DEVPLAN §6.3's "documented rules that nothing enforces get
  * violated" asks for. */
enum MutationKind(val operation: String):
  case ResetOffsets extends MutationKind("consumer.group.offsets.reset")
  case DeleteOffsets extends MutationKind("consumer.group.offsets.delete")
  case DeleteGroup extends MutationKind("consumer.group.delete")

trait MutationGuard[F[_]]:
  /** The only way a mutation happens in this service.
    *
    * Order, and it matters: (1) resolve the profile; (2) if `readOnly`, return `KUI-READ-ONLY`
    * **without touching the Kafka client** and record a `Refused`; (3) run `op`; (4) record the
    * outcome — always, including on failure and on cancellation; (5) invalidate the snapshot on
    * success, so the next read does not serve the pre-mutation state.
    */
  def guard[A](
      cluster: ClusterId,
      kind: MutationKind,
      resource: String,
      before: Map[String, Long],
      after: Map[String, Long]
  )(op: F[Either[KuiError, A]]): F[Either[KuiError, A]]

object MutationGuard:
  def make[F[_]: Temporal](
      profiles: ClusterProfileSource[F],
      audit: AuditSink[F],
      snapshots: GroupSnapshots[F],
      logger: StructuredLogger[F],
      principal: F[String]        // constant "anonymous" in M4; M6 supplies the real one
  ): MutationGuard[F]
```

The audit write is `guarantee`-shaped: it runs on success, on error and on cancellation, and its own
failure is logged at ERROR and swallowed. A sink that can fail a mutation is a sink that will one day
refuse a reset because a log was full, and an operator's cluster is more important than KUI's
bookkeeping.

## Tests required

`MutationGuardSuite` (MUnit + `munit-cats-effect` + `RecordingAuditSink` + fakes):

1. `aReadOnlyClusterIsRefusedBeforeTheOperationRuns` — **the headline assertion**: `KUI-READ-ONLY`,
   and the fake operation's call log is empty.
2. `aRefusalIsAudited` — one record, `outcome = Refused("KUI-READ-ONLY", _)`.
3. `aSuccessIsAudited` — one record, `Succeeded`, with `before` and `after`.
4. `aFailureIsAudited` — the operation returns `Left`; one record, `Failed`, and the error is
   returned unchanged.
5. `aRaisedExceptionIsAudited` — the operation raises; one record, `Failed`, and the exception
   propagates.
6. `cancellationIsAuditedAsUnknown` — **the D2/R-8 case**: cancel mid-operation, assert one record
   with `outcome = Unknown`. Kafka gives no guarantee the write did not land, and the record says so.
7. `exactlyOneRecordPerMutation` — a property over the five paths above: never zero, never two.
8. `aFailingSinkDoesNotFailTheMutation` — the sink raises; the operation still returns `Right`, and
   an ERROR was logged.
9. `theSnapshotIsInvalidatedOnSuccessOnly` — asserted on the fake snapshots' call log.
10. `noRecordFieldContainsACredential` — the profile carries `Secret("hunter2-distinctive")`; the
    serialised record does not contain that token anywhere. Asserted on the serialised form, not on
    the case class, because the leak would be in a `toString`.
11. `theTraceIdIsCarried`.
12. `everyMutationKindHasADistinctOperationString` — a property; two kinds sharing a string would
    make the audit trail ambiguous.

## Observability

| Signal | Name | Attributes |
| --- | --- | --- |
| Counter | `kui.consumer.mutations` | `cluster.id`, `operation`, `outcome` — the four outcomes, so a rise in `unknown` is visible |
| Counter | `kui.consumer.mutations.refused_read_only` | `cluster.id` |
| Counter | `kui.audit.write_failures` | `sink` — the sink failing is invisible otherwise, by design |
| Span | `kui.consumer.mutation` | `cluster.id`, `operation`, `resource` |

Logging: every mutation at INFO, before and after, with `cluster.id`, `operation`, `resource`,
`outcome` and the partition count. Never the profile, never a secret.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| Cluster profile unavailable | The mutation is refused with `KUI-UPSTREAM-UNAVAILABLE` and audited as `Refused`. **Not** attempted with a stale profile: a stale profile may be missing exactly the `readOnly` flag that was just set |
| Audit sink down | Logged at ERROR, counted, mutation proceeds |
| Cluster marked read-only after the plan was made | The guard refuses at apply time; this is the second half of the two-phase flow's re-check |
