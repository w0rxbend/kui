# GRP-010 — `services/consumer/domain`: the module, the model and `docs/domain/consumer.md`

- **ID:** GRP-010
- **Title:** `services/consumer/domain`: the module, the model and `docs/domain/consumer.md`
- **Milestone / Feature:** M4 / CG-001, CG-002
- **Owner role:** Domain Architect (Consumer Group Management context)
- **Context / module:** `services/consumer/domain`
- **Size:** M
- **Dependencies / blocked by:** GRP-001

## Goal (user value)

The vocabulary the rest of the milestone is written in. A `ConsumerGroup` in KUI is not a Kafka
`ConsumerGroupDescription`: it is a group *plus* what it is consuming, how far behind it is, and how
well any of that is known. Getting that shape right once is what keeps five use cases and three
screens from each inventing their own.

## Scope

1. The Mill module `services.consumer.domain` (`KuiPureModule with KuiJvmModule`, `libs.kernel.jvm`
   and cats-core only — rule A1), and its test module.
2. The aggregate: `ConsumerGroup`, `GroupSummary`, `GroupMember`, `Assignment`, `TopicSubscription`.
3. `GroupCoordinatorRef` and `GroupCompleteness` — the type that says which parts of a group's data
   were actually obtained, so a screen can distinguish "no members" from "we were not allowed to
   ask".
4. `docs/domain/consumer.md`, created: the context's ubiquitous language, the aggregate boundary,
   and the two invariants this task can already state.

## Non-goals

- **No lag arithmetic.** `PartitionLag` and `LagMath` are GRP-011, in this module, in the next task.
- **No reset types.** GRP-012.
- **No ports.** GRP-012 declares them, after the model they are stated in terms of exists.
- **No effects.** `KuiPureModule` forbids `var`; there is no `F[_]` in this task's files at all.
- **No DTO, no Circe, no Tapir.** Rule A1.

## Design references

- `ARCHITECTURE.md` §4.3's consumer row: `ConsumerGroup`, `Member`, `PartitionLag` (`Option[Lag]` +
  anomaly flags), `ResetSpec`, `GroupAdmin[F]`, `ClusterProfileSource[F]`.
- `research/kafbat/ui-analysis.md` "Consumer group details" — the six metric indicators the page

- `research/kafka/admin-capabilities.md` §3 — what a broker can and cannot tell us, which is what

## Public Scala signatures to implement

```scala
package kui.consumer.domain

import java.time.Instant

import kui.kernel.{BrokerId, GroupId, TopicName, TopicPartition}
import kui.kernel.group.{GroupProtocol, GroupState}

final case class GroupCoordinatorRef(id: BrokerId, host: String, port: Int)

/** What one member holds, and where it is going.
  *
  * `targetPartitions` is `Some` only when the coordinator is moving this member somewhere else —
  * which is the definition of "this member is mid-rebalance" and is what the detail page's stale
  * badge keys on (DC-H10).
  */
final case class GroupMember(
    memberId: String,
    groupInstanceId: Option[String],
    clientId: String,
    host: String,
    partitions: Set[TopicPartition],
    targetPartitions: Option[Set[TopicPartition]]
):
  def isRebalancing: Boolean = targetPartitions.exists(_ != partitions)
  def topics: Set[TopicName] = partitions.map(_.topic)

/** Which parts of a group's picture were actually obtained.
  *
  * "No members" and "we were not allowed to ask about members" render the same if this type does
  * not exist, and they mean opposite things to an operator. Each field is `true` when that part is
  * known and `false` when the call was skipped, refused or failed.
  */
final case class GroupCompleteness(
    membersKnown: Boolean,
    committedOffsetsKnown: Boolean,
    endOffsetsKnown: Boolean,
    /** Partitions excluded from every offset figure, with why (leaderless, forbidden, not found). */
    excludedPartitions: Map[TopicPartition, String]
):
  def isComplete: Boolean

object GroupCompleteness:
  val Complete: GroupCompleteness

/** The list-page row. Everything on it is derivable from the snapshot with no further call. */
final case class GroupSummary(
    groupId: GroupId,
    state: GroupState,
    protocol: GroupProtocol,
    isSimple: Boolean,
    memberCount: Int,
    topicCount: Int,
    partitionCount: Int,
    coordinator: Option[GroupCoordinatorRef],
    /** `None` when no partition of this group has a computable lag — never `Some(0)` (D6). */
    totalLag: Option[Long],
    /** Committed-offset movement per second between the last two snapshot passes (D12). */
    pace: Option[Double],
    completeness: GroupCompleteness
)

/** The detail-page aggregate.
  *
  * The aggregate boundary is one group on one cluster. It deliberately does not hold the cluster,
  * the topic's configuration or the broker set: those belong to other contexts, and a group that
  * held them could not be refreshed without refreshing them too.
  */
final case class ConsumerGroup(
    groupId: GroupId,
    state: GroupState,
    protocol: GroupProtocol,
    isSimple: Boolean,
    partitionAssignor: String,
    members: List[GroupMember],
    coordinator: Option[GroupCoordinatorRef],
    subscriptions: List[TopicSubscription],
    completeness: GroupCompleteness,
    observedAt: Instant
):
  def summary: GroupSummary
  def isRebalancing: Boolean          // state says so, or any member's target differs
  /** DEVPLAN §10 D4: the union of both halves. The single place this rule is expressed. */
  def permitsOffsetChange: Boolean = GroupState.permitsOffsetChange(state) && members.isEmpty

/** One topic this group consumes, with its partitions. `TopicSubscription` rather than a bare
  * `TopicName` because the detail page's rows are topics and its expanded rows are partitions
  * (`research/kafbat/ui-analysis.md`), and a shape that matches the screen needs no reshaping in
  * the API layer. */
final case class TopicSubscription(
    topic: TopicName,
    partitions: List[PartitionState]
):
  def totalLag: Option[Long]      // GRP-011 supplies the rule; declared here, implemented there
```

`PartitionState` and `PartitionLag` are declared in GRP-011; this task leaves
`TopicSubscription.partitions` typed against them and the two tasks land in order.

## Tests required

`ConsumerGroupSuite` (MUnit + ScalaCheck, using `GroupFixtures`):

1. `permitsOffsetChangeNeedsBothHalves` — the D4 rule, on the aggregate that states it.
2. `isRebalancingIsTrueFromEitherSignal` — the state, or a member whose target differs.
3. `summaryCountsDistinctTopicsNotAssignments` — a member holding four partitions of one topic gives
   `topicCount = 1`.
4. `summaryPartitionCountIsTheUnionNotTheSum` — two members must never both count a partition, which
   they can briefly during a rebalance.
5. `completenessDistinguishesNoMembersFromNotAsked` — the two render differently, asserted on the
   type rather than on a screen.
6. `excludedPartitionsSurviveIntoTheSummary`.
7. `anEmptyGroupIsRepresentable` — no members, no subscriptions, and still a valid aggregate.
8. `aSimpleGroupHasNoAssignor` — the empty assignor string is legal and is not rendered as a name.
9. `observedAtIsRequired` — there is no aggregate without a timestamp, because every screen shows
   one.

`GroupFixtures` is reused by GRP-011 … GRP-020's suites and by GRP-024's golden files; it is the
one place a sample group is constructed.

## Degraded behavior

Expressed as data, not as behaviour: every partial answer this context can receive is a
`GroupCompleteness` field, and every use case downstream renders from it. The table of what each
combination means to a screen lives in `docs/domain/consumer.md`.
