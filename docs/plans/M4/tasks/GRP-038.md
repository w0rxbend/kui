# GRP-038 — Fault-isolation and rebalance E2E

- **ID:** GRP-038
- **Title:** Fault-isolation and rebalance E2E
- **Milestone / Feature:** M4 / CG-001 … CG-006, TP-015, KU-013
- **Owner role:** QA Engineer
- **Context / module:** `e2e`
- **Size:** L
- **Dependencies / blocked by:** GRP-039, GRP-035

## Goal (user value)

Proof, against real containers in a browser, that the milestone's two hardest claims are true: a
dead consumer service does not take the topic page down, and a rebalancing group does not blank the
page an operator is reading.

## Scope

1. `ConsumerServiceDownSuite`: stop `kui-consumer`, assert what still works, start it, assert
   recovery without a page reload.
2. `ConsumerRebalanceSuite`: force a rebalance while the detail page is open, assert the badge, the
   greyed assignments and the intact lag figures.
3. `ConsumerBundleSuite`: the network assertion that `ui-consumers`' module is **not** downloaded for
   a cluster whose consumer capability is `NotConfigured` (risk R-9).
4. `ConsumerResetSuite`: the destructive path end to end — plan, review, confirm, and the audit line
   in the container's log.

## Non-goals

- **No functional coverage.** Everything a stub can prove is proved in a faster suite. An E2E asserts
  the things only real containers and a real browser can: process death, module loading, and the
  browser's own behaviour under a mid-flight change.
- **No new Compose topology.** GRP-039 adds the consumer service to the existing one.
- **No screenshots as assertions.** A screenshot is evidence for a human; the assertions are on the
  DOM and the network.

## Design references

- `docs/ROADMAP.md` M4's third and fourth exit criteria — the topic page with the consumers panel
  unavailable, and the rebalance keeping last-seen assignments.
- `STATUS.md` M1 integration defect 3 — `./mill e2e.test` depended on the all-in-one jar but not on
  the container images, so the suite that proved M1's headline claim ran against **M0 images for the
  whole of M1**. This task's `build.mill` change must declare the image dependency, and the
  Implementation Report must show the image digest the run used.
- ADR-032 — the degraded-tab rendering this suite asserts.
- `e2e`'s existing `ClusterServiceDownSuite` — the shape to copy.
- DEVPLAN §8's fault-injection list, scenarios 1, 3 and 4.

The `build.mill` change is the one that matters: `e2e.test` must depend on **every** image the
Compose topology runs, by task, so that a stale image cannot silently be tested. Name the dependency
and assert the digest in the suite's `beforeAll`, logging it, so the Implementation Report can quote
it.

## Public Scala signatures to implement

None; these are suites. The shared helper is `e2e`'s existing `ComposeStack` fixture, extended with
`kui-consumer`.

## Tests required

`ConsumerServiceDownSuite` — with `docker stop kui-consumer`:

1. `theShellStillRenders`.
2. `theDashboardStillLoads`.
3. `theTopicPageStillLoadsItsOwnSections` — **exit criterion 5**.
4. `theConsumersTabIsPresentAndDimmed`.
5. `theConsumersTabBodyShowsTheReason`.
6. `theSidebarConsumersEntryIsDimmedAndClickable`.
7. `clickingItLandsOnTheFallbackPanelWithWhatStillWorks`.
8. `dockerStartRecoversWithoutAPageReload` — the capability stream flips it back, which is the
   property that makes the fallback panel bearable.
9. `noConsoleErrorIsLoggedDuringTheOutage` — a dead upstream is an expected condition, and a browser
   console full of stack traces during one trains everyone to ignore it.

`ConsumerRebalanceSuite`:

1. `theDetailPageRendersTheStableGroup`.
2. `forcingARebalanceKeepsTheAssignmentsOnScreen` — **exit criterion 6**: the member rows are still
   there, greyed.
3. `theStaleBadgeAppearsWithATimestamp`.
4. `theLagColumnsAreNotGreyed` — they are still true (GRP-032's DC-H10 rule).
5. `theTableRecoversWhenTheRebalanceCompletes`.

`ConsumerBundleSuite`:

1. `theConsumersModuleLoadsWhenTheCapabilityIsAvailable` — asserted on the network log, so the
   negative case below means something.
2. `theConsumersModuleIsNotRequestedWhenTheCapabilityIsNotConfigured` — **risk R-9's proof**.
3. `theTopicPageLoadsWithoutTheConsumersModuleUntilTheTabIsOpened`.
4. `theBundleShapeCheckStillPasses` — two feature modules split out, `main.js` under its budget.

`ConsumerResetSuite`:

1. `theWizardPlansAgainstTheSeededEmptyGroup`.
2. `thePlanTableShowsTheProposedOffsets`.
3. `confirmingAppliesThemAndTheGroupPageShowsTheNewOffsets`.
4. `theAuditLineAppearsInTheServiceLog` — `docker logs kui-consumer | grep '"logger":"kui.audit"'`,
   parsed, with the operation, the group and the before/after offsets asserted. **Exit criterion 9,
   end to end.**
5. `resettingTheStableGroupIsRefusedInTheBrowser` — with the refusal's own message on screen.
6. `theResetIsNotReversibleSentenceIsPresent` — the one sentence that must survive every redesign.

## Observability

The suites assert on observability rather than emitting it: test 4 of `ConsumerResetSuite` reads the
audit log, and `ConsumerServiceDownSuite` asserts the capability transitions appear in
`/api/v1/capabilities`.

## Degraded behavior

The suite's own: a container that will not start fails with its log tail; a Playwright timeout
reports the last screenshot and the console log. Neither reports a bare timeout, because an E2E that
fails opaquely is an E2E that gets disabled.
