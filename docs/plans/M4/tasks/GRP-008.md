# GRP-008 — `GroupFeature`: the capability probe for the four version-gated group calls

- **ID:** GRP-008
- **Title:** `GroupFeature`: the capability probe for the four version-gated group calls
- **Milestone / Feature:** M4 / CG-001, CG-002, CG-004
- **Owner role:** Principal Scala Engineer
- **Context / module:** `libs/kafka`
- **Size:** M
- **Dependencies / blocked by:** GRP-003

## Goal (user value)

KUI never guesses what a cluster can do from its version number. Four things in M4 are version-gated
— the listing's state filter (2.6), its type filter (3.8), multi-group offset fetches (3.3) and
KIP-848 target assignments — and every managed Kafka service in the world reports a version that
does not predict which of them work. The probe asks.

## Scope

1. `GroupFeature`, an enum of the four gated capabilities plus `ResetOffsets` (2.5) and
   `DeleteOffsets` (2.4), which gate buttons rather than code paths.
2. `GroupCapabilityProbe`: one cheap call per feature against the live cluster, run once at connect
   and hourly thereafter, producing the same **three-valued** shape M1's `ClusterFeatures`
   established: `present`, `absent`, `unknown`, plus `probedAt`.
3. The downgrade rule: `UnsupportedVersionException` and `InvalidRequestException` mean "feature
   absent"; a timeout or an authorization failure means **`unknown`**, never `absent`.

## Non-goals

- **No hourly loop here.** The cadence belongs to the snapshot that holds the result (GRP-013), as
  `ClusterSnapshots` does for `ClusterFeatures`. This task provides one probe pass.
- **No version parsing.** ADR-030 forbids it. `KafkaVersion` exists and is displayed; it is never
  branched on.
- **No new capability plumbed to the gateway.** `GroupFeature` is internal to the consumer service;
  what reaches `/api/v1/capabilities` is the service-level `consumer` capability (GRP-029).

## Design references

- `research/kafka/admin-capabilities.md` §0's capability-probing table and §3's minimum-version
  column.
- ADR-030 — probe, never assume; the managed-service behaviour where a call is rejected with
  `InvalidRequestException` rather than `UnsupportedVersionException`.
- M1's `libs/kafka/src/kui/kafka/admin/CapabilityProbe.scala` and `ClusterFeature.scala` — the shape
  to copy exactly, including the three-set invariant `present ++ absent ++ unknown == All` and
  pairwise disjointness, which M1's gate review (F-05) had to restore once already after a caller
  collapsed it to a `Set`.

## Public Scala signatures to implement

```scala
package kui.kafka.admin

import java.time.Instant

enum GroupFeature(val probeDescription: String):
  case StateFilter extends GroupFeature("list groups filtered by state (Kafka 2.6)")
  case TypeFilter extends GroupFeature("list groups filtered by type (Kafka 3.8)")
  case MultiGroupOffsets extends GroupFeature("fetch committed offsets for several groups in one request (Kafka 3.3)")
  case RequireStable extends GroupFeature("fetch only stable committed offsets (Kafka 2.6)")
  case TargetAssignment extends GroupFeature("read a KIP-848 member's target assignment")
  case ResetOffsets extends GroupFeature("alter a group's committed offsets (Kafka 2.5)")
  case DeleteOffsets extends GroupFeature("delete a group's committed offsets for a topic (Kafka 2.4)")

object GroupFeature:
  val All: Set[GroupFeature] = values.toSet

/** Three sets, never two.
  *
  * A probe that timed out must not be recorded as "this cluster cannot do that": an hour-long cache
  * of a lie is exactly the bug M1's gate review found when a caller collapsed the same shape to a
  * `Set` (F-05). `unknown` is the third answer and it renders as "not determined", never as absent.
  *
  * Invariant, asserted as a property: `present ++ absent ++ unknown == GroupFeature.All`, and the
  * three sets are pairwise disjoint.
  */
final case class GroupFeatures(
    present: Set[GroupFeature],
    absent: Set[GroupFeature],
    unknown: Set[GroupFeature],
    probedAt: Instant
):
  def has(f: GroupFeature): Boolean = present.contains(f)
  def isUnknown(f: GroupFeature): Boolean = unknown.contains(f)

object GroupFeatures:
  def unprobed(at: Instant): GroupFeatures

trait GroupCapabilityProbe[F[_]]:
  def probe(conn: ClusterConnection): F[GroupFeatures]   // never fails

object GroupCapabilityProbe:
  def make[F[_]: Async](pool: AdminClientPool[F], logger: StructuredLogger[F]): GroupCapabilityProbe[F]
```

The probe calls, one per feature, each with a short timeout of its own (`AdminTuning.probeTimeout`,
default 5 s) so that a slow cluster does not make the probe pass take a minute:

| Feature | Probe | `present` when |
| --- | --- | --- |
| `StateFilter` | `listGroups` with `inGroupStates(Set(Empty))` | it returns without `UnsupportedVersion` / `InvalidRequest` |
| `TypeFilter` | `listGroups` with `withTypes(Set(Classic))` | same |
| `MultiGroupOffsets` | `listConsumerGroupOffsets` with two spec entries, one of them a group id that certainly does not exist | same |
| `RequireStable` | `listConsumerGroupOffsets` with `requireStable(true)` on that same id | same |
| `TargetAssignment` | `describeConsumerGroups` on the non-existent id, reading whether the member type exposes the accessor | the call succeeds on a broker that reports the consumer group type |
| `ResetOffsets` | **not probed by calling.** Inferred from `describeFeatures`' `metadata.version` where available, `unknown` otherwise | — |
| `DeleteOffsets` | as `ResetOffsets` | — |

`ResetOffsets` and `DeleteOffsets` are not probed by calling because the only honest probe is
performing the mutation. They gate a button, and a button that is enabled and then fails with a
typed `Unsupported` is better than a mutation performed to find out whether mutations work. The
spec says so out loud so that nobody "improves" it later.

## Tests required

`GroupCapabilityProbeSuite` (MUnit + Testcontainers + stub):

1. `theThreeSetsPartitionAll` — a ScalaCheck property over arbitrary probe outcomes.
2. `everyFeatureIsPresentOnAModernBroker` — against the pinned 4.x container.
3. `unsupportedVersionIsAbsent`.
4. `invalidRequestIsAbsent` — the managed-service shape.
5. `aTimeoutIsUnknownNotAbsent` — **the F-05 assertion**, at its source.
6. `anAuthorizationFailureIsUnknownNotAbsent` — KUI lacking `DESCRIBE` on groups says nothing about
   what the broker supports.
7. `theProbeNeverFails` — an `Admin` that throws on every call still yields a `GroupFeatures` with
   everything `unknown`.
8. `theProbeIsBoundedByItsOwnTimeout` — under `TestControl`, an `Admin` that never answers: the probe
   completes in `probeTimeout × features`, not in `default.api.timeout.ms`.
9. `cancellationLeavesNoLeasedClient`.

Logging: the full three-set result at INFO once per probe pass, because it is the answer to "why is
that button disabled" and an operator should be able to find it in the log.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| Cluster unreachable | Every feature `unknown`; callers take the conservative path (no state filter, one offsets request per group) and buttons that depend on `ResetOffsets` are shown enabled — because `unknown` is not `absent`, and disabling on a probe failure would hide a working feature |
| Feature `unknown` on a screen that depends on it | Rendered as "not determined" with the probe's reason, never as unsupported (ADR-032) |
