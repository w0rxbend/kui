# GRP-020 — `DeleteGroupUseCase` and `DeleteOffsetsUseCase`

- **ID:** GRP-020
- **Title:** `DeleteGroupUseCase` and `DeleteOffsetsUseCase`
- **Milestone / Feature:** M4 / CG-003, CG-005
- **Owner role:** Domain Architect (Consumer Group Management context)
- **Context / module:** `services/consumer/application`
- **Size:** M
- **Dependencies / blocked by:** GRP-019

## Goal (user value)

The two other destructive operations on a consumer group: removing a group that is no longer used,
and removing its committed offsets for one topic so that it starts fresh there without touching the
rest of what it consumes. Both under exactly the same safety net as the reset.

## Scope

1. `DeleteGroupUseCase[F]`: existence, precondition, guard, delete, invalidate.
2. `DeleteOffsetsUseCase[F]`: existence, precondition, the topic's partition set resolved from the
   group's own commits, guard, delete, invalidate.
3. A `before` map for the audit record in both cases — what the group's offsets were at the moment
   they were removed, because "it is gone" is not an audit trail.

## Non-goals

- **No bulk delete.** One group per request. The port supports many (GRP-007) because Kafka does;
  the API does not, because a bulk destructive action with no RBAC is not a thing M4 should ship.
- **No two-phase token.** Deletes take no parameters an operator could get wrong: there is nothing to
  preview but the fact itself, and the confirmation is the UI's typed-name dialog (GRP-035). The
  reset's token exists because the *offsets* need confirming, and copying it here would be ceremony.
- **No cascade.** Deleting a group does not delete anything else. Deleting offsets for a topic does
  not delete the group even when it leaves it with none.

## Public Scala signatures to implement

```scala
package kui.consumer.application

import kui.kernel.{ClusterId, GroupId, TopicName, TopicPartition}

trait DeleteGroupUseCase[F[_]]:
  /** `KUI-GROUP-NOT-FOUND` for a group that is not there — checked by listing, never by describing.
    * `KUI-INVALID-STATE` for one with members. `KUI-READ-ONLY` on a read-only cluster. */
  def delete(cluster: ClusterId, group: GroupId): F[Either[KuiError, Unit]]

final case class DeletedOffsets(topic: TopicName, partitions: Set[TopicPartition])

trait DeleteOffsetsUseCase[F[_]]:
  /** Deletes the group's committed offsets for one topic.
    *
    * The partition set is resolved from the group's **own commits**, not from the topic's partition
    * list: deleting offsets for a partition the group never committed on is a no-op that Kafka
    * answers with `UnknownTopicOrPartitionException`, and asking the topic service for a partition
    * count would put a second service on this path.
    *
    * A group with a member still subscribed to the topic is refused by the broker with
    * `GroupSubscribedToTopicException`; the precondition catches it first, and the mapped error is
    * the second line. */
  def delete(cluster: ClusterId, group: GroupId, topic: TopicName): F[Either[KuiError, DeletedOffsets]]

object DeleteGroupUseCase:
  val Operation: String = "kui.consumer.deleteGroup"
  def make[F[_]: Temporal](admin: ClusterId => GroupAdminPort[F], guard: MutationGuard[F], logger: StructuredLogger[F]): DeleteGroupUseCase[F]

object DeleteOffsetsUseCase:
  val Operation: String = "kui.consumer.deleteOffsets"
  def make[F[_]: Temporal](admin: ClusterId => GroupAdminPort[F], guard: MutationGuard[F], logger: StructuredLogger[F]): DeleteOffsetsUseCase[F]
```

Both read the group's committed offsets **before** the mutation, purely to fill `MutationRecord.before`.
That read is best-effort: if it fails, the mutation still proceeds and the record carries an empty
`before` with a note. Refusing to delete a group because KUI could not write down what it was
deleting would be the bookkeeping-over-operator failure GRP-018 already rules out.

| Signal | Name | Attributes |

Logging: INFO before, with the group id, the topic where applicable, and the count of offsets about
to be removed; INFO after, with the outcome. The `MutationRecord` carries the offsets themselves.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| Group has members | Refused with `KUI-INVALID-STATE`; the UI's message is "stop the group's consumers first", which is the action that resolves it |
| Cluster read-only | `KUI-READ-ONLY`; both actions are absent from the UI rather than disabled, because a read-only cluster has no destructive affordances at all |
| Broker below 2.4 | Delete-offsets is `Unsupported` (gated by `GroupFeature.DeleteOffsets`); the row's action is disabled with the reason |
| Cancelled mid-delete | Audited `Unknown`; the group may or may not be gone, and the next snapshot pass will say |
