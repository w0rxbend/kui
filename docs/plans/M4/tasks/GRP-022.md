# GRP-022 — `ClusterProfileSource` adapter: ETag, SSE change, cached last known

- **ID:** GRP-022
- **Title:** `ClusterProfileSource` adapter: ETag, SSE change, cached last known
- **Milestone / Feature:** M4 / OT-003, and precondition P1
- **Owner role:** Domain Architect (Consumer Group Management context)
- **Context / module:** `services/consumer/infrastructure`
- **Size:** L
- **Dependencies / blocked by:** GRP-021

## Goal (user value)

The consumer service is the first service in KUI that has to *obtain* a cluster's connection
settings rather than being handed them by its own configuration. This is that hop: one direct call
to the cluster service, an ETag so an unchanged profile costs a 304, an SSE subscription so a
rotated password takes effect within a poll interval rather than on the next restart, and a cached
last-known profile so the cluster service being down does not take the consumer service with it.

**Read DEVPLAN §3, precondition P1 before starting.** M1 shipped
`GET /internal/v1/clusters/{id}/profile` with **every credential removed**, because M1 had no
consumer, and `ARCHITECTURE.md` §14 says the first consumer decides how it receives them. Run:

```
$ grep -rn "ClusterProfileSource" libs services --include=*.scala
```

- **If a shared credential-bearing profile client already exists** (M2 built one): this task wires
  it into the consumer service and adds only the tests below that are about *this* service's use of
  it. Size drops to M.
- **If it does not** (the expected case): this task builds it, in this module, and the decision
  below is this task's to take and to record in `ARCHITECTURE.md` §14 and in a new ADR-046.

## Scope

1. `HttpClusterProfileSource`: a typed sttp client over `services/cluster/contract`'s
   `ProfileEndpoints`, through `libs/http`'s per-upstream timeout, breaker and bulkhead.
2. **The credential decision** (below), and the change to `ClusterProfileDto` it requires — which is
   a change to the cluster service's contract module and therefore needs a note in `TECH_DEBT.md`
   naming the cross-lane edit, or a two-line PR to lane D's owner. It is the only file outside this
   task's area that it may touch, and the DEVPLAN's boundary table records the exception here.
3. The cache: last-known profile per cluster, held in a `Ref`, served while the cluster service is
   unreachable, with its age exposed so the capability can report `Degraded`.
4. The change subscription: the cluster service's `/internal/v1/clusters/stream` SSE, with reconnect
   and backoff, feeding `ClusterProfileSource.changes`.

## The credential decision

**Credentials travel in the profile response, over the internal network, with the response marked
non-cacheable, and never in a log, a trace attribute or an error message.**

The alternatives and why not:

- *Each service reads `kui.clusters[]` itself.* Then the metadata store's whole point — a cluster
  registered at runtime is usable without restarting anything — is lost for every service but the
  cluster service, and ADR-036's single-writer ownership becomes six readers of one file.
- *A short-lived credential broker.* There is nothing to broker: Kafka SASL credentials are static
  strings, and a broker that hands out the same static string with an expiry is ceremony.
- *Credentials by reference, resolved by each service from the store.* That gives every service the
  store's encryption key, which is strictly worse than giving it the password.

What makes it safe enough for M4: the endpoint is `/internal/v1`, which the gateway does not proxy
(ADR-043); it requires a `SignedPrincipal` header the gateway mints and a service cannot forge
(ADR-020); the response carries `Cache-Control: no-store`; `Secret[String]` renders as `***` in every
`toString`, log and trace (M0's exit criterion, still enforced); and GRP-037's seam suite asserts
that no rendered profile appears in any log line the service emits during a full run.

Recorded as **ADR-046** by GRP-040, with `ARCHITECTURE.md` §14 amended from "M2's first consumer
decides" to what was decided.

## Non-goals

- **No cluster registration, no writes.** The consumer service reads profiles; it never writes one.
- **No profile for a cluster the caller did not ask about.** One id per call.
- **No retry storm.** `libs/http`'s breaker owns the retry policy; this adapter adds none of its own.

## Public Scala signatures to implement

```scala
package kui.consumer.infrastructure

import scala.concurrent.duration.FiniteDuration
import cats.effect.kernel.{Resource, Temporal}
import fs2.Stream

import kui.consumer.domain.{ClusterProfileSource, ClusterProfileView}
import kui.kernel.ClusterId
import kui.kernel.error.KuiError

/** What this service needs from a cluster profile, and nothing more.
  *
  * `readOnly` is here because `MutationGuard` reads it (GRP-018) and it is the one field whose
  * staleness is dangerous: a cluster marked read-only a minute ago must not have a mutation applied
  * against a cached profile that predates the flag. That is why `MutationGuard` refuses on an
  * unavailable profile rather than using the cached one, while the read paths happily use it.
  */
final case class ClusterProfileView(
    cluster: ClusterId,
    connection: kui.kernel.cluster.ClusterConnection,
    readOnly: Boolean,
    version: String,          // the ETag
    fetchedAt: java.time.Instant
)

object HttpClusterProfileSource:
  def resource[F[_]: Temporal](
      client: kui.http.client.KuiHttpClient[F],
      clusterServiceBase: sttp.model.Uri,
      pollInterval: FiniteDuration,     // fallback when the SSE stream is down; default 60 s
      logger: StructuredLogger[F]
  ): Resource[F, ClusterProfileSource[F] & ProfileHealth[F]]

trait ProfileHealth[F[_]]:
  /** `Fresh` while the last fetch succeeded; `Stale(age, reason)` while it did not and a cached
    * profile is being served; `Unavailable(reason)` when nothing was ever fetched. Read by the
    * capability report (GRP-024's consumer half) so the service reports `Degraded` rather than
    * silently running on a profile from an hour ago. */
  def health: F[ProfileHealthState]
```

## Tests required

`HttpClusterProfileSourceSuite` (MUnit + `munit-cats-effect` + a Tapir stub server, no socket):

1. `fetchesAProfileAndCachesIt`.
2. `aSecondFetchSendsIfNoneMatch` — asserted on the stub's captured headers.
3. `aThreeOhFourKeepsTheCachedProfile` — and does not re-parse a body that was not sent.
4. `aVersionBumpReplacesTheCachedProfile`.
5. `theClusterServiceBeingDownServesTheCachedProfile` — **the fault-isolation property**: the port
   answers, and `health` is `Stale`.
6. `nothingEverFetchedIsUnavailableNotAnEmptyProfile`.
7. `theSseStreamPublishesAChange` — a change event on the stub stream appears on `changes` within
   one event.
8. `theSseStreamReconnectsWithBackoff` — under `TestControl`: the stream drops, the client retries at
   the documented backoff, and the poll fallback keeps the profile fresh in the meantime.
9. `thePollFallbackRunsOnlyWhileTheStreamIsDown` — two mechanisms doing the same work at once is
   double load on the one Core service.
10. `theSignedPrincipalHeaderIsSent` — a request without it is what a forged direct call looks like,
    and the cluster service rejects it (M1's own test); this asserts KUI's own client is not that.
11. `noCredentialAppearsInAnyLogLine` — **the security assertion**: a profile whose password is a
    distinctive token, a full fetch-and-change cycle, and an assertion that the token appears in no
    line the fake logger recorded and in no span attribute.
12. `theResponseIsNotCached` — `Cache-Control: no-store` asserted on the server half.
13. `cancellationClosesTheSseConnection` — **the named cancellation test**: cancel the resource, and
    the stub server observes the connection closed within one second.
14. `theTimeoutIsTheConfiguredUpstreamTimeout` — asserted against the configured value, not a
    literal, so changing the default cannot silently invalidate the test (M1's decision D9).

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| Cluster service down, cached profile held | Reads continue against the cached profile; `health` is `Stale`; the consumer capability reports `Degraded` with the age. **Mutations are refused** (GRP-018), because `readOnly` may have changed |
| Cluster service down, nothing cached | `Unavailable`; the consumer capability reports `Unavailable` with the reason, and the screens show the fallback panel |
| SSE stream down, HTTP up | The 60 s poll keeps profiles fresh; a rotated password takes effect within a minute instead of within a second |
| Profile removed (cluster deleted) | `changes` emits; `GroupAdminRegistry` releases the client; the snapshot cell is cancelled |
