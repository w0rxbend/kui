# GRP-011 — `LagMath`: per-partition lag, anomalies, and totals that skip what is undefined

- **ID:** GRP-011
- **Title:** `LagMath`: per-partition lag, anomalies, and totals that skip what is undefined
- **Milestone / Feature:** M4 / CG-002, CG-006
- **Owner role:** Domain Architect (Consumer Group Management context)
- **Context / module:** `services/consumer/domain`
- **Size:** M
- **Dependencies / blocked by:** GRP-010

## Goal (user value)

The number the whole milestone is named for, computed honestly. Lag looks like one subtraction and
is not: a partition with no committed offset has no lag, a committed offset past the end of the log
has no lag either (and certainly not a negative one), a partition whose leader is down has no end
offset to subtract from, and a total that quietly turns any of those into a zero tells an operator
their consumers are caught up when they have never run.

## Scope

1. `PartitionLag` and `PartitionState`: the per-partition value, its anomalies and its inputs.
2. `LagMath`: the pure functions that produce them, and the totals that aggregate them.
3. `Pace`: committed-offset movement per second between two snapshot passes (DEVPLAN §10 D12).
4. `docs/domain/consumer.md` gains the "Lag" section: the rules, in prose, with the two-line
   justification for each.

## Non-goals

- **No fetching.** Committed offsets come from GRP-005, end offsets from GRP-006, and the domain
  receives them. There is no `F[_]` in this file.
- **No trend.** The sparkline's samples are held by the browser (GRP-033); the domain computes one
  point at a time.
- **No lag *history* on the server.** M8's metrics service, if anyone wants it. Keeping samples
  would be a second cache with a second staleness contract for a line drawing.

## Public Scala signatures to implement

```scala
package kui.consumer.domain

import kui.kernel.{Offset, PartitionId, TopicPartition}
import kui.kernel.group.LagAnomaly

/** One partition of one group, as far as this context is concerned.
  *
  * All four offset fields are `Option` because all four can genuinely be missing, and each absence
  * means something different. Collapsing any of them to a default is how a wrong number reaches a
  * capacity decision.
  */
final case class PartitionState(
    partition: PartitionId,
    /** Where the group has committed to. `None` = it never has. */
    committed: Option[Offset],
    /** Log start offset. `None` = it could not be read. */
    begin: Option[Offset],
    /** Log end offset (LEO). `None` = it could not be read, usually no leader. */
    end: Option[Offset],
    /** The member currently holding this partition, if any is assigned. */
    memberId: Option[String],
    host: Option[String],
    lag: PartitionLag
)

/** How far behind, or why that question has no answer.
  *
  * `value` and `anomalies` are independent: a partition can have a computable lag *and* an anomaly
  * (`CommittedBeforeStart` is exactly that case — the lag is real and the consumer will not read
  * from where it committed), and a partition can have neither.
  */
final case class PartitionLag(value: Option[Long], anomalies: Set[LagAnomaly]):
  def isDefined: Boolean = value.isDefined

object PartitionLag:
  val Unknown: PartitionLag = PartitionLag(None, Set.empty)
  def noCommit: PartitionLag
  def noLeader: PartitionLag

/** The rules. Pure, total, and each one a test.
  *
  * The four cases, from DEVPLAN §10 D6:
  *
  *   - no committed offset ⇒ `None` + `NoCommit`. The group has never read this partition; it is
  *     not "zero behind".
  *   - no end offset ⇒ `None` + `NoLeader` (that is the only reason M4 can produce). Subtracting
  *     from an unknown is not zero.
  *   - committed > end ⇒ `None` + `CommittedBeyondEnd`. This happens after a topic is recreated or
  *     records are deleted, and the honest answer is "the numbers do not make sense", not a
  *     negative lag.
  *   - committed < begin ⇒ the lag **is** computed (`end - committed`) and flagged
  *     `CommittedBeforeStart`, because the consumer really is that far behind; it will simply
  *     resume from the earliest record still retained rather than from where it committed.
  */
object LagMath:

  def lagOf(committed: Option[Offset], begin: Option[Offset], end: Option[Offset]): PartitionLag

  /** The sum of the defined lags, and nothing else.
    *
    * `None` when **no** partition has a defined lag — an empty total is not zero. `excluded` is the
    * count of partitions that contributed nothing, so the UI can say "of 12 partitions, 3 have no
    * committed offset" instead of showing a number that silently means less than it looks like.
    */
  final case class LagTotal(value: Option[Long], counted: Int, excluded: Int)

  def total(lags: Iterable[PartitionLag]): LagTotal

  /** Committed-offset movement per second between two observations of the same group.
    *
    * `None` when there is only one observation, when the elapsed time is zero, or when the
    * partition set changed between them — arithmetic across a changed partition set is a
    * subtraction of two different quantities, and it renders as a spike exactly when an operator is
    * looking at a rebalance and least needs a fictional number.
    */
  def pace(previous: Option[PaceSample], current: PaceSample): Option[Double]

  final case class PaceSample(
      at: java.time.Instant,
      committedTotal: Option[Long],
      partitions: Set[TopicPartition]
  )
```

## Tests required

`LagMathSuite` (MUnit + ScalaCheck):

1. `lagIsEndMinusCommitted` — a property over arbitrary ordered pairs.
2. `noCommitIsNoneWithNoCommitAnomaly`.
3. `noEndIsNoneWithNoLeaderAnomaly`.
4. `committedBeyondEndIsNoneNotNegative` — **the assertion that no lag is ever negative**, as a
   property over arbitrary pairs including inverted ones.
5. `committedBeforeStartStillComputes` — value is `Some(end - committed)`, anomalies contain
   `CommittedBeforeStart`.
6. `anomaliesCanBeEmpty`.
7. `totalIsTheSumOfTheDefined` — a property: `total(lags).value == lags.flatMap(_.value).sum`, and
   `None` when that list is empty.
8. `totalNeverSubstitutesZero` — a property over lists containing at least one undefined lag: the
   total differs from the total computed with `orElse(0)` whenever any lag is undefined and any
   defined lag is non-zero. This is the reference product's bug, expressed as a test that fails if
   someone reintroduces it.
9. `totalCountsWhatItExcluded`.
10. `totalOfAnEmptyListIsNoneWithZeroCounted`.
11. `paceIsNoneOnTheFirstSample`.
12. `paceIsNoneWhenThePartitionSetChanged` — the D12 rule.
13. `paceIsNoneOnZeroElapsedTime` — no division by zero, ever.
14. `paceIsRecordsPerSecond` — 600 records over 30 s is 20.0.
15. `paceCanBeNegative` — a reset moves offsets backwards, and a negative pace is the honest report
    of that; it is not clamped to zero.
16. `topicSubscriptionTotalUsesTheSameRule` — the aggregate's convenience method is `LagMath.total`
    and not a second implementation. Asserted by comparing the two on random data.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| Group has never committed anywhere | Every partition `NoCommit`; `LagTotal(None, 0, n)`; the list renders `—` and the detail page says "this group has not committed any offsets" |
| One broker down | Its partitions carry `NoLeader`; the total is the rest, and the response says how many were excluded |
| Topic recreated under a group | `CommittedBeyondEnd`; the UI shows `—` with the anomaly's `description` as a tooltip, which is the sentence that tells the operator what happened |
| Retention deleted past the commit | Lag computed, `CommittedBeforeStart` flagged; the UI shows the number with a warning icon, because the number is right and the consumer is about to skip records |
