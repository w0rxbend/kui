# GRP-031 — Group list screen: state filter, search, sort, paging, empty states

- **ID:** GRP-031
- **Title:** Group list screen: state filter, search, sort, paging, empty states
- **Milestone / Feature:** M4 / CG-001
- **Owner role:** Frontend Architect
- **Context / module:** `frontend/ui-consumers`
- **Size:** L
- **Dependencies / blocked by:** GRP-030

## Goal (user value)

The Consumers screen. Every group on the cluster, with its state, its members, how many topics it
reads and how far behind it is — filterable by state, searchable by id, sortable by any column, and
honest about every figure it cannot compute.

## Scope

1. `GroupListPage` filled in: a control bar, a table, paging, and four distinct empty states.
2. The columns below, with the rendering rules that make an undefined lag readable as undefined.
3. The state chip: a filled chip in a container colour with its paired text colour (the design's
   rule — never a bare dot), with the state's own `description` as its tooltip.
4. The state filter as a multi-select whose options carry the counts from `stateCounts`.
5. Row click opens the group.

## Columns

| Column | Source | Rendering | Sortable |
| --- | --- | --- | --- |
| Group | `groupId` | the id, as the row's link; wraps rather than widening the table | yes, default ascending |
| State | `state` | a filled state chip with the state's `description` as its tooltip | yes, **by severity** (rebalancing, stable, empty, dead, unknown), not alphabetically |
| Members | `members` | number; `0` is a real answer here and renders as `0`, not `—` | yes |
| Topics | `topics` | number | yes |
| Lag | `totalLag` | the number with a magnitude bar; **`—` when null**, with "no committed offsets" as the tooltip; a footnote "3 of 12 partitions excluded" when `excludedPartitions > 0` | yes, undefined last in both directions |
| Pace | `pace` | `+1.2k/s`, `—` when null; negative values shown as negative, because a reset moves offsets backwards and hiding that would be a lie | yes |
| Coordinator | `coordinatorId` | the broker id, `—` when absent | **no** — the reference disables it and there is no ordering of coordinators an operator acts on |

Bytes in / out, and any throughput column: **not rendered**. There is no metrics service until M8,
and an empty "throughput" column reads as a statement about the consumer rather than about KUI.

## Non-goals

- **No CSV export.** M5. No button, not even disabled.
- **No FTS toggle.** DR-10 defers the index; a toggle that changes nothing is worse than none.
- **No live polling here.** GRP-033 adds it; this task renders one fetch.
- **No delete or reset from the list.** The destructive actions live on the detail page, where the
  operator can see what they are about to change (DEVPLAN §10 D3's spirit).
- **No client-side filtering.** The server filters, searches, sorts and pages; the URL carries the
  query. A client that re-filtered a server page would show a page count that does not match the
  rows.

## Design references

- `research/kafbat/ui-analysis.md` "Consumer groups list": the column set, the state tooltips, the
  server-side query parameters, `perPage` 25, the empty message, the row-click navigation, and the
  reference's `N/A` for a null lag — which KUI renders as an em dash with a reason.
- `research/design/REFERENCE.md`: magnitude bars beside quantities; status as a filled chip, never a
  bare dot; threshold colouring rather than constant colouring; the compact-density switch changing
  row padding only.
- ADR-026 (paging), ADR-032 (stale rendering), DEVPLAN §10 D6 (never a zero), D12 (pace), D14
  (search scope).

## Public Scala signatures to implement

```scala
package kui.ui.consumers.list

import com.raquo.laminar.api.L.*
import kui.consumer.contract.dto.{GroupSummaryDto, GroupPageDto}
import kui.kernel.group.GroupState

object LagCell:
  /** The one place a lag is turned into text. Four cases and no fifth:
    *   Some(n)  → the number, with a magnitude bar scaled against the page's largest lag
    *   None     → an em dash, with the reason as a tooltip
    *   and, independently, an excluded-partition footnote when some partitions contributed nothing.
    *
    * It is a component rather than a formatting function because the tooltip and the footnote are
    * part of the answer, and a `String` return type would make them somebody else's problem —
    * which is how `—` ends up rendered with no explanation. */
  def apply(lag: Option[Long], excluded: Int, maxOnPage: Option[Long]): HtmlElement

object StateChip:
  /** A filled chip, not a dot. The tooltip is `GroupState.description`, which comes from
    * `libs/kernel` — the six sentences are declared once and rendered here (rule A11). */
  def apply(state: GroupState): HtmlElement

object StateFilter:
  def apply(selected: Var[Set[GroupState]], counts: Signal[Map[GroupState, Int]]): HtmlElement
```

## Tests required

`LagCellSuite` (MUnit + `domtestutils`):

1. `aDefinedLagRendersTheNumber`.
2. `anUndefinedLagRendersAnEmDash` — **and the assertion that the text is not `"0"`**, written
   against the rendered text rather than the input, because the bug this prevents is a formatting
   one.
3. `anUndefinedLagCarriesAReasonTooltip`.
4. `zeroIsRenderedAsZeroNotAnEmDash` — a group that is genuinely caught up is a different answer from
   one whose lag is unknown, and both appear on every real cluster.
5. `theExcludedFootnoteAppearsOnlyWhenSomethingWasExcluded`.
6. `theMagnitudeBarIsScaledToThePageMaximum`.
7. `aPageWhereEveryLagIsUndefinedRendersNoBars` — no division by zero, no full-width bars.

`GroupListPageSuite`:

1. `rendersTheGoldenPageDocument` — decoded from **the golden file GRP-024 committed**, not from a
   hand-written sample. The browser half of the seam.
2. `sixStatesRenderSixDistinctChips`.
3. `theChipTooltipIsTheKernelDescription`.
4. `theStateFilterUpdatesTheUrl`.
5. `theSearchBoxUpdatesTheUrlAndIsDebounced`.
6. `sortingByLagPutsUndefinedLastInBothDirections`.
7. `clickingARowNavigatesToTheGroup`.
8. `theCoordinatorColumnIsNotSortable`.
9. `emptyStateNoGroups` — "No consumer groups on this cluster".
10. `emptyStateNoMatches` — "No groups match this filter", with a clear-filter action. A different
    sentence from 9, because they suggest different next actions.
11. `emptyStateUnavailable` — the fallback panel with the reason, **not** an empty table.
12. `emptyStateLoading` — skeleton rows, not "no groups". ADR-032's "Starting is not Unavailable".
13. `staleDataIsGreyedWithATimestamp`.
14. `theIncompleteCoordinatorBannerAppears` — "one coordinator did not answer; some groups may be
    missing", naming the broker.
15. `noThroughputColumnIsRendered` — asserted, so nobody adds one before M8.
16. `theDensitySwitchChangesRowPaddingOnly`.
17. `theTableIsKeyboardNavigable` — rows are focusable and Enter opens the group.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| `stale` on the response | Rows greyed, timestamp shown, filters and sorting still work locally on what is there; a refresh action offered |
| 503 | The feature's fallback panel with the reason and `since` |
| `incompleteCoordinators` | The banner above; the rows that did arrive are shown |
| A row with `incomplete` | Its member and lag cells render `—` with "KUI is not permitted to describe this group" rather than a zero |
| Slow response | Skeleton rows, and the previous page's rows kept underneath while a new page loads, so paging does not flash |
