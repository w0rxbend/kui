# GRP-035 — Delete actions, and the topic page's Consumers guest panel

- **ID:** GRP-035
- **Title:** Delete actions, and the topic page's Consumers guest panel
- **Milestone / Feature:** M4 / CG-003, CG-005, TP-015, KU-013
- **Owner role:** Frontend Architect
- **Context / module:** `frontend/ui-consumers`, `frontend/ui-kernel`
- **Size:** L
- **Dependencies / blocked by:** GRP-032, GRP-029

## Goal (user value)

Two things: the last two destructive actions get their confirmations, and the topic page gains a
Consumers tab that is rendered by the consumers feature without the topics feature ever importing
it. The second is the first real test of ADR-012's microfrontend boundary — until now the split
bundle has had one feature in it — and getting it wrong means the two features can never be
deployed, degraded or loaded independently again.

## Scope

1. **Delete group** and **delete offsets for a topic**: menu items, confirmations, optimistic
   removal with rollback, and the toasts.
2. **The kernel `FeaturePanel` slot** (KU-013): a registry keyed by `FeatureId` into which a feature
   registers a renderer, and which a host feature renders without knowing who fills it. Created here
   if precondition P3 says it does not exist.
3. **The guest panel**: `ui-consumers` registers a `topic.consumers` panel that renders the
   `consumerGroups` section of the topic overview.
4. The proof that the boundary holds: a build assertion that `frontend.uiTopics` has no dependency
   on `frontend.uiConsumers`, and the network assertion in GRP-038.

## Non-goals

- **No changes to `ui-topics`' own content.** The host renders a slot; what goes in it is not its
  business. If `ui-topics` does not exist (P2/P3), this task ships the slot, the registration and
  their tests, and the tab appears when the topics feature lands.
- **No second data path.** The panel renders the section the gateway already put in the topic
  overview (DEVPLAN §10 D13). It does **not** call the consumer service itself, which would defeat
  the aggregation and put a second upstream on the topic page's critical path.
- **No delete from the list screen.** GRP-031's non-goals.
- **No bulk delete.**

## Design references

- DC-H6 (`research/kafbat/ui-analysis.md`): *"cross-feature panels are rendered through the kernel
  `FeaturePanel` slot, never a direct import"*, and the note that the reference imports
  `ConsumerGroups` components directly into the topic page — which is exactly what KUI must not do.
- ADR-012 — the split-bundle model and `js.dynamicImport` keyed by `FeatureId`.
- ADR-032 — a tab whose feature is `Unavailable` shows the tab with a dimmed dot and a card fallback
  in its body; the host page's other tabs are unaffected.
- `research/kafbat/ui-analysis.md` "Consumers tab": the four columns, and "No active consumer
  groups" as the empty message.
- `research/kafbat/ui-analysis.md` "Consumer group details": the delete confirmations and the exact
  toasts, which KUI's messages follow in substance.
- DEVPLAN §10 D13, risk R-9.

## Public Scala signatures to implement

```scala
package kui.ui.kernel.feature

import com.raquo.laminar.api.L.*

/** A named hole in one feature's page that another feature fills.
  *
  * The host renders `FeaturePanel(slotId, context)`. The guest calls `register(slotId, renderer)`
  * when its module loads. Neither module names the other, and neither module's build depends on the
  * other's — which is what lets a cluster with no consumer capability never download
  * `ui-consumers` at all.
  *
  * When nothing is registered, the panel renders its host-supplied placeholder. When the guest's
  * capability is `Unavailable`, it renders the guest's fallback card. Both are the host's tab
  * staying visible and useful, which is ADR-032's rule for a degraded tab.
  */
opaque type SlotId = String

trait FeaturePanelRegistry:
  def register(slot: SlotId, render: FeaturePanelContext => HtmlElement): Unit
  def rendererFor(slot: SlotId): Signal[Option[FeaturePanelContext => HtmlElement]]

final case class FeaturePanelContext(clusterId: String, params: Map[String, String], data: Option[io.circe.Json])

object FeaturePanel:
  def apply(slot: SlotId, ctx: Signal[FeaturePanelContext], placeholder: => HtmlElement): HtmlElement
```

```scala
package kui.ui.consumers.panel

object TopicConsumersPanel:
  val Slot: SlotId = SlotId("topic.consumers")
  /** Renders the `consumerGroups` section the gateway already put in the topic overview. Four
    * columns — group, active consumers, lag on this topic, coordinator, state — each linking to the
    * group page. Empty message: "No consumer groups read this topic". */
  def render(ctx: FeaturePanelContext): HtmlElement
```

## Tests required

`FeaturePanelSuite` (MUnit + `domtestutils`):

1. `anUnregisteredSlotRendersThePlaceholder`.
2. `aRegisteredRendererFillsTheSlot`.
3. `registeringAfterTheHostMountedStillFills` — the guest module loads lazily and will usually be
   late; a slot that only reads its registry at mount time renders empty for ever.
4. `twoSlotsDoNotCollide`.
5. `aRendererThatThrowsIsCaughtAndRendersTheFallback` — a broken guest must not take the host page
   down. This is the fault isolation of ADR-012 at the DOM level.
6. `theContextIsPassedThrough`.
7. `unregisteringOnUnmountLeavesNoLeak`.

`TopicConsumersPanelSuite`:

1. `rendersTheFourColumns`.
2. `readsTheSectionFromTheContextNotFromANewRequest` — **the D13 assertion**: no HTTP call is made
   by the panel, asserted on a stubbed client's empty call log.
3. `anUnavailableSectionRendersTheFallbackCard`.
4. `aStaleSectionGreysWithATimestamp`.
5. `aNotConfiguredSectionHidesTheTab`.
6. `theEmptyMessageIsRendered`.
7. `groupLinksNavigateToTheGroupPage`.
8. `thisTopicsLagIsShownNotTheGroupsTotal` — the two differ for a multi-topic group, and showing the
   wrong one is the mistake the DTO's two fields exist to prevent.
9. `aDormantGroupIsMarked` — offsets but no members, which is what an operator about to delete a
   topic needs to see.

`DeleteActionsSuite`:

1. `deleteGroupAsksForConfirmation` — with the group id in the sentence.
2. `theConfirmationRequiresTypingTheGroupId`.
3. `deleteGroupNavigatesBackToTheListOnSuccess` — with a toast naming what was deleted.
4. `deleteGroupOnAGroupWithMembersShowsTheRefusalAndItsRemedy`.
5. `deleteOffsetsIsPerTopicRow`.
6. `deleteOffsetsAsksForConfirmationNamingTheTopic`.
7. `deleteOffsetsRemovesTheRowOptimisticallyAndRestoresItOnFailure` — the row comes back with an
   error, rather than vanishing on a request that failed.
8. `bothActionsAreAbsentOnAReadOnlyCluster`.
9. `bothActionsAreDisabledWithAMergedTooltipWhenTheCapabilityIsDegraded`.
10. `aFiveOhThreeShowsTheReasonNotAGenericError`.
11. `theToastsNameTheResource`.
12. `neitherActionIsReachableByAGetNavigation` — a bookmarked URL cannot delete anything.

## Observability

None beyond the kernel's.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| Consumer capability `Unavailable` | The topic page's Consumers tab is present, dimmed, and its body is the fallback card with the reason. **The topic page's other tabs are untouched** — exit criterion 5 |
| Consumer capability `NotConfigured` | The tab is hidden and `ui-consumers` is never downloaded (GRP-038's network assertion) |
| Guest module fails to load | The slot renders the host's placeholder with an error line; the topic page keeps working |
| Cluster read-only | Both delete actions absent; the panel is unaffected, because it is a read |
