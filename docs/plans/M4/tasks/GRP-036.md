# GRP-036 — `kui.consumer.*` configuration and `libs/testkit`'s consumer-group fixture

- **ID:** GRP-036
- **Title:** `kui.consumer.*` configuration and `libs/testkit`'s consumer-group fixture
- **Milestone / Feature:** M4 / CG-001 … CG-006
- **Owner role:** Infrastructure Lead with the QA Engineer
- **Context / module:** `libs/config`, `libs/testkit`
- **Size:** L
- **Dependencies / blocked by:** GRP-001

## Goal (user value)

Two things every other task in the milestone depends on: the knobs an operator turns, validated at
startup with every error in one message; and a Testcontainers broker that comes up with real
consumer groups on it in known states, so that every integration suite in M4 asserts against a
cluster that looks like a real one instead of an empty one.

**Start this early.** DEVPLAN §7.3: making a container hold a genuinely `Stable` group with a live
member, a genuinely `Empty` group, and a group that can be forced into a rebalance on demand is not
knowable from a document, and lanes A and C both stop without it.

## Scope

1. The `kui.consumer.*` Ciris slice: intervals, tuning, the cluster-service base URL, the startup
   grace.
2. `ConsumerGroupFixture` in `libs/testkit`: a seeded broker and a handle for manipulating it.
3. `docs/operations/configuration.md` gains the consumer section.

## Non-goals

- **No new security configuration.** The consumer service connects with the profile the cluster
  service hands it (GRP-022); it has no `kui.clusters[]` of its own and must not grow one.
- **No SASL/SSL container variants.** M1's three-mode matrix covers the pool; adding two more
  container topologies here would add minutes to CI to re-prove someone else's property.
- **No fixture in the cross-compiled test tree.** `STATUS.md` M1 defect 5: `libs/testkit`'s container
  suite sat in the cross-compiled tree, imported the Kafka client, and broke the whole repository's
  compile. This fixture is JVM-only, in `libs/testkit`'s JVM tree, and the Implementation Report says
  where it lives.

## Design references

- ADR-013 (Ciris, accumulated errors), ADR-030, ADR-018.
- `libs/config`'s existing `kui.cluster.*` slice — the house shape for a service section, including
  how its errors accumulate and how it is documented.
- `libs/testkit`'s `KafkaFixture` / `KafkaTopology` from M1's CFGOP-004 — **reuse the container**;
  this fixture adds seeding on top of it and must not start a second one.
- `research/kafka/admin-capabilities.md` §3 — the states the fixture must be able to produce, and §4
  for the manual-assignment consumer the seeder uses.
- `DEPENDENCY_MATRIX.md` — `org.testcontainers:testcontainers-kafka:2.0.5` (not `:kafka`).

## Public Scala signatures to implement

```scala
package kui.config.consumer

import scala.concurrent.duration.FiniteDuration

/** Every field is read by a component, and `ConfigReachesComponentsSuite` (GRP-028) proves it field
  * by field. M1's integration found a whole section parsed and discarded; a config field nothing
  * reads is a promise to an operator that KUI does not keep. */
final case class ConsumerServiceConfig(
    /** How often the group snapshot refreshes. Default 30 s (`ARCHITECTURE.md` §9). Minimum 5 s,
      * because below that the describe-all cost dominates the cluster's coordinator load and the
      * operator gains nothing a manual refresh would not. */
    refreshInterval: FiniteDuration,
    /** How often the group capability probe runs. Default 1 h. */
    capabilityInterval: FiniteDuration,
    /** Ids per describe request and requests in flight. Defaults 50 and 4 — the reference product's
      * own numbers (`ConsumerGroupService.java:529-537`), which are the only numbers anyone has
      * measured against a real cluster. */
    describeChunkSize: Int,
    describeParallelism: Int,
    /** Where the cluster service is. `http://kui-cluster:8081` in Compose; the all-in-one wires an
      * in-process client instead and this is unused there. */
    clusterServiceBaseUrl: sttp.model.Uri,
    /** Fallback poll for cluster profiles while the SSE stream is down. Default 60 s. */
    profilePollInterval: FiniteDuration,
    /** How long a service with no profile yet reports "starting" rather than "unavailable".
      * Default 30 s (GRP-028). */
    startupGrace: FiniteDuration,
    /** Bound and TTL of the last-seen assignment cache. Defaults 2 000 and 1 h. */
    lastSeenAssignmentsMax: Int,
    lastSeenAssignmentsTtl: FiniteDuration
)

object ConsumerServiceConfig:
  val Default: ConsumerServiceConfig
  def load: ConfigValue[Effect, ConsumerServiceConfig]
```

```scala
package kui.testkit.kafka

/** A broker with consumer groups on it, in known states.
  *
  * Built on `KafkaFixture(KafkaTopology.Plaintext)` — the one container topology in this
  * repository. It does not start a container of its own.
  */
object ConsumerGroupFixture:

  final case class Seeded(
      bootstrap: String,
      /** `orders` (3 partitions, 120 records), `payments` (2 partitions, 40 records),
        * `audit` (1 partition, 0 records). */
      topics: Map[String, Int],
      /** `stable-consumer`: one live member on `orders`, genuinely `STABLE`.
        * `empty-consumer`: committed offsets on `orders`, no members, genuinely `EMPTY`.
        * `partial-consumer`: committed on `orders-0` only, never on `orders-1` or `orders-2`.
        * `two-topic-consumer`: commits on `orders` and `payments`, for the per-topic lag tests.
        * `dormant-consumer`: commits on `payments`, never had a member in this run. */
      groups: Set[String],
      handle: Handle
  )

  trait Handle:
    /** Starts a second consumer in `stable-consumer`, which forces a rebalance. Returns when the
      * group reports `PREPARING_REBALANCE` or a member's target differs — polled, never slept. */
    def forceRebalance(group: String): IO[Unit]
    /** Stops every member of a group and waits until it reports `EMPTY`. The precondition every
      * reset test needs, and the one thing a test cannot fake. */
    def drain(group: String): IO[Unit]
    def produce(topic: String, count: Int): IO[Unit]
    def commit(group: String, topic: String, partition: Int, offset: Long): IO[Unit]

  def resource: Resource[IO, Seeded]
```

Every wait in `Handle` polls for the condition with a deadline and a message naming what never
happened. M1's integration found three flaky suites, all asserting on sleeps; a fixture that sleeps
makes every suite that uses it flaky at once.

## Tests required

`ConsumerServiceConfigSuite`:

1. `defaultsMatchTheDocumentedValues` — asserted against literals, so a default change is deliberate.
2. `everyFieldCanBeOverridden`.
3. `anUnknownKeyIsRejected`.
4. `everyProblemIsReportedNotJustTheFirst` — three bad values, one message naming all three.
5. `aRefreshIntervalBelowFiveSecondsIsRejected` — with a message saying why.
6. `describeChunkSizeIsBounded` — 1 to 200; zero would loop, and above 200 the broker rejects.
7. `anInvalidClusterServiceUrlIsRejectedAtStartup`.
8. `theUrlPolicyRejectsLinkLocalAndMetadataAddresses` — the existing `UrlPolicy` from M1, applied
   here too. A configuration value that becomes an outbound request is an SSRF surface.
9. `theConfigRendersWithNoSecret` — there is none in this section, and the test asserts the section
   stays that way.
10. `theYamlInDeploymentParses` — the committed Compose config file is loaded by the test, so a
    documentation example that does not parse fails CI.
11. `theExampleInTheOperationsDocParses` — same, for `docs/operations/configuration.md`'s snippet.

`ConsumerGroupFixtureSuite`:

1. `theFixtureStartsAndSeeds`.
2. `stableConsumerIsGenuinelyStable` — polled from a real `Admin`, not assumed.
3. `emptyConsumerIsGenuinelyEmptyWithCommittedOffsets` — both halves; a group with no commits would
   not exercise the reset tests.
4. `partialConsumerHasACommitOnOnePartitionOnly`.
5. `forceRebalanceProducesARebalancingState`.
6. `drainReturnsOnlyWhenTheGroupIsEmpty`.
7. `theFixtureIsIdempotentAcrossSuites` — two suites sharing the container get the same seed and do
   not interfere, or the fixture says how they are isolated.
8. `noSleepIsUsed` — a grep-shaped assertion over the fixture's own source, because this is the one
   file whose flakiness would spread to every suite in the milestone.

## Observability

None. Configuration and test fixtures.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| A configuration value is out of range | Startup fails with every problem in one message and a non-zero exit; the container restarts and fails identically, which is the correct loop for a config error |
| The container will not start | The fixture fails with the container's log tail in the message, never a bare timeout |
| A seed step fails | The fixture fails naming which group and which step, so a broken suite says what is broken |
