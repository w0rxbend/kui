# GRP-015 — `GroupDetailUseCase`: live describe, per-partition lag, last-seen assignments

- **ID:** GRP-015
- **Title:** `GroupDetailUseCase`: live describe, per-partition lag, last-seen assignments
- **Milestone / Feature:** M4 / CG-002
- **Owner role:** Domain Architect (Consumer Group Management context)
- **Context / module:** `services/consumer/application`
- **Size:** L
- **Dependencies / blocked by:** GRP-013

## Goal (user value)

The page an operator opens when a consumer is behind: every member with its host and client id,
every topic the group consumes, and — expanded — every partition with its current offset, the end
offset, its lag and who holds it. Computed live, because a detail page for one group can afford a
round trip that a list of four thousand cannot. And during a rebalance it keeps showing the last
assignment it saw, greyed and timestamped, instead of an empty table.

## Scope

1. `GroupDetailUseCase[F]`: `detail(cluster, group)` and `refresh(cluster, group)`.
2. `GroupDetailView`: the aggregate, its per-partition rows, its totals, its freshness and its
   rebalance state.
3. The **last-seen assignment cache** (DC-H10): a bounded per-cluster map of
   `GroupId -> (assignments, seenAt)`, written on every successful describe where members were
   present, and read when a describe returns a group mid-rebalance with no stable assignment.
4. The live call sequence and its partial-failure policy.

## Non-goals

- **No snapshot write.** The detail page reads the snapshot for a first paint and then computes
  live; it never writes the shared snapshot, because one user opening a page must not change what
  every other user's list shows.
- **No message data.** Offsets, never payloads.
- **No topic configuration.** That is the topic service's; the detail page links to it.
- **No mutation.** GRP-019, GRP-020.

## Public Scala signatures to implement

```scala
package kui.consumer.application

import java.time.Instant

import kui.consumer.domain.*
import kui.kernel.{ClusterId, GroupId, TopicName}

/** Whether the assignments on screen are the ones the coordinator has right now. */
enum AssignmentFreshness:
  case Current
  /** The group is rebalancing; these are the assignments last seen, and when. The screen greys them
    * and shows a badge (DC-H10). Rendering an empty table instead is the failure this exists to
    * prevent: an operator watching a rebalance sees the page they were reading go blank. */
  case LastSeen(at: Instant)
  /** Rebalancing and nothing was ever seen. The table is genuinely empty and says why. */
  case Unknown

final case class GroupDetailView(
    group: ConsumerGroup,
    topics: List[TopicSubscription],
    total: LagMath.LagTotal,
    assignments: AssignmentFreshness,
    freshness: SnapshotFreshness,
    computedAt: Instant
)

trait GroupDetailUseCase[F[_]]:
  /** Computed live. `Left(NotFound)` with `ErrorCode.ClusterNotFound` for an unknown cluster.
    *
    * An unknown *group* is **not** a 404: the port fabricates a dead group (GRP-002's invariant) and
    * this returns it, so a stale bookmark lands on an empty group page rather than an error. Where
    * existence matters — the mutations — it is checked by listing (GRP-019). */
  def detail(cluster: ClusterId, group: GroupId): F[Either[KuiError, GroupDetailView]]

object GroupDetailUseCase:
  val Operation: String = "kui.consumer.detail"
  def make[F[_]: Temporal](
      snapshots: GroupSnapshots[F],
      admin: ClusterId => GroupAdminPort[F],
      lastSeen: LastSeenAssignments[F],
      logger: StructuredLogger[F]
  ): GroupDetailUseCase[F]

/** Bounded, per cluster, TTL 1 hour, at most 2 000 entries, LRU. Declared in `ARCHITECTURE.md` §9.
  *
  * A group's assignments are a few hundred bytes; two thousand of them is a megabyte, and a cluster
  * with more groups than that is one where the operator opening a detail page during a rebalance is
  * rarer than the memory is expensive. */
trait LastSeenAssignments[F[_]]:
  def put(cluster: ClusterId, group: GroupId, members: List[GroupMember], at: Instant): F[Unit]
  def get(cluster: ClusterId, group: GroupId): F[Option[(List[GroupMember], Instant)]]
  def invalidate(cluster: ClusterId, group: GroupId): F[Unit]
```

### The live call sequence

```
1. describe([group])                        — REQUIRED. Left ⇒ the whole read fails.
2. committedOffsets(group, partitions=None) — OPTIONAL. Left ⇒ every partition NoCommit-shaped,
                                              completeness.committedOffsetsKnown = false.
3. endOffsets(union of committed and assigned)
                                            — OPTIONAL. Left ⇒ endOffsetsKnown = false; lag is
                                              None everywhere and the page says so.
2 and 3 are sequential (3 needs 2's partition set); 1 and nothing else precede them.
```

The rebalance rule: if `group.isRebalancing` **and** every member's `partitions` is empty, read
`lastSeen`; if it has an entry, render those members with `AssignmentFreshness.LastSeen(at)`;
otherwise `Unknown`. If the group is not rebalancing and has members, write `lastSeen` before
returning. Never write during a rebalance — that would overwrite the good data with the empty data
the badge exists to hide.

## Tests required

`GroupDetailUseCaseSuite`:

1. `describesTheGroupLive` — asserted on the fake's call log: a describe happened, and the snapshot
   was not the source of the offsets.
2. `perPartitionRowsCarryMemberAndHost`.
3. `topicsAreGroupedFromThePartitions`.
4. `totalSkipsUndefinedLags` — the D6 rule, at this layer.
5. `describeFailureFailsTheRead`.
6. `committedOffsetFailureStillRenders` — every partition `NoCommit`, `completeness` says so.
7. `endOffsetFailureStillRenders`.
8. `anUnknownGroupRendersAsAnEmptyDeadGroup` — **the invariant, at the use-case layer**: `Right`,
   not `Left(NotFound)`.
9. `aRebalancingGroupShowsTheLastSeenAssignments` — **the exit criterion**: describe returns members
   with empty partitions; the view carries the previous assignment and `LastSeen(at)`.
10. `aRebalanceDoesNotOverwriteTheLastSeenCache` — the assertion that makes test 9 keep working on
    the second refresh.
11. `aRebalancingGroupWithNoHistoryIsUnknownNotEmpty`.
12. `aStableGroupWritesTheLastSeenCache`.
13. `cancellationDuringADescribeReleasesTheClient`.

`LastSeenAssignmentsSuite`: TTL expiry; the LRU bound (2 001 entries evicts one); per-cluster
isolation (two clusters, same group id, no collision — the M1 lesson that a broker id must be paired
with a cluster id in a cache key); explicit invalidation; `get` on an empty cache is `None`; metrics
are emitted on hit and miss.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| Group rebalancing | Last-seen assignments, greyed, with a badge and the timestamp; lag still computed from the committed offsets, which are valid during a rebalance |
| Group does not exist | An empty dead group page, not a 404 |
| No `DESCRIBE` on the group | `Forbidden`, and the screen says which permission is missing rather than showing an empty page |
| End offsets unavailable | Every lag `—`, the total `—`, and a line saying the end offsets could not be read |
| Cluster unreachable | `Unavailable`; the fallback panel with the reason and "what still works" |

## Cancellation and shutdown

`detail` is one fiber with no children beyond the port calls. Test 13 cancels mid-describe and
asserts the pooled client was released. `LastSeenAssignments` holds a `Ref` and needs no teardown;
its `Resource` is trivial and the Implementation Report says so explicitly rather than leaving it
unstated.
