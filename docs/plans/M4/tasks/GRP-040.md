## Rule A11, precisely

**What it forbids:** declaring a wire vocabulary — an enum, or a set of string constants that is
serialised across the process boundary — anywhere but `libs/kernel` or `libs/contracts-core`.

**How it is checked**, in `build.mill`'s architecture task:

1. Collect the `wire` values of every enum in `kui.kernel.group` (and, going forward, any package
   registered in the rule's own list).
2. Fail if any of those string literals appears in a `.scala` source outside `libs/kernel` and
   `libs/contracts-core` — with two documented exceptions: `libs/kafka`'s mapping file, which must
   read the Kafka enum and name the KUI one, and test sources, which assert against literals on
   purpose.
3. Fail if a second `enum` declaring the same case names exists anywhere.

The exceptions are named in the rule, so a third one has to be argued in the commit that adds it —
the same discipline rule A10 uses for its allow-list.

**Proven to fail.** The Implementation Report includes the output of deliberately adding
`val Stable = "STABLE"` to `frontend/ui-consumers` and running `./mill checkArchitecture`. M0's
BUILD-005 was held to this standard and it is the only evidence that a rule works.

## Docs to update

All of the above. The two new ADRs are the only substantial writing:

- **ADR-045 — Reset plan confirmation.** Context: M4 ships the first destructive operation before
  read-only mode, RBAC and audit exist. Decision: two phases, a server-computed plan, an HMAC'd plan
  token over the resolved offsets, a precondition checked at both ends. Consequences: every later
  mutation with parameters an operator can get wrong (M5's topic edits, partition increases,
  replication-factor changes) reuses this shape, and the cursor key gains a second use.
  Alternatives rejected: a single-request form (the reference's, which shows the operator nothing),
  and a client-computed preview (a second implementation of the planner).
- **ADR-046 — Cluster credentials to services.** Context, decision and consequences as GRP-022's
  spec sets them out, including the three rejected alternatives and the four things that make the
  chosen one safe enough for a product that has no identity service yet.
