# GRP-006 — `OffsetLookup`: end and beginning offsets with the leaderless-partition filter

- **ID:** GRP-006
- **Title:** `OffsetLookup`: end and beginning offsets with the leaderless-partition filter
- **Milestone / Feature:** M4 / CG-002, CG-004, CG-006
- **Owner role:** Principal Scala Engineer
- **Context / module:** `libs/kafka`
- **Size:** M
- **Dependencies / blocked by:** GRP-002

## Goal (user value)

The other half of lag, and the reason a healthy-looking cluster does not make the consumer-groups
page hang for a minute. If any partition in a `listOffsets` request has no leader, the AdminClient
does not fail — it retries metadata quietly until `default.api.timeout.ms` expires, sixty seconds
with KUI's defaults, and then reports a timeout that names nothing useful. One offline partition
turns a millisecond call into a one-minute failure on a cluster that is 99 % healthy, and it happens
exactly when an operator most needs the screen.

## Scope

1. `OffsetLookup`, a small component in `kui.kafka.admin` used by `GroupAdmin`'s callers and — when
   M2's `TopicAdmin` lands — by it as well.
2. `endOffsets` and `beginningOffsets` over `Admin.listOffsets`, with `OffsetSpec.latest()` /
   `OffsetSpec.earliest()`.
3. `offsetsForTimes` over `OffsetSpec.forTimestamp`, returning `None` per partition when no record
   is at or after the timestamp — the case KIP-122's rule turns into "use the end offset"
   (GRP-012), decided in the planner and not here.
4. **The filter.** Partitions with no leader are removed from the request *before* it is sent, using
   the metadata the pooled `Admin` already has, and returned as `SkipReason.NoLeader` entries. A
   request whose every partition is leaderless makes **no Kafka call at all**.
5. `PORT-INVARIANTS.md` §1's rule recorded as the scaladoc of `OffsetLookup`, with the file's §1 left
   in place but annotated to point here, because M2's `TopicAdmin.listOffsets` is the other owner
   and must use this component rather than write a second filter.

## Non-goals

- **No `TopicAdmin`.** This task must not create, edit or reference a `TopicAdmin` file. If M2 has
  shipped one with its own inline filter, GRP-006 records a `TECH_DEBT.md` entry to converge them
  and does not touch the file.
- **No isolation-level handling.** `read_committed` LSO semantics belong to the message browser
  (M3, DC-D8). Lag is computed against the LEO, as the reference products do.
- **No caching.** GRP-013 holds the results.

## Public Scala signatures to implement

```scala
package kui.kafka.admin

import kui.kernel.{Offset, TopicPartition}
import kui.kernel.cluster.ClusterConnection
import kui.kernel.error.KuiError
import kui.kafka.{PartialResult, SkipReason}

/** Reading log offsets, with the one filter Kafka forces on anyone who does.
  *
  * ## Leaderless partitions are filtered before the request, at the port
  *
  * If any partition named in a `listOffsets` request has no leader, the AdminClient does not fail
  * the call. It retries metadata, quietly, until `default.api.timeout.ms` expires — sixty seconds
  * with KUI's defaults — and only then reports a timeout that names nothing useful.
  *
  * That is worse than an error: a single offline partition turns a millisecond call into a
  * one-minute failure, the timeout is charged to the whole request rather than to the partition
  * that caused it, and it happens only while a broker is down, which is when the screen matters
  * most.
  *
  * **The port filters, not the caller.** Every partition removed appears in the returned
  * `PartialResult` as `SkipReason.NoLeader`, so a caller can render "offline" for that partition
  * instead of a number, and an aggregate can refuse to compute rather than report a wrong total.
  *
  * Evidence: `research/kafka/admin-capabilities.md` §2. Recorded in
  * `libs/kafka/PORT-INVARIANTS.md` §1 before this component existed; **`TopicAdmin.listOffsets`
  * must use this component rather than repeat the filter.**
  */
trait OffsetLookup[F[_]]:
  def endOffsets(
      conn: ClusterConnection,
      partitions: Set[TopicPartition]
  ): F[Either[KuiError, PartialResult[TopicPartition, Offset]]]

  def beginningOffsets(
      conn: ClusterConnection,
      partitions: Set[TopicPartition]
  ): F[Either[KuiError, PartialResult[TopicPartition, Offset]]]

  /** `None` for a partition with no record at or after `timestampMs`. The caller decides what that
    * means; KIP-122 says "the end offset" for a reset (GRP-012). */
  def offsetsForTimes(
      conn: ClusterConnection,
      timestamps: Map[TopicPartition, Long]
  ): F[Either[KuiError, PartialResult[TopicPartition, Option[Offset]]]]

  /** The leaders known to the pooled client, exposed because the reset planner needs to refuse
    * before it plans rather than discover during the write (DEVPLAN §10 D8). */
  def leaderless(
      conn: ClusterConnection,
      partitions: Set[TopicPartition]
  ): F[Either[KuiError, Set[TopicPartition]]]

object OffsetLookup:
  def make[F[_]: Async](pool: AdminClientPool[F], metrics: AdminMetrics[F]): OffsetLookup[F]
```

## Tests required

`OffsetLookupSuite` (MUnit + Testcontainers, plus a stubbed `Admin` for the leaderless case, which
cannot be produced reliably against a single-broker container):

1. `endOffsetsMatchAProducedRecordCount` — produce 17 records, assert 17.
2. `beginningOffsetsAreZeroOnAFreshTopic`.
3. `offsetsForTimesFindsTheFirstRecordAtOrAfter`.
4. `offsetsForTimesIsNoneWhenEveryRecordIsOlder` — `Some(None)`, not an error and not a zero.
5. `aLeaderlessPartitionIsFilteredAndReported` — the stub reports one partition with a null leader:
   the request that reaches the stub does **not** contain it, and the result's `skipped` does.
6. `everyPartitionLeaderlessMakesNoCall` — asserted on the stub's call log. This is the sixty-second
   timeout, prevented rather than merely handled.
7. `theFilterUsesMetadataNotATrialRequest` — one metadata read, one offsets request; a
   fetch-and-see-what-fails implementation fails this test.
8. `emptyPartitionSetMakesNoCall`.
9. `cancellationReleasesTheClient` — cancel mid-call, assert the pool has no leased client.

Logging: the skip at DEBUG with the partition list truncated to ten entries and a count, because a
cluster losing a broker produces thousands and a log line per partition is a denial of service on
the log.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| One partition leaderless | Filtered; the caller renders `—` for it and, for lag, counts it in `excludedPartitions` |
| Every partition leaderless | `Right` with an empty `values` and a full `skipped`. A caller that treats "no values" as "no lag" is wrong, and the domain's total-with-exclusions shape (GRP-011) is what stops it |
| Topic deleted mid-call | `UnknownTopicOrPartitionException` per partition → `SkipReason.NotFound` |

## Cancellation and shutdown

`OffsetLookup` owns no fiber. Every method must release the pooled `Admin` on cancellation; test 9
asserts it.
