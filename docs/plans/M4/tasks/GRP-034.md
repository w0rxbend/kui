# GRP-034 — Reset-offsets wizard: six modes, the plan preview, the confirmation

- **ID:** GRP-034
- **Title:** Reset-offsets wizard: six modes, the plan preview, the confirmation
- **Milestone / Feature:** M4 / CG-004
- **Owner role:** Frontend Architect
- **Context / module:** `frontend/ui-consumers`
- **Size:** L
- **Dependencies / blocked by:** GRP-032, GRP-026

## Goal (user value)

The screen the milestone is named for. An operator picks a topic, some partitions and a mode; KUI
asks the server what that would actually write; the operator sees the resulting offset for every
partition, every clamp, and every surprise — and only then confirms. The reference product submits a
form and reports a toast; KUI shows the numbers first, because the numbers are the thing that can be
wrong.

## Scope

1. The wizard as three steps in one page: **choose**, **review**, **confirm**.
2. Mode-dependent fields for all six `ResetTarget` values, rendered from `ResetTarget.values` rather
   than a hand-written list.
3. The plan table: partition, current offset, proposed offset, delta, and per-partition warnings.
4. The confirmation: the group's id typed back, or — for a plan that moves nothing — a plain
   acknowledgement. Submit is disabled until a plan has been fetched **and** the plan on screen is
   the one the token names.
5. Post-apply: the applied plan rendered as a result, a link back to the group, and the sentence
   that says a reset is not reversible by KUI.

## The three steps

**Choose.** Topic (a select over the group's own topics — a reset can only target what the group has
offsets or an assignment on); partitions (multi-select, default all); mode (six radios, each with
its `ResetTarget.label`); and the mode's parameter: a timestamp picker for `TIMESTAMP`, one numeric
field per selected partition for `OFFSET`, a signed integer for `SHIFT_BY`, a duration for
`DURATION`, and nothing for `EARLIEST` and `LATEST`.

**Review.** `POST .../offsets/plan`. The table, the warnings, and a summary sentence: *"12 partitions
will move; the group will re-read approximately 4.1 million records."* The estimate is
`Σ (current − proposed)` over partitions where both are known, and it is labelled approximate,
because compacted topics and control records make it exactly that.

**Confirm.** The operator types the group id. Submit calls `POST .../offsets` with the token and
nothing else.

## Non-goals

- **No client-side offset arithmetic.** The browser never computes a proposed offset. Every number on
  the review step came from the server, which is the entire point of the two-phase design (DEVPLAN
  §10 D3). A client-side preview would be a second implementation of `ResetPlanner` in a language
  with different integer semantics.
- **No editing the plan.** A plan is applied or discarded. An edited plan is a new plan and gets a
  new token.
- **No date library.** The timestamp picker is a native `datetime-local` input plus the kernel's
  timezone handling; `research/kafbat/ui-analysis.md` records the reference pulling in
  `react-datepicker` for this, and KUI does not have that budget or that need.
- **No bulk reset across groups.**

## Design references

- `research/kafbat/ui-analysis.md` "Reset offsets": the field set, the defaults (`EARLIEST`, the
  first topic, the current time), that changing the topic clears the partition selection, that the
  timestamp field appears only when the mode is `TIMESTAMP` **and** at least one partition is
  selected, that the offset fields are one per selected partition with `min 0`, and that submit is
  disabled with no partitions. KUI copies all of it and adds the review step.
- DEVPLAN §10 D3 (two phases, the token), D4 (the refusals), D10 (six modes, including the two the
  reference does not have).
- ADR-032 — a destructive action disabled by capability or permission shows one merged tooltip
  (`ActionPermissionWrapper`).
- `research/design/REFERENCE.md` — the rounder radii, the filled chips, and the rule that a value
  crossing a threshold changes colour rather than being coloured constantly. The proposed-offset
  column is coloured only where it moves backwards past the log start.

## Public Scala signatures to implement

```scala
package kui.ui.consumers.reset

import com.raquo.laminar.api.L.*
import kui.consumer.contract.dto.{ResetPlanDto, ResetPlanRequest}
import kui.kernel.group.ResetTarget

enum WizardStep:
  case Choose, Review, Confirm, Done

object ResetModeFields:
  /** Rendered from `ResetTarget.values`, so a seventh mode added in `libs/kernel` appears here as a
    * compile error in the exhaustive match rather than as a radio nobody added. */
  def apply(mode: Var[ResetTarget], selected: Signal[Set[Int]], form: Var[ResetPlanRequest]): HtmlElement

object ResetPlanTable:
  /** Four columns and a warning column. The delta is signed and rendered with its sign, because
    * "−4 100 000" and "4 100 000" are the difference between replaying and skipping. */
  def apply(plan: Signal[ResetPlanDto]): HtmlElement

object ResetConfirmDialog:
  /** Focus-trapped, Escape closes, the group id must be typed to enable the button — and the button
    * says what it will do ("Reset 12 partitions of orders-consumer"), not "OK". A destructive
    * dialog whose button says OK is a dialog people click through. */
  def apply(plan: ResetPlanDto, groupId: String, onConfirm: Observer[Unit]): HtmlElement
```

## Tests required

`ResetModeFieldsSuite`:

1. `sixModesAreRendered` — from `ResetTarget.values`, asserted by count and by label.
2. `earliestAndLatestShowNoParameterField`.
3. `timestampShowsThePickerOnlyWithAPartitionSelected`.
4. `offsetShowsOneFieldPerSelectedPartition`.
5. `offsetFieldsRejectNegatives`.
6. `shiftByAcceptsANegativeNumber` — the one numeric field that must.
7. `durationAcceptsAHumanValue` — "2h", "30m", "1d", parsed in the browser and sent as milliseconds.
8. `changingTheTopicClearsThePartitionSelection`.
9. `changingTheModeClearsTheOtherModesParameters` — so a stale timestamp cannot be sent with an
   `OFFSET` request.

`ResetWizardPageSuite`:

1. `theTopicSelectOffersOnlyTheGroupsTopics`.
2. `submitIsDisabledWithNoPartitions`.
3. `reviewFetchesAPlanAndRendersIt` — against a golden `ResetPlanDto`.
4. `theDeltaColumnIsSigned`.
5. `everyWarningIsRenderedWithItsPartition` — **no warning is collapsed into a count**: a clamp on
   partition 7 must name partition 7.
6. `aClampIsVisuallyDistinctFromANormalRow`.
7. `theTimestampBeyondEndWarningIsExplained` — in the sentence an operator needs: "no record at or
   after that time; this partition will be moved to the end, so the group will skip everything".
   The most surprising rule in the feature, spelled out.
8. `theSummarySentenceCountsMovedPartitionsAndRecords`.
9. `aNoOpPlanSaysSoAndStaysApplicable`.
10. `confirmIsDisabledUntilTheGroupIdIsTyped`.
11. `theConfirmButtonNamesTheAction`.
12. `applySendsOnlyTheToken` — asserted on the stubbed client's captured body. **The D3 assertion in
    the browser**: no spec, no offsets, no topic.
13. `editingTheFormAfterAPlanInvalidatesIt` — going back to Choose discards the token and the review
    must be re-fetched. A token applied against a form the operator has since edited is exactly what
    the token exists to prevent.
14. `anExpiredTokenIsHandledWithARePlanPrompt` — not an error toast: "this plan is more than five
    minutes old; review it again".
15. `anActiveGroupRefusalIsExplainedInTheGroupsWords` — "the group has members again; stop its
    consumers and try once more".
16. `aReadOnlyClusterHidesTheWizardEntry`.
17. `aFiveOhThreeKeepsThePlanOnScreenForRetry`.
18. `theResultStepShowsWhatWasApplied`.
19. `theResultStepSaysTheResetIsNotReversible` — the one sentence on this screen that must never be
    removed, and the audit record is named as the way back.
20. `theDialogTrapsFocusAndEscapeCloses`.
21. `theWholeFlowIsKeyboardOperable` — a destructive action reachable only by mouse is one an
    operator performs less carefully.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| Plan request fails | The Choose step keeps every field; the error is shown inline with its code; nothing is lost |
| Token expired | A prompt to review again; the form is intact |
| Group became active | The refusal's message, and a link to the group so the operator can see the members |
| Cluster read-only | The entry is absent from the action menu, and a direct navigation to the wizard route renders "this cluster is read-only" rather than an empty form |
| Capability degraded | The wizard works; a banner says the service is degraded and the plan may take longer |
| Cluster unreachable | The wizard route renders the feature fallback with the reason |
