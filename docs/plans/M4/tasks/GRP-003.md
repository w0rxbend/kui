# GRP-003 — `GroupAdmin.listGroups`: state and type filters, per-coordinator partial listing

- **ID:** GRP-003
- **Title:** `GroupAdmin.listGroups`: state and type filters, per-coordinator partial listing
- **Milestone / Feature:** M4 / CG-001
- **Owner role:** Principal Scala Engineer
- **Context / module:** `libs/kafka`
- **Size:** M
- **Dependencies / blocked by:** GRP-002

## Goal (user value)

The cheap call the group list is built on: every group id on the cluster with its state, without
describing any of them. And an honest answer when one coordinator broker is down — the reference
product returns a short list and says nothing, so an operator sees a group vanish and concludes it
was deleted.

## Scope

1. `listGroups` implemented over the raw `Admin` from `AdminClientPool`.
2. The state filter pushed **to the broker** when the cluster supports it (Kafka 2.6), and applied
   in memory when it does not, with the difference invisible to the caller.
3. The Kafka `ConsumerGroupState` / `GroupState` → `kui.kernel.group.GroupState` mapping, in one
   private function, in this file, and nowhere else in KUI.
4. Per-coordinator partial results: a `CoordinatorNotAvailableException` from one broker yields a
   `PartialResult` whose `skipped` names that broker with `SkipReason.Unavailable`, and whose
   `values` hold everything the other coordinators answered.
5. Share groups and any non-consumer group type filtered out, counted and logged once per refresh.

## Non-goals

- **No describe.** GRP-004. A listing that describes to fill in a state is the expensive mistake
  this method exists to avoid.
- **No paging, no sorting, no search.** Those are the application layer's (GRP-014); this returns
  everything the cluster has.
- **No caching.** GRP-013.

## Design references

- `research/kafka/admin-capabilities.md` §3, row "List groups": `listConsumerGroups(...inGroupStates
  (...).withTypes(...))`, the 4.0 `listGroups`, the minimum versions (0.10.1 / state filter 2.6 /
  type filter 3.8), `CoordinatorNotAvailableException` meaning a partial listing, `state()` being
  `Optional`, and Kafbat filtering state in memory (`ConsumerGroupService.java:181-192`).
- ADR-030 — the state filter is used only when `GroupFeature.StateFilter` is present (GRP-008); the
  in-memory path is the fallback, never a version check.
- `libs/kafka/src/kui/kafka/BatchResult.scala` and `SkipReason.scala` — the existing partial-result
  vocabulary. Do not invent a second one.

## Public Scala signatures to implement

```scala
// in AdminConversions
/** The only place in KUI that reads a Kafka group-state value.
  *
  * Total by construction: an enum value this build does not know maps to `GroupState.Unknown` and
  * increments `kui.kafka.group.unknown_state`. A broker newer than KUI is not an error.
  */
private[kafka] def toGroupState(raw: Option[org.apache.kafka.common.GroupState]): GroupState

private[kafka] def toGroupProtocol(raw: Option[org.apache.kafka.common.GroupType]): GroupProtocol

// in KafkaGroupAdmin
override def listGroups(
    conn: ClusterConnection,
    states: Set[GroupState]
): F[Either[KuiError, PartialResult[BrokerId, List[GroupListing]]]]
```

Behaviour, precisely:

- `states.isEmpty` means "every state" and sends no filter.
- When `GroupFeature.StateFilter` is present, the states are translated and sent in
  `ListGroupsOptions`; when it is absent, no filter is sent and the result is filtered in memory by
  `listing.state`. **A group whose state is `Unknown` survives an in-memory filter** — filtering it
  out would hide a group because a broker declined to describe it.
- The result's `values` is a single `List[GroupListing]` keyed, in `PartialResult`, by the
  coordinator `BrokerId` that answered it, so the caller can say which brokers contributed.
- `errors` in Kafka's `ListConsumerGroupsResult` are per-broker and are mapped one-to-one to
  `skipped` entries. **A single coordinator failure is not a failed call.** Every coordinator
  failing *is*: the method returns `Left` rather than an empty list, because "there are no groups"
  and "nobody would tell me" must not render the same.

## Tests required

`GroupStateMappingSuite` (MUnit + ScalaCheck):

1. `everyKafkaGroupStateMapsToAKuiState` — a property over
   `org.apache.kafka.common.GroupState.values`, asserting the mapping is total and never throws.
2. `anAbsentStateIsUnknownNotDead` — `None` maps to `Unknown`. The single most consequential line in
   the file: mapping it to `Dead` would tell an operator a healthy group is being removed.
3. `anUnrecognisedStateIsUnknownAndCounted`.
4–5. The same two for `GroupType` → `GroupProtocol`.
6. `shareGroupsAreNotConsumerGroups` — a `GroupType.SHARE` listing is filtered out.
7. `theMappingIsInjectiveOnKnownStates`.
8. `noKuiStateIsUnreachable` — every `GroupState` except `Unknown` is produced by some Kafka value,
   so a case nothing can produce is caught rather than living as decoration.

`ListGroupsSuite` (MUnit + Testcontainers, PLAINTEXT via `KafkaFixture` from `libs/testkit`):

1. `listsTheSeededGroups` — the fixture's three groups appear with their expected states.
2. `anEmptyStateSetReturnsEverything`.
3. `theStateFilterNarrowsTheResult` — `states = Set(Empty)` returns only the empty group.
4. `theInMemoryFallbackGivesTheSameAnswer` — the same assertion with the feature forced absent, so
   the two code paths are proven equivalent rather than assumed to be.
5. `anUnknownStateSurvivesAnInMemoryFilter`.
6. `oneFailingCoordinatorIsASkipNotAFailure` — a stubbed `Admin` whose per-broker map carries one
   error: `Right`, with one `skipped` entry naming the broker.
7. `everyCoordinatorFailingIsALeft`.

Logging: one DEBUG line per call with the group count and the skipped-coordinator count. A skipped
coordinator logs WARN **on transition only** — a coordinator that has been down all weekend must not
produce a warning every thirty seconds.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| One coordinator down | `Right` with a `skipped` entry; the application layer marks the list `Section.Stale`-adjacent by carrying `incompleteCoordinators` into its response (GRP-014) |
| Every coordinator down | `Left(ApplicationError.Unavailable)`, so the screen says so rather than showing an empty list |
| Broker below 2.6 | No state filter sent; identical results, one more call's worth of data over the wire |
| Broker returns a state name from the future | `Unknown`, counted, rendered as a neutral chip |
