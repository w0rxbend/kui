# GRP-014 — `GroupListUseCase`: filter, search, sort, page, over the snapshot

- **ID:** GRP-014
- **Title:** `GroupListUseCase`: filter, search, sort, page, over the snapshot
- **Milestone / Feature:** M4 / CG-001
- **Owner role:** Domain Architect (Consumer Group Management context)
- **Context / module:** `services/consumer/application`
- **Size:** M
- **Dependencies / blocked by:** GRP-013

## Goal (user value)

The Consumers screen: every group on the cluster, filtered by state, searched by id, sorted by any
column and paged — answered from memory in microseconds, with an honest freshness label, on a
cluster with four thousand groups.

## Scope

1. `GroupListUseCase[F]`: one method, `list(cluster, query)`, returning a page plus its freshness.
2. `GroupQuery`: state filter, search term, sort field and direction, page and page size, with
   documented defaults and bounds.
3. The order of operations: **filter, then search, then sort, then page** — and the page count
   computed after filtering, not before.
4. `SnapshotFreshness` reused from the cluster context's shape (`Loading` / `Fresh` / `Stale` /
   `Unavailable`), declared here for this context because rule A5 forbids reaching into another
   service.

## Non-goals

- **No full-text search, no FTS toggle.** DR-10 defers the n-gram index to M9; a toggle that does
  nothing is worse than no toggle (DEVPLAN §10 D14).
- **No CSV.** M5.
- **No describe on the request path.** Everything comes from the snapshot. A read that called a
  broker would make this the slowest screen in KUI, which is precisely the outcome risk R-4 names.
- **No cross-cluster listing.** One cluster per request.

## Design references

- ADR-026 §"Lists with in-memory sort": `page`/`pageSize`, `sort=<field>:<asc|desc>`, `q`,
  `Page{items, page, pageSize, totalItems}`, and **"the reference `pageCount` bug (computed before
  the internal-topic filter) is not reproduced"** — the same bug shape applies here to the state
  filter.
- `research/kafbat/ui-analysis.md` "Consumer groups list": the sortable set is NAME, MEMBERS, STATE,
  MESSAGES_BEHIND, TOPIC_NUM; Coordinator is deliberately not sortable; `perPage` default 25; the
  state filter is a multi-select; the empty message is "No active consumer groups found".
- ADR-038 / DEVPLAN §10 D14 — substring search over group ids through `libs/kernel`'s `NameIndex`.
- ADR-032 — how `Stale` renders.

## Public Scala signatures to implement

```scala
package kui.consumer.application

import kui.consumer.domain.GroupSummary
import kui.kernel.{ClusterId, Page}
import kui.kernel.group.GroupState

enum GroupSortField(val wire: String):
  case Id extends GroupSortField("id")
  case Members extends GroupSortField("members")
  case Topics extends GroupSortField("topics")
  case Lag extends GroupSortField("lag")
  case State extends GroupSortField("state")

final case class GroupQuery(
    states: Set[GroupState],          // empty = every state
    search: Option[String],           // substring, case-insensitive, over the group id
    sort: GroupSortField,             // default Id
    descending: Boolean,              // default false
    page: Int,                        // 1-based; default 1
    pageSize: Int                     // default 25, max 200
)

object GroupQuery:
  val Default: GroupQuery
  val MaxPageSize: Int = 200
  /** Bounds rather than rejects: a page size of 5 000 is clamped to 200 and reported, because a
    * client asking for too much should get an answer, not a 400. A page beyond the last is an empty
    * page with the correct `totalItems`, not a 404. */
  def normalise(raw: GroupQuery): (GroupQuery, List[String])

final case class GroupListView(
    page: Page[GroupSummary],
    freshness: SnapshotFreshness,
    /** Non-empty when a coordinator did not answer this pass; the screen says the list may be
      * incomplete rather than silently showing fewer groups. */
    incompleteCoordinators: Set[kui.kernel.BrokerId],
    /** Every state present on the cluster with its count, computed **before** the state filter is
      * applied, so the filter chips can show counts of what filtering them in would reveal. */
    stateCounts: Map[GroupState, Int]
)

trait GroupListUseCase[F[_]]:
  /** Never fails for a reachable configured cluster. `Left(NotFound)` for a cluster id that is not
    * configured; a configured but unreachable cluster is a `Right` whose freshness is
    * `Unavailable`. */
  def list(cluster: ClusterId, query: GroupQuery): F[Either[KuiError, GroupListView]]

object GroupListUseCase:
  val Operation: String = "kui.consumer.list"
  def make[F[_]: Temporal](snapshots: GroupSnapshots[F]): GroupListUseCase[F]

  /** Pure, and exported so the ordering rule is asserted directly rather than through six effectful
    * scenarios. Filter → search → sort → page, in that order. */
  def applyQuery(rows: Vector[GroupSummary], q: GroupQuery, index: NameIndex[GroupId]): Page[GroupSummary]
```

Sorting rules, each a test case:

- `Lag` sorts on `totalLag`, and **groups whose lag is `None` sort last in both directions**. An
  undefined lag is not a zero and must not lead an ascending sort; it is also not the largest and
  must not lead a descending one. "Unknown last" is the only ordering that is not a lie in one
  direction.
- `State` sorts by the operational severity an operator cares about, not alphabetically:
  `PreparingRebalance`, `CompletingRebalance`, `Stable`, `Empty`, `Dead`, `Unknown`. Alphabetical
  order puts `COMPLETING_REBALANCE` above `DEAD` for no reason anybody can act on.
- Every sort is **stable** and ties break on the group id, so paging is deterministic and page 2 of
  two identical requests holds the same rows.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| Snapshot stale | Rows served greyed with `takenAt` and the reason (ADR-032 DC-H3); the state filter and search still work, because they are local |
| Snapshot absent | `Unavailable(reason, since)`; the screen shows the fallback panel, not an empty table, so "no groups" and "we cannot tell" never render the same |
| One coordinator down | Rows render; a banner says the listing may be incomplete and names the broker |
| Cluster has no groups | An empty page with `totalItems = 0` and the empty state "No consumer groups on this cluster" — distinct from the unavailable case above |
