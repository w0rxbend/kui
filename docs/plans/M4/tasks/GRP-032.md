# GRP-032 — Group detail screen: members, assignments, per-partition lag, stale badge

- **ID:** GRP-032
- **Title:** Group detail screen: members, assignments, per-partition lag, stale badge
- **Milestone / Feature:** M4 / CG-002
- **Owner role:** Frontend Architect
- **Context / module:** `frontend/ui-consumers`
- **Size:** L
- **Dependencies / blocked by:** GRP-031

## Goal (user value)

The page an operator opens when something is behind: a summary strip that answers "what is this
group doing" in one glance, a topic table sorted worst-first, and — expanded — every partition with
its current offset, the end offset, its lag and which consumer holds it. During a rebalance it keeps
showing the last assignment it saw, greyed and badged, rather than going blank while the coordinator
sorts itself out.

## Scope

1. `GroupDetailPage` filled in: heading, breadcrumbs, back link, the summary strip, the topic table
   with expandable partition rows, and the action menu (whose items GRP-034 and GRP-035 fill).
2. **The summary strip**: state chip, members, assigned topics, assigned partitions, coordinator id,
   total lag with its excluded-partition footnote, and pace. Seven indicators, all from one response.
3. **The topic table**: topic name (linking to the topic page when the topics feature exists),
   this-topic lag with a magnitude bar, partition count, and an expander.
4. **The partition table** inside each expanded row: partition, consumer id, host, current offset,
   end offset, lag, anomalies. Client-side sortable, default by partition ascending.
5. **The stale-assignment badge** (DC-H10): when `assignments` is `LAST_SEEN`, the member and
   partition-holder columns grey, the badge says "assignments as of <time>; the group is
   rebalancing", and the lag columns stay normal — because committed offsets are valid during a
   rebalance and greying them would hide the number the operator came for.

## Non-goals

- **No message browsing.** The partition rows link to the message explorer when it exists; they do
  not embed it.
- **No live polling.** GRP-033.
- **No destructive actions implemented.** The menu exists; GRP-034 and GRP-035 wire its items.
- **No CSV.** M5.
- **No editing anything.** There is no inline offset field on this page; the only way to change an
  offset is the wizard, and the wizard shows a plan first (DEVPLAN §10 D3).

## Design references

- `research/kafbat/ui-analysis.md` "Consumer group details": the six metric indicators, the topics
  table, the expandable partition table and its exact six columns, the client-side sort with a
  numeric comparator for offsets and an IPv4 comparator for hosts, the search over topic names, and
  the states (`PageLoader`, `ErrorPage` with `resourceName`).
- DC-H10 — the last-seen assignment behaviour and its badge; DEVPLAN §2.6, the exit criterion.
- `research/design/REFERENCE.md` — a row expands in place rather than opening a drawer; magnitude
  bars; threshold colouring; status as a filled chip.
- ADR-032 — the stale rule and how a greyed region reads.
- DEVPLAN §10 D6 — every undefined lag is an em dash with a reason.

## Public Scala signatures to implement

```scala
package kui.ui.consumers.detail

import com.raquo.laminar.api.L.*
import kui.consumer.contract.dto.*

object GroupSummaryStrip:
  def apply(d: Signal[GroupDetailDto]): HtmlElement

object TopicTable:
  /** Rows sorted by this-topic lag descending, undefined last — the operator is looking for the one
    * that is behind, and putting it first is the point of the table. A client-side search box
    * filters by topic name, as the reference's does, because the list is short and a round trip for
    * a substring match on twenty rows is worse than free. */
  def apply(rows: Signal[List[TopicSubscriptionDto]], onExpand: Observer[String]): HtmlElement

object PartitionTable:
  /** Six columns, client-side sortable. Comparators: numeric for partition and offsets, so
    * partition 10 sorts after partition 9; IPv4-aware for host, so 10.0.0.9 sorts before 10.0.0.10;
    * case-insensitive for consumer id. A lexical sort of any of the three is wrong in a way that is
    * only noticed when it matters. */
  def apply(topic: String, partitions: Signal[List[PartitionDto]], assignmentsStale: Signal[Boolean]): HtmlElement

object AssignmentBadge:
  /** `CURRENT` renders nothing. `LAST_SEEN(at)` renders the badge and the timestamp.
    * `UNKNOWN` renders "the group is rebalancing and no previous assignment is known", which is a
    * different sentence from "this group has no members". */
  def apply(freshness: AssignmentFreshnessDto): HtmlElement
```

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| Rebalancing | Last-seen assignments, greyed, badged with the time; lag unaffected |
| Rebalancing with no history | The partition table shows partitions with no holder and says why |
| No `DESCRIBE` permission | The members strip and the consumer column say "not permitted", and the offsets — which come from a different call — still render if that one succeeded |
| End offsets unavailable | Every lag `—`, a line under the strip saying the end offsets could not be read and which broker is the reason |
| Group deleted while the page is open | The next load renders an empty dead group with a note that the group no longer exists — not a crash and not a 404 page |
