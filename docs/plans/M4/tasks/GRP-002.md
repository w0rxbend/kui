# GRP-002 — `libs/kafka`: `GroupAdmin[F]` port, result types, and the fabricated-dead-group invariant

- **ID:** GRP-002
- **Title:** `libs/kafka`: `GroupAdmin[F]` port, result types, and the fabricated-dead-group invariant
- **Milestone / Feature:** M4 / CG-001, CG-002
- **Owner role:** Principal Scala Engineer
- **Context / module:** `libs/kafka`
- **Size:** M
- **Dependencies / blocked by:** GRP-001

## Goal (user value)

The second admin port family in KUI, and the place where a behaviour that has been written down for
two milestones finally becomes code: *describing a consumer group that does not exist returns a
fabricated dead group rather than an error.* Every caller in M4 and every caller in M5 and M8 gets
one answer to "what does this broker do when the group is not there", instead of each one
rediscovering it.

## Scope

1. The `GroupAdmin[F]` port trait in `kui.kafka.admin`, declaring all six operations M4 needs.
   GRP-003 … GRP-007 fill in the implementations; this task declares the signatures so that later
   tasks add bodies, not shapes.
2. The result types: `GroupListing`, `GroupDescription`, `GroupMember`, `MemberAssignment`,
   `CommittedOffset`, `GroupCoordinator`.
3. `KafkaGroupAdmin`, the adapter shell over `AdminClientPool`, with every method not yet
   implemented returning `ApplicationError.Unsupported("not yet implemented")` — permitted **only**
   because GRP-003 … GRP-007 land inside this same milestone. A worker who finds one still stubbed
   after GRP-007 has found a bug.
4. **The invariant.** `PORT-INVARIANTS.md` §2's text is moved verbatim into the scaladoc of
   `GroupAdmin.describeGroups` and deleted from that file in this commit, as the file itself
   instructs.

## Non-goals

- **No implementations.** `listGroups` is GRP-003, `describeGroups` GRP-004, `committedOffsets`
  GRP-005, the offset lookup GRP-006, the mutations GRP-007, the probe GRP-008.
- **No `removeMembersFromConsumerGroup`.** Not in the feature matrix (DEVPLAN §4). Do not declare
  the method "so it is there".
- **No share groups, no `describeShareGroups`.**
- **No domain types.** This port speaks `libs/kernel` vocabulary and its own result types only;
  rule A5 forbids it seeing a service.

## Design references

- `libs/kafka/PORT-INVARIANTS.md` §2 — the behaviour, the evidence, the rule, and the instruction to
  move it here.
- `research/kafka/admin-capabilities.md` §3 — every row is one method of this trait; §0 for the
  single-I/O-thread and timeout facts that make batching the adapter's job.
- ADR-006 Amendment 1 — raw `Admin` for admin work. `KafkaGroupAdmin` uses the raw `Admin` the
  existing `AdminClientPool` hands out, exactly as `KafkaClusterAdmin` does.
- DC-D1 — one admin port per bounded context, not one global port. `GroupAdmin` is separate from
  `ClusterAdmin` for that reason and must not gain a broker method.
- ADR-030, ADR-041 A10.
- The existing `libs/kafka/src/kui/kafka/admin/ClusterAdmin.scala` is the shape to copy: a trait of
  `F[Either[KuiError, A]]` methods taking a `ClusterProfile`-free connection value.

## Public Scala signatures to implement

```scala
package kui.kafka.admin

import java.time.Instant

import kui.kernel.{BrokerId, GroupId, TopicName, TopicPartition, Offset}
import kui.kernel.cluster.ClusterConnection
import kui.kernel.error.KuiError
import kui.kernel.group.{GroupProtocol, GroupState}

final case class GroupCoordinator(id: BrokerId, host: String, port: Int)

/** One row of a listing. Cheap: a listing does not describe. */
final case class GroupListing(
    groupId: GroupId,
    /** A "simple" group was created by the low-level assign API and has no protocol; it can still
      * hold committed offsets, and it can still be reset. */
    isSimple: Boolean,
    /** `Unknown` when the broker did not report one — see `GroupState`'s scaladoc. */
    state: GroupState,
    protocol: GroupProtocol
)

final case class MemberAssignment(partitions: Set[TopicPartition])

final case class GroupMember(
    memberId: String,
    /** Present only for static members (`group.instance.id`). */
    groupInstanceId: Option[String],
    clientId: String,
    host: String,
    /** What the member holds now. For a KIP-848 consumer-protocol member this is `assignment()`
      * and `targetAssignment` carries where the coordinator is moving it to. */
    assignment: MemberAssignment,
    /** KIP-848 only; `None` for classic members and when the two are equal. A member whose target
      * differs from its assignment is mid-rebalance, and the UI says so. */
    targetAssignment: Option[MemberAssignment]
)

final case class GroupDescription(
    groupId: GroupId,
    isSimple: Boolean,
    state: GroupState,
    protocol: GroupProtocol,
    /** The assignor name the group negotiated ("range", "cooperative-sticky", …); empty for a
      * simple group. */
    partitionAssignor: String,
    members: List[GroupMember],
    /** `None` when the coordinator could not be determined — a real state during a coordinator
      * move, and not an error. */
    coordinator: Option[GroupCoordinator],
    /** `None` when the cluster has no authorizer configured, which means "ACLs are off" and must
      * not be confused with an empty set. */
    authorizedOperations: Option[Set[GroupOperation]]
):
  /** DEVPLAN §10 D4: the union of the two references' checks. Both halves, never one. */
  def permitsOffsetChange: Boolean =
    GroupState.permitsOffsetChange(state) && members.isEmpty

enum GroupOperation:
  case Describe, Read, Delete, All, Unknown

final case class CommittedOffset(
    partition: TopicPartition,
    offset: Offset,
    /** Kafka's free-text metadata field on the commit. Rendered, never parsed. */
    metadata: Option[String],
    /** Present from Kafka 2.1; `None` on older brokers and on some managed services. */
    committedAt: Option[Instant]
)

trait GroupAdmin[F[_]]:

  /** Every group the coordinators will admit to, optionally narrowed by state.
    *
    * A listing is per coordinator broker: a down broker hides its groups and the call still
    * succeeds. The result therefore says how many coordinators failed rather than pretending the
    * listing is complete (GRP-003).
    */
  def listGroups(
      conn: ClusterConnection,
      states: Set[GroupState]
  ): F[Either[KuiError, PartialResult[BrokerId, List[GroupListing]]]]

  /** Describe groups in bulk.
    *
    * ## An unknown group is a dead group, not an error
    *
    * Brokers disagree about what "that group does not exist" means. Older brokers answer
    * `describeConsumerGroups` for an unknown group id with a perfectly ordinary description whose
    * state is `DEAD` and whose member list is empty. Newer brokers throw
    * `GroupIdNotFoundException`.
    *
    * A port that passes the difference through makes every caller branch on broker version — and
    * ADR-030 is explicit that KUI gates on *capabilities*, never on version numbers. Two callers
    * written six months apart will branch differently, and the one that forgot will show a stack
    * trace on a cluster that is behaving correctly.
    *
    * **This port normalises to the older behaviour**: an unknown group is a `GroupDescription` in
    * state `Dead`, with no members and no assignment. `GroupIdNotFoundException` is caught inside
    * the adapter and turned into that value, *before* `KafkaErrorMapper` ever sees it.
    *
    * "Dead with no members" is a true statement about a group that does not exist, and it is what a
    * screen wants to render — an empty group page rather than a 404 — whereas an error forces every
    * caller to decide what to do about it. **Where existence genuinely matters, the caller confirms
    * it with `listGroups` first** (`OffsetsResetService.java:66-92`); in KUI that caller is
    * `OffsetResetUseCase`, and `ErrorCode.GroupNotFound` is the code it raises.
    *
    * Evidence: `research/kafka/admin-capabilities.md` §3, "Describe groups". Moved here from
    * `libs/kafka/PORT-INVARIANTS.md` §2 by task GRP-002, which deleted it there.
    */
  def describeGroups(
      conn: ClusterConnection,
      ids: List[GroupId]
  ): F[Either[KuiError, PartialResult[GroupId, GroupDescription]]]

  /** Committed offsets for several groups at once. A partition the group has never committed on is
    * absent from the map — never present with a zero (GRP-005). */
  def committedOffsets(
      conn: ClusterConnection,
      groups: List[GroupId],
      /** `None` means every partition the group has a commit for. */
      partitions: Option[Set[TopicPartition]],
      requireStable: Boolean
  ): F[Either[KuiError, PartialResult[GroupId, List[CommittedOffset]]]]

  /** Write committed offsets. Refuses nothing itself: the precondition is the caller's, and the
    * broker's own rejection is mapped (GRP-007). */
  def alterOffsets(
      conn: ClusterConnection,
      group: GroupId,
      offsets: Map[TopicPartition, Offset]
  ): F[Either[KuiError, Unit]]

  def deleteOffsets(
      conn: ClusterConnection,
      group: GroupId,
      partitions: Set[TopicPartition]
  ): F[Either[KuiError, Unit]]

  def deleteGroups(
      conn: ClusterConnection,
      ids: List[GroupId]
  ): F[Either[KuiError, PartialResult[GroupId, Unit]]]

object GroupAdmin:
  val Component: String = "kui.kafka.group"
```

`PartialResult` and `SkipReason` are the existing `libs/kafka` types (`BatchResult.scala`,
`SkipReason.scala`) and are not redefined.

## Tests required

`GroupTypesSuite` (MUnit):

1. `permitsOffsetChangeNeedsBothHalves` — a description with `state = Empty` and one member is
   `false`; `state = Stable` with no members is `false`; `Empty` with no members is `true`. The
   union rule of DEVPLAN §10 D4, asserted on the type that states it.
2. `deadIsPermitted` — a fabricated dead group permits an offset change, which is what makes a
   reset on a group that has gone dead work rather than being refused.
3. `authorizedOperationsNoneIsNotEmpty` — `None` and `Some(Set.empty)` are distinguishable, and a
   helper that treats them the same does not exist.
4. `targetAssignmentIsNoneWhenEqual` — the smart constructor for `GroupMember` collapses an
   identical target to `None`, so "mid-rebalance" is a question with one answer.
5. `groupListingCarriesUnknownStateRatherThanFailing`.
6. `everyGroupAdminMethodIsStubbedOrImplemented` — a reflective assertion that no method of the
   trait is missing from `KafkaGroupAdmin`, so a later task cannot add a signature and forget the
   body.

| Counter | `kui.kafka.group.fabricated_dead` | `cluster.id` — a `GroupIdNotFoundException` normalised away. An operator seeing this rise knows callers are asking for groups that are not there |

## Cancellation and shutdown

The trait's methods are single effects with no fibers of their own; cancellation is whatever
`AdminClientPool` already guarantees. No new teardown path is introduced, and the Implementation
Report states that explicitly rather than leaving it unsaid.
