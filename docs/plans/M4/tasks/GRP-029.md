# GRP-029 — Gateway: consumer routes, group-page aggregation, topic-overview section, capabilities, OpenAPI

- **ID:** GRP-029
- **Title:** Gateway: consumer routes, group-page aggregation, topic-overview section, capabilities, OpenAPI
- **Milestone / Feature:** M4 / CG-001 … CG-006, TP-015, KU-011
- **Owner role:** Chief Architect
- **Context / module:** `services/gateway/{contract,application,api}`
- **Size:** L
- **Dependencies / blocked by:** GRP-025, GRP-020

## Goal (user value)

The browser talks to one origin. The group page arrives as one document whose sections fail
independently, the topic page gains a Consumers section that is `Unavailable` rather than absent when
the consumer service is down, and the sidebar's Consumers entry knows, per cluster, whether it can
be used.

## Scope

1. Proxy routes for the consumer service's public endpoints, with `X-Kui-Cluster-Id` validation and
   the per-upstream timeout (ADR-037).
2. **The group-page aggregation** (KU-011): `GET /api/v1/clusters/{id}/consumer-groups/{group}`
   returning the group detail as one section plus, when the topic service exists, the topic sections
   the page links to. Sections fail independently and a failing section never fails the response.
3. **The topic-overview `consumerGroups` section** (TP-015, DEVPLAN §10 D13): the gateway calls
   `/internal/v1/.../topics/{topic}/consumer-groups` and folds the result into the topic overview it
   already aggregates.
4. Per-cluster `consumer` capability entries, from the consumer service's report (ADR-039).
5. OpenAPI aggregation regenerated and committed.

## Non-goals

- **No business logic.** The gateway composes; it does not compute lag, does not filter groups and
  does not decide preconditions.
- **No Kafka.** Rule A8. The gateway gains no Kafka edge of any kind, and `checkArchitecture`
  enforces it.
- **No caching of consumer data.** The consumer service's snapshot is the cache; a second one in the
  gateway would have a second staleness contract and a second invalidation problem.
- **No new streaming.** The capability stream already exists; the lag delta is polled.

## Design references

- `ARCHITECTURE.md` §6 — the `Section` envelope and the list of aggregations, which names
  `GET /consumer-groups/{groupId}` explicitly.
- ADR-037 — the per-upstream timeout that bounds the aggregation; **no new timeout knob**, the
  assertion is expressed against the configured value (M1's decision D9).
- ADR-039 §6 — only a transport failure *of the upstream service* dims a capability. A cluster the
  consumer service cannot reach is a section inside a 200, never an unavailable capability. This is
  M1's decision D4 applied to the second service, and `STATUS.md` records that M1 shipped the
  cluster half of it incompletely — CLAPI-008's unfinished half, where a per-cluster capability
  reads `available` for a cluster whose row correctly says otherwise. **Do not reproduce that
  here**, and the suite below asserts it.
- ADR-043, ADR-040 (edge header policy), ADR-012 / DC-H6 (the feature panel, whose data this
  section is).
- `services/gateway/application/.../cluster/ClusterOverviewUseCase.scala` — M1's aggregation, the
  shape to copy, including its two independent section levels.

## Public Scala signatures to implement

```scala
package kui.gateway.application.consumer

/** The group page as one document.
  *
  * Two independent section levels, as `GET /clusters` has: the outer one says whether the consumer
  * service could be reached at all, and the inner sections say whether each part of the page could
  * be filled. A page where the group loaded and the topic list did not is a real state and renders
  * as such.
  */
final case class GroupPageDto(
    group: Section[GroupDetailDto],
    /** Present from M4 when the topic service exists; `NotConfigured` otherwise. Links the page's
      * topic rows to their topic pages without the browser making N calls. */
    topics: Section[List[TopicRefDto]]
)

trait GroupPageUseCase[F[_]]:
  /** Never fails. Every upstream failure becomes a section, and the response returns within the
    * per-upstream timeout regardless of how many upstreams are slow — because the sections are
    * fetched in parallel, which the suite asserts with virtual time so that a serialising
    * regression fails the test rather than merely slowing it. */
  def page(cluster: ClusterId, group: GroupId): F[GroupPageDto]

/** The one place the gateway knows how to ask the consumer service for a topic's groups. Used by
  * the topic overview aggregation; kept separate so that `TopicOverviewRoutes` gains one line
  * rather than a dependency. */
trait ConsumerSectionSource[F[_]]:
  def consumerGroupsOf(cluster: ClusterId, topic: TopicName): F[Section[TopicConsumersDto]]
```

## Tests required

`GroupPageUseCaseSuite` (MUnit + `munit-cats-effect` + `TestControl` + stub upstreams):

1. `bothSectionsPopulate`.
2. `aFailingConsumerServiceIsAnUnavailableSectionNotAFailedResponse`.
3. `aFailingTopicServiceLeavesTheGroupSectionIntact`.
4. `sectionsAreFetchedInParallel` — **the ADR-037 assertion under virtual time**: two upstreams each
   taking the full timeout, and the response returns in one timeout, not two.
5. `theResponseIsBoundedByTheConfiguredUpstreamTimeout` — asserted against the configured value, not
   a literal.
6. `aStaleUpstreamSectionIsStaleNotUnavailable`.
7. `anUnknownClusterIsFourOhFour`.
8. `anUnknownGroupIsAnEmptyDeadGroupPage` — the invariant, at the edge.
9. `theTopicSectionIsNotConfiguredWithoutTheTopicService`.
10. `noUpstreamErrorBodyReachesTheClient` — the upstream's message is mapped to a `KuiError`; its raw
    body, headers and host never appear. ADR-034's rule, asserted.
11. `cancellationOfTheRequestCancelsBothUpstreamCalls` — the named cancellation test: the browser
    goes away, both stubs observe their connections closed.

`ConsumerProxyRoutesSuite`:

1–4. Each proxied endpoint round-trips, asserted against the **golden documents from GRP-024** —
the same files the service's suite and the browser's client use. This is the gateway-vs-service seam
(GRP-037 formalises it; these four are its first instances).
5. `anUnknownClusterIdIsRejectedAtTheEdge`.
6. `theClusterIdHeaderAndPathMustAgree`.
7. `theCsrfHeaderIsRequiredOnMutations`.
8. `anInternalV1PathIsNotProxied` — **the D13 assertion**: the browser cannot reach
   `/internal/v1/.../topics/{t}/consumer-groups` through the gateway.
9. `theConsumerCapabilityIsPerClusterNotFolded` — **the assertion that M1's CLAPI-008 lacked**: with
   two clusters, one unreachable, the `consumer` capability for cluster A is `available` and for
   cluster B is not, and neither is folded into a single service-level verdict.
10. `aClusterTheConsumerServiceCannotReachDoesNotDimTheCapabilityForOthers`.
11. `theConsumerServiceBeingDownDimsTheServiceLevelCapability` — the other direction, which *is* a
    transport failure of the upstream service.
12. `theSuggestedPollIntervalIsCarriedInTheDegradedReason` — exit criterion 4's gateway half.
13. `theOpenApiDocumentIncludesTheConsumerEndpoints`.

## Degraded behavior

| Condition | Behaviour |
| --- | --- |
| Consumer service down | Every consumer section `Unavailable` with the reason; the service-level `consumer` capability dims; the sidebar entry is dimmed and clickable and lands on the fallback panel; **the topic page's other sections are untouched** (exit criterion 5) |
| Consumer service slow | Bounded by the per-upstream timeout; the section is `Unavailable` with a timeout reason and the rest of the page renders |
| One cluster unreachable | That cluster's `consumer` capability reports it; every other cluster is unaffected |
| Topic service absent | The `topics` section is `NotConfigured`, which the browser hides rather than showing as an error |
